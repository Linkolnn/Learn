# Блок 1: Архитектура сетей и интернет (Основы)

Этот этап необходим, чтобы понимать, что происходит, когда пользователь вводит адрес сайта в строку браузера.

- **Модель OSI и стек TCP/IP.** Понимание 7 уровней сетевой модели и реального 4-уровневого стека интернета.
- **Физический и канальный уровни.** Работа коммутаторов (switches), MAC-адреса, ARP-протокол.
- **Сетевой уровень (Network).** IP-адресация (IPv4, IPv6), подсети, маски, базовая маршрутизация и протоколы (OSPF, BGP).
- **Транспортный уровень.** Разница между надежным TCP (трехэтапное рукопожатие, контроль перегрузок) и быстрым UDP.
- **Прикладной уровень.** Работа протокола DNS (разрешение имен в IP), DHCP (автоматическое получение настроек сети).
- **Протоколы веб-передачи.** Глубокое изучение HTTP/HTTPS (методы GET/POST, коды ответов, заголовки, куки).
- **Инструменты.** Базовая работа в консоли (ping, traceroute, nslookup) и анализ сетевых пакетов в Wireshark.

Блок 2: Фронтенд-разработка (Frontend)

Переход к созданию визуальной и интерактивной части веб-сайтов, которая работает внутри браузера.

- **Верстка (HTML5 & CSS3).** Семантическая структура страницы, блочная модель (Box Model), флексы (Flexbox), сетки (Grid), адаптивность под мобильные устройства (Media Queries).
- **Базовый JavaScript (ES6+).** Синтаксис, типы данных, работа с DOM (управление элементами на странице), обработка событий (клики, ввод текста).
- **Асинхронный JavaScript.** Работа с API браузера, fetch, промисы (Promises), синтаксис async/await. На этом этапе вы соединяете Блок 1 с фронтендом, делая сетевые запросы к серверам.
- **Сборщики и инструменты.** Система контроля версий Git, работа с GitHub, пакетный менеджер npm, базовые сборщики (Vite или Webpack).
- **Фронтенд-фреймворк.** Изучение одного из популярных инструментов на выбор: React (рекомендуется как самый востребованный), Vue.js или Angular. Компонентный подход и управление состоянием.

Блок 3: Бэкенд и переход в Фуллстек (Backend & Fullstack)

Разработка серверной логики, которая обрабатывает запросы от фронтенда, сохраняет данные и обеспечивает безопасность.

- **Серверный язык и среда.** Изучение Node.js и фреймворка Express (для JS-разработчиков это самый быстрый путь в фуллстек). Альтернативы: Python (FastAPI/Django) или Go.
- **Проектирование API.** Архитектурный стиль REST API (правильные URL, статус-коды, JSON-формат для обмена данными), основы WebSocket для работы в реальном времени.
- **Базы данных (БД).** Реляционные БД (PostgreSQL или MySQL) и язык запросов SQL (таблицы, связи, индексы). Нереляционные БД (MongoDB) для хранения документов.
- **Авторизация и безопасность.** Механизмы сессий, работа с JWT (JSON Web Tokens), хеширование паролей (bcrypt), основы веб-безопасности (защита от CORS, XSS, CSRF атак).
- **Деплой и окружение.** Работа в терминале Linux, контейнеризация приложений с помощью Docker, оркестрация и развертывание проекта на облачный сервер (VPS).

Детализированный план обучения (Месяцы 1–3)

План совмещает теорию сетей, низкоуровневое программирование на **C (Си)** для понимания алгоритмов и переход к веб-технологиям.

Месяц 1: Архитектура сетей и погружение в язык C

**Цель:** Понять, как пакеты ходят по сети, и освоить синтаксис C для работы с памятью.

- **Неделя 1: Модель OSI и стек TCP/IP**
    - _Теория:_ Разбор уровней: от физического провода до протокола HTTP.
    - _Практика:_ Установка анализатора трафика [Wireshark](https://www.wireshark.org/). Перехватите свой первый незашифрованный HTTP-пакет и посмотрите его заголовки.
    - _Источники:_ Плейлист «Компьютерные сети» Андрея Созыкина (Смотреть видео 1–10).
- **Неделя 2: IP-адресация и Маршрутизация**
    - _Теория:_ IPv4, маски подсетей (CIDR), NAT, работа DNS и DHCP.
    - _Практика:_ В консоли (терминале) вбейте команды `ping`, `traceroute` (или `tracert`) до сайта google.com. Разберитесь, через сколько узлов прошел ваш запрос.
    - _Источники:_ Статья «Как работает DNS» на MDN Web Docs.
- **Неделя 3: Основы языка C (Си)**
    - _Теория:_ Переменные, типы данных, циклы, функции и самое важное — **указатели** (работа с адресами памяти).
    - _Практика:_ Написать простую программу на Си, которая меняет значения двух переменных местами с помощью указателей.
    - _Источники:_ Легендарный курс [Гарвардского университета CS50 на русском](https://www.youtube.com/playlist?list=PLawfWYMUziZqyUL5QDLVbe3j5BKWj42E5) (Лекции 1, 2 и 3).
- **Неделя 4: Транспортный уровень и Сетевой код**
    - _Теория:_ Разница между TCP и UDP. Понятие сетевого порта.
    - _Практика:_ Попробуйте написать в коде Си простейший сетевой сокет (Socket), который умеет отправлять строку текста на локальный сервер.
    - _Источники:_ Документация [Beej's Guide to Network Programming](https://beej.us/guide/bgnet/) (лучший мировой гид по сокетам, можно использовать переводчик).

    - _Источники:_ Раздел [«Сетевые запросы» на learn.javascript.ru](https://learn.javascript.ru/network).

Подробная программа по неделям

Неделя 1: Модель OSI, стек TCP/IP и первый перехват пакетов

**Цель:** Понять абстракцию, по которой построен интернет, и увидеть реальный сетевой трафик.

- **Что изучить (Теория):**
    - Разница между эталонной 7-уровневой моделью OSI и реальной 4-уровневой TCP/IP.
    - Зачем нужны уровни (Физический, Канальный, Сетевой, Транспортный, Прикладной) и как они общаются друг с другом.
    - Процесс **инкапсуляции**: как ваши данные «одеваются» в заголовки разных уровней (данные → сегмент → пакет → кадр).
    **Что читать у Таненбаума:**
    - **Глава 1: Введение.**
    - Раздел **1.3 «Сетевое программное обеспечение»** (особенно подразделы про иерархию протоколов, разработку уровней и интерфейсы).
    - Раздел **1.4 «Эталонные модели»** (подробное сравнение модели OSI и модели TCP/IP, а также критика обеих моделей).
- **Практика:**
    1. Посмотрите видео 1–6 из бесплатного курса «Компьютерные сети» Андрея Созыкина.
    2. Запустите Wireshark, выберите свой сетевой адаптер (Wi-Fi или Ethernet) и включите запись трафика. Откройте любой незашифрованный сайт (например, `http://httpbin.org`) и найдите в Wireshark строку `HTTP GET`. Разверните её и посмотрите, из каких уровней состоит этот пакет.

Неделя 2: IP-адресация, маршрутизация и DNS

**Цель:** Разобраться, как компьютеры находят друг друга в глобальной сети.

- **Что изучить (Теория):**
    - Что такое IP-адрес (IPv4) и из каких двух частей он состоит (сеть и хост).
    - Маски подсетей и CIDR-нотация (например, что значит `/24` в конце IP).
    - Разница между белыми (публичными) и серыми (приватными) IP-адресами. Как технология **NAT** спасает интернет от нехватки адресов.
    - Протокол **DNS**: как текстовое имя `google.com` превращается в IP-адрес `142.250.186.46`.
    **Что читать у Таненбаума:**
    - **Глава 5: Сетевой уровень.**
    - Раздел **5.6 «Сетевой уровень в интернете»** (подразделы: _IP-протокол_, _IP-адреса_, _CIDR — бесклассовая междоменная маршрутизация_, _NAT — трансляция сетевых адресов_).
    - **Глава 7: Прикладной уровень.**
    - Раздел **7.1 «DNS — система доменных имен»** (как устроено пространство имен и как работают серверы имен).
- **Практика:**
    1. Прочитайте статью «Что такое IP-адрес» на MDN.
    2. Откройте терминал (командную строку) и выполните команду `nslookup yandex.ru`, чтобы узнать IP-адреса сервера.
    3. Выполните команду `traceroute google.com` (на Windows — `tracert google.com`), чтобы увидеть цепочку роутеров, через которые ваш запрос летит до дата-центра Google.

Неделя 3: Старт в языке Си (C) и управление памятью

**Цель:** Освоить базовый синтаксис Си и понять, как устроена оперативная память.

- **Что изучить (Теория):**
    - Почему Си — компилируемый язык и чем он отличается от интерпретируемых.
    - Базовые кирпичики: переменные, жесткие типы данных (`int`, `char`, `float`), циклы (`for`, `while`) и условия (`if/else`).
    - Главная тема Си: **Указатели (Pointers)**. Что такое адрес переменной в памяти и как на него сослаться.
    - **Где читать:** Книга Таненбаума здесь выступает как ментальный ориентир. Понимание того, как работают указатели в Си, напрямую связано с тем, как устроена оперативная память компьютера и буферы сетевых карт, о которых Таненбаум пишет в контексте канального уровня (Глава 3).
- **Практика:**
    1. Посмотрите первые 3 лекции [Гарвардского курса CS50 на русском](https://www.youtube.com/playlist?list=PLawfWYMUziZqyUL5QDLVbe3j5BKWj42E5).
    2. Напишите в VS Code свою первую программу: пусть она принимает от пользователя два числа, сохраняет их в переменные, а затем с помощью указателей меняет их значения в памяти местами. Разберитесь с операторами `&` (взятие адреса) и `*` (разыменование).

Неделя 4: Транспортный уровень (TCP vs UDP) и Сетевые Сокеты

**Цель:** Объединить знания о сетях и программировании, написав программу, которая умеет слать данные по сети.

- **Что изучить (Теория):**

Неделя 5: Сложность алгоритмов и Массивы

- **Что изучить (Теория):**

    - Разница между временной сложностью (Time Complexity) и пространственной (Space Complexity).
    - Оценка худшего, среднего и лучшего случаев.

- **Практика:**

Неделя 6: Алгоритмы сортировки и Рекурсия

- **Что изучить (Теория):**
    - Понятие **рекурсии**: как функция вызывает саму себя, что такое базовый случай (условие выхода) и как устроен стек вызовов (Call Stack) в памяти.
    - Простые сортировки: Пузырьком (Bubble Sort) и Вставками (Insertion Sort) со сложностью O(n²).
    - Эффективные сортировки: Быстрая сортировка (QuickSort) со средней сложностью \(O(n \log n)\), работающая по принципу «разделяй и властвуй».
- **Практика:**
    1. Напишите рекурсивную функцию для вычисления чисел Фибоначчи или факториала на Си.
    2. Реализуйте алгоритм QuickSort на Си вручную. Сравните его скорость работы на больших массивах с сортировкой пузырьком.
- **Источники:**
    - _Книга Фило:_ Глава 2 «Рекурсия» и Глава 4 «Сортировка».

Неделя 7: Динамические структуры данных (Связанные списки, Стек, Очередь)

    - Что такое **структуры (`struct`)** в Си.
    - Односвязные и двусвязные списки (Linked Lists): узлы, хранящие данные и указатель на следующий элемент.
    - Концепции Стека (LIFO — последним пришел, первым ушел) и Очереди (FIFO — первым пришел, первым ушел).
- **Практика:**

Неделя 8: Хеш-таблицы и Деревья поиска

- **Что изучить (Теория):**
    - Идея хэширования. Хэш-функции и требования к ним.
    - Что такое **Хеш-таблица** и как она обеспечивает поиск за фантастические O(1). Проблема коллизий и методы их решения (метод цепочек через связанные списки).
    - Иерархические структуры: Деревья.
    - Бинарное дерево поиска (BST): правила построения (все, что меньше корня — налево, все, что больше — направо) и скорость поиска \(O(\log n)\).
- **Практика:**

    - _Интерактивная карта:_ [Roadmap.sh — Data Structures and Algorithms](https://roadmap.sh/computer-science) (используйте для самопроверки, все ли термины из списка вам знакомы).

Неделя 15: Знакомство с React, Компоненты и JSX

- **Что изучить (Теория):**

    - Передача данных в компоненты через атрибуты (**Props**).
- **Практика:**
    1. Создайте новый проект на Vite, но теперь укажите шаблон React: `npm create vite@latest my-react-app -- --template react`.
    2. Напишите свой первый кастомный компонент (например, `Button` или `Card`), передайте в него разные тексты через `props` и отрендерите его на странице несколько раз с разными данными.
- **Источники:**
    - _Официальный сайт:_ Документация React — Быстрый старт (рекомендуется читать на английском или использовать встроенный переводчик браузера, так как это первоисточник).

Неделя 16: Состояние компонента (State) и работа с Хуками

- **Что изучить (Теория):**
    - Что такое **Состояние (State)** компонента и чем оно отличается от Props (Props — неизменяемые данные извне, State — внутренние изменяемые данные компонента).
    - Хук **`useState`**: как заставить React перерисовать компонент, когда пользователь что-то ввел или кликнул.
    - Работа со списками в React: как с помощью метода массивов `.map()` превратить массив обычных данных (строк или объектов) в массив JSX-компонентов.
    - Жизненный цикл компонента и хук **`useEffect`**: где именно внутри React-приложения нужно делать `fetch`-запросы к серверу, чтобы не вызвать бесконечный цикл обновлений.
- **Практика:**
    1. Напишите классическое приложение **Todo App (Список задач)** на React.
    2. В нем должна быть форма для ввода новой задачи, список текущих задач (выводимый через `.map()`), кнопка удаления задачи (меняющая `state`) и счетчик выполненных дел. Это задание — главный лакмусовый лист того, что вы поняли логику работы реактивного фреймворка.
- **Источники:**
    - _Раздел документации:_ [React — Managing State](https://react.dev/learn/managing-state).
    - _Практический интерактивный курс:_ [Scूटba/Scrimba React Course](https://scrimba.com/learn/learnreact) (удобный бесплатный формат, где можно ставить видео на паузу и писать код прямо внутри видеоплеера).

# Блок 3: Бэкенд и переход в Фуллстек (Backend & Fullstack)
## Месяц 5: Старт в Бэкенде (Node.js & Express) и проектирование API

**Главная цель месяца:** Понять, как работает серверная сторона веб-приложений. Вы научитесь запускать JavaScript вне браузера, обрабатывать сетевые запросы (которые вы научились слать в Месяце 3) и строить архитектуру **REST API** для обмена данными между вашим фронтендом и сервером.

Основным учебным материалом на этом этапе станут документация Express и продвинутые разделы учебника JavaScript.

Неделя 17: Анатомия бэкенда на Node.js и глобальные объекты

- **Что изучить (Теория):**
    - Как устроен Node.js «под капотом»: движок V8 (из Chrome) и библиотека Libuv, обеспечивающая асинхронность.
    - Понятие **Event Loop (Цикл событий)** в Node.js.
    - Отличия серверного JS от браузерного: отсутствие объектов `window` и `document`, но появление встроенных модулей для работы с операционной системой и файлами (`fs`, `path`, `os`).
    - Работа с переменными окружения через файл `.env` для безопасного хранения секретных ключей и портов.
- **Практика:**
    1. Напишите скрипт на Node.js, который с помощью модуля `fs` считывает текстовый файл с вашего компьютера, находит в нем определенные слова и записывает результат анализа в новый файл.
    2. Разберитесь, как передавать аргументы в скрипт через терминал с помощью `process.argv`.
- **Источники:**
    - _Документация:_ [Официальные руководства Node.js (Гайды по API)](https://nodejs.org/en/learn/asynchronous-work/overview-of-blocking-vs-non-blocking).
    - _Учебник:_ Разделы по Node.js в конце [learn.javascript.ru](https://learn.javascript.ru/).

Неделя 18: Создание HTTP-сервера и фреймворк Express

- **Что изучить (Теория):**
    - Как Node.js слушает сетевой порт (вспоминаем Месяц 1) и ловит входящие TCP/HTTP запросы.
    - Зачем нужен фреймворк **Express** (стандарт индустрии для создания веб-серверов на Node.js).
    - Понятие Маршрутизации (Routing): как сервер понимает, какую функцию запустить, если пользователь пришел на адрес `/users`, а какую — если на `/products`.
    - Что такое **Middleware (Промежуточное ПО)** — концепция функций-фильтров, через которые запрос проходит последовательно от получения сервером до отправки ответа.
- **Практика:**
    1. Установите Express через npm: `npm install express`.
    2. Напишите свой первый сервер, который слушает порт `5000` и на запрос по адресу `GET /api/hello` возвращает JSON-объект вида `{ message: "Привет из бэкенда!" }`.
- **Источники:**
    - _Сайт фреймворка:_ Express.js — Начало работы (полностью переведен на русский язык).
    - _Видеокурс:_ Плейлист по Node.js и Express от Владилена Минина на YouTube (отличная бесплатная база).

Неделя 19: Архитектура REST API и CRUD-операции

- **Что изучить (Теория):**
    - Принципы построения **REST API** (клиент-серверная независимость, отсутствие состояния).
    - Что такое **CRUD** (Create, Read, Update, Delete) — четыре базовые функции управления данными.
    - Правильное использование HTTP-методов: `GET` (чтение), `POST` (создание), `PUT`/`PATCH` (обновление), `DELETE` (удаление).
    - Передача параметров в запросе: Query параметры (`/products?category=shoes`), URL-параметры (`/products/:id`) и тело запроса (`req.body` в формате JSON).
- **Практика:**
    1. Создайте полноценное REST API для управления списком задач (ToDo), но пока без постоянной базы данных — храните данные прямо в оперативной памяти сервера в виде обычного массива JS-объектов.
    2. Реализуйте эндпоинты для получения всех задач, добавления новой, обновления статуса (выполнено/нет) и удаления по ID. Протестируйте работу вашего API с помощью бесплатной программы [Postman](https://www.postman.com/) или расширения _Thunder Client_ внутри VS Code.
- **Источники:**
    - _Гайд:_ [Статья «Что такое REST API» на Хабре](https://habr.com/ru/articles/483202/) (с хорошими архитектурными примерами).
    - _Практика:_ [Раздел по REST в треке roadmap.sh/backend](https://roadmap.sh/backend).

Неделя 20: Связь Фронтенда с Бэкендом и проблема CORS

- **Что изучить (Теория):**
    - Как объединить React-приложение (из Месяца 4) с сервером на Express.
    - Что такое **Политика одного источника (Same-Origin Policy)** в браузерах.
    - Ошибка **CORS (Cross-Origin Resource Sharing)**: почему браузер блокирует запросы от вашего React-приложения (работающего на порту `5173`) к вашему серверу Express (на порту `5000`), и как правильно настроить заголовки ответа на сервере, чтобы разрешить доступ.
- **Практика:**
    1. Возьмите ваше React-приложение Todo App из Недели 16.
    2. Перепишите его логику: вместо сохранения задач во внутреннем стейте React, используйте хук `useEffect` и метод `fetch()`, чтобы при загрузке страницы скачивать задачи с вашего Express-сервера (созданного на Неделе 19). При добавлении новой задачи делайте `fetch(..., { method: 'POST' })`.
    3. Установите middleware `cors` на сервер Express, чтобы подружить фронтенд и бэкенд.
- **Источники:**
    - _Документация:_ Что такое CORS на MDN Web Docs.
    - _Пакет:_ [Документация модуля cors на npm](https://www.npmjs.com/package/cors).

**Главная цель месяца:** Сделать так, чтобы данные не пропадали при перезапуске сервера, защитить приложение от взлома и выложить готовый Fullstack-проект на настоящий сервер в интернет.

Неделя 21: Реляционные базы данных и язык SQL

- **Что изучить (Теория):**
    - Зачем нужны СУБД (Системы управления базами данных). Разница между SQL (таблицы, связи) и NoSQL (документы).
    - Установка и базовая теория **PostgreSQL** (или MySQL).
    - Язык запросов **SQL**: создание таблиц (`CREATE TABLE`), вставка данных (`INSERT`), выборка (`SELECT` с фильтрацией `WHERE`), обновление и удаление.
    - Связи между таблицами (Один-ко-многим, Многие-ко-многим) и внешние ключи (`FOREIGN KEY`).
- **Практика:**
    1. Установите PostgreSQL на компьютер.
    2. Напишите SQL-запросы, чтобы создать таблицу `users` и таблицу `todos`. Настройте связь между ними так, чтобы у каждой задачи был ID автора из таблицы пользователей.
- **Источники:**
    - _Интерактивный тренажер:_ [SQL Academy](https://sql-academy.org/ru) — бесплатный ресурс, где можно писать SQL-запросы прямо в браузере и решать задачи.
    - _Курс:_ Курс по PostgreSQL на Stepik или плейлисты на YouTube (например, от канала _Oleg Shpagin_).

Неделя 22: Интеграция БД в Node.js и ORM-системы

- **Что изучить (Теория):**
    - Как Node.js общается с базой данных через специальные драйверы-клиенты (модуль `pg`).
    - Что такое **ORM (Object-Relational Mapping)** — технология, которая позволяет работать с таблицами базы данных как с обычными JS-объектами, не написав ни одной строчки чистого SQL-кода.
    - Изучение популярной современной ORM для Node.js — **Prisma** (или Sequelize).
- **Практика:**
    1. Подключите Prisma к вашему Express-серверу.
    2. Перепишите эндпоинты вашего API: теперь при запросе `POST /api/todos` сервер должен не пушить элемент в массив, а делать асинхронный вызов к базе данных (например, `await prisma.todo.create({ data: ... })`). Теперь ваши данные будут сохраняться вечно, даже если выключить компьютер.
- **Источники:**
    - _Документация:_ [Prisma ORM — Quickstart guide](https://www.prisma.io/docs/getting-started/quickstart) (эталонная документация с пошаговыми схемами).

Неделя 23: Аутентификация, Пароли и JWT (Безопасность)

- **Что изучить (Теория):**
    - Почему нельзя хранить пароли пользователей в базе данных в чистом виде. Что такое хэширование и библиотека `bcrypt`.
    - Как сервер понимает, какой именно пользователь делает запрос. Механизм **JWT (JSON Web Tokens)**.
    - Анатомия токена: Header, Payload (полезная нагрузка с ID пользователя), Signature (цифровая подпись сервера).
    - Как фронтенд сохраняет токен (в `localStorage` или защищенные куки) и прикрепляет его к заголовкам HTTP-запроса (`Authorization: Bearer <token>`).
- **Практика:**
    1. Создайте эндпоинты `POST /api/auth/register` (хэширует пароль и сохраняет юзера в БД) и `POST /api/auth/login` (проверяет пароль и выдает сгенерированный JWT-токен).
    2. Напишите middleware-фильтр для Express, который проверяет токен. Если токен валидный — пропускает запрос к задачам, если нет — возвращает ошибку `401 Unauthorized`.
- **Источники:**
    - _Сайт технологии:_ [JWT.io](https://jwt.io/) — здесь можно вставить свой токен и визуально посмотреть, из каких частей он состоит.
    - _Учебник:_ Раздел «Безопасность» на learn.javascript.ru.

Неделя 24: Контейнеризация (Docker) и Деплой проекта на VPS

- **Что изучить (Теория):**
    - Проблема «На моем компьютере все работает, а на сервере сломалось».
    - Что такое **Docker** и как он изолирует ваше приложение (Node.js + PostgreSQL) в независимый виртуальный контейнер. Понятие `Dockerfile` и `docker-compose.yml`.
    - Что такое облачный сервер (**VPS/VDS**) и как подключиться к нему по протоколу SSH через терминал (привет из Месяца 1).
- **Практика:**
    1. Напишите простой `Dockerfile` для своего бэкенда.
    2. Арендуйте самый дешевый Linux-сервер (например, на Ubuntu у любого хостинга).
    3. Подключитесь по SSH, установите туда Docker, склонируйте свой проект с GitHub и запустите его командой `docker compose up --build`. Ваш сайт теперь работает 24/7 по публичному IP-адресу в интернете.
- **Источники:**
    - _Гайд:_ Docker для новичков — статья на Хабре.
    - _Интерактивный трек:_ [Roadmap.sh — DevOps (раздел Docker)](https://roadmap.sh/devops).
