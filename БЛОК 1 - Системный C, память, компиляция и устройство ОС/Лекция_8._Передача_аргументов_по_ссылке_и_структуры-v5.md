# Лекция 8: Передача аргументов по ссылке и структуры

В предыдущих лекциях мы изучили функции и стек вызовов, а также детально разобрали указатели и их связь с оперативной памятью (ОЗУ). Теперь пришло время объединить эти две фундаментальные концепции. Мы узнаем, как преодолеть ограничение передачи аргументов по значению, научимся создавать сложные пользовательские типы данных (структуры) и разберем, как компилятор упаковывает и выравнивает их в физической памяти компьютера.

## Подглава 8.1: Передача параметров по ссылке (Pass by Reference)

В Лекции 7 мы детально разобрали, что при обычном вызове функции все параметры передаются **по значению** (Pass by Value). Компилятор создает изолированную **копию** переменной на вершине стека во фрейме вызываемой функции. Любые изменения этой копии никак не влияют на оригинальную переменную в вызывающей функции (например, в `main`).

Но что делать, если функция *должна* изменить оригинальные данные? Для этого в Си применяется **передача аргументов по ссылке** (Pass by Reference).

### Физический смысл передачи по ссылке

Вместо того чтобы копировать само значение переменной, мы передаем функции **её физический адрес в оперативной памяти** (указатель). 

В этом случае:
1. Во фрейме стека вызываемой функции создается переменная-указатель (размером 8 байт на 64-битной системе).
2. В этот указатель копируется адрес оригинальной переменной из фрейма вызывающей функции (например, из `main`).
3. Используя оператор разыменования `*`, вызываемая функция может зайти по этому адресу напрямую в ОЗУ и перезаписать оригинальные данные.

### Пример кода: работающий инкремент

Давайте перепишем функцию инкремента, которая теперь действительно увеличивает значение оригинальной переменной:

```c
#include <stdio.h>

// Функция принимает указатель на целое число
void increment_value(int *num) {
    // Разыменовываем указатель и прибавляем единицу к значению в ОЗУ
    (*num) = (*num) + 1; 
}

int main() {
    int x = 10;
    
    // Передаем адрес переменной x с помощью оператора взятия адреса (&)
    increment_value(&x); 
    
    printf("Значение x в main после вызова функции: %d\n", x); // Выведет 11!
    return 0;
}
```

### Как этот код выполняется в ОЗУ по шагам:

1. В ОЗУ во фрейме функции `main` выделяется 4 байта под переменную `x` со значением `10` (допустим, по адресу `0x3000`).
2. При вызове `increment_value(&x)` в стек помещается адрес `0x3000`.
3. На вершине стека создается фрейм функции `increment_value`, где под переменную `num` (тип `int *`) выделяется 8 байт. В неё записывается адрес `0x3000`.
4. Команда `(*num) = (*num) + 1` заставляет процессор:
   * Прочесть значение по адресу из `num` (из ячейки `0x3000` считывается число `10`).
   * Сложить `10 + 1 = 11`.
   * Записать результат `11` обратно по адресу `0x3000`.
5. При выходе из функции фрейм `increment_value` уничтожается, но оригинальная переменная `x` по адресу `0x3000` теперь хранит новое число `11`.

## Подглава 8.2: Структуры данных (struct) — организация памяти

До сих пор мы работали только с простыми встроенными типами данных (`char`, `int`, `float`, `double`) или их однородными наборами (массивами). Однако в реальной жизни объекты гораздо сложнее. Например, географическая точка на карте описывается парой координат (широта и долгота), а карточка пользователя содержит имя, возраст и рейтинг.

Для группировки разнородных переменных под одним именем в языке Си существуют **структуры** (`struct`). Структуры являются фундаментом для построения объектов и классов.

### Синтаксис объявления структуры

Чтобы объявить структуру, используется ключевое слово `struct`, за которым следует имя структуры (тег) и список её членов (полей) в фигурных скобках:

```c
struct point {
    int x; // Координата X
    int y; // Координата Y
};
```

Теперь мы можем создавать переменные этого типа и обращаться к их полям через **оператор "точка" (`.`)**:

```c
#include <stdio.h>

struct point {
    int x;
    int y;
};

int main() {
    struct point p1; // Создаем экземпляр структуры
    p1.x = 10;       // Записываем значение в поле x
    p1.y = 5;        // Записываем значение в поле y

    printf("Координаты точки: X = %d, Y = %d\n", p1.x, p1.y);
    return 0;
}
```

### Что такое «экземпляр структуры»? (Чертеж против готового дома)

Чтобы понять, что такое «экземпляр структуры» (его также часто называют *объектом структуры*), давайте разделим процесс работы со структурами в Си на два принципиально разных этапа.

#### Этап 1: Описание структуры (Создание чертежа)

Когда мы описываем структуру в коде:

```c
struct person {
    char *name;
    int age;
};
```

Мы **не создаем** никаких данных. Мы просто пишем **чертеж** (шаблон, рецепт или новый пользовательский тип данных). 
* На этом этапе компьютер **не выделяет ни одного байта** в оперативной памяти (ОЗУ).
* Процессор ничего не знает о существовании конкретных людей. Мы просто объяснили компилятору: *«Если я когда-нибудь захочу создать человека (person), помни, что он должен состоять из указателя на имя (8 байт) и возраста (4 байта)»*.

Вы не можете жить в чертеже дома. Точно так же вы не можете написать `person.age = 20;` — компилятор выдаст ошибку, потому что физически в памяти еще нет места, куда это число можно записать.

#### Этап 2: Создание экземпляра структуры (Строительство дома)

А вот когда внутри функции мы пишем:

```c
struct person student; // Создаем физический экземпляр структуры
```

Вот это и есть **создание экземпляра структуры**. В этот самый момент компилятор:
1. Берет наш «чертеж» под названием `struct person`.
2. Видит, что для него требуется определенный объем памяти в ОЗУ.
3. **Физически выделяет** эту память на Стеке вызовов.
4. Закрепляет за этим выделенным участком памяти имя `student` и конкретный физический адрес в ОЗУ.

**Экземпляр (или объект)** — это и есть та самая конкретная, физически существующая в оперативной памяти переменная `student`, построенная по чертежу `struct person`. Теперь у нас есть реальное место в ОЗУ, и мы можем начать записывать туда данные: `student.age = 20;`.

По одному и тому же чертежу можно построить сколько угодно независимых экземпляров одной структуры:

```c
struct person student1; // Первый физический экземпляр в памяти
struct person student2; // Второй физический экземпляр в памяти
struct person student3; // Третий физический экземпляр в памяти
```

Каждый из них живет в своем собственном уникальном месте в ОЗУ, у каждого свои значения полей, но все они построены по единому правилу `struct person`.

### Размещение структур в оперативной памяти

На низком уровне структура — это **единый непрерывный блок байт в ОЗУ**, внутри которого поля располагаются строго в том порядке, в котором они объявлены в коде.

Для структуры `point p1`:
* Поле `x` (тип `int`, 4 байта) занимает первые 4 байта блока структуры.
* Поле `y` (тип `int`, 4 байта) занимает следующие 4 байта.
* Итоговый физический размер структуры в памяти составляет 4 + 4 = 8 байт.

## Подглава 8.2.1: Выравнивание данных в памяти (Structure Padding)

Казалось бы, размер структуры всегда должен быть равен простой сумме размеров всех её полей. Но в системном программировании это не так. Давайте рассмотрим следующую структуру:

```c
struct sample {
    char a; // 1 байт
    int b;  // 4 байта
};
```

Математическая сумма полей: 1 + 4 = 5 байт. Но если мы выведем размер этой структуры на экран с помощью встроенного оператора `sizeof(struct sample)`, мы увидим сюрприз: размер равен **8 байтам**! Куда делись еще 3 байта?

### Что такое выравнивание (Alignment) и падинг (Padding)?

Современные процессоры считывают данные из оперативной памяти не по одному байту, а целыми блоками по 4 или 8 байт (в зависимости от разрядности шины данных). Такие блоки называют **машинными словами**.

Если переменная размером 4 байта (например, тип `int`) расположена в памяти по «неровному» адресу (не кратному 4), процессору для её чтения придется сделать **два цикла обращения к ОЗУ** вместо одного, а затем программно склеивать полученные части. Это сильно снижает производительность системы.

Чтобы избежать этого, компилятор Си автоматически применяет **выравнивание данных (Alignment)**. Он размещает переменные в памяти только по адресам, кратным их размеру. Для этого компилятор вставляет между полями структуры невидимые пустые байты-заполнители — **падинг (Padding)**.

### Физическое устройство структуры sample в ОЗУ:

```text
Байт:        [  0  ] [  1  ] [  2  ] [  3  ] [  4  ] [  5  ] [  6  ] [  7  ]
Содержимое:  [  a  ] [    пусто (падинг)    ] [             b             ]
Размер:      |<-------- char (1 б) -------->|<---------- int (4 б) --------->|
```

* Поле `char a` помещается в байт 0.
* Поле `int b` требует адреса, кратного 4. Поэтому компилятор оставляет байты 1, 2 и 3 пустыми (падинг) и записывает `b` в байты 4, 5, 6 и 7.
* В результате структура занимает в ОЗУ два полных машинных слова (8 байт), обеспечивая процессору максимально быстрое чтение поля `b` за один такт.

## Подглава 8.3: Ключевое слово typedef

Писать каждый раз словосочетание `struct имя_структуры` при объявлении новых переменных довольно утомительно. Чтобы сделать код более лаконичным и читаемым, в Си используют ключевое слово **`typedef`** (определение типа).

`typedef` позволяет дать любому типу данных новое, более короткое имя (псевдоним).

### Синтаксис создания структур с typedef

Мы можем объединить объявление структуры и создание её псевдонима в одну конструкцию:

```c
typedef struct {
    char *name; // Указатель на строку (имя)
    int age;    // Возраст
} person;
```

Теперь мы можем объявлять новые переменные этого типа напрямую:

```c
person student;
student.name = "Алексей";
student.age = 20;

// Выводим данные на экран (используя %s для имени)
printf("Имя: %s, Возраст: %d\n", student.name, student.age);
```

### Краткая справка: как работают строки в текущих примерах

Вы могли заметить, что в полях структуры мы объявили переменную `char *name` и присвоили ей текстовое значение `"Алексей"`, а также выводили его на экран через спецификатор `%s` в `printf`. 

Полноценно и во всех деталях устройство строк в Си мы разберем в **Лекции 9**, но для выполнения текущих задач достаточно понимать простой низкоуровневый принцип:
1. Тип `char *` — это указатель на символ (адрес первой буквы текста в памяти).
2. Любой текстовый литерал в кавычках (например, `"Алексей"`) компилятор сохраняет в ОЗУ как непрерывную цепочку символов, а в самом конце автоматически дописывает невидимый **нулевой байт (нуль-терминатор `\0`)** в качестве маркера завершения.
3. Спецификатор `%s` сообщает функции `printf` команду: *«Возьми адрес первой буквы из указателя и выводи символы на экран один за другим, пока не встретишь нулевой байт»*.


Структуры также могут содержать указатели на другие типы данных и даже указатели на структуры того же типа. Это свойство является базой для построения сложных динамических цепочек в ОЗУ — связанных списков и бинарных деревьев.

## Подглава 8.4: Указатели на структуры и оператор «стрелка» (->)

Передача целой структуры в функцию обычным способом (по значению) крайне неэффективна. Если структура содержит десятки полей (например, массивы или длинные строки) и занимает 500 байт, то при вызове функции все эти 500 байт будут физически скопированы на стек вызовов, перегружая память и тратя процессорное время.

Поэтому в профессиональном Си-программировании структуры **практически всегда передают в функции по ссылке (через указатели)**. Даже если функцию не просят изменить структуру, передача 8-байтового адреса вместо копирования всей структуры экономит колоссальный объем ресурсов.

### Синтаксис доступа через указатель

Допустим, у нас есть указатель на структуру:

```c
person john;
person *ptr = &john;
```

Если мы попытаемся получить доступ к полям через обычное разыменование, нам придется написать:

```c
(*ptr).age = 21;
```

*Круглые скобки здесь обязательны, так как у оператора "точка" (`.`) приоритет выше, чем у оператора разыменования (`*`). Без скобок компилятор решит, что мы пытаемся разыменовать само поле `ptr.age`.*

### Оператор «стрелка» (->) как удобный синтаксический сахар

Запись `(*ptr).поле` выглядит громоздко и неудобно. Для упрощения этой операции в язык Си добавлен специальный оператор **`->`** (минус и знак больше, образующие стрелочку).

Оператор `->` делает две вещи одновременно: **разыменовывает указатель на структуру и обращается к её полю**.

Запись через стрелку абсолютно эквивалентна записи со скобками:

```c
ptr->age = 21; // Просто, чисто и понятно
```

Давайте посмотрим на полноценный пример использования указателей на структуры:

```c
#include <stdio.h>

typedef struct {
    char *brand;
    int model_year;
} vehicle;

// Функция принимает структуру по ссылке (через указатель)
void update_car_model(vehicle *car, int new_year) {
    // Изменяем поле оригинальной структуры через оператор ->
    car->model_year = new_year; 
}

int main() {
    vehicle my_car;
    my_car.brand = "Ford";
    my_car.model_year = 2018;

    printf("До обновления: %s, %d\n", my_car.brand, my_car.model_year);

    // Передаем адрес структуры в функцию
    update_car_model(&my_car, 2024);

    printf("После обновления: %s, %d\n", my_car.brand, my_car.model_year);
    return 0;
}
```

Напишите программу на Си, в которой:

2. В функции `main` создайте экземпляр этой структуры и инициализируйте её поля (например, имя "Иван", возраст 27).

4. Внутри функции `celebrate_birthday` возраст человека увеличивается на 1, после чего на экран выводится поздравительное сообщение с именем и новым возрастом.
5. Вызовите функцию из `main` и убедитесь, что в оригинальной структуре возраст успешно изменился.

### Задача 2: Расчет физического размера структуры в памяти
Напишите программу на Си, которая наглядно демонстрирует феномен выравнивания данных компилятором:
1. Объявите две структуры с одинаковым набором полей, но в разном порядке:
   * Структура `struct bad_order`, содержащая поля: `char a;` (1 байт), `int b;` (4 байта), `char c;` (1 байт).
   * Структура `struct good_order`, содержащая поля: `char a;` (1 байт), `char c;` (1 байт), `int b;` (4 байта).
2. В функции `main` выведите на экран размер каждой структуры с помощью оператора `sizeof` (например, `sizeof(struct bad_order)`).
3. Объясните в комментариях к коду (или устно), почему размеры этих двух структур различаются, несмотря на то что они содержат абсолютно идентичные переменные. Нарисуйте схемы расположения байтов в ОЗУ для обеих структур (по аналогии со схемой из подглавы 8.2.1).

### Задача 3: Теоретический анализ выравнивания (устно)

2. В чем разница между операторами `.` (точка) и `->` (стрелка)? В каких конкретных случаях мы обязаны использовать каждый из них?

## Подсказки к задачам

* **Подсказка к задаче 1:** Помните, что для увеличения возраста внутри функции `celebrate_birthday` вы должны обратиться к полю структуры через указатель с помощью оператора `->`. Например: `p->age = p->age + 1;` или `p->age++;`. При вызове функции не забудьте передать адрес структуры: `celebrate_birthday(&my_struct);`.
* **Подсказка к задаче 2:** В структуре `bad_order` компилятору придется вставлять падинг дважды, чтобы выровнять поле `b` по кратному адресу и завершить выравнивание самой структуры. * **Подсказка к задаче 3:** Обратите внимание на тип переменной, с которой вы работаете.
