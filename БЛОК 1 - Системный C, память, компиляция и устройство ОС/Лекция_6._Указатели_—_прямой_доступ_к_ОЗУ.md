# Лекция 6: Указатели (Pointers) — прямой доступ к ОЗУ

## Подглава 6.1: Что такое адрес памяти на физическом уровне?

До сих пор мы работали с переменными как с именованными контейнерами для данных. Мы писали `int x = 42;`, и компилятор сам решал, в какую именно ячейку оперативной памяти (ОЗУ) поместить это число. Однако для того чтобы стать профессиональным системным программистом, необходимо убрать эту абстракцию и посмотреть на память глазами процессора.

Как мы знаем из Лекции 1, оперативная память — это гигантский массив однобайтовых ячеек. У каждой такой ячейки есть свой уникальный физический номер — **адрес**. 

### Адрес памяти
Адрес памяти — это обычное беззнаковое целое число. Когда процессор хочет прочитать данные из памяти, он не ищет их по имени "x". Он отправляет числовой адрес нужной ячейки по **адресной шине** в ОЗУ, а ОЗУ в ответ возвращает байты данных по **шине данных**.

> 📌 **Уточнение: физические и виртуальные адреса.** В этой лекции мы упрощаем картину и говорим об «адресе в ОЗУ». На самом деле в современных операционных системах программа работает не с физическими, а с **виртуальными** адресами: специальный блок процессора (MMU) вместе с операционной системой переводит их в физические. Для нас это означает, что числа, которые выведет `%p`, — адреса в «личном» адресном пространстве вашей программы, а не номера ячеек физической планки памяти. Подробно виртуальная память разбирается в Лекции 29.

### Разрядность архитектуры процессора и размер адреса
Почему разрядность процессора (32 бита или 64 бита) так важна для работы с памятью? Разрядность процессора определяет **размер его регистров** и, как следствие, максимальную длину адреса, с которым работают программы (в простейшей модели — адреса, который процессор может отправить по адресной шине).

*   **32-битная архитектура:** 
    Длина адреса памяти составляет ровно 32 бита (4 байта). 
    Максимальное количество уникальных адресов, которые можно закодировать 32 битами, равно:
    2^32 = 4 294 967 296 байт (ровно 4 Гигабайта).
    Даже если физически установить в такой компьютер 16 ГБ оперативной памяти, 32-битный процессор физически не сможет отправить в ОЗУ адрес выше, чем 4 294 967 295. Оставшаяся память окажется для него просто «невидимой». (Существует расширение PAE, позволяющее 32-битной ОС суммарно использовать больше 4 ГБ физической памяти, но адресное пространство каждой отдельной программы всё равно остаётся не больше 4 ГБ, и часть его занимает сама ОС.)
*   **64-битная архитектура:** 
    Длина адреса составляет 64 бита (8 байт). 
    Максимальный объем адресуемой памяти равен:
    2^64 = 18 446 744 073 709 551 616 байт (16 эксбибайт, это около 17 миллиардов гибибайт).
    Этот объём настолько велик, что на практике процессоры используют лишь часть адресных разрядов: например, большинство процессоров x86-64 работают с 48-битными адресами (256 ТиБ).

**Важнейший вывод:** На распространённых 64-битных платформах переменная, хранящая адрес, всегда занимает в ОЗУ ровно **8 байт**, независимо от того, данные какого типа лежат по этому адресу (символ `char` размером 1 байт или число `double` размером 8 байт).

## Подглава 6.2: Объявление указателей и оператор взятия адреса (&)

Чтобы хранить и обрабатывать эти физические адреса ОЗУ в коде нашей программы, в языке Си существует специальный тип данных — **указатели**.

**Указатель (Pointer)** — это переменная, значением которой является не обычное число или символ, а **числовой адрес другой ячейки памяти**.

### Оператор взятия адреса (&)
В языке Си есть специальный унарный оператор **`&`** (амперсанд). Он возвращает адрес переменной в памяти (в адресном пространстве вашей программы).

Давайте посмотрим на простой пример:
```c
#include <stdio.h>

int main() {
    int age = 25;
    printf("Значение переменной age: %d\n", age);
    printf("Адрес переменной age в памяти: %p\n", (void *)&age);
    return 0;
}
```
*   Оператор `&age` приказывает компилятору: «Не бери значение внутри `age`, а найди адрес в памяти, по которому эта переменная размещена».
*   Спецификатор формата **`%p`** в функции `printf` используется специально для вывода адресов в удобном для системного программиста шестнадцатеричном виде (например, `0x7ffdd9a1c8bc`). При каждом запуске адрес может оказаться другим: операционная система намеренно размещает данные по разным адресам (механизм ASLR), поэтому не удивляйтесь, если у вас будет иное число. Зачем в `printf` написано `(void *)` перед `&age`, объясняется в подглаве 6.2.1.

### Синтаксис объявления указателей
Чтобы создать переменную-указатель, способную хранить адрес, мы пишем:
`тип_данных *имя_указателя;`

Символ «звездочка» (`*`) при объявлении сообщает компилятору, что создается именно указатель, а не обычная переменная.

> ⚠️ **Ловушка объявления:** звёздочка относится к имени, а не к типу. Запись `int *a, b;` создаёт указатель `a` и **обычную** переменную `b` типа `int`. Чтобы создать два указателя, пишите `int *a, *b;` (или объявляйте их в разных строках).

Пример:
```c
int num = 42;
int *p = &num; // Создаем указатель p и записываем в него адрес переменной num
```

Давайте визуализируем, как это выглядит в ОЗУ:

```
Адрес в ОЗУ   |  Имя переменной  |  Значение в памяти  |  Тип данных
--------------|------------------|---------------------|------------
0x1000        |  num             |  42                 |  int (4 байта)
--------------|------------------|---------------------|------------
0x1008        |  p               |  0x1000             |  int* (8 байт в 64-бит системе)
```
Адреса в таблице условные. Указатель `p` лежит по адресу `0x1008`, а не `0x1004`, потому что 8-байтовые данные обычно размещаются по адресам, кратным 8 (подробнее о выравнивании — в Лекции 8).

Переменная `p` хранит адрес `0x1000`. Мы говорим, что указатель `p` **указывает** на переменную `num`.

Почему при создании указателя мы обязаны указывать тип данных (например, `int *` или `char *`), если все адреса в 64-битной системе занимают одинаковые 8 байт?
Компилятору крайне важно знать этот тип, чтобы понимать, **сколько байт памяти нужно прочитать или изменить**, когда мы обратимся к данным через этот указатель. Если указатель имеет тип `char *`, то по адресу лежит 1 байт данных. Если `int *` — то (на распространённых платформах) 4 байта.

### Опасность: неинициализированный указатель и NULL
Обычная локальная переменная без инициализации содержит «мусор» — случайные байты, оставшиеся в памяти. Указатель — не исключение: `int *p;` хранит случайный адрес («дикий» указатель). Если разыменовать его (например, `*p = 5;`), программа попытается записать данные по случайному адресу. Это **неопределённое поведение**: в лучшем случае программа аварийно завершится с ошибкой `Segmentation fault` (процессор и ОС обнаружат обращение к недоступной памяти), в худшем — тихо испортит чужие данные.

Чтобы пометить «указатель пока ни на что не указывает», в Си используется специальное значение **`NULL`** (нулевой указатель; определён, в частности, в `<stdio.h>`):
```c
int *p = NULL; // «указатель пока никуда не указывает»
```
Разыменование `NULL` тоже аварийно завершает программу, зато ошибка проявляется сразу и предсказуемо. Правило: **указатель должен либо указывать на реальную переменную, либо быть равен `NULL`, а перед разыменованием нужно быть уверенным, что это не `NULL`** (например, проверить `if (p != NULL)`).

## Подглава 6.2.1: Спецификатор %p, универсальный указатель void* и приведение типов (Casting)

Когда мы выводим адрес переменной с помощью функции `printf` и спецификатора `%p`, мы сталкиваемся с важным правилом стандарта языка Си.

### Почему для %p нужен явный каст?
По стандарту языка Си, спецификатор `%p` ожидает на вход исключительно универсальный (нетипизированный) указатель типа **`void *`**. 

Если мы передадим туда типизированный указатель (например, `int *` или `char *`), компилятор может выдать предупреждение (warning; например, при компиляции с флагом `-Wpedantic`): *«format "%p" expects argument of type "void *", but argument has type "int *"»*. Чтобы программа была строго стандартизированной и компилировалась без предупреждений на любых системах, типизированный указатель нужно явно **привести к типу void***. Формально передача `int *` вместо `void *` — неопределённое поведение, хотя на большинстве платформ программа при этом работает.

### Что такое приведение типов (Type Casting / Каст)?
**Приведение типов (Type Casting)** — это операция, которая заставляет компилятор временно относиться к значению одного типа так, будто оно принадлежит другому типу.

Синтаксис явного приведения типов в Си выглядит очень просто:
`(новый_тип)выражение`

В случае с указателями, когда мы пишем `(void *)ptr`, мы говорим компилятору: *«Забудь на секунду, что ptr указывает на конкретный тип (например, int). Относись к нему просто как к абстрактному, универсальному адресу памяти void*»*.

### Что такое void* (универсальный указатель)?
Указатель типа **`void *`** — это особый тип указателя в Си, который:
1.  **Может хранить адрес любого типа данных** (хоть символа, хоть огромного массива).
2.  **Не имеет привязанного типа**. Это просто «голый» адрес ячейки памяти.
3.  **Его нельзя разыменовать без предварительного указания типа**. Поскольку у типа `void` нет размера, компилятор при попытке разыменования `*p_void` просто не поймет, сколько байт ему нужно считать или записать в ОЗУ — 1, 4 или 8.

### Ключевая дилемма: Почему бы сразу не объявить указатель как void*?
Если тип `void *` такой универсальный и идеально подходит для работы с адресами, почему мы не используем его для всех указателей в программе?

В этом кроется главное архитектурное отличие: **для изменения или чтения значения нам жизненно необходим конкретный тип данных**.

Если мы объявим указатель как `void *ptr = &lives;`, то мы **не сможем** изменить значение переменной `lives` с помощью команды `*ptr = 5;`. Компилятор выдаст ошибку, потому что он не знает, сколько байт в памяти нужно перезаписать по этому адресу. Для типа `int` нужно изменить ровно 4 байта, для `char` — 1 байт, для `double` — 8 байт.

Поэтому в Си используется красивое разделение обязанностей (дуализм):
1.  Мы создаем **строго типизированный указатель** (например, `int *ptr`), чтобы иметь возможность безопасно считывать и изменять данные в памяти: `*ptr = 5;`.
2.  Мы приводим его к **универсальному указателю** `(void *)ptr` исключительно в момент вывода на экран через `%p`, чтобы соблюсти строгий стандарт функции `printf`.

Правильный пример кода:
```c
#include <stdio.h>

int main() {
    int lives = 3;
    int *h = &lives;

    // 1. Изменение значения (работаем через типизированный int* указатель)
    *h = 5;

    // 2. Вывод адреса (приводим int* к void* строго для printf)
    printf("Адрес переменной lives в памяти: %p\n", (void *)h);
    printf("Значение переменной lives: %d\n", *h);

    return 0;
}
```
Вывод (адрес у вас будет другим):
```text
Адрес переменной lives в памяти: 0x7ffc3a1b2c4c
Значение переменной lives: 5
```

## Подглава 6.3: Оператор разыменования (*)

Просто хранить адреса памяти бессмысленно. Самая мощная возможность указателей — это доступ к данным, которые по этим адресам лежат. Для этого используется **оператор разыменования**, который записывается той же звездочкой — **`*`**.

У символа `*` в Си три разных смысла, и важно не путать их:

| Где встречается | Пример | Значение |
|---|---|---|
| Между двумя числами | `a * b` | умножение |
| В объявлении | `int *p;` | «`p` — указатель на `int`» |
| Перед уже объявленным указателем в выражении | `*p = 5;`, `x = *p;` | разыменование |

Когда мы пишем звездочку перед уже объявленным указателем, мы приказываем процессору: «Пройди по адресу, который хранится внутри указателя, и работай напрямую с теми данными, которые там лежат».

Разыменование позволяет решать две задачи:
1.  **Прочесть** значение из ячейки памяти по адресу.
2.  **Записать (изменить)** значение в ячейке памяти по адресу.

Давайте детально разберем этот процесс на примере кода:

```c
#include <stdio.h>

int main() {
    int x = 10;
    int *ptr = &x; // ptr хранит адрес переменной x

    printf("Значение x напрямую: %d\n", x);
    printf("Значение x через указатель ptr: %d\n", *ptr);

    // Меняем значение x через указатель ptr!
    *ptr = 99;

    printf("Новое значение x после изменения через ptr: %d\n", x);

    return 0;
}
```
Вывод программы:
```text
Значение x напрямую: 10
Значение x через указатель ptr: 10
Новое значение x после изменения через ptr: 99
```

### Как этот код выполняется по шагам:
1.  `int x = 10;` — в памяти выделяется 4 байта под переменную `x`, туда записывается число `10`.
2.  `int *ptr = &x;` — выделяется 8 байт под указатель `ptr`. В него копируется числовой адрес переменной `x`.
3.  `*ptr` в первом выводе — процессор берет адрес из `ptr`, идет в ОЗУ по этому адресу, считывает 4 байта (так как тип указателя `int *`) и выводит число `10`.
4.  `*ptr = 99;` — процессор берет адрес из `ptr`, идет в ОЗУ по этому адресу и перезаписывает лежащие там 4 байта новым числом `99`. Физическая переменная `x` изменилась, хотя мы не обращались к ней по имени!

### Аналогия с почтовым ящиком
Представьте переменную как дом с почтовым ящиком.
*   Имя переменной `x` — это название дома (например, "Дом Смита").
*   Значение `10` — это письмо внутри ящика.
*   Адрес `&x` — это точный географический адрес дома (например, "ул. Ленина, д. 5").
*   Указатель `ptr` — это бумажка, на которой вы записали адрес: "ул. Ленина, д. 5".
*   Разыменование `*ptr` — это физическая поездка по адресу, написанному на бумажке, открытие почтового ящика и чтение/замена лежащего там письма.

## Подглава 6.4: Указатели и одномерные массивы

В Лекции 4 мы изучали одномерные массивы и говорили, что они располагаются в памяти в виде непрерывного блока байт. Теперь мы можем открыть главный секрет языка Си: **в большинстве выражений имя массива автоматически преобразуется в указатель на его самый первый элемент**.

Это не означает, что массив *и есть* указатель. Например, оператор `sizeof` (он возвращает размер в байтах) покажет разницу: для `int numbers[3]` значение `sizeof(numbers)` равно 12 (размер всего массива), а размер указателя на 64-битной платформе — 8. Кроме того, имени массива нельзя присвоить другой адрес.

Рассмотрим объявление массива:
```c
int numbers[3] = {10, 20, 30};
```

В памяти этот массив выглядит так:
```
Адрес в ОЗУ   |  Элемент массива  |  Значение
--------------|-------------------|----------
0x2000        |  numbers[0]       |  10
--------------|-------------------|----------
0x2004        |  numbers[1]       |  20
--------------|-------------------|----------
0x2008        |  numbers[2]       |  30
```

Если мы напишем имя массива `numbers` без квадратных скобок — это даст нам адрес первого элемента, то есть `0x2000`.

Это значит, что мы можем направить обычный указатель на массив следующим образом:
```c
int *p = numbers; // p теперь хранит адрес numbers[0] (0x2000)
```
Запись `int *p = numbers;` абсолютно эквивалентна записи `int *p = &numbers[0];`.

Поскольку указатель `p` теперь указывает на первый элемент массива, мы можем использовать его для поэлементного доступа:
```c
printf("%d %d\n", *p, p[1]); // выведет: 10 20 (то же, что numbers[0] и numbers[1])
```
Запись `p[1]` читается как «элемент с индексом 1, считая от адреса, который хранится в `p`». В следующих лекциях мы изучим арифметику указателей, которая позволит нам элегантно перемещаться по массивам без квадратных скобок, сдвигая адрес на размер типа данных.

## Практические задачи

### Задача 1: Манипуляция данными через указатель
Напишите программу на Си, в которой:
1.  Объявляется переменная `int score` со значением `100`.
2.  Объявляется указатель на эту переменную.
3.  Выводится адрес переменной `score` в памяти.
4.  Выводится значение переменной `score`, полученное путем разыменования указателя.
5.  Значение переменной изменяется на `250` строго через указатель (без прямого обращения по имени `score`).
6.  Новое значение переменной `score` выводится на экран.

### Задача 2: Поочередное управление переменными
Напишите программу на Си, в которой:
1.  Объявляются две целочисленные переменные `int temperature_city_A = 15;` и `int temperature_city_B = 22;`.

## Подсказки к задачам

*   **Подсказка к задаче 1:** Помните, что для вывода адреса в `printf` используется спецификатор `%p`, а перед именем переменной ставится оператор взятия адреса `&` (не забудьте приведение `(void *)`, см. подглаву 6.2.1). Для изменения значения переменной через указатель используйте конструкцию `*имя_указателя = новое_значение;`.
*   **Подсказка к задаче 2:** Указатель можно перенаправлять в любой момент выполнения программы, просто присваивая ему новые адреса с помощью оператора `=`. Например: `temp_ptr = &variable;`. Запись `*temp_ptr = *temp_ptr + 8;` читается так: «взять значение по адресу из `temp_ptr`, прибавить 8 и записать результат обратно по тому же адресу». Звёздочка всегда ставится перед именем указателя. Не разыменовывайте `temp_ptr` до того, как в него записан адрес (см. «неинициализированный указатель» в подглаве 6.2).
*   **Подсказка к задаче 3:** Перечитайте подглаву 6.1. Вспомните, что именно хранит в себе указатель и от чего зависит разрядность адресов в ОЗУ. Подумайте, имеет ли значение размер типа данных, на который указывает указатель, когда мы оцениваем размер *самого* указателя (адреса). Для второго вопроса вспомните, сколько различных адресов можно закодировать 32 битами, и чем ограничено адресное пространство одной программы.
