# Лекция 1: Архитектура фон Неймана и первый Hello, World!

## Подглава 1.1: Архитектура фон Неймана — что происходит внутри компьютера?

В основе почти любого современного компьютера (от вашего ноутбука до процессора в смартфоне) лежат принципы, которые в 1945 году описал математик Джон фон Нейман. С точки зрения этой архитектуры, компьютер состоит из двух ключевых компонентов: **центрального процессора (ЦП)** и **оперативной памяти (ОЗУ)**.

> ℹ️ Реальные процессоры устроены сложнее (кэши, несколько ядер и так далее). Мы начинаем с упрощённой модели и будем уточнять её по ходу курса: базовые идеи от этого не меняются.

### Как устроена оперативная память (ОЗУ)

**Оперативная память** — это временное рабочее пространство компьютера: её содержимое пропадает при выключении питания. Представьте её как длинную ленту, разделённую на ячейки.

- Каждая ячейка хранит ровно **1 байт** данных (8 бит).
- Каждая ячейка имеет свой уникальный числовой **адрес** (порядковый номер, начиная с 0).
- Процессор может выполнять с памятью две базовые операции: **прочитать** значение из ячейки с конкретным адресом или **записать** туда новое значение.

```text
Адрес:    0      1      2      3      4    ...
       +------+------+------+------+------+
Ячейка |  25  |  3   | 200  |  17  |  0   | ...   (в каждой ячейке — 1 байт)
       +------+------+------+------+------+
```

Связь между процессором и ОЗУ осуществляется по физическим проводам, которые сгруппированы в **шины**:

1. **Адресная шина** — по ней процессор отправляет в ОЗУ числовой адрес ячейки, с которой хочет работать. В нашей упрощённой модели эта шина однонаправленная: адрес идёт только от ЦП к ОЗУ.
2. **Шина данных** — по ней передаётся само содержимое ячеек. Она двунаправленная: при чтении данные идут из ОЗУ в процессор, а при записи — из процессора в ОЗУ.
3. **Шина управления** — по ней идут служебные сигналы, например «сейчас нужно прочитать» или «сейчас нужно записать». Благодаря ей память понимает, что именно от неё хотят: ведь адрес и данные сами по себе этого не говорят.

### Как работает центральный процессор (ЦП)

Процессор — это вычислитель. Внутри него есть крошечные ячейки сверхбыстрой памяти, которые называются **регистрами**. Основные вычисления (сложение, сравнение, логические операции) процессор выполняет над числами, которые лежат в регистрах. Поэтому, чтобы что-то посчитать, данные обычно сначала переносят из ОЗУ в регистры.

Главный секрет архитектуры фон Неймана: **и команды программы (инструкции), и данные (текст, числа) хранятся в одной и той же оперативной памяти в виде чисел**. Чем является число в ячейке — командой или данными — определяется тем, как его использует процессор: если на ячейку указывает счётчик команд (о нём ниже), её содержимое считается инструкцией.

Для выполнения программы процессор использует специальный регистр — **счётчик команд (PC — Program Counter)**. В нём всегда хранится адрес ячейки ОЗУ, где лежит следующая инструкция.

Для простоты будем считать, что **каждая инструкция занимает ровно одну ячейку памяти**. (В реальных процессорах это не так: инструкция x86-64 занимает от 1 до 15 байт, а ARM64 — 4 байта, поэтому PC увеличивается на длину инструкции, а не на 1. Идея при этом остаётся той же.)

Процессор работает в бесконечном цикле выполнения:

1. **Выборка (Fetch):** ЦП считывает инструкцию из ОЗУ по адресу, который указан в регистре PC.
2. **Инкремент PC:** сразу после выборки, ещё до выполнения, ЦП увеличивает значение PC (в нашей модели — на 1), чтобы он указывал на следующую инструкцию.
3. **Декодирование (Decode):** ЦП определяет по коду операции, что это за инструкция и над чем она должна работать.
4. **Выполнение (Execute):** ЦП выполняет инструкцию (например, складывает два числа или переносит байт из ОЗУ в регистр).
5. **Возврат к шагу 1.**

> 💡 Есть особая инструкция — **переход (jump)**. Она записывает в PC новый адрес, и процессор продолжает работу с другого места программы. Именно так позже заработают условия и циклы (лекции 3 и 5).

## Подглава 1.2: Почему C и что делает компилятор?

Язык программирования C (Си) был создан в начале 1970-х годов Деннисом Ритчи в Bell Labs для написания операционной системы Unix. Он даёт программисту прямой доступ к памяти и устроен так, что код на нём хорошо отражает работу процессора и ОЗУ. Именно поэтому мы начинаем изучение программирования с него: понимание того, как работает память компьютера, — важная часть работы с Си.

### Зачем нужен компилятор и что такое инструкции процессора?

Процессор не понимает текст на человеческих языках. На аппаратном уровне он оперирует электрическими сигналами, которые логические схемы внутри кристалла интерпретируют как двоичные числа — нули и единицы.

- **Что такое машинные инструкции (инструкции процессора)?** Это элементарные, неделимые команды, которые процессор умеет распознавать и выполнять непосредственно на физическом уровне (с помощью транзисторов и логических вентилей). Каждая такая инструкция имеет свой числовой код — **код операции (opcode — operation code)**. Например, в архитектуре Intel x86-64 двоичная последовательность `10110000 01100001` (или шестнадцатеричные байты `B0 61`) — это инструкция, приказывающая: _«Загрузить число 97 (код символа 'a' в таблице ASCII) в регистр AL»_ (AL — младший байт регистра RAX). Машинный код готовой программы — это просто длинный список таких чисел-инструкций, последовательно лежащих в оперативной памяти.
    
- **Связь кода на Си и машинных инструкций:** В языках более высокого уровня одна строчка кода может скрывать огромное количество действий. Язык Си стоит к процессору ближе: одна строчка исходного кода (например, вызов функции вывода текста `printf` или простое математическое выражение) обычно превращается в небольшую цепочку машинных инструкций.
    

Писать программы напрямую в виде чисел очень долго и неудобно, поэтому мы пишем исходный код на Си, а специальная программа — **компилятор** — переводит наш текст в машинный код, заменяя человеческие слова на конкретные аппаратные инструкции и сохраняя их в готовый исполняемый файл.

## Подглава 1.2.1: Четыре этапа превращения кода C в исполняемый файл (бинарник)

Когда вы запускаете команду компиляции (например, `gcc hello.c -o hello`), кажется, что исходный файл `.c` мгновенно превращается в готовое приложение. На самом деле `gcc` — это «диспетчер», который по очереди запускает несколько отдельных программ. Процесс разбит на четыре строго последовательных этапа:

```text
[ hello.c ] (Исходный код)
     │
     ▼  1. Препроцессинг (Preprocessor)
[ hello.i ] (Код на C с выполненными директивами, без комментариев)
     │
     ▼  2. Компиляция (Compiler)
[ hello.s ] (Код на языке ассемблера)
     │
     ▼  3. Ассемблирование (Assembler)
[ hello.o ] (Объектный файл с машинным кодом)
     │
     ▼  4. Компоновка / Линковка (Linker)
[ hello.exe / hello ] (Исполняемый бинарный файл)
```

Разберём каждый шаг «под капотом»:

### 1. Препроцессинг (Preprocessing)

На первом этапе работает **препроцессор**. Его задача — подготовить текст программы к анализу компилятором. Он не анализирует логику программы и синтаксис Си, а работает исключительно как текстовый редактор.

- **Что он делает:**
    - Ищет строки, начинающиеся с символа `#` (директивы препроцессора).
    - Находит строчку `#include <stdio.h>` и физически вставляет всё содержимое файла `stdio.h` на место этой директивы.
    - Удаляет все комментарии из кода (для компилятора они не несут смысла).
    - Заменяет макросы (если они объявлены через `#define`) на их значения.
- **Что получается на выходе:** Временный файл с расширением `.i`. Это всё ещё обычный текст программы на Си, но сильно разросшийся (в нём теперь сотни строк из подключённых заголовочных файлов) и очищенный от комментариев. Если откроете его, вы увидите служебные строки, начинающиеся с `#`: это пометки, откуда пришёл тот или иной кусок кода.

### 2. Компиляция (Compilation)

На втором этапе работает сам **компилятор** Си.

- **Что он делает:**
    - Проверяет ваш код на ошибки: синтаксические (пропущенные точки с запятой, непарные скобки) и смысловые (например, несовместимые типы).
    - Переводит код Си на язык **ассемблера** — текстовый формат низкоуровневых команд, которые напрямую соответствуют инструкциям конкретного процессора (например, `MOV` — переслать данные, `ADD` — сложить, `CALL` — вызвать функцию).
- **Что получается на выходе:** Текстовый файл с расширением `.s` (в GCC; в некоторых других компиляторах, например MSVC, — `.asm`), содержащий ассемблерные команды под вашу архитектуру процессора (например, x86-64 или ARM).

### 3. Ассемблирование (Assembly)

На третьем этапе работает программа-**ассемблер**.

- **Что он делает:**
    - Переводит текстовые ассемблерные команды из `.s` файла в двоичные инструкции — **машинный код** (нули и единицы).
- **Что получается на выходе:** **Объектный файл** с расширением `.o` (в MSVC — `.obj`). Это уже бинарный файл с машинными инструкциями, однако запустить его _нельзя_. Почему? В нашей программе вызывается внешняя функция `printf`. Инструкция вызова в `hello.o` есть, но адрес функции `printf` на этом этапе неизвестен: там стоит временная заглушка и пометка «здесь нужно подставить адрес `printf`».

### 4. Компоновка / Линковка (Linking)

На финальном этапе работает программа-**компоновщик** (линкер).

- **Что он делает:**
    - Собирает все объектные файлы вашего проекта (если их несколько) в один файл.
    - Связывает вашу программу со стандартной библиотекой Си (**libc**), в которой лежит готовый машинный код `printf`. Это можно сделать двумя способами:
        - **Динамическая компоновка** (по умолчанию в Linux): код `printf` в ваш файл не копируется. В исполняемый файл записывается лишь пометка «эта функция лежит в библиотеке `libc.so`» (на Windows — в DLL), а реальный адрес функции определяет загрузчик операционной системы в момент запуска программы. Так файл получается компактным, а библиотека существует в одном экземпляре на все программы.
        - **Статическая компоновка** (флаг `-static`): код `printf` копируется прямо в исполняемый файл. Он получается больше, зато не зависит от библиотек на конкретной машине.
    - Подставляет настоящие адреса вместо заглушек там, где они известны на этом этапе (например, для ваших собственных функций).
    - Формирует структуру исполняемого файла по правилам вашей операционной системы (формат ELF для Linux или PE — `.exe` — для Windows).
- **Что получается на выходе:** Итоговый **исполняемый бинарный файл** (в Linux — без расширения, по умолчанию с именем `a.out`, если вы не задали своё через `-o`; в Windows — `.exe`). Именно его операционная система может загрузить в ОЗУ и запустить.

## Подглава 1.3: Разбор первой программы "Hello, World!"

Давайте напишем и разберём классическую программу на Си, которая выводит текст на экран.

```c
#include <stdio.h>

int main() {
    printf("Hello, World!\n");
    return 0;
}
```

Разберём каждую строчку «под микроскопом»:

1. `#include <stdio.h>` Это **директива препроцессора** (preprocessor directive).
    - **Что такое директива?** Это специальная команда, предназначенная не для центрального процессора, а для **препроцессора** — вспомогательной программы, которая выполняет предварительную текстовую подготовку вашего кода _до_ того, как начнётся собственно компиляция.
    - **Как их распознать?** Все директивы в Си начинаются с символа решётки `#`. Препроцессор обрабатывает их «вслепую», как продвинутый текстовый редактор. Обратите внимание: в конце директив точка с запятой **не** ставится.
    - **Какую роль она играет здесь?** Директива `#include` буквально переводится как «включить». Она приказывает препроцессору найти заголовочный файл `stdio.h` (Standard Input/Output — стандартный ввод/вывод) в системных папках компилятора и физически «вклеить» всё его содержимое в наш файл на место этой строчки. В этом файле есть описание (объявление) функции `printf` из стандартной библиотеки Си, которая умеет выводить текст. Без этой вставки компилятор не знает, что такое `printf`: в современных версиях gcc (с 14-й) это ошибка, в более старых — предупреждение `implicit declaration`. В любом случае так писать нельзя.
2. `int main() { ... }` Это объявление **главной функции** программы. Любая программа на Си начинает своё выполнение с функции под названием `main`. Фигурные скобки `{` и `}` ограничивают блок кода, который принадлежит этой функции.
    - `int` означает, что функция по завершении вернёт целое число (типы данных мы подробно разберём в лекции 2).
    - Пустые скобки `()` означают, что программа не принимает параметров. В строгом стиле здесь пишут `(void)`, но к этому мы вернёмся в лекции 7, где будем изучать функции.
3. `printf("Hello, World!\n");` Это вызов функции вывода текста. Внутри двойных кавычек указана строка, которую нужно напечатать.
    - Символ `\n` — это управляющий символ **перевода строки**. Он заставляет курсор перейти на новую строчку после вывода текста. Забывать его в конце вывода не рекомендуется: иначе следующий текст в терминале (например, приглашение командной строки) «прилипнет» к вашему.
    - **Важно:** в конце каждого оператора (statement) в Си обязательно должна стоять **точка с запятой (`;`)**. Она служит сигналом для компилятора, что инструкция завершена.
    - `printf` — это **функция стандартной библиотеки Си**, а не системный вызов. Системный вызов делает она сама, где-то внутри (подробности ниже).
4. `return 0;` Эта команда завершает работу функции `main`. Возвращаемое число — **код завершения** программы. `0` традиционно сообщает операционной системе, что программа выполнилась успешно. Любое **ненулевое** значение означает сбой.

### Что происходит при запуске программы

Когда вы запускаете программу, операционная система загружает её машинные инструкции с диска в ОЗУ и устанавливает счётчик команд PC на **точку входа** программы. Это небольшой стартовый код, который добавил линкер: он подготавливает окружение и вызывает вашу функцию `main`. Дальше процессор начинает последовательно выполнять инструкции по циклу из подглавы 1.1.

Дойдя до `printf`, программа выполняет код этой библиотечной функции. Она формирует итоговый текст и в конечном счёте обращается к операционной системе через **системный вызов** `write`. Системный вызов — это запрос программы к ядру ОС выполнить действие, которое сама программа выполнить не может (например, обратиться к устройству). Ядро передаёт байты текста в **стандартный поток вывода** (stdout), и программа-терминал отрисовывает символы на экране.

## Подглава 1.4: Компиляция и запуск программы через `gcc`

### Что понадобится

- **Linux:** компилятор ставится одной командой, например `sudo apt install build-essential` (Ubuntu/Debian).
- **macOS:** выполните `xcode-select --install`. Команда `gcc` там запускает компилятор clang, для наших задач это неважно.
- **Windows:** проще всего установить WSL (Windows Subsystem for Linux) и работать как в Linux. Альтернатива — MSYS2 с пакетом MinGW-w64.

Проверка установки:

```bash
gcc --version
```

### Сборка и запуск

Сохраните программу из подглавы 1.3 в файл `hello.c` и выполните:

```bash
gcc hello.c -o hello    # скомпилировать; результат будет в файле hello
./hello                 # запустить (в Windows: hello.exe)
```

Программа выведет `Hello, World!`.

Рекомендуется всегда включать предупреждения компилятора:

```bash
gcc -Wall -Wextra hello.c -o hello
```

Флаг `-o имя` задаёт имя итогового файла. Без него gcc назовёт результат `a.out`.

### Посмотрите четыре этапа своими глазами

```bash
gcc -E hello.c -o hello.i    # только препроцессинг
gcc -S hello.c -o hello.s    # препроцессинг + компиляция: получим ассемблер
gcc -c hello.c -o hello.o    # + ассемблирование: получим объектный файл
gcc hello.o -o hello         # компоновка: получим исполняемый файл
```

Откройте `hello.i` и `hello.s` в текстовом редакторе: первый вырастет до сотен строк, а во втором вы найдёте инструкцию `call` — вызов функции. Не удивляйтесь, если там будет `puts`, а не `printf`: для простого текста без подстановок gcc сам заменяет `printf` на более лёгкую функцию `puts` (результат на экране тот же). На Linux команда `ldd hello` покажет, что программа динамически подключает библиотеку `libc`.

### Код завершения

Проверить, что вернула `main`, можно сразу после запуска:

```bash
./hello
echo $?                 # Linux/macOS: выведет 0
# Windows (cmd): echo %ERRORLEVEL%     PowerShell: $LASTEXITCODE
```
