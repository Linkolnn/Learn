# Лекция 11: Многомерные массивы и двойные указатели

В предыдущих лекциях мы детально разобрали, как устроена физическая оперативная память, как работают указатели и как запрашивать блоки байт на куче (Heap) прямо во время работы программы при помощи функций `malloc`, `calloc`, `realloc` и `free`. До сих пор мы работали с линейными (одномерными) структурами данных — массивами и строками.

Однако в реальной практике данные часто имеют сложную структуру: это могут быть игровые карты (сетки), таблицы баз данных, математические матрицы или массивы текстовых строк разной длины. В этой лекции мы изучим, как представлять многомерные данные в оперативной памяти компьютера, разберём концепцию двойных указателей и научимся вручную строить динамические матрицы в куче с защитой от утечек памяти.

> 🗺️ **Место лекции в курсе.** Эта лекция опирается на Лекции 4 (массивы), 6 (указатели) и 10 (куча, `malloc` / `free`). > ℹ️ **Про слово «физический адрес».** В лекции для наглядности адреса в памяти названы «физическими», а числа вроде `0x1000` — условные. На самом деле программа работает с **виртуальными** адресами, которые операционная система сопоставляет с физической памятью. Как это устроено, мы изучим в Лекции 29; для понимания этой лекции разницы нет.

## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. Row-major order (развёртывание по строкам)**
> * **Что это:** Способ, которым компилятор Си укладывает двумерный массив в линейную память: сначала все элементы строки 0, затем все элементы строки 1 и так далее.

> 📌 **2. Двойной указатель (указатель на указатель)**
> * **Что это:** Переменная типа `int **`, которая хранит адрес другого указателя (типа `int *`). Разыменовав её дважды (`**p`), мы добираемся до самого значения.

> 📌 **3. Динамическая матрица**
> * **Что это:** Двумерная таблица, размеры которой становятся известны во время работы программы, поэтому память под неё выделяется на куче через `malloc`. В этой лекции она строится как «массив указателей на строки».

> 📌 **4. Утечка памяти (Memory Leak)**
> * **Что это:** Ситуация, когда блок памяти выделен, но больше не нужен программе, и при этом не освобождён, а его адрес потерян. Вернуть такой блок системе уже невозможно, пока программа работает.

> 📌 **5. Висячий указатель (Dangling Pointer)**
> * **Что это:** Указатель, который хранит адрес уже освобождённой памяти. Обращаться по такому адресу нельзя (неопределённое поведение). Поэтому после `free` указатель принято обнулять: `p = NULL;`. Повторный `free(NULL)` безопасен (ничего не происходит), а повторный `free` по старому адресу — это ошибка двойного освобождения.

> 📌 **6. Аварийный откат (Rollback)**
> * **Что это:** Приём программирования: если очередной шаг не удался (например, `malloc` вернул `NULL`), мы освобождаем всё, что успели выделить на предыдущих шагах, и только потом выходим с ошибкой.

> 📌 **7. Ступенчатый (рваный) массив (Jagged Array)**
> * **Что это:** Динамическая матрица, у которой строки имеют разную длину.

## Подглава 11.1: Физическая реальность многомерных массивов в ОЗУ (Row-major order)

Когда мы объявляем в Си двумерный статический массив (матрицу), например:

```c
int arr[3][4]; // Матрица из 3 строк и 4 столбцов
```

Мы представляем её себе в виде удобной таблицы, состоящей из строк и столбцов. Однако на физическом уровне **многомерных массивов в аппаратной памяти компьютера не существует**.

### Линейное строение ОЗУ

Физическая оперативная память — это длинная, строго одномерная цепочка байтов, где у каждого байта есть свой уникальный числовой адрес. Память адресуется одним числом, а не парой «строка-столбец». Поэтому компилятор Си вынужден «разворачивать» двумерные таблицы в одну непрерывную линию.

В языке Си для этого используется стандарт **Row-major order** (развёртывание по строкам). Это значит, что компилятор укладывает в ОЗУ сначала все элементы первой строки (строка 0), сразу за ними — все элементы второй строки (строка 1), затем третьей и так далее.

### Физическая визуализация матрицы arr[3][4] в ОЗУ:

Допустим, начальный адрес массива в памяти равен `0x1000`. Поскольку тип `int` занимает 4 байта, вся таблица из 3 * 4 = 12 элементов займёт ровно 48 байт:

```text
Элемент:  | arr[0][0] | arr[0][1] | arr[0][2] | arr[0][3] | arr[1][0] | arr[1][1] | ... | arr[2][3] |
Адрес:    |  0x1000   |  0x1004   |  0x1008   |  0x100C   |  0x1010   |  0x1014   | ... |  0x102C   |
Строка:   |<------------------ Строка 0 ----------------->|<------------------ Строка 1 ----------------->|
```

### Формула смещения адреса

Поскольку память строго линейна, как процессор мгновенно находит нужный элемент, например `arr[i][j]`? Он не бежит по массиву в поиске нужной ячейки. Вместо этого вычисляется точный адрес элемента по простой арифметической формуле за константное время O(1):

`Адрес arr[i][j] = Базовый_адрес + (i * Количество_столбцов + j) * Размер_элемента`

Давайте проверим эту формулу для элемента `arr[1][1]` (вторая строка, второй столбец) из нашей схемы:
*   Базовый адрес = `0x1000` (в десятичной системе пусть это будет 4096)
*   Количество столбцов (Cols) в объявлении массива = 4
*   Индекс строки `i` = 1
*   Индекс столбца `j` = 1
*   Размер элемента `sizeof(int)` = 4 байта

Считаем:  
`Адрес = 4096 + (1 * 4 + 1) * 4 = 4096 + 5 * 4 = 4096 + 20 = 4116`  
Переведём число 4116 обратно в шестнадцатеричную систему: `4116 = 0x1014`.

Формула работает безупречно! Для вычисления адреса нужны всего две операции умножения и две операции сложения (на практике компиляторы часто заменяют умножения на более быстрые сдвиги и специальные адресные инструкции).

**Важное наблюдение:** в формуле участвует количество **столбцов**, а количество строк не нужно вовсе. Поэтому при передаче статического двумерного массива в функцию Си требует указывать размер всех измерений, кроме первого.

### Проверьте сами

Убедиться в линейности памяти можно, распечатав адреса элементов (конкретные числа у вас будут другими, но разности — те же):

```c
#include <stdio.h>

int main(void) {
    int arr[3][4];

    printf("arr[0][0]: %p\n", (void *)&arr[0][0]);
    printf("arr[0][3]: %p\n", (void *)&arr[0][3]); // на 12 байт дальше arr[0][0]
    printf("arr[1][0]: %p\n", (void *)&arr[1][0]); // ровно на 4 байта дальше arr[0][3]!
    printf("arr[2][3]: %p\n", (void *)&arr[2][3]); // на 44 байта дальше arr[0][0]

    return 0;
}
```

Обратите внимание: последний элемент строки 0 и первый элемент строки 1 лежат в памяти **вплотную** друг к другу.

## Подглава 11.2: Двойные указатели (Указатели на указатели)

В Лекции 6 мы изучили, что указатель — это переменная, которая хранит адрес другой переменной. Но поскольку сам указатель тоже является переменной, он физически занимает место в ОЗУ (8 байт на привычных 64-битных платформах) и, следовательно, тоже имеет свой собственный уникальный адрес памяти.

Это значит, что мы можем создать переменную, которая будет хранить адрес этого указателя. Такая переменная называется **двойным указателем** (или указателем на указатель) и обозначается двумя звёздочками:

```c
int x = 42;
int *ptr = &x;     // Одинарный указатель: хранит адрес переменной x
int **dptr = &ptr; // Двойной указатель: хранит адрес указателя ptr
```

### Физическая визуализация цепочки адресов в ОЗУ:

Давайте посмотрим, как эта конструкция распределяется в оперативной памяти компьютера (адреса условные):

```text
Переменная:       x (тип int)          ptr (тип int*)        dptr (тип int**)
Значение:        [     42     ]       [   0x3000   ]        [   0x5000   ]
Адрес:              0x3000               0x5000               0x7000
```

1.  Переменная `x` лежит по адресу `0x3000` и хранит число `42`.
2.  Переменная `ptr` лежит по адресу `0x5000` и хранит адрес `0x3000` (ссылается на `x`).
3.  Переменная `dptr` лежит по адресу `0x7000` и хранит адрес `0x5000` (ссылается на `ptr`).

### Разыменование двойного указателя

Чтобы добраться до оригинального значения переменной `x` через двойной указатель `dptr`, нам нужно применить оператор разыменования `*` дважды:

*   Однократное разыменование `*dptr` заставляет процессор пойти по адресу `0x7000`, прочитать там значение `0x5000` и вернуть его. То есть `*dptr` — это сам указатель `ptr` (со значением `0x3000`).
*   Двукратное разыменование `**dptr` заставляет процессор сделать второй шаг: пойти по полученному адресу `0x3000`, прочитать значение `42` и вернуть его. То есть `**dptr` — это сама переменная `x`.

```c
printf("Значение x через dptr: %d\n", **dptr); // Выведет 42!
```

*Важное системное замечание:* на привычных 64-битных платформах (x86-64, ARM64) размер любого указателя (будь то `int *`, `char **`, `double ***` или `void *`) составляет **8 байт**: это ширина адреса архитектуры. Тип указателя сообщает компилятору другое: данные какого типа лежат по этому адресу. От этого зависят размер чтения при разыменовании и шаг арифметики указателей (`+1` для `int *` сдвигает на 4 байта, а для `int **` — на 8).

## Подглава 11.3: Связь двойных указателей с массивами указателей

Зачем нам нужны двойные указатели на практике? Их основная сила раскрывается при работе с **массивами указателей**.

Представьте, что мы объявили массив, элементами которого являются не числа, а адреса других переменных:

```c
int x = 10, y = 20, z = 30;
int *arr[3] = {&x, &y, &z}; // Массив из трёх одинарных указателей
```

Имя массива в выражениях автоматически преобразуется в адрес его первого элемента (это называют «затуханием» массива в указатель; как мы помним из Лекции 6, так мы получали указатель на начало массива). Поэтому `arr` в выражении означает адрес элемента `arr[0]`.

Но элементом `arr[0]` является указатель `int *`. Значит, `arr` превращается в адрес указателя. Соответственно, мы можем присвоить этот адрес переменной типа **двойной указатель**:

```c
int **ptr_to_arr = arr; // ptr_to_arr указывает на первый элемент массива указателей
```

Используя арифметику указателей, мы можем перемещаться по этому массиву:
*   `ptr_to_arr` указывает на `arr[0]` (хранит адрес ячейки, где лежит указатель на `x`).
*   `*(ptr_to_arr)` вернёт адрес переменной `x`.
*   `**(ptr_to_arr)` вернёт число `10`.
*   `*(ptr_to_arr + 1)` — это значение ячейки `arr[1]` (сдвиг на 8 байт вперёд, ведь размер указателя 8 байт), то есть адрес переменной `y`.
*   `**(ptr_to_arr + 1)` вернёт число `20`.

Именно на этом принципе строятся динамические матрицы на куче и структуры для хранения текстовых строк в Си.

> ⚠️ **Двумерный массив и `int **` — это НЕ одно и то же!** Массив указателей (`int *arr[3]`) хранит адреса строк, и каждая строка может лежать в памяти где угодно. Статический двумерный массив (`int arr[3][4]`) — это один сплошной блок из 12 `int` без каких-либо указателей внутри (см. 11.1). Поэтому строка `int **p = arr;` для `int arr[3][4]` неверна: компилятор выдаст предупреждение о несовместимых типах, а программа при обращении `p[i][j]` будет трактовать числа как адреса и, скорее всего, упадёт. Динамическая матрица из следующей подглавы устроена именно как массив указателей, и поэтому к ней применимо `int **`.

## Подглава 11.4: Динамические матрицы в куче (Двухэтапное выделение)

В Лекции 10 мы научились выделять память под одномерный массив с помощью `malloc`. Но как выделить память под двумерную матрицу, размеры которой (количество строк и столбцов) мы узнаём от пользователя только в момент работы программы?

Для этого применяется **двухэтапное выделение памяти** (шаги 1 и 2), после которого матрицу можно заполнять и читать (шаг 3). Результат — связная структура данных в куче.

### Шаг 1: Выделение памяти в куче под массив указателей на строки

Сначала мы должны создать в куче непрерывный массив (каркас), элементами которого будут указатели на будущие строки нашей матрицы. Поскольку элементами этого массива являются указатели (`int *`), то указатель на этот массив должен иметь тип `int **` (двойной указатель, или указатель на указатель):

```c
int rows = 3;
int cols = 4;

// Выделяем массив из 3 указателей на int (каркас строк)
int **matrix = malloc(rows * sizeof(int *));
if (matrix == NULL) {
    return 1; // Памяти не хватило: освобождать пока нечего
}
```

*Обратите внимание на `sizeof(int *)`! На 64-битной платформе мы выделяем память под адреса будущих строк, поэтому размер каждого элемента равен 8 байтам (размер указателя), а не 4 байтам (размер `int`).*

*Проверка на `NULL` обязательна после **каждого** вызова `malloc`: если пропустить её, обращение `matrix[i]` по нулевому указателю приведёт к аварийному завершению.*

После этого шага в куче создаётся следующая структура из 3 ячеек по 8 байт. Ячейки пока **не заполнены**: `malloc` не обнуляет память, поэтому там лежит случайный «мусор», а не `NULL`:

```text
Переменная matrix (на стеке)
     |
     v
[Адрес в куче (массив указателей на строки)]:
| matrix[0] (тип int*) | matrix[1] (тип int*) | matrix[2] (тип int*) |
|       (мусор)        |       (мусор)        |       (мусор)        |
```

*(Если нужна память, заполненная нулями, используйте `calloc`: `calloc(rows, sizeof(int *))`.)*

### Шаг 2: Выделение памяти под элементы (столбцы) для каждой строки

Теперь мы должны запустить цикл и для каждого элемента `matrix[i]` (который является одинарным указателем `int *`) выделить в куче свой собственный одномерный массив из чисел типа `int` — то есть выделить память под столбцы внутри каждой строки.

#### Защита от утечек памяти: механизм аварийного отката (Rollback)

При выделении памяти в цикле может произойти сбой: например, первые `i` строк успешно выделились, а на шаге `i` функция `malloc` вернула `NULL` из-за нехватки ОЗУ.

Если в этот момент просто написать `return 1;`, мы потеряем адреса уже выделенных блоков: первые `i` строк и сам главный массив указателей останутся «висеть» в куче. Если этот код находится внутри функции, которая вернёт управление вызывающему коду, или в программе, которая продолжит работать (например, в сервере), получится **утечка памяти (Memory Leak)**. При завершении всего процесса операционная система сама заберёт память, но опираться на это — плохая практика: код нельзя будет безопасно переиспользовать.

Чтобы этого не произошло, мы применяем приём **аварийного отката (Rollback)**:

```c
for (int i = 0; i < rows; i++) {
    matrix[i] = malloc(cols * sizeof(int)); // Выделяем cols элементов для i-й строки

    // Проверка успешности выделения памяти под текущую строку
    if (matrix[i] == NULL) {
        // АВАРИЙНЫЙ ОТКАТ (ROLLBACK):
        // 1. Освобождаем все строки от 0 до (i - 1), которые успели выделить ранее
        for (int k = 0; k < i; k++) {
            free(matrix[k]);
            matrix[k] = NULL;
        }
        // 2. Освобождаем сам главный массив указателей
        free(matrix);
        matrix = NULL;

        return 1; // Завершаем программу с ошибкой
    }
}
```

#### Что физически делает аварийный откат:
1. `i` — это индекс строки, на которой произошёл сбой (`matrix[i] == NULL`).
2. Строки с индексами от `0` до `i - 1` **уже успели физически выделиться в куче**, и их верные адреса хранятся в ячейках `matrix[0]`, `matrix[1]`, ..., `matrix[i - 1]`. Ячейки с индексами `i` и выше нам не нужны (там NULL или мусор), и мы их не трогаем.
3. Цикл `for (int k = 0; k < i; k++) free(matrix[k]);` поочерёдно обходит все ранее созданные строки в ОЗУ и возвращает каждую из них операционной системе.
4. Вызов `free(matrix);` сразу после цикла освобождает сам главный массив указателей.
5. Инструкция `matrix = NULL;` зануляет указатель, чтобы он не остался «висячим» (см. глоссарий).

Если сбоев нет, в куче выстраивается полноценная двумерная сетка данных (адреса на схеме условные: реальные блоки лежат в куче в произвольных местах):

```text
matrix (указатель на стеке)
   |
   v
[Массив указателей в куче]:
|  matrix[0]  |  matrix[1]  |  matrix[2]  |
|   0xA000    |   0xB000    |   0xC000    |
      |             |             |
      |             |             +-------------------> [Строка 2 в куче (4 столбца)]: | int | int | int | int |
      |             +---------------------------------> [Строка 1 в куче (4 столбца)]: | int | int | int | int |
      +-----------------------------------------------> [Строка 0 в куче (4 столбца)]: | int | int | int | int |
```

> ⚠️ В отличие от статического массива из 11.1, **строки динамической матрицы не обязаны лежать вплотную друг к другу**: каждая выделена отдельным вызовом `malloc`. Внутри одной строки элементы идут подряд, а между строками могут быть промежутки.

### Шаг 3: Заполнение матрицы данными и работа с элементами

После того как выделена память под массив указателей и под элементы каждой строки, матрица полностью готова к записи и чтению. Теперь мы можем заполнить её данными с помощью двух вложенных циклов:

```c
for (int i = 0; i < rows; i++) {
    for (int j = 0; j < cols; j++) {
        matrix[i][j] = (i + 1) * 10 + (j + 1); // Записываем значение в i-ю строку, j-й столбец
    }
}
```

Как компилятор обрабатывает запись `matrix[i][j]` на низком уровне?
1. **Первый индекс `matrix[i]`**: процессор читает из памяти элемент главного массива указателей с индексом `i` и получает адрес нужной строки (например, `0xB000`).
2. **Второй индекс `[j]`**: процессор берёт полученный адрес строки (`0xB000`), отступает `j` ячеек типа `int` (по 4 байта на столбец) и записывает значение прямо в нужную ячейку ОЗУ.

Заметьте разницу со статическим массивом: там адрес вычислялся одной формулой, а здесь нужно **дополнительное чтение** из памяти (адрес строки). Кроме того, строки разбросаны по куче, а не лежат единым блоком, что для кэша процессора менее выгодно.

### Ступенчатые массивы (Jagged Arrays)

Поскольку каждая строка динамической матрицы выделяется независимым вызовом `malloc`, мы не обязаны делать их одинаковой длины! Мы можем создать матрицу, у которой в первой строке будет 2 элемента (столбца), во второй — 10, а в третьей — 5. Такие структуры называют **ступенчатыми (или рваными) массивами**. Они позволяют заметно экономить память при хранении треугольных матриц или списков текстовых строк разной длины. Длины строк при этом нужно хранить отдельно (например, в массиве `int lengths[]`), потому что по указателю длину блока узнать нельзя.

### Полный пример: создание и очистка в виде функций

Удобно вынести выделение и освобождение в отдельные функции (так проще не забыть про откат и не дублировать код, например в задаче 2):

```c
#include <stdio.h>
#include <stdlib.h>

// Создаёт матрицу rows x cols. При нехватке памяти возвращает NULL, не оставляя утечек.
int **create_matrix(int rows, int cols) {
    int **matrix = malloc(rows * sizeof(int *));
    if (matrix == NULL) {
        return NULL;
    }

    for (int i = 0; i < rows; i++) {
        matrix[i] = malloc(cols * sizeof(int));
        if (matrix[i] == NULL) {
            for (int k = 0; k < i; k++) { // откат: освобождаем уже созданные строки
                free(matrix[k]);
            }
            free(matrix);
            return NULL;
        }
    }
    return matrix;
}

// Освобождает матрицу: сначала строки, затем массив указателей на них.
void free_matrix(int **matrix, int rows) {
    if (matrix == NULL) {
        return;
    }
    for (int i = 0; i < rows; i++) {
        free(matrix[i]);
    }
    free(matrix);
}

int main(void) {
    int rows = 3;
    int cols = 4;

    int **matrix = create_matrix(rows, cols);
    if (matrix == NULL) {
        printf("Ошибка: не хватило памяти\n");
        return 1;
    }

    for (int i = 0; i < rows; i++) {
        for (int j = 0; j < cols; j++) {
            matrix[i][j] = (i + 1) * 10 + (j + 1);
            printf("%4d", matrix[i][j]);
        }
        printf("\n");
    }

    free_matrix(matrix, rows);
    matrix = NULL; // в функции free_matrix обнулить переданную копию указателя нельзя, делаем это здесь
    return 0;
}
```

## Подглава 11.5: Освобождение памяти матрицы (сначала строки, потом массив указателей)

Самая частая и разрушительная ошибка при работе с динамическими матрицами — это некорректное освобождение памяти.

Давайте посмотрим на неправильный код очистки:

```c
// ОШИБКА! УТЕЧКА ПАМЯТИ!
free(matrix);
matrix = NULL;
```

### Физическая суть катастрофы

Что произойдёт в куче при вызове `free(matrix)`?
Менеджер памяти Си возьмёт адрес главного массива указателей и объявит этот блок (3 указателя по 8 байт = 24 байта) свободным для будущего использования.

Но сами строки, расположенные по адресам `0xA000`, `0xB000` и `0xC000`, **останутся нетронутыми в куче**! Они будут продолжать занимать оперативную память. Однако адреса этих строк хранились только внутри массива `matrix`, который мы только что освободили.

У нас больше нет возможности узнать, где лежат эти строки, чтобы их удалить. Мы получили классические **«сиротские» блоки памяти** — утечку памяти (Memory Leak). Если такой код выполняется многократно (например, на сервере при каждом запросе), утекающая память накапливается, и рано или поздно её не хватит.

### Правильный алгоритм освобождения памяти

Правило системного программиста гласит: **сначала освобождай то, на что ссылаются, и только потом — того, кто хранит эти ссылки.** Иначе вместе со «справочником» адресов пропадёт и возможность добраться до самих данных. В нашем случае порядок освобождения строк между собой значения не имеет, важно, чтобы главный массив указателей освобождался **последним**.

1.  **Сначала освобождаем сами строки:** запускаем цикл и освобождаем память каждой отдельной строки по адресу, хранящемуся в массиве указателей:
    ```c
    for (int i = 0; i < rows; i++) {
        free(matrix[i]); // Освобождаем каждую строку в куче
        matrix[i] = NULL; // Зануляем указатель на строку (защита от висячих указателей)
    }
    ```
2.  **Затем освобождаем главный массив указателей:** только после того, как все строки освобождены, можно безопасно освободить сам массив адресов:
    ```c
    free(matrix); // Освобождаем массив указателей
    matrix = NULL; // Обнуляем главный указатель
    ```

Этот алгоритм освобождает всю память, выделенную под матрицу.

> 💡 Занулять `matrix[i]` перед `free(matrix)` — скорее привычка: сам массив всё равно сразу освобождается. А вот `matrix = NULL` важен: если позже случайно вызвать `free(matrix)` ещё раз, при `NULL` ничего не произойдёт, а по старому адресу получилась бы ошибка двойного освобождения.

### Альтернатива: вся матрица одним блоком

Если нужна «обычная» прямоугольная матрица, можно выделить память **одним** вызовом и использовать формулу смещения из 11.1:

```c
int *data = malloc(rows * cols * sizeof(int)); // один блок, строки лежат вплотную
if (data == NULL) { return 1; }

data[i * cols + j] = 42; // элемент [i][j] вычисляем по формуле

free(data);              // освобождается тоже одним вызовом
data = NULL;
```

Плюсы: один `malloc` и один `free`, данные лежат сплошным куском (быстрее для кэша процессора). Минусы: нельзя писать `data[i][j]` и нельзя сделать строки разной длины. Выбор зависит от задачи.

### Задача 2: Транспонирование матрицы на куче

Транспонирование матрицы — это математическая операция, при которой строки матрицы становятся её столбцами, а столбцы — строками. То есть матрица размером `A x B` превращается в матрицу `B x A`.

4.  С помощью циклов скопируйте элементы оригинальной матрицы в новую так, чтобы выполнялось правило: `transposed[j][i] = matrix[i][j]`.
5.  Выведите на экран обе матрицы для наглядного сравнения.
6.  Корректно и без утечек освободите память обеих матриц на куче.

### Задача 3: Вычисление адресов в ОЗУ (устно)
