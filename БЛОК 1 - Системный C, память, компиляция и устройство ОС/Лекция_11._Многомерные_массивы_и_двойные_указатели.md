# Лекция 11: Многомерные массивы и двойные указатели

В предыдущих лекциях мы детально разобрали, как устроена физическая оперативная память, как работают указатели и как запрашивать блоки байт на куче (Heap) прямо во время работы программы при помощи функций `malloc`, `free` и `realloc`. Однако в реальной практике данные часто имеют сложную структуру: это могут быть игровые карты (сетки), таблицы баз данных, математические матрицы или массивы текстовых строк разной длины. В этой лекции мы изучим, как представлять многомерные данные в оперативной памяти компьютера, разберем концепцию двойных указателей и научимся вручную строить динамические матрицы в куче с гарантированной защитой от утечек памяти.

## Подглава 11.1: Физическая реальность многомерных массивов в ОЗУ (Row-major order)

Когда мы объявляем в Си двумерный статический массив (матрицу), например:

```c
int arr[3][4]; // Матрица из 3 строк и 4 столбцов
```

Мы представляем её себе в виде удобной таблицы, состоящей из строк и столбцов. Однако на физическом уровне **многомерных массивов в аппаратной памяти компьютера не существует**.

### Линейное строение ОЗУ

Физическая оперативная память — это длинная, строго одномерная цепочка байтов, где у каждого байта есть свой уникальный числовой адрес. Процессор не умеет адресовать память «в двух измерениях». Поэтому компилятор Си вынужден «разворачивать» двумерные таблицы в одну непрерывную линию.

В языке Си для этого используется стандарт **Row-major order** (развертывание по строкам). Это значит, что компилятор укладывает в ОЗУ сначала все элементы первой строки (строка 0), сразу за ними — все элементы второй строки (строка 1), затем третьей и так далее.

### Физическая визуализация матрицы arr[3][4] в ОЗУ:

Допустим, начальный адрес массива в памяти равен `0x1000`. Поскольку тип `int` занимает 4 байта, вся таблица из 3 * 4 = 12 элементов займет ровно 48 байт:

```text
Элемент:  | arr[0][0] | arr[0][1] | arr[0][2] | arr[0][3] | arr[1][0] | arr[1][1] | ... | arr[2][3] |
Адрес:    |  0x1000   |  0x1004   |  0x1008   |  0x100C   |  0x1010   |  0x1014   | ... |  0x102C   |
Строка:   |<------------------ Строка 0 ----------------->|<------------------ Строка 1 ----------------->|
```

### Формула смещения адреса

Поскольку память строго линейна, как процессор мгновенно находит нужный элемент, например `arr[i][j]`? Он не бежит по массиву в поиске нужной ячейки. Вместо этого он использует простую арифметическую формулу, чтобы вычислить точный физический адрес элемента за константное время O(1):

`Физический адрес arr[i][j] = Базовый_адрес + (i * Количество_столбцов + j) * Размер_элемента`

Давайте проверим эту формулу для элемента `arr[1][1]` (вторая строка, второй столбец) из нашей схемы:
*   Базовый адрес = `0x1000` (в десятичной системе пусть это будет 4096)
*   Количество столбцов (Cols) в объявлении массива = 4
*   Индекс строки `i` = 1
*   Индекс столбца `j` = 1
*   Размер элемента `sizeof(int)` = 4 байта

Считаем:  
`Адрес = 4096 + (1 * 4 + 1) * 4 = 4096 + 5 * 4 = 4096 + 20 = 4116`  
Переведем число 4116 обратно в шестнадцатеричную систему: `4116 = 0x1014`.

Формула работает безупречно! Процессор делает всего две операции умножения и две операции сложения, чтобы мгновенно получить прямой доступ к любому элементу двумерного массива.

## Подглава 11.2: Двойные указатели (Указатели на указатели)

В Лекции 6 мы изучили, что указатель — это переменная, которая хранит адрес другой переменной. Но поскольку сам указатель тоже является переменной, он физически занимает место в ОЗУ (8 байт на 64-битной архитектуре) и, следовательно, тоже имеет свой собственный уникальный адрес памяти.

Это значит, что мы можем создать переменную, которая будет хранить адрес этого указателя. Такая переменная называется **двойным указателем** (или указателем на указатель) и обозначается двумя звездочками:

```c
int x = 42;
int *ptr = &x;     // Одинарный указатель: хранит адрес переменной x
int **dptr = &ptr; // Двойной указатель: хранит адрес указателя ptr
```

### Физическая визуализация цепочки адресов в ОЗУ:

Давайте посмотрим, как эта конструкция физически распределяется в оперативной памяти компьютера:

```text
Переменная:       x (тип int)          ptr (тип int*)        dptr (тип int**)
Значение:        [     42     ]       [   0x3000   ]        [   0x5000   ]
Физический адрес:   0x3000               0x5000               0x7000
```

1.  Переменная `x` лежит по адресу `0x3000` и хранит число `42`.
2.  Переменная `ptr` лежит по адресу `0x5000` и хранит адрес `0x3000` (ссылается на `x`).
3.  Переменная `dptr` лежит по адресу `0x7000` и хранит адрес `0x5000` (ссылается на `ptr`).

### Разыменование двойного указателя

Чтобы добраться до оригинального значения переменной `x` через двойной указатель `dptr`, нам нужно применить оператор разыменования `*` дважды:

*   Однократное разыменование `*dptr` заставляет процессор пойти по адресу `0x7000`, прочитать там значение `0x5000` и вернуть его. То есть `*dptr` — это сам указатель `ptr` (адрес `0x3000`).
*   Двукратное разыменование `**dptr` заставляет процессор сделать второй шаг: пойти по полученному адресу `0x3000`, прочитать значение `42` и вернуть его. То есть `**dptr` — это физическое значение переменной `x`.

```c
printf("Значение x через dptr: %d\n", **dptr); // Выведет 42!
```

*Важное системное замечание:* На 64-битной архитектуре размер любого указателя (будь то `int *`, `char **`, `double ***` или `void *`) всегда составляет ровно **8 байт**, так как для адресации памяти всегда требуется 64 бита информации. Тип данных указывает компилятору лишь на то, сколько шагов разыменования нужно сделать и какой размер данных лежит в самом конце цепочки.

## Подглава 11.3: Связь двойных указателей с массивами указателей

Зачем нам нужны двойные указатели на практике? Их основная сила раскрывается при работе с **массивами указателей**.

Представьте, что мы объявили массив, элементами которого являются не числа, а адреса других переменных:

```c
int x = 10, y = 20, z = 30;
int *arr[3] = {&x, &y, &z}; // Массив из трех одинарных указателей
```

Поскольку имя любого массива является константным указателем на его первый элемент (как мы помним из Лекции 6), имя массива `arr` хранит адрес элемента `arr[0]`.

Но элементом `arr[0]` является указатель `int *`. Значит, имя массива `arr` хранит адрес указателя. Соответственно, мы можем присвоить этот адрес переменной типа **двойной указатель**:

```c
int **ptr_to_arr = arr; // ptr_to_arr указывает на первый элемент массива указателей
```

Используя арифметику указателей, мы можем перемещаться по этому массиву:
*   `ptr_to_arr` указывает на `arr[0]` (хранит адрес указателя на `x`).
*   `*(ptr_to_arr)` вернет адрес переменной `x`.
*   `**(ptr_to_arr)` вернет число `10`.
*   `*(ptr_to_arr + 1)` перешагнет на 8 байт вперед, укажет на `arr[1]` и вернет адрес переменной `y`.
*   `**(ptr_to_arr + 1)` вернет число `20`.

Именно на этом принципе строятся динамические матрицы на куче и структуры для хранения текстовых строк в Си.

## Подглава 11.4: Динамические матрицы в куче (Двухэтапное выделение)

В Лекции 10 мы научились выделять память под одномерный массив с помощью `malloc`. Но как выделить память под двумерную матрицу, размеры которой (количество строк и столбцов) мы узнаем от пользователя только в момент работы программы?

Для этого применяется **трехэтапный алгоритм работы с динамической матрицей**, который строит в куче связную структуру данных.

### Шаг 1: Выделение памяти в куче под массив указателей на строки

Сначала мы должны создать в куче непрерывный массив (каркас), элементами которого будут указатели на будущие строки нашей матрицы. Поскольку элементами этого массива являются указатели (`int *`), то указатель на этот массив должен иметь тип `int **` (двойной указатель, или указатель на указатель):

```c
int rows = 3;
int cols = 4;

// Выделяем массив из 3 указателей на int (каркас строк)
int **matrix = malloc(rows * sizeof(int *));
```

*Обратите внимание на `sizeof(int *)`! На 64-битной архитектуре мы выделяем память под адреса будущих строк, поэтому размер каждого элемента равен 8 байтам (размер указателя), а не 4 байтам (размер `int`).*

После этого шага в куче создается следующая физическая структура из 3 ячеек по 8 байт:

```text
Переменная matrix (на стеке)
     |
     v
[Адрес в куче (массив указателей на строки)]:
| matrix[0] (тип int*) | matrix[1] (тип int*) | matrix[2] (тип int*) |
|       (NULL)         |       (NULL)         |       (NULL)         |
```

### Шаг 2: Выделение памяти под элементы (столбцы) для каждой строки

Теперь мы должны запустить цикл и для каждого элемента `matrix[i]` (который является одинарным указателем `int *`) выделить в куче свой собственный одномерный массив из чисел типа `int` — то есть выделить память под столбцы внутри каждой строки.

#### Защита от утечек памяти: механизм аварийного отката (Rollback)

При выделении памяти в цикле может произойти сбой: например, первые `i` строк успешно выделились, а на шаге `i` функция `malloc` вернула `NULL` из-за нехватки ОЗУ. 

Если в этот момент просто написать `return 1;`, произойдет **тяжелейшая утечка памяти (Memory Leak)**: первые `i` строк и сам главный массив указателей останутся «висеть» в куче, а их адреса будут навсегда утеряны.

Чтобы этого не произошло, мы обязаны применить **выражение аварийного отката (Rollback)**:

```c
for (int i = 0; i < rows; i++) {
    matrix[i] = malloc(cols * sizeof(int)); // Выделяем cols элементов для i-й строки
    
    // Проверка успешности выделения памяти под текущую строку
    if (matrix[i] == NULL) {
        // АВАРИЙНЫЙ ОТКАТ (ROLLBACK):
        // 1. Освобождаем все строки от 0 до (i - 1), которые успели выделить ранее
        for (int k = 0; k < i; k++) {
            free(matrix[k]);
            matrix[k] = NULL;
        }
        // 2. Освобождаем сам главный массив указателей
        free(matrix);
        matrix = NULL;
        
        return 1; // Завершаем программу с ошибкой
    }
}
```

#### Что физически делает выражение аварийного отката:
1. `i` — это индекс строки, на которой произошел сбой (`matrix[i] == NULL`).
2. Строки с индексами от `0` до `i - 1` **уже успели физически выделиться в куче**, и их верные адреса хранятся в ячейках `matrix[0]`, `matrix[1]`, ..., `matrix[i - 1]`.
3. Цикл `for (int k = 0; k < i; k++) free(matrix[k]);` поочередно обходит все ранее созданные строки в ОЗУ и возвращает каждую из них операционной системе.
4. Вызов `free(matrix);` сразу после цикла удаляет сам главный массив указателей из кучи.
5. Инструкция `matrix = NULL;` зануляет указатель, устраняя висячий адрес на стеке.

После выполнения этого безопасного цикла в куче гарантированно выстраивается полноценная двумерная сетка данных (а в случае сбоя — память чиста без единой утечки):

```text
matrix (указатель на стеке)
   |
   v
[Массив указателей в куче]:
|  matrix[0]  |  matrix[1]  |  matrix[2]  |
|   0x5000    |   0x6000    |   0x7000    |
      |             |             |
      |             |             +-------------------> [Строка 2 в куче (4 столбца)]: | int | int | int | int |
      |             +---------------------------------> [Строка 1 в куче (4 столбца)]: | int | int | int | int |
      +-----------------------------------------------> [Строка 0 в куче (4 столбца)]: | int | int | int | int |
```

### Шаг 3: Заполнение матрицы данными и работа с элементами

После того как выделена память под массив указателей и под элементы каждой строки, матрица полностью готова к записи и чтению. Теперь мы можем заполнить её данными с помощью двух вложенных циклов:

```c
for (int i = 0; i < rows; i++) {
    for (int j = 0; j < cols; j++) {
        matrix[i][j] = (i + 1) * 10 + (j + 1); // Записываем значение в i-ю строку, j-й столбец
    }
}
```

Как компилятор обрабатывает запись `matrix[i][j]` на низком уровне?
1. **Первый индекс `matrix[i]`**: Процессор обращается к главному массиву указателей в куче, берет элемент по индексу `i` и считывает адрес нужной строки (например, `0x6000`).
2. **Второй индекс `[j]`**: Процессор берёт полученный адрес строки (`0x6000`), отступает `j` ячеек типа `int` (по 4 байта на столбец) и записывает значение прямо в нужную ячейку ОЗУ.

### Ступенчатые массивы (Jagged Arrays)

Поскольку каждая строка динамической матрицы выделяется независимым вызовом `malloc`, мы не обязаны делать их одинаковой длины! Мы можем создать матрицу, у которой в первой строке будет 2 элемента (столбца), во второй — 10, а в третьей — 5. Такие структуры называют **ступенчатыми (или рваными) массивами**. Они позволяют колоссально экономить память при хранении треугольных матриц или списков текстовых строк разной длины.

## Подглава 11.5: Освобождение памяти матрицы (Обратный порядок)

Самая частая и разрушительная ошибка при работе с динамическими матрицами — это некорректное освобождение памяти. 

Давайте посмотрим на катастрофический код очистки:

```c
// ОШИБКА! КАТАСТРОФА В ОЗУ!
free(matrix); 
matrix = NULL;
```

### Физическая суть катастрофы

Что произойдет в куче при вызове `free(matrix)`? 
Менеджер памяти Си честно возьмет адрес главного массива указателей и объявит эти 24 байта (3 указателя по 8 байт) свободными для будущей записи.

Но сами строки, расположенные по адресам `0x5000`, `0x6000` и `0x7000`, **останутся нетронутыми в куче**! Они будут продолжать занимать физическую оперативную память компьютера. Однако адреса этих строк хранились только внутри массива `matrix`, который мы только что стерли. 

У нас больше нет физической возможности узнать, где лежат эти строки, чтобы их удалить. Мы получили классические **«сиротские» блоки памяти** — тяжелейшую утечку памяти (Memory Leak). Если этот код будет выполняться на сервере по кругу, оперативная память машины исчерпается за считанные минуты.

### Безупречный алгоритм освобождения памяти (Строгий обратный порядок)

Правило системного программиста гласит: **Освобождай память в порядке, строго обратном выделению**.

1.  **Сначала удаляем «листья» дерева (сами строки):** Мы запускаем цикл и освобождаем память каждой отдельной строки по адресу, хранящемуся в массиве указателей:
    ```c
    for (int i = 0; i < rows; i++) {
        free(matrix[i]); // Освобождаем каждую строку в куче
        matrix[i] = NULL; // Зануляем указатель на строку (защита от висячих указателей)
    }
    ```
2.  **Затем удаляем «ствол» (главный массив указателей):** Только после того, как все строки успешно стерты из кучи, мы можем безопасно удалить сам массив адресов:
    ```c
    free(matrix); // Освобождаем массив указателей
    matrix = NULL; // Полностью обнуляем главный указатель
    ```

Этот двухэтапный алгоритм гарантирует 100% очистку оперативной памяти от любых следов динамической матрицы.

### Задача 1: Динамическая таблица умножения

Напишите программу на Си, которая строит и выводит динамическую таблицу умножения:
1.  Программа запрашивает у пользователя количество строк (`Rows`) и столбцов (`Cols`) с клавиатуры.
2.  Реализуйте строгую проверку пользовательского ввода через `scanf` (ввод должен быть успешным, а числа должны быть строго положительными).
3.  Используя двухэтапное выделение памяти (`malloc`), создайте динамическую матрицу соответствующего размера на куче. Обязательно проверяйте результат каждого выделения памяти на `NULL`.
4.  В цикле заполните таблицу умножения: элемент матрицы по индексам `i` и `j` должен хранить значение `(i + 1) * (j + 1)`.
5.  Красиво выведите таблицу на экран (используйте форматирование вывода, например `printf("%4d", matrix[i][j])`, чтобы столбцы не съезжали).
6.  Полностью и безопасно освободите всю выделенную память в строгом обратном порядке, занулив все указатели.

### Задача 2: Транспонирование матрицы на куче

Транспонирование матрицы — это математическая операция, при которой строки матрицы становятся её столбцами, а столбцы — строками. То есть матрица размером `A x B` превращается в матрицу `B x A`.

Напишите программу на Си, в которой:

## Подсказки к задачам

*   **Подсказка к задаче 1:** При проверке выделения памяти строк, если на каком-то шаге `matrix[i]` вернул `NULL`, вы обязаны прервать работу. *   **Подсказка к задаче 2:** Размер выделения для `transposed` будет отличаться: для главного массива указателей потребуется `Cols * sizeof(int *)`, а для каждой строки — `Rows * sizeof(int)`.
