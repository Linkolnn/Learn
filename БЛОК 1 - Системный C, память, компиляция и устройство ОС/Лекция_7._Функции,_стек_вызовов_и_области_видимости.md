# Лекция 7: Функции, стек вызовов и области видимости

Мы научились писать линейный код, ветвить его с помощью условий, зацикливать и хранить наборы данных в массивах. Однако по мере роста программы её исходный код быстро превращается в огромный, трудночитаемый массив текста. Для борьбы со сложностью в программировании применяется фундаментальный принцип: декомпозиция — разделение большой задачи на мелкие, независимые и повторно используемые блоки.

В языке Си такими блоками являются **функции**. В этой лекции мы подробно разберем, как функции работают на физическом уровне компьютера, где хранятся их локальные переменные и какая магия происходит в оперативной памяти (ОЗУ) в момент вызова функции.

---

## Подглава 7.1: Функции в Си — объявление, определение и прототипы

**Функция** — это именованный блок кода, который решает конкретную изолированную задачу. Функцию можно вызвать из любой другой части программы множество раз, передав ей входные данные (аргументы) и получив взамен результат работы.

### Синтаксис объявления и определения функции

Определение функции состоит из заголовка и тела функции, заключенного в фигурные скобки:

```c
тип_возвращаемого_значения имя_функции(список_параметров) {
    // Тело функции (код, который будет выполняться)
    return значение;
}
```

Разберем структуру на конкретном примере функции, которая вычисляет сумму двух целых чисел:

```c
int calculate_sum(int a, int b) {
    int sum = a + b;
    return sum; // Возвращаем результат вызывающему коду
}
```

*   **`int` (тип возвращаемого значения)** — указывает компилятору, данные какого типа функция вернет после завершения работы. Если функция не должна возвращать ничего (например, она просто выводит текст на экран), используется специальный тип **`void`**.
*   **`calculate_sum` (имя функции)** — уникальный идентификатор, по которому мы будем вызывать эту функцию в коде.
*   **`int a, int b` (список параметров)** — переменные, которые функция принимает на вход. Они ведут себя как обычные локальные переменные внутри тела функции и инициализируются теми значениями, которые мы передадим при вызове. Если функция не принимает параметров, в скобках пишут `void`: `int get_value(void)`. Пустые скобки `()` в Си (до стандарта C23) означают не «параметров нет», а «список параметров не указан», и компилятор не проверит, правильно ли вы вызвали такую функцию. Поэтому начиная с этой лекции мы пишем `int main(void)` вместо `int main()`.
*   **`return sum;` (оператор возврата)** — завершает работу функции и передает значение переменной `sum` обратно в точку вызова. Как только процессор доходит до инструкции `return`, выполнение кода функции немедленно прекращается.

### Проблема однопроходного компилятора и прототипы функций

Компилятор языка Си анализирует исходный файл строго сверху вниз, строка за строкой. Если вы попытаетесь вызвать функцию в `main`, а её определение (код) написали ниже по тексту файла, компилятор не сможет проверить вызов: он просто ещё не знает о существовании такой функции. В зависимости от версии компилятора это предупреждение (`implicit declaration of function`) или ошибка. Предупреждение особенно опасно: компилятор «на глазок» предполагает, что функция возвращает `int`, и если на самом деле она устроена иначе, программа будет работать неправильно.

Есть два способа решить эту проблему:

1.  **Располагать функции выше функции `main`**. Это работает для крошечных программ, но в крупных проектах функции часто вызывают друг друга по цепочке, и выстроить их в идеальном порядке сверху вниз становится физически невозможно.
2.  **Использовать прототипы функций (опережающее объявление)**. 

**Прототип функции** — это просто заголовок функции (сигнатура) без её тела, завершающийся точкой с запятой. Он сообщает компилятору: *«Эта функция существует, у неё такое-то имя, она принимает такие-то параметры и возвращает такой-то тип. Её полный код будет описан позже»*.

В прототипе имена параметров можно не писать: `int calculate_sum(int, int);` — компилятору важны только типы. Но с именами код читается проще.

Пример использования прототипа:

```c
#include <stdio.h>

// 1. Прототип функции (опережающее объявление)
int calculate_sum(int a, int b);

int main(void) {
    // Компилятор знает о функции благодаря прототипу и не выдает ошибку
    int result = calculate_sum(15, 30);
    printf("Сумма равна: %d\n", result);
    return 0;
}

// 2. Полное определение функции
int calculate_sum(int a, int b) {
    return a + b;
}
```

## Подглава 7.2: Стек вызовов (Call Stack) на физическом уровне

Когда мы запускаем программу, операционная система выделяет ей адресное пространство (виртуальное, как мы говорили в Лекции 6; подробности — в Лекции 29). Оно делится на несколько **сегментов**:

```text
Высокие адреса
+-------------------------------+
|  Стек (Stack)                 |  фреймы функций, локальные переменные
|            |                  |  (на x86-64 растёт вниз, к меньшим адресам)
|            v                  |
|     (свободное место)         |
|            ^                  |
|            |                  |
|  Куча (Heap)                  |  динамическая память (Лекция 10), растёт вверх
+-------------------------------+
|  .bss                         |  глобальные и static-переменные без значения (нули)
+-------------------------------+
|  .data                        |  глобальные и static-переменные с ненулевым значением
+-------------------------------+
|  .text (код программы)        |  машинные инструкции, только для чтения
+-------------------------------+
Низкие адреса
```

Точное расположение зависит от системы, но общая картина такая. Код программы лежит в сегменте `.text`; глобальные и `static`-переменные — в `.data` и `.bss`; а один из важнейших сегментов, с которого мы начнём, называется **Стеком (Stack)** или **Стеком вызовов (Call Stack)**.

### Физический смысл Стека

Стек — это область ОЗУ, которая работает по принципу **LIFO (Last In, First Out — последним пришел, первым ушел)**. Представьте себе стопку тарелок: вы можете положить новую тарелку только на самый верх стопки, и забрать можете тоже только верхнюю тарелку.

Стек вызовов используется процессором для автоматического управления памятью при вызове функций. Когда программа вызывает любую функцию, на вершине стека выделяется отдельный блок памяти, который называется **фреймом стека (Stack Frame)**. Вершину стека процессор отслеживает с помощью специального регистра — **указателя стека (SP, Stack Pointer)**.

### Что хранится внутри фрейма стека?

Каждый раз, когда функция начинает работу, её персональный фрейм на стеке заполняется следующими данными:
1.  **Аргументы функции** — копии значений, переданных функции при вызове. (На практике на многих 64-битных платформах первые аргументы передаются через регистры — это быстрее, а в стек попадают остальные. Логика «функция получает копии» от этого не меняется.)
2.  **Адрес возврата** — адрес инструкции в ОЗУ (вспомните регистр PC из Лекции 1), к которой процессор должен вернуться на выполнение сразу после того, как функция завершит свою работу.
3.  **Локальные переменные** — все переменные, объявленные внутри этой функции.

(Кроме того, в реальном фрейме обычно хранятся сохранённые значения регистров, но для понимания темы этого достаточно.)

### Как это работает по шагам в ОЗУ:

Допустим, в нашей программе функция `main` вызывает функцию `calculate_sum`.

1.  **До вызова:** В стеке существует только фрейм функции `main`. В нём лежат её локальные переменные (например, `result`).
2.  **Момент вызова `calculate_sum`:** Процессор приостанавливает выполнение `main`. На вершину стека «накатывается» новый фрейм для функции `calculate_sum`. В этот фрейм записывается адрес возврата в `main` и выделяется место под входные параметры `a` и `b`, а также под локальную переменную `sum`.
3.  **Выполнение функции:** Функция работает со своим фреймом стека на вершине. К переменным `main` она не может обратиться по имени: за областью видимости следит компилятор (физически же фреймы лежат в одной и той же области памяти, никакой «стены» между ними процессор не ставит).
4.  **Завершение работы (инструкция `return`):** Процессор считывает из фрейма адрес возврата, «схлопывает» фрейм функции `calculate_sum` (сдвигает указатель стека обратно, после чего эта память считается свободной), возвращает управление в `main` на сохранённый адрес, а возвращённое значение передаётся через регистр (на x86-64 — `RAX`).

Благодаря стеку память под локальные переменные выделяется автоматически при старте функции и освобождается при её завершении простым сдвигом указателя стека. Это один из самых быстрых способов управления временной памятью.

> ⚠️ **Важно:** освобождённая память стека **не обнуляется**. Старые данные лежат там, пока их не перезапишет следующий вызов. Поэтому локальная переменная без инициализации содержит «мусор» — остатки чужих данных.

> ⚠️ **Размер стека ограничен** (обычно порядка 1–8 МБ в зависимости от системы). Если вызовы вкладываются слишком глубоко, стек переполняется, и программа аварийно завершается (**Stack Overflow**). Подробнее об этом — в Лекции 18 про рекурсию.

## Подглава 7.3: Передача аргументов по значению (Pass by Value)

В языке Си действует фундаментальное правило: **все аргументы передаются в функции исключительно по значению**.

Это означает, что когда вы передаете переменную в функцию, функция **никогда не получает саму эту переменную**. Вместо этого компилятор создает точную **копию** значения этой переменной и помещает её во фрейм стека вызванной функции.

Давайте посмотрим на классическую ошибку новичка, иллюстрирующую это правило:

```c
#include <stdio.h>

void increment_value(int num) {
    num = num + 1; // Увеличиваем локальную копию переменной на 1
}

int main(void) {
    int x = 10;
    increment_value(x); // Пытаемся увеличить x с помощью функции
    printf("Значение x в main: %d\n", x); // Выведет 10, а не 11!
    return 0;
}
```

### Почему переменная `x` в `main` не изменилась?

1.  В функции `main` создается переменная `x` со значением `10` в её фрейме стека.
2.  При вызове `increment_value(x)` компилятор берет значение `10`, делает его копию и кладет её на вершину стека во фрейм функции `increment_value` под именем локального параметра `num`.
3.  Внутри функции `increment_value` команда `num = num + 1` изменяет локальную копию `num` (она становится равной `11`). Но эта копия физически лежит в другой ячейке ОЗУ на вершине стека!
4.  Когда функция завершается, её фрейм стека (вместе с переменной `num`, равной `11`) бесследно уничтожается. Процессор возвращается в `main`, где переменная `x` как лежала нетронутой во фрейме `main` со значением `10`, так там и лежит.

**Важнейший вывод:** Функция в Си не может напрямую изменить значение оригинальной переменной из вызывающего кода, если мы передали её обычным способом. Для того чтобы функция могла изменить оригинал, нам придется передавать не значение, а адрес переменной — то есть использовать указатели (Лекция 6). Эту тему (передачу по ссылке с помощью указателей) мы подробно разберем в Лекции 8.

## Подглава 7.4: Области видимости и время жизни переменных

В программировании критически важно различать два понятия: где переменная доступна для использования (область видимости) и когда она физически существует в оперативной памяти (время жизни).

### 1. Локальные переменные

Локальные переменные объявляются внутри фигурных скобок `{}` (в теле функции или даже внутри блока условий или циклов).

*   **Область видимости:** Ограничена блоком `{}`, в котором переменная объявлена. Ни одна функция снаружи не знает о существовании этой переменной.
*   **Время жизни:** Переменная существует с момента объявления до конца блока `{}`, в котором она объявлена. Физически память под неё находится во фрейме стека функции и освобождается вместе с фреймом, когда функция завершается.

```c
void some_function(void) {
    int local_var = 5; // Локальная переменная. Видна только здесь.
}
```

Параметры функции (`a` и `b` в `calculate_sum`) тоже являются локальными переменными. Область видимости может быть и у внутреннего блока:

```c
int x = 1;
if (x > 0) {
    int y = 5;   // y существует только внутри этого блока
}
printf("%d", y); // ОШИБКА компиляции: здесь переменной y уже нет
```

Локальные переменные **не обнуляются автоматически**: без явной инициализации они содержат мусор (см. подглаву 7.2).

### 2. Глобальные переменные

Глобальные переменные объявляются вне любых функций (обычно в самом верху файла под директивами препроцессора).

*   **Область видимости:** Все функции файла, расположенные ниже объявления переменной. Любая из них может свободно читать и перезаписывать эту переменную в любой момент. (В программах из нескольких файлов глобальную переменную можно сделать видимой и в других файлах, но об этом позже.)
*   **Время жизни:** Живёт в течение всего времени работы программы: создаётся при запуске и уничтожается только при завершении. Хранится не на стеке, а в сегментах `.data` или `.bss` (см. схему в подглаве 7.2).
*   **Начальное значение:** Если не задать его явно, глобальная переменная автоматически равна нулю (в отличие от локальных).

```c
#include <stdio.h>

int global_counter = 0; // Глобальная переменная. Видна всем функциям.

void count_event(void) {
    global_counter++; // Изменяем глобальное состояние (++ — то же, что global_counter = global_counter + 1)
}

int main(void) {
    count_event();
    printf("Событий произошло: %d\n", global_counter);
    return 0;
}
```

### Почему глобальных переменных стоит избегать
Как правило, использование изменяемых глобальных переменных считается признаком плохого тона (bad practice). Поскольку любая функция может изменить глобальную переменную, становится невероятно сложно отслеживать логику работы программы. Если в крупном проекте глобальная переменная примет ошибочное значение, вам придется проверять тысячи строк кода во всех функциях, чтобы понять, кто именно её испортил.

## Подглава 7.5: Ключевое слово static в локальном контексте

Что делать, если нам нужно, чтобы локальная переменная вела себя как глобальная с точки зрения времени жизни (не уничтожалась при выходе из функции), но при этом оставалась скрытой от внешнего мира внутри своей функции (сохраняла локальную область видимости)?

Для решения этой задачи в Си используется ключевое слово **`static`**.

Когда мы объявляем локальную переменную как статическую, её физическая природа полностью меняется:

```c
void count_calls(void) {
    static int counter = 0; // Статическая локальная переменная
    counter++;
}
```

(У слова `static` есть и другое значение — для глобальных переменных и функций; об этом поговорим позже. Здесь речь только о локальных переменных.)

### Физические отличия статических переменных в ОЗУ:

1.  **Они НЕ хранятся на стеке вызовов**. Компилятор выделяет под них память в сегменте статических данных (`.data` или `.bss`, см. схему в подглаве 7.2), который существует всё время работы программы.
2.  **Они инициализируются ровно один раз** — до начала выполнения программы. Строчка `static int counter = 0;` — это не команда, которую процессор выполняет при каждом вызове, а указание компилятору заранее записать начальное значение в сегмент данных. Поэтому начальное значение должно быть константой, известной при компиляции (`static int x = other_var;` вызовет ошибку). Если значение не указано, статическая переменная автоматически равна нулю.
3.  **Они сохраняют свое значение между вызовами функции**. Когда функция завершает работу, её фрейм стека уничтожается, но статическая переменная продолжает тихо лежать в сегменте данных и помнить свое последнее значение.
4.  **Они остаются локальными**. Никакая другая функция в программе не может прочитать или изменить эту переменную, потому что область видимости по-прежнему ограничена телом вашей функции.

Давайте посмотрим на работающий пример счетчика вызовов:

```c
#include <stdio.h>

void trigger_sensor(void) {
    static int activations_count = 0; // Инициализируется только один раз при старте программы
    activations_count++;
    printf("Срабатывание №%d\n", activations_count);
}

int main(void) {
    trigger_sensor(); // Выведет: Срабатывание №1
    trigger_sensor(); // Выведет: Срабатывание №2
    trigger_sensor(); // Выведет: Срабатывание №3
    return 0;
}
```

Если бы мы убрали ключевое слово `static`, переменная `activations_count` создавалась бы на стеке заново при каждом вызове со значением `0`, увеличивалась до `1` и уничтожалась при выходе. Программа трижды вывела бы единицу. Но благодаря `static` переменная сохраняет состояние между вызовами, оставаясь скрытой от остальных функций.

> ⚠️ **Цена такого удобства:** функция со `static`-переменной хранит скрытое состояние и может возвращать разные результаты на одинаковые вызовы. Такие функции труднее тестировать, поэтому `static` стоит применять осознанно.

### Задача 1: Конвертер температур с прототипом
Напишите программу на Си, в которой:

## Подсказки к задачам

*   **Подсказка к задаче 1:** Формула перевода содержит деление. Если `celsius` имеет тип `float`, то запись `celsius * 9 / 5` вычисляется слева направо в вещественных числах и даёт верный результат. А вот запись `9 / 5 * celsius` ошибочна: `9 / 5` — это деление двух целых чисел, оно даёт `1`, и дробная часть теряется. Чтобы такого не случилось, можно писать константы как `9.0f / 5.0f`. Для вывода `float` используйте спецификатор `%f` (например, `%.1f` для одного знака после запятой). Для 25 градусов Цельсия ответ — 77 по Фаренгейту.
*   **Подсказка к задаче 2:** Статическая переменная должна быть инициализирована нулем при объявлении: `static int total_bytes = 0;`. Помните, что эта инициализация сработает только один раз. При каждом последующем вызове функции значение переменной `total_bytes` будет сохранять результат предыдущего сложения.
*   **Подсказка к задаче 3:** Вспомните принцип работы стека LIFO (Last In, First Out). Та функция, которая была вызвана последней, оказывается на самом верху стопки. Изоляция локальных переменных обеспечивается правилами языка (областью видимости), которые проверяет компилятор, а не процессором: для процессора стек — это обычная память, и он прочитает любую её ячейку, если получит её адрес (именно на этом основана передача указателей в Лекции 8 и некоторые уязвимости с переполнением буфера).
