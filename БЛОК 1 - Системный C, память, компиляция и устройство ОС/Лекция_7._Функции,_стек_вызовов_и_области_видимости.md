# Лекция 7: Функции, стек вызовов и области видимости

Мы научились писать линейный код, ветвить его с помощью условий, зацикливать и хранить наборы данных в массивах. Однако по мере роста программы её исходный код быстро превращается в огромный, трудночитаемый массив текста. Для борьбы со сложностью в программировании применяется фундаментальный принцип: декомпозиция — разделение большой задачи на мелкие, независимые и повторно используемые блоки.

В языке Си такими блоками являются **функции**. В этой лекции мы подробно разберем, как функции работают на физическом уровне компьютера, где хранятся их локальные переменные и какая магия происходит в оперативной памяти (ОЗУ) в момент вызова функции.

---

## Подглава 7.1: Функции в Си — объявление, определение и прототипы

**Функция** — это именованный блок кода, который решает конкретную изолированную задачу. Функцию можно вызвать из любой другой части программы множество раз, передав ей входные данные (аргументы) и получив взамен результат работы.

### Синтаксис объявления и определения функции

Определение функции состоит из заголовка и тела функции, заключенного в фигурные скобки:

```c
тип_возвращаемого_значения имя_функции(список_параметров) {
    // Тело функции (код, который будет выполняться)
    return значение;
}
```

Разберем структуру на конкретном примере функции, которая вычисляет сумму двух целых чисел:

```c
int calculate_sum(int a, int b) {
    int sum = a + b;
    return sum; // Возвращаем результат вызывающему коду
}
```

*   **`int` (тип возвращаемого значения)** — указывает компилятору, данные какого типа функция вернет после завершения работы. Если функция не должна возвращать ничего (например, она просто выводит текст на экран), используется специальный тип **`void`**.
*   **`calculate_sum` (имя функции)** — уникальный идентификатор, по которому мы будем вызывать эту функцию в коде.
*   **`int a, int b` (список параметров)** — переменные, которые функция принимает на вход. Они ведут себя как обычные локальные переменные внутри тела функции и инициализируются теми значениями, которые мы передадим при вызове. Если функция не принимает параметров, скобки оставляют пустыми или пишут в них `void`.
*   **`return sum;` (оператор возврата)** — завершает работу функции и передает значение переменной `sum` обратно в точку вызова. Как только процессор доходит до инструкции `return`, выполнение кода функции немедленно прекращается.

### Проблема однопроходного компилятора и прототипы функций

Компилятор языка Си анализирует исходный файл строго сверху вниз, строка за строкой. Если вы попытаетесь вызвать функцию в `main`, а её определение (код) написали ниже по тексту файла, компилятор выдаст ошибку: он просто ещё не знает о существовании такой функции.

Есть два способа решить эту проблему:

1.  **Располагать функции выше функции `main`**. Это работает для крошечных программ, но в крупных проектах функции часто вызывают друг друга по цепочке, и выстроить их в идеальном порядке сверху вниз становится физически невозможно.
2.  **Использовать прототипы функций (опережающее объявление)**. 

**Прототип функции** — это просто заголовок функции (сигнатура) без её тела, завершающийся точкой с запятой. Он сообщает компилятору: *«Эта функция существует, у неё такое-то имя, она принимает такие-то параметры и возвращает такой-то тип. Её полный код будет описан позже»*.

Пример использования прототипа:

```c
#include <stdio.h>

// 1. Прототип функции (опережающее объявление)
int calculate_sum(int a, int b);

int main() {
    // Компилятор знает о функции благодаря прототипу и не выдает ошибку
    int result = calculate_sum(15, 30);
    printf("Сумма равна: %d\n", result);
    return 0;
}

// 2. Полное определение функции
int calculate_sum(int a, int b) {
    return a + b;
}
```

## Подглава 7.2: Стек вызовов (Call Stack) на физическом уровне

Когда мы запускаем программу, операционная система выделяет ей определенный объем оперативной памяти. Эта память делится на несколько сегментов. Один из важнейших сегментов называется **Стеком (Stack)** или **Стеком вызовов (Call Stack)**.

### Физический смысл Стека

Стек — это область ОЗУ, которая работает по принципу **LIFO (Last In, First Out — последним пришел, первым ушел)**. Представьте себе стопку тарелок: вы можете положить новую тарелку только на самый верх стопки, и забрать можете тоже только верхнюю тарелку.

Стек вызовов используется процессором для автоматического управления памятью при вызове функций. Когда программа вызывает любую функцию, в самом верху стека выделяется изолированный блок памяти, который называется **фреймом стека (Stack Frame)**.

### Что хранится внутри фрейма стека?

Каждый раз, когда функция начинает работу, её персональный фрейм на стеке заполняется следующими данными:
1.  **Аргументы функции** — копии значений, переданных функции при вызове.
2.  **Адрес возврата** — адрес инструкции в ОЗУ (вспомните регистр PC из Лекции 1), к которой процессор должен вернуться на выполнение сразу после того, как функция завершит свою работу.
3.  **Локальные переменные** — все переменные, объявленные внутри этой функции.

### Как это работает по шагам в ОЗУ:

Допустим, в нашей программе функция `main` вызывает функцию `calculate_sum`.

1.  **До вызова:** В стеке существует только фрейм функции `main`. В нём лежат её локальные переменные (например, `result`).
2.  **Момент вызова `calculate_sum`:** Процессор приостанавливает выполнение `main`. На вершину стека «накатывается» новый фрейм для функции `calculate_sum`. В этот фрейм записывается адрес возврата в `main` и выделяется место под входные параметры `a` и `b`, а также под локальную переменную `sum`.
3.  **Выполнение функции:** Функция работает исключительно со своим фреймом стека на вершине. Она не имеет прямого доступа к переменным во фрейме `main`.
4.  **Завершение работы (инструкция `return`):** Процессор считывает из фрейма адрес возврата, уничтожает (схлопывает) фрейм функции `calculate_sum` на стеке, освобождая всю занимаемую им память, возвращает управление в `main` на сохраненный адрес и помещает возвращенное значение в нужный регистр.

Благодаря стеку память под локальные переменные выделяется автоматически при старте функции и мгновенно зачищается при её завершении. Это самый быстрый и эффективный способ управления временной памятью в компьютере.

## Подглава 7.3: Передача аргументов по значению (Pass by Value)

В языке Си действует фундаментальное правило: **все аргументы передаются в функции исключительно по значению**.

Это означает, что когда вы передаете переменную в функцию, функция **никогда не получает саму эту переменную**. Вместо этого компилятор создает точную **копию** значения этой переменной и помещает её во фрейм стека вызванной функции.

Давайте посмотрим на классическую ошибку новичка, иллюстрирующую это правило:

```c
#include <stdio.h>

void increment_value(int num) {
    num = num + 1; // Увеличиваем локальную копию переменной на 1
}

int main() {
    int x = 10;
    increment_value(x); // Пытаемся увеличить x с помощью функции
    printf("Значение x в main: %d\n", x); // Выведет 10, а не 11!
    return 0;
}
```

### Почему переменная `x` в `main` не изменилась?

1.  В функции `main` создается переменная `x` со значением `10` в её фрейме стека.
2.  При вызове `increment_value(x)` компилятор берет значение `10`, делает его копию и кладет её на вершину стека во фрейм функции `increment_value` под именем локального параметра `num`.
3.  Внутри функции `increment_value` команда `num = num + 1` изменяет локальную копию `num` (она становится равной `11`). Но эта копия физически лежит в другой ячейке ОЗУ на вершине стека!
4.  Когда функция завершается, её фрейм стека (вместе с переменной `num`, равной `11`) бесследно уничтожается. Процессор возвращается в `main`, где переменная `x` как лежала нетронутой во фрейме `main` со значением `10`, так там и лежит.

**Важнейший вывод:** Функция в Си не может напрямую изменить значение оригинальной переменной из вызывающего кода, если мы передали её обычным способом. Для того чтобы функция могла изменить оригинал, нам придется передавать не значение, а физический адрес переменной — то есть использовать указатели. Эту тему (передачу по ссылке с помощью указателей) мы подробно разберем в Лекции 8.

## Подглава 7.4: Области видимости и время жизни переменных

В программировании критически важно различать два понятия: где переменная доступна для использования (область видимости) и когда она физически существует в оперативной памяти (время жизни).

### 1. Локальные переменные

Локальные переменные объявляются внутри фигурных скобок `{}` (в теле функции или даже внутри блока условий или циклов).

*   **Область видимости:** Ограничена блоком `{}`, в котором переменная объявлена. Ни одна функция снаружи не знает о существовании этой переменной.
*   **Время жизни:** Переменная рождается на стеке в момент входа процессора в её блок кода и уничтожается, когда процессор выходит из этого блока (фрейм стека схлопывается).

```c
void some_function() {
    int local_var = 5; // Локальная переменная. Видна только здесь.
}
```

### 2. Глобальные переменные

Глобальные переменные объявляются вне любых функций (обычно в самом верху файла под директивами препроцессора).

*   **Область видимости:** Вся программа. Любая функция в этом файле может свободно читать и перезаписывать эту переменную в любой момент.
*   **Время жизни:** Живет в течение всего времени работы программы. Она рождается в момент запуска приложения и уничтожается только при его полном закрытии.

```c
#include <stdio.h>

int global_counter = 0; // Глобальная переменная. Видна всем функциям.

void count_event() {
    global_counter++; // Изменяем глобальное состояние
}

int main() {
    count_event();
    printf("Событий произошло: %d\n", global_counter);
    return 0;
}
```

### Почему глобальные переменные — это зло?
В системном программировании использование глобальных переменных считается признаком плохого тона (bad practice). Поскольку любая функция может изменить глобальную переменную, становится невероятно сложно отслеживать логику работы программы. Если в крупном проекте глобальная переменная примет ошибочное значение, вам придется проверять тысячи строк кода во всех функциях, чтобы понять, кто именно её испортил.

## Подглава 7.5: Ключевое слово static в локальном контексте

Что делать, если нам нужно, чтобы локальная переменная вела себя как глобальная с точки зрения времени жизни (не уничтожалась при выходе из функции), но при этом оставалась скрытой от внешнего мира внутри своей функции (сохраняла локальную область видимости)?

Для решения этой задачи в Си используется ключевое слово **`static`**.

Когда мы объявляем локальную переменную как статическую, её физическая природа полностью меняется:

```c
void MyFunction() {
    static int counter = 0; // Статическая локальная переменная
    counter++;
}
```

### Физические отличия статических переменных в ОЗУ:

1.  **Они НЕ хранятся на стеке вызовов**. Компилятор выделяет под них память в специальном сегменте постоянных данных (Data Segment).
2.  **Они инициализируются ровно один раз** — при самом первом запуске программы. Строчка `static int counter = 0;` при повторных вызовах функции процессором просто игнорируется.
3.  **Они сохраняют свое значение между вызовами функции**. Когда функция завершает работу, её фрейм стека уничтожается, но статическая переменная продолжает тихо лежать в сегменте данных и помнить свое последнее значение.
4.  **Они остаются локальными**. Никакая другая функция в программе не может прочитать или изменить эту переменную, потому что область видимости по-прежнему ограничена телом вашей функции.

Давайте посмотрим на работающий пример счетчика вызовов:

```c
#include <stdio.h>

void trigger_sensor() {
    static int activations_count = 0; // Инициализируется только один раз при старте программы
    activations_count++;
    printf("Сенсор сработал %d раз\n", activations_count);
}

int main() {
    trigger_sensor(); // Выведет: Сенсор сработал 1 раз
    trigger_sensor(); // Выведет: Сенсор сработал 2 раз
    trigger_sensor(); // Выведет: Сенсор сработал 3 раз
    return 0;
}
```

Если бы мы убрали ключевое слово `static`, переменная `activations_count` создавалась бы на стеке заново при каждом вызове со значением `0`, увеличивалась до `1` и уничтожалась при выходе. Программа трижды вывела бы единицу. Но благодаря `static` переменная сохраняет состояние между вызовами, обеспечивая безопасное инкапсулированное хранение данных.

## Практические задачи

### Задача 1: Конвертер температур с прототипом
Напишите программу на Си, в которой:
1.  В самом верху файла (до функции `main`) объявлен прототип функции `float celsius_to_fahrenheit(float celsius);`.
2.  В функции `main` объявляется переменная для хранения температуры в градусах Цельсия (например, `25.0f`).
3.  Вызывается функция `celsius_to_fahrenheit`, ей передается значение температуры.
4.  Функция производит расчет по формуле: `fahrenheit = (celsius * 9 / 5) + 32`.
5.  Результат возвращается в `main` и выводится на экран с поясняющим текстом.
6.  Само определение функции `celsius_to_fahrenheit` должно быть написано строго ниже функции `main`.

### Задача 2: Накопитель объема данных (Локальный статический буфер)
Представьте, что вы пишете прошивку для сетевого шлюза. Вам нужно фиксировать общий объем проходящего трафика.
Напишите программу, в которой:
1.  Создана функция `void register_packet(int packet_size);`.
2.  Внутри этой функции объявлена статическая переменная `total_bytes`, которая хранит накопленный объем переданных данных.
3.  При каждом вызове функция должна прибавлять полученный `packet_size` к общему объему и выводить на экран сообщение: «Получен пакет размером X байт. Всего обработано: Y байт».
4.  В функции `main` сымитируйте последовательное получение трех пакетов, вызвав функцию три раза с разными значениями (например, 120, 300, 50).

### Задача 3: Теоретический анализ Стека вызовов (устно)
Опираясь на подглаву 7.2, ответьте на вопросы:
1.  Представьте цепочку вызовов: функция `main` вызывает функцию `A`, которая внутри себя вызывает функцию `B`. Фрейм какой из этих трех функций будет находиться в самом низу стека вызовов, а фрейм какой функции — на самой вершине? 
2.  Фрейм какой функции будет уничтожен первым, когда программа начнет возвращать управление обратно?
3.  Если функция `B` попытается напрямую прочитать значение локальной переменной, объявленной в функции `A`, разрешит ли это сделать процессор? Почему?

## Подсказки к задачам

*   **Подсказка к задаче 1:** Формула перевода содержит деление. Будьте аккуратны с типами данных: используйте вещественные числа (`float`), а при инициализации констант не забывайте ставить суффикс `f` (например, `9.0f / 5.0f`), чтобы деление не превратилось в целочисленное с потерей дробной части. Для вывода float используйте спецификатор формата `%f`.
*   **Подсказка к задаче 2:** Статическая переменная должна быть инициализирована нулем при объявлении: `static int total_bytes = 0;`. Помните, что эта инициализация сработает только один раз. При каждом последующем вызове функции значение переменной `total_bytes` будет сохранять результат предыдущего сложения.
*   **Подсказка к задаче 3:** Вспомните принцип работы стека LIFO (Last In, First Out). Та функция, которая была вызвана последней, оказывается на самом верху стопки. Локальные переменные изолированы внутри своих фреймов стека; фрейм одной функции физически не видит и не может адресовать ячейки памяти, принадлежащие чужому фрейму.
