# Лекция 2: Системы счисления, переменные и типы данных

## Подглава 2.1: Позиционные системы счисления — язык, на котором говорит память

Любая информация в компьютере выражается в виде чисел. Буквы сопоставляются с числами (символьные таблицы), цвета кодируются интенсивностью световых потоков красного, зеленого и синего (каждая интенсивность — это число), а изображения представляются в виде мозаики из цветных точек.

Современные компьютеры используют позиционные системы счисления. Это значит, что значение каждой цифры в числе зависит от её позиции (разряда). В позиционной системе с основанием "d" значение цифры в позиции "i" умножается на основание "d" в степени "i" (считая позиции справа налево, начиная с нуля).

Мы в повседневной жизни пользуемся десятичной системой (основание d = 10), так как у нас десять пальцев на руках. Но компьютерным схемам гораздо удобнее работать с двоичной системой (основание d = 2), где есть только две цифры: 0 (низкое электрическое напряжение в полупроводнике) и 1 (высокое напряжение). Также в системном программировании часто применяются шестнадцатеричная (d = 16) и восьмеричная (d = 8) системы — они позволяют компактно записывать двоичные адреса памяти и значения флагов.

Давайте посмотрим, как одно и то же число 4321 представляется в разных системах счисления:

1. **Десятичная система (основание d = 10):**
   Мы используем цифры от 0 до 9. Позиции цифр в числе 4321 считаются справа налево:
   * Цифра 1 стоит на позиции 0 (разряд единиц): 1 * 10^0 = 1 * 1 = 1
   * Цифра 2 стоит на позиции 1 (разряд десятков): 2 * 10^1 = 2 * 10 = 20
   * Цифра 3 стоит на позиции 2 (разряд сотен): 3 * 10^2 = 3 * 100 = 300
   * Цифра 4 стоит на позиции 3 (разряд тысяч): 4 * 10^3 = 4 * 1000 = 4000
   
   Складываем разряды:
   4321 (в десятичной системе) = 4 * 10^3 + 3 * 10^2 + 2 * 10^1 + 1 * 10^0 = 4000 + 300 + 20 + 1 = 4321

2. **Шестнадцатеричная система (основание d = 16):**
   В этой системе используются цифры от 0 до 9 и латинские буквы от A до F для обозначения чисел от 10 до 15:
   A = 10, B = 11, C = 12, D = 13, E = 14, F = 15.
   Возьмем шестнадцатеричное число 10E1. Переведем его в десятичную систему:
   * Буква E на позиции 1 означает число 14.
   
   10E1 (в шестнадцатеричной системе) = 1 * 16^3 + 0 * 16^2 + 14 * 16^1 + 1 * 16^0 = 4096 + 0 + 224 + 1 = 4321

3. **Восьмеричная система (основание d = 8):**
   Используются только цифры от 0 до 7.
   Возьмем восьмеричное число 10341 и переведем его в десятичную систему:
   
   10341 (в восьмеричной системе) = 1 * 8^4 + 0 * 8^3 + 3 * 8^2 + 4 * 8^1 + 1 * 8^0 = 4096 + 0 + 192 + 32 + 1 = 4321

4. **Двоичная система (основание d = 2):**
   Используются только цифры 0 и 1.
   Возьмем двоичное число 1000011100001 (обратите внимание на точную последовательность нулей и единиц, где единицы стоят на 0, 5, 6, 7 и 12 позициях) и переведем его в десятичную систему:
   
   1000011100001 (в двоичной системе) = 1 * 2^12 + 1 * 2^7 + 1 * 2^6 + 1 * 2^5 + 1 * 2^0 = 4096 + 128 + 64 + 32 + 1 = 4321

## Подглава 2.2: Байты в памяти и порядок байтов (Endianness)

Как мы уже знаем из первой лекции, минимальная адресуемая ячейка оперативной памяти — это **байт**, состоящий из 8 бит. Каждый бит физически представляет собой крошечный конденсатор или транзистор в микросхеме ОЗУ, способный хранить либо заряд (1), либо его отсутствие (0).

Когда процессор считывает группу битов из ОЗУ, способ их интерпретации зависит от архитектурного стандарта процессора. Этот стандарт называется **порядком байтов (Endianness)**. Он определяет, как многобайтовые данные (например, 4-байтовые целые числа) располагаются в ячейках памяти:

* **Прямой порядок байтов (Big-Endian):** Числа записываются и читаются в естественном для человека порядке — слева направо (от самых старших байтов к самым младшим). Например, если мы рассмотрим структуру отдельного байта, где биты читаются слева направо, двоичная последовательность `10000011` будет интерпретироваться процессором как:
  1 * 2^7 + 0 * 2^6 + 0 * 2^5 + 0 * 2^4 + 0 * 2^3 + 0 * 2^2 + 1 * 2^1 + 1 * 2^0 = 128 + 0 + 0 + 0 + 0 + 0 + 2 + 1 = 131

* **Обратный порядок байтов (Little-Endian):** Данные записываются справа налево (от младших разрядов к старшим). На уровне процессора та же физическая последовательность битов `10000011` при обратном чтении будет истолкована «наоборот»:
  1 * 2^0 + 0 * 2^1 + 0 * 2^2 + 0 * 2^3 + 0 * 2^4 + 0 * 2^5 + 1 * 2^6 + 1 * 2^7 = 1 + 0 + 0 + 0 + 0 + 0 + 64 + 128 = 193

Большинство современных процессоров (включая архитектуры x86 и x86-64 от Intel/AMD) используют обратный порядок байтов (Little-Endian). Однако глобальные компьютерные сети, интернет-протоколы и сетевое оборудование исторически стандартизировали прямой порядок байтов (Big-Endian). 

Поэтому системный программист, пишущий сетевые приложения, всегда должен вручную контролировать порядок байтов. Если переслать число из памяти Little-Endian компьютера в сеть без преобразования, удаленный компьютер (или роутер) прочитает совершенно другие, искаженные данные.

## Подглава 2.3: Переменные и статическая типизация в Си

В реальном программировании нам крайне неудобно обращаться к ячейкам оперативной памяти по их физическим числовым адресам (например, записывать данные по адресу `0x7ffee3bf8`). Вместо этого язык Си предоставляет нам удобную абстракцию — **переменные**.

**Переменная** — это именованная область памяти, значение которой можно изменять в процессе работы программы. Когда мы объявляем переменную, компилятор сам выделяет под неё нужный объем свободной памяти в ОЗУ и связывает имя этой переменной с выделенным адресом.

Язык Си является **статически типизированным**. Это означает две вещи:
1. Каждая переменная должна иметь строго определенный тип данных, который указывается при её объявлении.
2. Тип переменной жестко закрепляется за ней на этапе компиляции и не может быть изменен во время работы программы.

Зачем это нужно? Статическая типизация решает важнейшие задачи оптимизации и безопасности:
* **Распределение ресурсов:** Компилятор точно знает, сколько байт памяти нужно выделить под переменную (например, 1 байт для символа или 4 байта для целого числа).
* **Интерпретация данных:** Компьютер понимает, как трактовать нули и единицы в памяти — как целое число, дробь или текстовый символ.
* **Безопасность:** Компилятор проверяет код на совместимость типов еще до запуска программы. Он выдаст ошибку, если вы попытаетесь выполнить бессмысленную операцию — например, вычесть символ из дробного числа.

## Подглава 2.4: Базовые типы данных в Си

В языке Си существует несколько встроенных элементарных типов данных. Давайте подробно разберем четыре фундаментальных типа, которые вы будете использовать постоянно:

1. **`char` (символьный тип)**
   * **Размер в памяти:** Ровно 1 байт (8 бит).
   * **Назначение:** Хранение одного символа (буквы, цифры или специального знака), заключенного в одиночные кавычки.
   * **Как работает под капотом:** На самом деле в памяти хранится не сама буква, а её целочисленный код согласно таблице кодировки ASCII (например, символ `'A'` физически хранится как число `65`).
   * **Пример кода:** `char grade = 'A';`

2. **`int` (целочисленный тип)**
   * **Размер в памяти:** Обычно 4 байта (32 бита) на современных системах.
   * **Назначение:** Хранение целых положительных и отрицательных чисел.
   * **Пример кода:** `int temperature = -15;`

3. **`float` (вещественный тип одинарной точности)**
   * **Размер в памяти:** 4 байта (32 бита).
   * **Назначение:** Хранение дробных чисел (чисел с плавающей точкой). При инициализации литерала принято ставить суффикс `f` на конце числа, чтобы компилятор не путал его с типом double.
   * **Пример кода:** `float price = 99.99f;`

4. **`double` (вещественный тип двойной точности)**
   * **Размер в памяти:** 8 байт (64 бита).
   * **Назначение:** Хранение дробных чисел с очень высокой точностью (в два раза больше знаков после запятой, чем у float).
   * **Пример кода:** `double exact_value = 0.1234567890123;`

### Вывод значений переменных с помощью printf

Чтобы функция `printf` вывела значение переменной, нам нужно указать в строке вывода специальную заглушку — **спецификатор формата**. При выводе компилятор заменит этот спецификатор на реальное значение переменной, переданной в качестве аргумента.

Для каждого типа данных существует свой спецификатор:
* `%d` — для целых чисел (`int`)
* `%c` — для символов (`char`)
* `%f` — для дробных чисел (`float`)
* `%lf` — для дробных чисел двойной точности (`double`)

Пример программы:

```c
#include <stdio.h>

int main() {
    int students_count = 12;
    char class_letter = 'B';
    float average_score = 4.75f;
    double exact_coefficient = 1.059463094359;

    printf("Класс: %d%c\n", students_count, class_letter);
    printf("Средний балл: %f\n", average_score);
    printf("Коэффициент: %lf\n", exact_coefficient);

    return 0;
}
```

## Подглава 2.5: Диапазоны значений и переполнение типов

Поскольку под каждый тип данных выделяется фиксированное количество байт в оперативной памяти, диапазон значений, которые мы можем записать в переменную, строго ограничен.

Например, если тип данных занимает 1 байт (8 бит), он может хранить только 2^8 = 256 различных комбинаций нулей и единиц. Если это беззнаковый тип (хранящий только положительные числа), его диапазон составит от `0` до `255`. 

Что произойдет, если мы попытаемся записать в такую переменную число `256`? 
Произойдет **переполнение памяти (Overflow)**. В этот момент значение переменной циклически сбросится до минимального значения диапазона.

**Физический пример:** Представьте механический счетчик пробега (одометр) в автомобиле, у которого есть только три цифры. Максимальное число, которое он может показать — `999`. Как только машина проедет еще один километр, счетчик покажет `000`. Старший разряд «тысяч» просто отбрасывается, так как для него физически нет места на панели.

То же самое происходит в ОЗУ: при превышении лимита битов старший переполнившийся бит отбрасывается процессором, а оставшиеся младшие биты дают нулевой или минимальный результат. Защита программы от переполнения типов — одна из ключевых задач при написании безопасного системного кода.

## Практические задачи

### Задача 1: Объявление и вывод переменных
Напишите программу на Си, в которой:
1. Объявляются четыре переменные: типа `int`, `char`, `float` и `double`.
2. Каждой переменной присваивается осмысленное значение (например: ваш текущий возраст, первая буква вашей фамилии, текущая температура воздуха, точное математическое число).
3. Значения всех переменных выводятся на экран с помощью функций `printf` (каждое значение на новой строке) вместе с поясняющим текстом.

### Задача 2: Теоретическая проверка (устно)
1. Переведите двоичное число `10101` в десятичную систему счисления, используя позиционный принцип (умножение цифр на степени двойки).
2. Представьте двоичную последовательность `11000000` в одном байте ОЗУ. Какое десятичное число она будет представлять при прямом порядке байтов (Big-Endian) и какое — при обратном порядке байтов (Little-Endian)?

## Подсказки к задачам

* **Подсказка к задаче 1:** Используйте правильные спецификаторы формата (`%d` для int, `%c` для char, `%f` для float, `%lf` для double) в строке вывода `printf`. Не забывайте ставить управляющий символ `\n` для переноса строки и точку с запятой `;` в конце каждой инструкции. Дробные числа типа `float` инициализируйте с буквой `f` на конце (например, `36.6f`).
* **Подсказка к задаче 2:** 
  * Для перевода двоичного числа распишите его по разрядам справа налево, начиная с нулевой степени: `1 * 2^0`, `0 * 2^1`, `1 * 2^2` и так далее, а затем сложите результаты.
  * Для определения десятичных значений при разном порядке байтов помните: при Big-Endian крайний левый бит имеет индекс 7 (`2^7 = 128`), а крайний правый — индекс 0 (`2^0 = 1`). При Little-Endian все биты переворачиваются: крайний левый бит считывается как нулевой разряд (`2^0 = 1`), а крайний правый — как седьмой разряд (`2^7 = 128`).
