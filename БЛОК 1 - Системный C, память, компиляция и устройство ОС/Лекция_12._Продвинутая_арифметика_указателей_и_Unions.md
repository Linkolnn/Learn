# Лекция 12: Продвинутая арифметика указателей и Объединения (Unions)

В предыдущих лекциях мы изучили указатели, динамическую память, массивы и структуры. Мы увидели, что указатель хранит 64-битный адрес ячейки оперативной памяти (ОЗУ). Начиная с Лекции 6, мы активно использовали простые операции над указателями: берем адрес через `&`, разыменовываем через `*` или переходим к следующему элементу массива через `ptr++`.

В этой лекции мы опустимся на самый глубокий уровень работы с памятью в Си. Мы разберем физические законы арифметики указателей, научимся проводить побайтовый анализ объектов любой сложности, изучим правила выравнивания памяти процессором и освоим специальную конструкцию — **объединения (`union`)**, позволяющие переинтерпретировать биты в ОЗУ на физическом уровне.

## Подглава 12.1: Арифметика указателей и физический шаг смещения (Pointer Scaling)

Указатель в Си — это не просто абстрактное число, хранящее адрес. Каждый указатель строго привязан к определенному типу данных (например, `int *`, `double *`, `char *`). Эта привязка определяет не только то, сколько байт компилятор прочитает при разыменовании `*ptr`, но и то, **на сколько байт сдвинется физический адрес при арифметических операциях**.

### 1. Масштабирование смещения (Pointer Scaling)

Обычная математическая арифметика работает с чистыми числами: `1000 + 1 = 1001`. 
Однако **арифметика указателей** работает с адресами объектов в ОЗУ. Когда вы пишете `ptr + n`, компилятор Си интерпретирует это действие не как прибавление `n` байт к адресу, а как **переход на `n` элементов вперед**.

Физическая формула расчета нового адреса процессором:

`Новый_Физический_Адрес = Стартовый_Адрес + n * sizeof(*ptr)`

Где `sizeof(*ptr)` — это физический размер в байтах того типа данных, на который указывает указатель.

#### Сравнение шага смещения для разных типов:

Представьте, что четыре указателя разных типов хранят один и тот же начальный адрес ОЗУ — `0x2000` (в десятичной системе: `8192`). Давайте посмотрим, что произойдет при прибавлении числа `1` (`ptr + 1`):

1. **Тип `char *`** (`sizeof(char) = 1` байт):
   * `Новый адрес = 8192 + 1 * 1 = 8193` (`0x2001`).
   * Смещение в ОЗУ составило ровно **1 байт**.

2. **Тип `short *`** (`sizeof(short) = 2` байта):
   * `Новый адрес = 8192 + 1 * 2 = 8194` (`0x2002`).
   * Смещение в ОЗУ составило **2 байта**.

3. **Тип `int *`** (`sizeof(int) = 4` байта):
   * `Новый адрес = 8192 + 1 * 4 = 8196` (`0x2004`).
   * Смещение в ОЗУ составило **4 байта**.

4. **Тип `double *`** (`sizeof(double) = 8` байт):
   * `Новый адрес = 8192 + 1 * 8 = 8200` (`0x2008`).
   * Смещение в ОЗУ составило **8 байт**.

5. **Указатель на структуру `struct Person *`** (допустим, `sizeof(struct Person) = 64` байта):
   * `Новый адрес = 8192 + 1 * 64 = 8256` (`0x2040`).
   * Смещение в ОЗУ составило сразу **64 байта**.

```text
Адрес ОЗУ:        0x2000   0x2001   0x2002   0x2003   0x2004   ...   0x2008
                  |--------|--------|--------|--------|--------| ... |--------|
char *p_char:     [ p_char ] -> +1 байт (0x2001)
short *p_short:   [    p_short     ] --------> +2 байта (0x2002)
int *p_int:       [         p_int          ] -----------------> +4 байта (0x2004)
double *p_double: [                  p_double                  ] ------------> +8 байт (0x2008)
```

**Главный физический вывод:** Тип указателя масштабирует любой шаг сложения или вычитания на физический размер типа данных. Компилятор берет на себя эту математику, чтобы программист мог обходить массивы любых типов простым шагом `ptr++`.

### 2. Вычитание указателей и тип `ptrdiff_t`

В Си можно не только прибавлять числа к указателям, но и **вычитать один указатель из другого**.

Однако вычитание двух указателей допустимо только тогда, когда они **указывают на элементы одного и того же массива** (или на элемент, следующий за последним).

Результатом выражения `ptr2 - ptr1` является не количество байтов между ними, а **количество элементов данного типа**, расположенных между этими адресами в памяти.

Формула вычисления разности указателей:

`Количество_элементов = (Адрес_ptr2 - Адрес_ptr1) / sizeof(*ptr1)`

#### Пример физического расчета:
Допустим, у нас есть массив `int arr[5]`, расположенный по адресу `0x1000`.
* `ptr1 = &arr[1]` (адрес `0x1004` / 4100).
* `ptr2 = &arr[4]` (адрес `0x1010` / 4112).

Вычисляем разность `ptr2 - ptr1`:
1. Разность физических адресов в байтах: `4112 - 4100 = 12` байт.
2. Деление на размер типа: `12 / sizeof(int) = 12 / 4 = 3`.
3. Результат вычитания равен `3` (между элементами с индексами 1 и 4 находится ровно 3 элемента).

#### Системный тип `ptrdiff_t`
Результат вычитания указателей имеет специальный знаковый целочисленный тип **`ptrdiff_t`**, объявленный в системном заголовочном файле **`<stddef.h>`** (который автоматически подключается через `<stdio.h>` и `<stdlib.h>`).

* На 64-битных системах `ptrdiff_t` является 64-битным знаковым целым числом (`long int`).
* Для вывода значений типа `ptrdiff_t` через `printf` используется специальный спецификатор **`%td`**:

```c
#include <stdio.h>
#include <stddef.h>

int main() {
    int numbers[5] = {10, 20, 30, 40, 50};
    int *p1 = &numbers[1];
    int *p2 = &numbers[4];

    ptrdiff_t diff = p2 - p1; // Вернет 3
    printf("Элементов между указателями: %td\n", diff);
    return 0;
}
```

### 3. Сравнение указателей

К указателям одинакового типа можно применять операторы сравнения: `<`, `>`, `<=`, `>=`, `==`, `!=`.

* **Сравнение на равенство (`ptr1 == ptr2`):** Проверяет, указывают ли два указателя на **один и тот же физический адрес в ОЗУ**.
* **Реляционное сравнение (`ptr1 < ptr2`):** Проверяет, находится ли адрес `ptr1` ниже в оперативной памяти (по меньшему адресу), чем `ptr2`.

*Правило стандарта ISO C:* Операции сравнения `<, >, <=, >=` физически корректны только тогда, когда оба указателя указывают на элементы одного массива или одной структуры. Сравнение указателей из двух совершенно разных, не связанных между собой локальных переменных на стеке считается непереносимым поведением (Undefined Behavior).

## Подглава 12.2: Приведение типов указателей (Pointer Casting) и побайтовый анализ памяти

Поскольку указатель — это просто 64-битное число-адрес, язык Си позволяет насильно изменить тип указателя с помощью **оператора приведения типов (Casting)**: `(new_type *)ptr`.

### 1. Физическая суть приведения типов указателей

Когда вы делаете приведение типа указателя:
```c
int x = 0x12345678;
int *p_int = &x;
char *p_char = (char *)p_int; // Приведение типов указателей
```

Сохраняется ли адрес в памяти? **Да, на 100%!** Значение в переменной `p_char` будет содержать точно такой же 64-битный адрес ОЗУ, что и `p_int`.

Что же изменяется при этом для процессора и компилятора?
1. **Размер считываемого блока при разыменовании (`*`):**
   * При `*p_int` процессор прочитает из памяти **4 байта** целиком.
   * При `*p_char` процессор прочитает из того же адреса всего **1 байт**.
2. **Шаг арифметики при смещении (`+`):**
   * При `p_int + 1` адрес увеличится на **4 байта**.
   * При `p_char + 1` адрес увеличится на **1 байт**.

---

### 2. Универсальный указатель `void *` и его ограничения

В Лекции 10 мы познакомились с универсальным указателем **`void *`**. Он используется такими функциями, как `malloc` и `free`, так как хранит «чистый» адрес памяти без привязки к конкретному типу данных.

#### Правила работы с `void *` на низком уровне:
1. **Запрет на прямое разыменование:** Нельзя написать `*void_ptr`. Поскольку тип `void` не имеет размера (`sizeof(void)` не существует), компилятор не знает, сколько байт нужно прочитать из памяти (1, 4 или 8).
2. **Запрет на арифметику указателей (по строгому стандарту ISO C):** Выражение `void_ptr + 1` в строгом стандарте C недопустимо, так как размер шага неизвестен.
   *(Примечание: в компиляторе GCC есть расширение, где `sizeof(void)` условно принимается равным 1 байту, но писать такой код не рекомендуется для обеспечения переносимости).*

Чтобы сдвинуть адрес или прочитать данные через `void *`, его необходимо явно привести к указателю конкретного типа (чаще всего к `unsigned char *`):

```c
void *raw_memory = malloc(100);
// Чтобы прочитать байт по смещению 5, приводим void* к unsigned char*:
unsigned char *byte_ptr = (unsigned char *)raw_memory + 5;
unsigned char value = *byte_ptr;
```

### 3. Типы данных с фиксированной шириной (<stdint.h>) и их физические свойства

До сих пор мы работали со стандартными типами данных Си — `char`, `short`, `int`, `long`. Однако на физическом уровне у стандартных типов есть существенный недостаток: **их точный размер в байтах не зафиксирован в стандарте Си строго**, а зависит от разрядности целевой платформы и операционной системы.

Например:
* Тип `int` занимает 4 байта на 32-битных и 64-битных системах x86/x64, но на 16-битных микроконтроллерах (например, Arduino) он занимает всего 2 байта.
* Тип `long` на 64-битной ОС Windows занимает 4 байта (модель памяти LLP64), а на 64-битном Linux — 8 байт (модель LP64).

В низкоуровневом системном программировании, при работе со структурами ОЗУ, бинарными протоколами передачи данных, объединениями (`union`) и кэшем процессора, программист обязан **гарантировать точный размер переменных в битах независимо от компилятора и платформы**.

Для решения этой задачи в стандарт C99 был добавлен заголовочный файл **`<stdint.h>`**, определяющий типы данных с строго фиксированной шириной.

#### Анатомия наименования типов `uintN_t` и `intN_t`:

Название любого фиксированного типа из `<stdint.h>` расшифровывается по строгому системному правилу:
* **Префикс `u` (Unsigned):** Означает беззнаковый тип (хранит только 0 и положительные числа). Если префикса `u` нет, тип является знаковым (хранит как положительные, так и отрицательные числа в формате дополнительного кода).
* **Корень `int`:** Означает целочисленный тип (Integer).
* **Число `N` (8, 16, 32, 64):** Точный физический размер переменной **в битах**.
* **Суффикс `_t` (Type):** Общепринятый стандарт наименования системных типов данных в языка Си.

#### Сводная таблица типов данных из `<stdint.h>`:

| Системный тип | Знаковость | Размер в битах | Размер в байтах | Физический диапазон значений в ОЗУ | Аналог в C |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`uint8_t`** | Беззнаковый | 8 бит | **1 байт** | `0` ... `255` (`0x00` – `0xFF`) | `unsigned char` |
| **`int8_t`** | Знаковый | 8 бит | **1 байт** | `-128` ... `127` | `signed char` |
| **`uint16_t`**| Беззнаковый | 16 бит | **2 байта** | `0` ... `65 535` | `unsigned short` |
| **`int16_t`** | Знаковый | 16 бит | **2 байта** | `-32 768` ... `32 767` | `short` |
| **`uint32_t`**| Беззнаковый | 32 бита | **4 байта** | `0` ... `4 294 967 295` | `unsigned int` |
| **`int32_t`** | Знаковый | 32 бита | **4 байта** | `-2 147 483 648` ... `2 147 483 647` | `int` |
| **`uint64_t`**| Беззнаковый | 64 бита | **8 байт** | `0` ... `18 446 744 073 709 551 615` | `unsigned long long` |
| **`int64_t`** | Знаковый | 64 бита | **8 байт** | `-9 223 372 036 854 775 808` ... `9 223 372 036 854 775 807` | `long long` |

#### Зачем мы используем `uint8_t` и `uint32_t` в этой лекции?

1. При побайтовом исследовании памяти мы приводим адреса к указателю **`const uint8_t *`** вместо `unsigned char *`. Это гарантирует, что шаги сдвига пойдут строго по **1 байту** (8 бит), а значения байт будут считываться без знакового расширения.
2. В объединениях (`union`) использование **`uint32_t`** гарантирует, что переменная займет **ровно 32 бита (4 байта)** на абсолютно любом компьютере, совпав по физическому размеру в ОЗУ с массивом из 4 отдельных байт **`uint8_t bytes[4]`**.

### 4. Ключевое слово const (Модификатор защиты памяти от записи)

Перед тем как переходить к побайтовому инспектору памяти, вы могли заметить появление ключевого слова **** в объявлениях указателей (например,  или ).

#### Что означает  на низком уровне?
1. **Модификатор «Только для чтения» (Read-Only):** Ключевое слово  — это строгая инструкция компилятору запретить любое изменение значения переменной или данных по адресу после их создания.
2. **Защита памяти в функциях ():** Когда мы передаем указатель в функцию с модификатором , мы даем **аппаратную и системную гарантию**: эта функция будет *только читать* данные из ОЗУ по этому адресу, но гарантированно **ничего не перезапишет**.
   * Если внутри функции  вы попытаетесь написать , компилятор сгенерирует ошибку ещё на этапе сборки.

### 5. Побайтовый анализ памяти (Byte-Level Memory Inspection)

Почему для побайтового исследования памяти системные программисты всегда используют тип **`unsigned char *`**?

1. **Размер:** Гарантированно занимает ровно **1 байт** на любых архитектурах (`sizeof(unsigned char) == 1`).
2. **Беззнаковость (Unsigned):** Диапазон значений от `0` до `255` (`0x00` – `0xFF`). Обычный знаковый `char` при выводе в шестнадцатеричном виде может давать отрицательные числа и паразитное расширение знакового бита (Sign Extension) при конвертации в `int`.

Давайте напишем простую функцию, которая принимает `void *` на абсолютно любой объект в ОЗУ (число, структуру, массив) и его размер, и выводит его физическое содержимое по байтам:

```c
#include <stdio.h>
#include <stdint.h>

void inspect_bytes(const void *ptr, size_t size) {
    // Приводим универсальный void* к побайтовому uint8_t* (гарантированный 1 байт)
    const uint8_t *byte_ptr = (const uint8_t *)ptr;

    printf("Анализ памяти по адресу %p (размер: %zu байт):\n", ptr, size);
    for (size_t i = 0; i < size; i++) {
        // %02X выводит байт как двузначное шестнадцатеричное число с ведущим нулем
        printf("[%02X] ", byte_ptr[i]);
    }
    printf("\n");
}
```

### 6. Выравнивание памяти (Memory Alignment)

На физическом уровне процессор компьютера общается с оперативной памятью не по отдельным байтам, а широкими блоками — **машинными словами** (по 4 байта на 32-битных архитектурах и по 8 байт на 64-битных).

По этой причине в аппаратуре действует правило **выравнивания данных (Data Alignment)**:
* Переменная размером **1 байт** (`char`) может размещаться по абсолютно любому адресу в ОЗУ.
* Переменная размером **2 байта** (`short`) должна размещаться по адресам, кратным 2 (четным адресам: `0x1000`, `0x1002`).
* Переменная размером **4 байта** (`int`, `float`) должна располагаться по адресам, кратным 4 (`0x1000`, `0x1004`, `0x1008`).
* Переменная размером **8 байт** (`double`, указатели) должна располагаться по адресам, кратным 8 (`0x1000`, `0x1008`, `0x1010`).

#### Что происходит при попытке невыравненного доступа (Unaligned Access)?
Если вы приведете нечетный адрес (например, `0x1001`) к типу `int *` и попытаетесь прочитать оттуда 4 байта:
1. **На архитектуре x86/x64:** Процессор выполнит эту операцию, но ему придется сделать **два обращения к ОЗУ** вместо одного и склеить результат на регистрах. Это приводит к падению производительности работы с памятью.
2. **На архитектурах ARM и RISC-V:** Процессор мгновенно сгенерирует аппаратное исключение **Alignment Fault**, и операционная система закроет программу с ошибкой сбоя шины (Bus Error / Segmentation Fault).

## Подглава 12.3: Объединения (`union`) — совместное использование одной области ОЗУ

В Лекции 8 мы изучили **структуры (`struct`)**, где каждое поле занимает свой отдельный участок памяти, а общий размер структуры равен сумме размеров полей (с учетом выравнивающих байтов padding).

В языке Си существует еще одна фундаментальная пользовательская конструкция — **Объединения (`union`)**.

### 1. Физическое отличие `union` от `struct`

**Объединение (`union`)** — это специальная структура данных, в которой **все поля располагаются по одному и тому же начальному физическому адресу в ОЗУ**.

Поля объединения накладываются друг на друга в памяти. Изменение значения одного поля **физически перезаписывает байты всех остальных полей**.

```c
// Структура: поля лежат ДРУГ ЗА ДРУГОМ
struct TestStruct {
    int x;    // 4 байта (смещение 0)
    char c;   // 1 байт  (смещение 4)
}; // Размер: 8 байт (с учетом padding)

// Объединение: поля лежат ПО ОДНОМУ И ТОМУ ЖЕ АДРЕСУ
union TestUnion {
    int x;    // 4 байта (смещение 0)
    char c;   // 1 байт  (смещение 0!)
}; // Размер: 4 байта (равен размеру наибольшего поля)
```

#### Визуализация распределения памяти в ОЗУ:

```text
Память struct TestStruct (8 байт):
+-------------------+-------+---------------+
|     Поле x        | Поле c| Padding (3B)  |
|    (4 байта)      | (1B)  |               |
+-------------------+-------+---------------+
0                   4       5               8  (байты)

Память union TestUnion (4 байта):
+-------------------------------------------+
|                 Поле x                    |
|                (4 байта)                  |
+-------------------------------------------+
| Поле c (1B) |                             |  <- Начинается по тому же адресу!
+-------------+-----------------------------+
0             1                             4  (байты)
```

**Правило размера `union`:** Размер объединения всегда равен размеру его **самого большого элемента** (округленному до кратного наибольшему выравниванию полей).

### 2. Порядок байтов в процессоре (Endianness: Little-Endian vs Big-Endian)

Работа с `union` позволяет нам лично увидеть, как процессор расккладывает многобайтовые числа в оперативной памяти.

Существует два основных стандарта порядка байтов:

1. **Little-Endian (Младший байт по младшему адресу):**
   * Используется во всех процессорах архитектуры **x86, x64, AMD64**, а также в большинстве процессоров **ARM**.
   * Младший (самый правый) байт числа записывается в память **первым** (по самому низкому адресу).

2. **Big-Endian (Старший байт по младшему адресу):**
   * Используется в сетевых протоколах (TCP/IP — сетевой порядок байтов) и некоторых мейнфреймах (IBM, SPARC).
   * Старший (самый левый) байт числа записывается в память первым (по самому низкому адресу).

#### Практический пример работы Little-Endian:

Запишем 32-битное шестнадцатеричное число `0x12345678` в `int` внутри `union`:

```c
#include <stdio.h>
#include <stdint.h>

union NumberConverter {
    uint32_t number;        // 4 байта: целое число
    uint8_t bytes[4];       // Всего 4 байта: массив из 4 элементов по 1 байту каждый (4 * 1 = 4 байта)
};

int main() {
    union NumberConverter data;
    data.number = 0x12345678; // Записываем целое число

    printf("Число целиком: 0x%X\n", data.number);
    printf("Разложение по байтам в ОЗУ (Little-Endian):\n");
    for (int i = 0; i < 4; i++) {
        printf("Байт по индексу [%d] (адрес + %d): 0x%02X\n", i, i, data.bytes[i]);
    }
    return 0;
}
```

#### Вывод этой программы на x86/x64 компьютере:
```text
Число целиком: 0x12345678
Разложение по байтам в ОЗУ (Little-Endian):
Байт по индексу [0] (адрес + 0): 0x78
Байт по индексу [1] (адрес + 1): 0x56
Байт по индексу [2] (адрес + 2): 0x34
Байт по индексу [3] (адрес + 3): 0x12
```

**Физическое объяснение:** Младший байт числа `0x78` записался по самому младшему адресу массива `bytes[0]`, а старший байт `0x12` — по правому адресу `bytes[3]`.

### 3. Анонимные структуры и объединения (C11)

В современном стандарте Си (C11) разрешено вкладывать анонимные (безымянные) `union` внутрь `struct` и наоборот. Это невероятно удобно для создания гибких структур данных.

Рассмотрим пример работы с 32-битным цветом формата `ARGB` (Alpha, Red, Green, Blue):

```c
#include <stdio.h>
#include <stdint.h>

struct Color {
    // Анонимный union позволяет обращаться к цвету и как к числу, и как к компонентам
    union {
        uint32_t value; // 32-битное число цвета целиком
        
        struct {
            uint8_t b;  // В Little-Endian синий байт идет первым!
            uint8_t g;  // Зеленый байт
            uint8_t r;  // Красный байт
            uint8_t a;  // Альфа-канал (прозрачность)
        } channels;
    };
};

int main() {
    struct Color c;
    c.value = 0xFF0000FF; // Красный цвет с полной прозрачностью (Alpha=255, Red=255, Green=0, Blue=0)

    // Благодаря анонимному union мы имеем прямой доступ к полям без лишних имён!
    printf("Красный канал: %u\n", c.channels.r);   // Выведет 255
    printf("Зеленый канал: %u\n", c.channels.g); // Выведет 0
    printf("Синий канал:   %u\n", c.channels.b);  // Выведет 0
    printf("Альфа-канал:   %u\n", c.channels.a);  // Выведет 255

    // Меняем только зеленый канал напрямую в ОЗУ:
    c.channels.g = 128;
    printf("Новое значение цвета целиком: 0x%08X\n", c.value);

    return 0;
}
```

## Подглава 12.4: Практика Си: Низкоуровневые манипуляции с байтами

Давайте объединим полученные знания и напишем завершенную программу, демонстрирующую побайтовое исследование различных типов данных с помощью универсального указателя и приведения типов.

```c
#include <stdio.h>
#include <stdint.h>

// Универсальная функция побайтового дампа любой структуры или переменной
void print_memory_dump(const void *ptr, size_t size, const char *label) {
    const uint8_t *byte_ptr = (const uint8_t *)ptr;

    printf("=== Дамп памяти для: %s (%zu байт) ===\n", label, size);
    printf("Адрес начала: %p\n", ptr);
    printf("Байты: ");
    
    for (size_t i = 0; i < size; i++) {
        printf("%02X ", byte_ptr[i]);
    }
    printf("\n----------------------------------------------------\n\n");
}

struct ExampleStruct {
    uint16_t id;    // 2 байта
    uint32_t code;  // 4 байта
};

int main() {
    int int_val = 1000;              // 0x000003E8
    double double_val = 3.14159265; 
    struct ExampleStruct s = {0x1234, 0xABCDEF00};

    print_memory_dump(&int_val, sizeof(int_val), "int_val (1000)");
    print_memory_dump(&double_val, sizeof(double_val), "double_val (3.14159265)");
    print_memory_dump(&s, sizeof(s), "struct ExampleStruct");

    return 0;
}
```

## Подсказки к задачам

* **Подсказка к задаче 1:** Для печати относительного смещения используйте индекс цикла `i` (например, `printf("+%zu: 0x%02X\n", i, byte_ptr[i])`). Подключение `<stdint.h>` и `<stdio.h>` гарантирует доступ к нужным типам данных.
* **Подсказка к задаче 2:** При использовании спецификатора `%x` в `scanf` пользователь сможет вводить числа вида `FF8000FF`. Помните, что на архитектуре Little-Endian самый младший байт числа равен первому полю структуры (`blue`).
* **Подсказка к задаче 3:**  
  * Для `short *`: размер `sizeof(short) = 2` байта. `8192 + 3 * 2 = 8198`. В шестнадцатеричном виде `8198 = 0x2006`.
  * Для `int *`: размер `sizeof(int) = 4` байта. `8192 + 3 * 4 = 8204`. В шестнадцатеричном виде `8204 = 0x200C`.
  * Для `double *`: размер `sizeof(double) = 8` байт. `8192 + 3 * 8 = 8216`. В шестнадцатеричном виде `8216 = 0x2018`.
  * Для `int **`: поскольку это двойной указатель, его тип указывает на `int *`. На 64-битной системе размер `sizeof(int *)` равен ровно **8 байтам**! Расчет аналогичен `double *`: `8192 + 3 * 8 = 8216` (`0x2018`).
