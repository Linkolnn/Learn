# Лекция 14: Указатели на функции и основы компиляции

В предыдущей лекции мы спустились на уровень отдельных бит, научились эффективно управлять флагами состояния с помощью битовых масок и манипулировать аппаратными регистрами через побитовые операции (`&`, `|`, `^`, `~`, `<<`, `>>`).

В этой лекции мы завершаем Первый Блок нашего курса («Системный Си, память, компиляция и устройство ОС»). Мы объединим знания об адресах ОЗУ и строении исполняемого файла, чтобы понять:
1. Как исходный текстовый файл `.c` превращается в бинарный исполняемый файл через **4 этапа компиляции**.
2. Как функции хранятся в **сегменте кода (`.text`)** оперативной памяти.
3. Что такое **указатели на функции** и как с их помощью реализовывать динамический выбор поведения, таблицы переходов (Jump Tables) и механизмы обратного вызова (Callbacks) в Си.

## Подглава 14.1: Анатомия компиляции — Четыре этапа превращения C-кода в бинарник

Процесс превращения человекочитаемого текста программы на языке Си в готовую к исполнению бинарную программу — это не единичное «магическое» действие. Когда вы вызываете команду `gcc main.c -o program`, утилита **GCC (GNU Compiler Collection)** последовательно запускает **четыре отдельные программы (подсистемы)**.

> ℹ️ Логически этапы разделены, но на практике GCC часто выполняет первые два этапа одной программой (`cc1`). Остановить сборку после любого этапа и посмотреть промежуточный результат можно флагами, которые указаны ниже. Чтобы сохранить сразу все промежуточные файлы (`main.i`, `main.s`, `main.o`), используйте `gcc -save-temps main.c -o program`.

### 1. Этап 1: Препроцессинг (Preprocessor)
* **Инструмент:** Препроцессор Си (утилита `cpp`).
* **Флаг GCC для остановки на этом этапе:** `gcc -E main.c -o main.i`
* **Что происходит:**
  * Препроцессор работает исключительно как текстовый процессор: он ничего не знает о типах и синтаксисе Си, а только преобразует текст.
  * **Раскрытие директив `#include`:** Препроцессор находит заголовочные файлы (например, `<stdio.h>`) и буквально вставляет их полное текстовое содержимое вместо строки `#include`.
  * **Замена макросов `#define`:** Выполняется сквозная текстовая замена всех объявленных констант и макросов на их значения.
  * **Обработка условной компиляции:** Вычисляются директивы `#if`, `#ifdef`, `#ifndef`, `#else`, `#endif`, а лишние блоки кода вырезаются.
  * **Очистка кода:** Из текста программы удаляются все комментарии (заменяются на одиночные пробелы).
* **Результат:** Промежуточный файл исходного кода `main.i`. В нём нет директив `#include` и `#define`, а размер обычно составляет сотни и тысячи строк из подключённых заголовков. (В файле остаются только служебные пометки вида `# 1 "main.c"`, по которым компилятор указывает номера строк в сообщениях об ошибках, и директивы `#pragma`.)

---

### 2. Этап 2: Трансляция / Компиляция (Compilation)
* **Инструмент:** Собственно компилятор (утилита `cc1`).
* **Флаг GCC для остановки на этом этапе:** `gcc -S main.c -o main.s` (или `gcc -S main.i -o main.s`)
* **Что происходит:**
  * **Лексический и синтаксический анализ:** Компилятор разбивает текст на лексемы (слова языка) и проверяет синтаксис (наличие точек с запятой, парность скобок), строя дерево разбора, или абстрактное синтаксическое дерево (AST — Abstract Syntax Tree).
  * **Семантический анализ:** Проверяется смысл программы: объявлены ли переменные, согласуются ли типы данных.
  * **Оптимизация кода:** Анализируются циклы, регистры и выражения для ускорения работы будущей программы (при флагах `-O2` или `-O3`; по умолчанию, без флагов, оптимизации минимальны).
  * **Генерация ассемблерного кода:** Си-конструкции перерабатываются в последовательность команд ассемблера под конкретную целевую архитектуру процессора (x86-64, ARM и т.д.).
* **Результат:** Текстовый файл на языке Ассемблера `main.s`.

---

### 3. Этап 3: Ассемблирование (Assembly)
* **Инструмент:** Ассемблер (утилита `as`).
* **Флаг GCC для остановки на этом этапе:** `gcc -c main.c -o main.o` (флаг `-c` выполняет все этапы до ассемблирования включительно)
* **Что происходит:**
  * Ассемблерный текст переводится в бинарные машинные инструкции (байтовый код процессора).
  * Создаются секции, таблица символов (имена функций и переменных) и список мест, где адреса ещё нужно будет подставить при линковке.
* **Результат:** Некомпонованный **объектный файл** `main.o`. Формат файла зависит от системы: ELF в Linux, Mach-O в macOS, COFF (`.obj`) в Windows.

#### Анатомия объектного/исполняемого файла (секции) и память процесса

Файл программы (в Linux — формат ELF) состоит из **секций**. При запуске операционная система загружает его в память и объединяет секции в **сегменты** с разными правами доступа:

| Имя секции | Полное название | Назначение | Права: Чтение / Запись / Исполнение |
| :--- | :--- | :--- | :--- |
| **`.text`** | Code Segment | Хранит машинные инструкции (скомпилированный код функций). | **R-X** (Read, Execute) — запись запрещена! |
| **`.rodata`** | Read-Only Data | Хранит строковые литералы и глобальные константы (`const` вне функций). Локальная `const`-переменная внутри функции лежит в стеке. | **R--** (только чтение) |
| **`.data`** | Initialized Data | Хранит инициализированные глобальные и `static` переменные. | **RW-** (Read, Write) |
| **`.bss`** | Block Started by Symbol | Хранит НЕинициализированные глобальные и `static` переменные; при старте программы автоматически заполняются нулями. В файле занимает только запись о размере. | **RW-** (Read, Write) |

Секции `.text`, `.rodata`, `.data` и `.bss` приходят из файла. **Стек (Stack)** и **куча (Heap)** в файле не хранятся: их создаёт операционная система при запуске программы (Лекции 7 и 10).

```text
Старшие адреса
+----------------------------+
| Stack (стек)               |  локальные переменные, адреса возврата
|            ↓ растёт вниз   |
|      (свободное место)     |
|            ↑ растёт вверх  |
| Heap (куча)                |  malloc / calloc / realloc
+----------------------------+
| .bss    (RW-)              |
| .data   (RW-)              |
| .rodata (R--)              |
| .text   (R-X)              |
+----------------------------+
Младшие адреса                    (схема упрощённая)
```

### 4. Этап 4: Линковка / Компоновка (Linker)
* **Инструмент:** Компоновщик / Линковщик (утилита `ld`; `gcc` вызывает её сам).
* **Команда сборки:** `gcc main.o utils.o -o program`
* **Что происходит:**
  * **Разрешение символов (Symbol Resolution):** Если в `main.c` вызывается функция `printf()` или функция из другого модуля `utils.c`, линковщик ищет её определение в объектных файлах (например, `utils.o`) и в библиотеках. Если определение не найдено, возникает ошибка `undefined reference`.
  * **Склеивание секций:** Секции `.text` всех объектных файлов объединяются в одну общую секцию `.text`.
  * **Подстановка адресов (Relocation):** Линковщик назначает итоговые адреса функциям и переменным и вписывает их в места вызовов.
  * **Точка входа:** В программу добавляется стартовый код `_start`: он подготавливает среду и затем вызывает вашу функцию `main()`.
* **Статическая и динамическая линковка:** Код библиотеки может быть *скопирован* в ваш файл (статическая линковка, библиотеки `.a`) или *подключаться при запуске* (динамическая линковка, библиотеки `.so`, как стандартная `libc.so`). В последнем случае итоговые адреса функций библиотеки определяет загрузчик ОС в момент запуска.
* **Результат:** Готовый к запуску исполняемый файл `program`.

| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. Препроцессинг** | `cpp` | `main.c` | `main.i` (текст) | `gcc -E` | Ненайденный заголовочный файл (`fatal error: stdio.h: No such file`), ошибки в макросах `#define`. |

## Подглава 14.2: Сегмент кода (.text) и указатели на функции

### 1. Физическая реальность функций в ОЗУ

Код каждой функции после компиляции представляет собой непрерывный блок байт — машинных инструкций процессора (`mov`, `add`, `push`, `ret`), лежащих в сегменте **`.text`** оперативной памяти.

У каждого блока инструкций есть свой **стартовый адрес** в памяти процесса. (Строго говоря, программа работает с *виртуальными* адресами, которые операционная система отображает на физическую ОЗУ; поэтому адрес функции может отличаться от запуска к запуску.)

Когда процессор выполняет функцию:
1. В специальный регистр процессора **`PC` (Program Counter)** — на x86-64 это регистр **`RIP` (Instruction Pointer)** — загружается адрес первой инструкции функции (это делает инструкция вызова `call`).
2. Процессор последовательно считывает байты из сегмента `.text` по адресу `RIP` и выполняет команды одну за другой.

В языке Си **имя функции в выражениях автоматически превращается в указатель на эту функцию**, то есть в её стартовый адрес в сегменте `.text` (так же, как имя массива превращается в указатель на его первый элемент).

```c
#include <stdio.h>

void foo(void) {
    printf("Hello from foo!\n");
}

int main(void) {
    // Печатаем адрес функции foo в сегменте .text.
    // Формально стандарт Си не разрешает преобразовывать указатель на функцию в void *,
    // но GCC и стандарт POSIX (Linux) это допускают; при флаге -pedantic будет предупреждение
    printf("Адрес функции foo в ОЗУ: %p\n", (void *)foo);
    printf("Альтернативная запись:    %p\n", (void *)&foo);
    return 0;
}
```

### 2. Синтаксис указателей на функции

Поскольку функция имеет адрес в памяти, мы можем создать переменные-указатели, способные хранить этот адрес и вызывать функцию «дистанционно».

#### Канонический синтаксис объявления:
```c
возвращаемый_тип (*имя_указателя)(тип_парам1, тип_парам2, ...);
```

#### Важнейшее отличие (Забытые скобки):
```c
int *func(int, int);   // Объявление ФУНКЦИИ, которая возвращает указатель на int (int *)
int (*func)(int, int); // Объявление УКАЗАТЕЛЯ на функцию, которая принимает два int и возвращает int
```

*Разбор синтаксиса:* Скобки `(*func)` заставляют компилятор сначала применить `*` к имени `func`, то есть прочитать: «`func` — это указатель». Далее скобки справа `(int, int)` показывают, что это указатель именно на функцию с такими аргументами. Без скобок `*` относился бы к возвращаемому типу.

#### Пример использования указателя на функцию:

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int multiply(int a, int b) {
    return a * b;
}

int main(void) {
    // 1. Объявление указателя на функцию
    int (*op_ptr)(int, int) = NULL;

    // 2. Присваивание адреса функции add
    op_ptr = add; // Эквивалентно op_ptr = &add;

    // 3. Вызов функции через указатель (перед вызовом убедитесь, что указатель не NULL!)
    int sum = op_ptr(10, 20); // Эквивалентно (*op_ptr)(10, 20);
    printf("Сумма: %d\n", sum); // 30

    // 4. Перенаправление указателя на функцию multiply
    op_ptr = multiply;
    int prod = op_ptr(10, 20);
    printf("Произведение: %d\n", prod); // 200

    return 0;
}
```
> ⚠️ Вызов через указатель, равный `NULL` (или не инициализированный), приводит к аварийному завершению программы (Segmentation Fault), как и разыменование любого нулевого указателя. Если указатель может быть пустым, проверяйте его: `if (op_ptr != NULL) { ... }`.

### 3. Упрощение синтаксиса с помощью `typedef`

Записывать синтаксис `int (*ptr)(int, int)` при каждом объявлении неудобно и громоздко. Для создания понятных псевдонимов типов используется ключевое слово **`typedef`**.

```c
#include <stdio.h>

// Объявляем новый тип "operation_func_t" — указатель на функцию, принимающую (int, int) и возвращающую int
typedef int (*operation_func_t)(int, int);

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }

int main(void) {
    // Теперь мы можем объявлять переменные как обычные типы!
    operation_func_t op1 = add;
    operation_func_t op2 = sub;

    printf("Result 1: %d\n", op1(5, 3)); // 8
    printf("Result 2: %d\n", op2(5, 3)); // 2
    return 0;
}
```

### 4. Массив указателей на функции (таблица переходов, Jump Table)

Указатели на функции можно хранить в массиве и вызывать нужную функцию **по индексу** — без цепочки `if/else`. Такой массив называют таблицей переходов (Jump Table).

```c
#include <stdio.h>

void cmd_hello(void) { printf("Привет!\n"); }
void cmd_help(void)  { printf("Команды: 0 - hello, 1 - help, 2 - bye\n"); }
void cmd_bye(void)   { printf("Пока!\n"); }

int main(void) {
    // Массив из 3 указателей на функции вида void func(void)
    void (*commands[3])(void) = { cmd_hello, cmd_help, cmd_bye };

    int id = 1;
    if (id >= 0 && id < 3) {   // ОБЯЗАТЕЛЬНО проверяем границы массива!
        commands[id]();        // вызов функции по номеру команды
    }
    return 0;
}
```
Выход индекса за границы массива указателей на функции — это неопределённое поведение: программа может «прыгнуть» по случайному адресу. Поэтому индекс всегда проверяется до вызова. Читать объявление `void (*commands[3])(void)` помогает `typedef`: `typedef void (*command_t)(void); command_t commands[3];`.

## Подглава 14.3: Коллбэки (Callbacks) и функция `qsort` из `<stdlib.h>`

### 1. Концепция обратного вызова (Callback)

**Коллбэк (Callback / Обратный вызов)** — это функция, указатель на которую передают как аргумент в другую функцию, чтобы та вызвала её в нужный момент.

Это позволяет писать **универсальный алгоритмический код**, абстрагированный от конкретных данных, и передавать внешнюю логику внутрь функции во время выполнения (Runtime).

#### Свой простой коллбэк:
```c
#include <stdio.h>

int square(int x) { return x * x; }
int negate(int x) { return -x; }

// Применяет функцию func к каждому элементу массива
void apply_to_each(int *arr, size_t n, int (*func)(int)) {
    for (size_t i = 0; i < n; i++) {
        arr[i] = func(arr[i]);
    }
}

int main(void) {
    int data[] = { 1, 2, 3, 4 };
    size_t n = sizeof(data) / sizeof(data[0]);

    apply_to_each(data, n, square); // 1 4 9 16
    apply_to_each(data, n, negate); // -1 -4 -9 -16

    for (size_t i = 0; i < n; i++) {
        printf("%d ", data[i]);
    }
    printf("\n");
    return 0;
}
```
Функция `apply_to_each` ничего не знает о том, *что* делается с элементами: это решает коллбэк.

---

### 2. Разбор функции `qsort` из стандартной библиотеки Си

Ярчайшим примером использования коллбэков в Си является встроенная функция сортировки `qsort` из заголовочного файла `<stdlib.h>`.

#### Сигнатура `qsort`:
```c
void qsort(
    void *base,                            // 1. Указатель на начало массива
    size_t nmemb,                          // 2. Количество элементов в массиве
    size_t size,                           // 3. Размер одного элемента в байтах (sizeof)
    int (*compar)(const void *, const void *) // 4. Указатель на функцию-компаратор!
);
```

#### Как работает функция-компаратор `compar(a, b)`:
Алгоритм `qsort` не знает, ЧТО именно он сортирует — целые числа, дроби, строки или сложные структуры. Ему нужно лишь знать, какой из двух элементов больше.

Для этого он вызывает вашу функцию `compar(p1, p2)`, передавая указатели на два сравниваемых элемента:
* **Возвращает `< 0` (отрицательное число):** если элемент `*p1` должен стоять **раньше** `*p2`.
* **Возвращает `0`:** если элементы равны.
* **Возвращает `> 0` (положительное число):** если элемент `*p1` должен стоять **позже** `*p2`.

> ⚠️ **Не пишите `return a - b;`** в компараторе для `int`: при больших по модулю значениях вычитание может переполниться и дать неверный знак. Используйте сравнения `<` и `>`, как в примере ниже.
>
> ℹ️ Стандарт не требует, чтобы `qsort` использовала именно алгоритм быстрой сортировки, и **не гарантирует стабильность**: равные элементы могут поменяться местами.

---

### 3. Практический пример: Сортировка массива `int` и массива структур через `qsort`

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// 1. Компаратор для целых чисел (сортировка по возрастанию)
int compare_ints(const void *a, const void *b) {
    // Приводим const void* к const int* и разыменовываем
    int arg1 = *(const int *)a;
    int arg2 = *(const int *)b;

    if (arg1 < arg2) return -1;
    if (arg1 > arg2) return 1;
    return 0;
}

// Структура для товаров
typedef struct {
    char name[32];
    float price;
    int rating;
} Product;

// 2. Компаратор для структур (сортировка по убыванию цены)
int compare_products_by_price_desc(const void *a, const void *b) {
    const Product *p1 = (const Product *)a;
    const Product *p2 = (const Product *)b;

    if (p1->price > p2->price) return -1; // Дорогие товары идут первыми
    if (p1->price < p2->price) return 1;
    return 0;
}

// 3. Компаратор для структур (сортировка по алфавиту названия)
int compare_products_by_name(const void *a, const void *b) {
    const Product *p1 = (const Product *)a;
    const Product *p2 = (const Product *)b;
    return strncmp(p1->name, p2->name, sizeof(p1->name));
}

// Вспомогательная функция печати таблицы товаров
void print_products(const Product *items, size_t count) {
    for (size_t i = 0; i < count; i++) {
        printf("- %-10s | Цена: %7.2f | Рейтинг: %d\n", items[i].name, items[i].price, items[i].rating);
    }
}

int main(void) {
    // --- Часть A: Сортировка чисел ---
    int numbers[] = { 42, 13, 7, 99, 0, -5 };
    size_t num_count = sizeof(numbers) / sizeof(numbers[0]);

    qsort(numbers, num_count, sizeof(int), compare_ints);

    printf("Отсортированный массив чисел:\n");
    for (size_t i = 0; i < num_count; i++) {
        printf("%d ", numbers[i]);
    }
    printf("\n\n");

    // --- Часть B: Сортировка структур ---
    Product items[] = {
        {"Laptop", 1200.50f, 5},
        {"Mouse", 25.00f, 4},
        {"Keyboard", 85.99f, 5},
        {"Monitor", 300.00f, 3}
    };
    size_t items_count = sizeof(items) / sizeof(items[0]);

    // Сортируем по цене (по убыванию)
    qsort(items, items_count, sizeof(Product), compare_products_by_price_desc);
    printf("Товары, отсортированные по цене (от дорогих к дешевым):\n");
    print_products(items, items_count);

    // Тот же массив, но другой компаратор — сортировка по названию (по алфавиту)
    qsort(items, items_count, sizeof(Product), compare_products_by_name);
    printf("\nТовары, отсортированные по названию:\n");
    print_products(items, items_count);

    return 0;
}
```
Обратите внимание: сам вызов `qsort` не меняется, а поведение определяется только переданным компаратором.
