# Лекция 4: Массивы и непрерывная физическая память

## Подглава 4.1: Что такое массив с точки зрения физической памяти?

До этого момента мы работали с одиночными переменными. Если нам нужно было сохранить три числа, мы создавали три отдельные переменные: `int a`, `int b` и `int c`. Но представьте, что нам нужно хранить результаты измерения температуры за каждый день месяца или базу данных из 1000 сотрудников. Создавать 1000 отдельных переменных вручную невозможно.

Для решения таких задач используются **массивы**.

**Массив** — это структура данных, которая хранит упорядоченный набор элементов одного и того же типа в непрерывном блоке оперативной памяти.

Ключевое слово здесь — **непрерывный**. На уровне физических транзисторов и ячеек ОЗУ массив представляет собой цельный, неразрывный кусок памяти, который резервируется компилятором под наши нужды. 

Представьте оперативную память как многоэтажный отель, где каждая комната (ячейка) имеет свой адрес и вмещает ровно 1 байт. 
* Одиночные переменные компилятор может раскидать по разным свободным комнатам в случайном порядке.
* Массив — это группа комнат, идущих строго друг за другом на одном этаже. Если мы создаем массив из 5 целых чисел (типа `int`), компилятор забронирует 5 соседних комнат. А так как один `int` занимает 4 байта, вся группа займет ровно 5 * 4 = 20 последовательных байт ОЗУ.

У массива есть два важнейших правила:
1. **Однородность:** Все элементы в массиве должны иметь абсолютно одинаковый тип данных (только все `int`, только все `char` и т.д.). Физически это необходимо, чтобы процессор знал точный размер каждого элемента.
2. **Фиксированный размер:** Размер массива (количество элементов) задается при его создании и не может быть изменен в процессе работы программы. Мы не можем "подселить" шестой элемент в массив из пяти ячеек, так как соседние байты в ОЗУ могут быть уже заняты другими программами или переменными.

## Подглава 4.2: Почему доступ по индексу a[i] занимает константное время O(1)?

В информатике и Computer Science есть понятие **сложности алгоритма по времени**. Когда говорят, что операция имеет сложность **O(1)** (читается как "О от единицы" или "константное время"), это означает, что время выполнения этой операции не зависит от объема данных.

Доступ к любому элементу массива по его индексу происходит **мгновенно (за время O(1))**, будь то первый элемент, десятый или миллионный.

Почему так происходит? Всё благодаря физическому устройству ОЗУ (адресации) и простой математической формуле.

Когда мы объявляем массив, компьютер запоминает только один адрес — **базовый адрес начала массива** (адрес самого первого элемента под индексом 0). Обозначим его как `BaseAddress`.

Чтобы найти физический адрес элемента под любым индексом `i`, процессору не нужно перебирать все ячейки памяти с самого начала. Он мгновенно вычисляет адрес по формуле:

`Адрес_элемента = BaseAddress + i * Размер_типа_данных`

Давайте разберем этот процесс на физическом примере.
Представьте, что мы объявили массив целых чисел `int numbers[5]`. Компилятор выделил под него память, начиная с адреса **1000**. Поскольку тип `int` занимает в памяти ровно **4 байта**, компьютер знает размер одной ячейки.

Как процессор находит элемент под индексом `3`?
1. Берет базовый адрес начала массива: `BaseAddress = 1000`.
2. Берет индекс элемента: `i = 3`.
3. Берет размер типа данных: `sizeof(int) = 4 байта`.
4. Считает: `1000 + 3 * 4 = 1000 + 12 = 1012`.

Процессор мгновенно отправляет число **1012** по адресной шине в ОЗУ и забирает 4 байта данных по шине данных. Для выполнения этого действия процессору требуется всего одна операция умножения и одна операция сложения, независимо от того, насколько огромен массив. Именно поэтому доступ по индексу в массивах работает невероятно быстро.

## Подглава 4.3: Синтаксис одномерных массивов в Си

Давайте разберем, как создавать массивы и работать с ними в коде Си.

### 1. Объявление массива
Чтобы объявить массив, нужно указать тип данных его элементов, имя массива и в квадратных скобках — его размер:

```c
int numbers[5]; // Объявлен массив из 5 целых чисел. Сейчас в нём лежит случайный "мусор" из ОЗУ.
```

### 2. Инициализация (заполнение значениями)
Мы можем заполнить массив значениями сразу при создании:

```c
int weights[5] = {70, 85, 62, 90, 55}; // Полная инициализация
```

Если мы инициализируем массив при объявлении, размер в квадратных скобках можно не указывать — компилятор сам посчитает количество элементов:

```c
int ages[] = {18, 20, 25}; // Компилятор сам создаст массив размером ровно 3 элемента
```

Если мы укажем размер, но предоставим меньше значений, оставшиеся элементы автоматически заполнятся нулями:

```c
int scores[10] = {5, 8, 10}; // Первые три элемента будут равны 5, 8, 10. Остальные 7 элементов станут нулями (0).
```

### 3. Доступ к элементам и запись данных
В Си индексация элементов всегда начинается **с нуля (0)**. 
* Первый элемент имеет индекс `0`.
* Последний элемент массива размером `N` имеет индекс `N - 1`.

Для чтения или изменения конкретной ячейки мы пишем имя переменной массива и индекс элемента в квадратных скобках:

```c
#include <stdio.h>

int main() {
    int arr[3]; // Создаем пустой массив из 3 элементов

    // Записываем значения вручную по каждому индексу
    arr[0] = 100;
    arr[1] = 200;
    arr[2] = 300;

    // Считываем значения и выводим их на экран
    printf("Элемент 0: %d\n", arr[0]);
    printf("Элемент 1: %d\n", arr[1]);
    printf("Элемент 2: %d\n", arr[2]);

    // Изменяем значение второго элемента
    arr[1] = 250;
    printf("Обновленный элемент 1: %d\n", arr[1]);

    return 0;
}
```

*Обратите внимание: поскольку мы еще не изучили циклы, мы работаем с каждым элементом массива вручную, обращаясь к ним последовательно. На следующей лекции мы научимся автоматизировать этот процесс.*

## Подглава 4.4: Выход за границы массива — тихая катастрофа

Язык Си создавался для обеспечения максимальной скорости работы программ, поэтому компилятор Си доверяет программисту на 100% и **не делает никаких автоматических проверок на выход за границы массива во время работы программы**.

Что произойдет, если мы объявим массив из 3 элементов, но попытаемся обратиться к четвертому элементу под индексом `3`?

```c
int arr[3] = {10, 20, 30}; // Индексы: 0, 1, 2
arr[3] = 999; // Выход за границы! Индекса 3 физически не существует в выделенном блоке памяти.
```

С точки зрения процессора, этот код означает: *«Возьми базовый адрес массива `BaseAddress`, прибавь к нему `3 * 4 = 12` байт и запиши туда число 999»*.

Процессор беспрекословно выполнит эту команду. Он перезапишет те 4 байта ОЗУ, которые лежат сразу за нашим массивом. Но что там находилось?
1. **Другая переменная:** Если сразу за массивом в памяти лежала другая ваша важная переменная (например, `int security_code`), её значение будет затерто числом 999. Программа продолжит работать, но выдаст абсолютно непредсказуемый результат. Такие баги невероятно сложно отлавливать.
2. **Служебные данные операционной системы или стек вызова:** Если программа попытается записать данные в системную область памяти, защищенную операционной системой, ОС немедленно принудительно закроет вашу программу с ошибкой **Segmentation fault (ошибка сегментации)** или завершит её аварийно.

Всегда помните: выход за границы массива в Си — это критическая уязвимость безопасности и причина большинства аппаратных сбоев. Программист обязан лично следить за тем, чтобы индексы никогда не выходили за пределы диапазона от `0` до `N - 1`.

## Практические задачи

### Задача 1: Расчет среднего балла
Напишите программу на Си, в которой:
1. Объявляется массив из 4 оценок студентов (целые числа `int`).
2. Присвойте элементам массива любые оценки (например, `5`, `4`, `3`, `5`).
3. Выведите на экран каждую оценку с указанием её индекса в массиве.
4. Рассчитайте средний балл этих студентов (как дробное число `float`) и выведите его на экран.
*(Внимание: в программе запрещено использовать циклы, условия, указатели или пользовательские функции. Код должен выполняться последовательно внутри функции `main`).*

### Задача 2: Расчет адресов в памяти (устно)
Представьте, что мы работаем на компьютере, где базовый адрес начала массива в оперативной памяти равен **2000** (в десятичной системе).
1. Нам дан символьный массив `char letters[4] = {'U', 'N', 'I', 'X'}`. По какому физическому адресу в ОЗУ будет лежать символ `'I'` (индекс 2)? *Помните, что размер типа `char` равен 1 байту*.
2. Нам дан целочисленный массив `int data[4] = {10, 20, 30, 40}`. По какому физическому адресу в ОЗУ будет лежать число `30` (индекс 2)? *Помните, что размер типа `int` равен 4 байтам*.

---

## Подсказки к задачам

* **Подсказка к задаче 1:** Чтобы рассчитать средний балл как вещественное дробное число, сложите все элементы массива вручную: `arr[0] + arr[1] + ...`, а затем разделите полученную сумму на общее число студентов — `4.0f`. Использование вещественного делителя `4.0f` заставит компилятор выполнить деление с сохранением дробной части. Для вывода дробного результата используйте спецификатор формата `%f`.
* **Подсказка к задаче 2:** Используйте формулу вычисления адреса из подглавы 4.2: `Адрес = BaseAddress + Index * Размер_типа`. Подставьте в нее базовый адрес 2000, нужный индекс элемента (вспомните, с какого числа начинаются индексы массива) и размер типа данных в байтах.
