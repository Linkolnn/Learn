# Лекция 19: Стратегия «Разделяй и властвуй». Быстрые сортировки (Merge Sort & QuickSort)

В предыдущих лекциях мы разобрали базовые алгоритмы сортировки со сложностью **O(n²)** (пузырьковую, выбором и вставками). Они просты в реализации и эффективны на малых объемах данных (10–20 элементов), но при росте массива до миллиона элементов требуют порядка триллиона (10¹²) операций и становятся неприменимыми на практике.

Сегодня мы совершим качественный скачок в скорости и изучим фундаментальную алгоритмическую парадигму — **«Разделяй и властвуй» (Divide and Conquer)**, а также два мощнейших алгоритма сортировки: **Сортировку слиянием (Merge Sort)** и **Быструю сортировку (QuickSort)**, работающие за время **O(n log n)**.

---

## Подглава 19.1: Парадигма «Разделяй и властвуй» (Divide and Conquer)

Стратегия «Разделяй и властвуй» состоит из трех последовательных шагов:

1. **Разделение (Divide):** Исходная задача разбивается на несколько меньших подзадач того же типа.
2. **Властвование (Conquer):** Подзадачи решаются рекурсивно. Если размер подзадачи достаточно мал (базовый случай), она решается непосредственно.
3. **Комбинирование (Combine):** Решения подзадач объединяются в единое решение исходной задачи.

Почему для сортировки это дает такой прирост скорости?
При делении массива размера `n` пополам на каждом шаге мы строим дерево рекурсии высотой всего **log₂ n** уровней. Если на каждом уровне мы выполняем суммарно **O(n)** работы, то итоговая сложность составляет **O(n log n)**.

> 💡 **Где выполняется основная работа.** В Merge Sort разделение тривиально (найти середину), а вся работа происходит на этапе **комбинирования** (слияние). В QuickSort наоборот: основная работа — на этапе **разделения** (partition), а комбинировать ничего не нужно: после сортировки частей массив уже отсортирован целиком.

Для массива из **1 000 000 элементов** (порядок величины, константные множители не учитываем):
* Алгоритм `O(n²)` делает около **1 000 000 000 000** операций.
* Алгоритм `O(n log n)` делает всего около **20 000 000** операций (примерно в 50 000 раз меньше!).

## Подглава 19.2: Сортировка слиянием (Merge Sort)

### 1. Идея и принцип работы
Сортировка слиянием — это классический представитель алгоритмов «Разделяй и властвуй».

1. **Разделение:** Массив рекурсивно делится на две половины (их длины отличаются не более чем на 1), пока не получатся подмассивы длиной 1 элемент (массив из 1 элемента отсортирован по определению).
2. **Комбинирование (Merge):** Два отсортированных соседних подмассива сливаются в один отсортированный массив большего размера с помощью двух указателей.

Пример для массива `[5, 2, 4, 7, 1, 3]`:

```text
                  [5 2 4 7 1 3]
                 /             \
          [5 2 4]               [7 1 3]
          /     \               /     \
      [5 2]     [4]         [7 1]     [3]
      /   \                 /   \
    [5]   [2]             [7]   [1]

Слияние снизу вверх:
    [5]     + [2]     ->  [2 5]
    [2 5]   + [4]     ->  [2 4 5]
    [7]     + [1]     ->  [1 7]
    [1 7]   + [3]     ->  [1 3 7]
    [2 4 5] + [1 3 7] ->  [1 2 3 4 5 7]
```

При слиянии двух отсортированных частей достаточно сравнивать только их первые (наименьшие) элементы: меньший из них переносится в результат. Поэтому слияние выполняется за один проход, то есть за `O(n)`.

### 2. Реализация функции слияния и сортировки на Си

```c
#include <stdio.h>
#include <stdlib.h>

// Вспомогательная функция слияния двух отсортированных подмассивов:
// [left .. mid] и [mid + 1 .. right]
// (для простоты память выделяется при каждом вызове; в промышленном коде
// временный буфер выделяют один раз, а при ошибке malloc сообщают о ней вызывающему коду)
void merge(int *arr, size_t left, size_t mid, size_t right) {
    size_t n1 = mid - left + 1;
    size_t n2 = right - mid;

    // Выделяем временную память под левую и правую половины
    int *L = (int *)malloc(n1 * sizeof(int));
    int *R = (int *)malloc(n2 * sizeof(int));

    if (L == NULL || R == NULL) {
        fprintf(stderr, "Ошибка выделения памяти в merge()\n");
        free(L);
        free(R);
        return;
    }

    // Копируем данные во временные массивы
    for (size_t i = 0; i < n1; i++) L[i] = arr[left + i];
    for (size_t j = 0; j < n2; j++) R[j] = arr[mid + 1 + j];

    // Слияние временных массивов обратно в arr[left .. right]
    size_t i = 0; // Индекс в L
    size_t j = 0; // Индекс в R
    size_t k = left; // Индекс в основном массиве

    while (i < n1 && j < n2) {
        if (L[i] <= R[j]) { // <= обеспечивает устойчивость сортировки
            arr[k] = L[i];
            i++;
        } else {
            arr[k] = R[j];
            j++;
        }
        k++;
    }

    // Дописываем оставшиеся элементы из L (если есть)
    while (i < n1) {
        arr[k] = L[i];
        i++;
        k++;
    }

    // Дописываем оставшиеся элементы из R (если есть)
    while (j < n2) {
        arr[k] = R[j];
        j++;
        k++;
    }

    // Освобождаем временную память
    free(L);
    free(R);
}

// Главная рекурсивная функция Merge Sort
void merge_sort(int *arr, size_t left, size_t right) {
    if (left < right) {
        // Вычисляем середину без риска переполнения size_t
        size_t mid = left + (right - left) / 2;

        // Рекурсивно сортируем левую и правую половины
        merge_sort(arr, left, mid);
        merge_sort(arr, mid + 1, right);

        // Сливаем отсортированные половины
        merge(arr, left, mid, right);
    }
}
```

### 3. Оценка сложности и особенности Merge Sort
* **Временная сложность (Time Complexity):**
  * Худший, средний и лучший случаи: **O(n log n)** (гарантированное время при любых данных!).
* **Пространственная сложность (Space Complexity):** **O(n)** — требование дополнительной памяти в куче под временные буферы слияния (стек рекурсии добавляет лишь `O(log n)`, так как глубина рекурсии равна `log₂ n`).
* **Устойчивость (Stability):** **Устойчивая (Stable)**. Устойчивая сортировка не меняет относительный порядок равных элементов (например, если отсортировать людей по возрасту, то люди одного возраста останутся в прежнем порядке, скажем, алфавитном). В Merge Sort это обеспечивает условие `L[i] <= R[j]`: при равенстве первым берётся элемент из левой части, которая в исходном массиве стояла раньше.

## Подглава 19.3: Быстрая сортировка (QuickSort)

### 1. Идея и принцип работы
Быстрая сортировка (разработанная Чарльзом Хоаром в 1960 году) считается одним из самых быстрых на практике универсальных алгоритмов сортировки массивов в оперативной памяти.

1. **Выбор опорного элемента (Pivot):** Из массива выбирается один элемент — *пивот*.
2. **Разделение (Partition):** Все элементы массива переупорядочиваются так, что элементы, не большие опорного (`<=`), перемещаются влево от него, а большие опорного — вправо (так работает схема Ломуто, которую мы реализуем). Сам опорный элемент занимает свое итоговое окончательное место.
3. **Рекурсия:** Алгоритм рекурсивно применяется к левому и правому подмассивам.

### 2. Схема разбиения Ломуто (Lomuto Partition) и реализация на Си

```c
#include <stdio.h>
#include <stddef.h>

// Функция обмена элементов
void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

// Схема разбиения Ломуто
size_t partition(int *arr, size_t low, size_t high) {
    int pivot = arr[high]; // В качестве pivot берем последний элемент
    size_t i = low; // Индекс границы элементов <= pivot

    for (size_t j = low; j < high; j++) {
        if (arr[j] <= pivot) {
            swap(&arr[i], &arr[j]);
            i++;
        }
    }

    // Ставим pivot на его итоговое место между меньшими и большими элементами
    swap(&arr[i], &arr[high]);
    return i; // Возвращаем индекс опорного элемента
}

// Рекурсивная быстрая сортировка
void quick_sort(int *arr, size_t low, size_t high) {
    if (low < high) {
        size_t p = partition(arr, low, high);

        // Рекурсивно сортируем левую и правую части
        if (p > 0) { // Защита: size_t беззнаковый, и выражение p - 1 при p == 0 даст огромное число
            quick_sort(arr, low, p - 1);
        }
        quick_sort(arr, p + 1, high);
    }
}
```

### 3. Проблема деградации до O(n²) и выбор опорного элемента
Если на каждом шаге выбирать в качестве опорного элемента крайний (первый или последний), а входной массив **уже отсортирован**, то деление будет происходить крайне неравномерно: `0` элементов с одной стороны и `n - 1` с другой.

В этом случае высота дерева рекурсии вырастет до **n**, а итоговая сложность деградирует до катастрофических **O(n²)**! Так же плохо ведёт себя массив, отсортированный в обратном порядке, и **массив из одинаковых элементов** (в нашей схеме Ломуто все элементы `<= pivot` уходят в левую часть, поэтому правая всегда пуста). Мы проверили это экспериментально: на 10 000 элементов глубина рекурсии для случайных данных составила около 30, а для отсортированных, обратных и одинаковых данных — ровно 10 000.

**Способы решения проблемы деградации:**
1. **Случайный выбор опорного элемента (Randomized QuickSort):** Выбирать `pivot` по случайному индексу.
2. **Медиана трех (Median-of-three):** Выбирать медиану из первого, среднего и последнего элементов массива.
3. **Трёхстороннее разбиение (3-way partition):** отдельно собирать элементы `<`, `==` и `>` опорного; решает проблему массивов с большим количеством одинаковых значений (в рамках курса мы его не реализуем).

Случайный выбор опорного не устраняет худший случай полностью, но делает его крайне маловероятным: ожидаемое время работы — `O(n log n)` на любых данных.

### 4. Оценка сложности QuickSort
* **Временная сложность (Time Complexity):**
  * Средний и лучший случаи: **O(n log n)** (на практике обычно заметно быстрее Merge Sort на массивах благодаря отсутствию выделения памяти и хорошей локальности кэша ЦП; точная разница зависит от данных и реализации).
  * Худший случай: **O(n²)** (при неудачном выборе pivot, например на отсортированных данных).
* **Пространственная сложность (Space Complexity):** дополнительный массив не нужен, сортировка выполняется *in-place* (на месте, без вспомогательного массива). Память нужна только под стек рекурсивных вызовов: в среднем **O(log n)**, но в худшем случае нашей простой реализации глубина рекурсии равна `n`, то есть **O(n)**, и на больших массивах возможен Stack Overflow (Лекция 18).

**Как гарантировать глубину O(log n):** рекурсивно обрабатывать *меньшую* из двух частей, а *большую* — циклом (в рекурсивный вызов уходит не больше половины элементов):

```c
void quick_sort_opt(int *arr, size_t low, size_t high) {
    while (low < high) {
        size_t p = partition(arr, low, high);
        if (p - low < high - p) {          // левая часть меньше
            if (p > low) {
                quick_sort_opt(arr, low, p - 1);
            }
            low = p + 1;                    // правую часть обработает цикл
        } else {                            // правая часть меньше (или равна)
            quick_sort_opt(arr, p + 1, high);
            high = p - 1;                   // левую часть обработает цикл
        }
    }
}
```

На случайных данных из 1 000 000 элементов эта версия показала глубину рекурсии около 13. Если же на каждом шаге делить плохо (отсортированные данные), время работы всё равно останется `O(n²)`: оптимизация защищает от переполнения стека, а не от медленной работы.
* **Устойчивость (Stability):** **Неустойчивая (Unstable)** — обмены при разбиении могут нарушить порядок равных элементов (например, `swap(&arr[i], &arr[high])` перебрасывает пивот через группу равных ему элементов).

## Подглава 19.4: Сравнительный анализ Merge Sort и QuickSort

| Критерий | Merge Sort | QuickSort |
| :--- | :--- | :--- |
| **Худшее время O(T)** | **O(n log n)** (гарантировано) | **O(n²)** (при плохом pivot) |
| **Среднее время O(T)** | **O(n log n)** | **O(n log n)** (быстрее на практике) |
| **Доп. память O(M)** | **O(n)** (требует буфер в куче) | **O(log n)** в среднем (только стек вызовов); в худшем случае простой реализации O(n) |
| **Устойчивость** | **Устойчивый (Stable)** | **Неустойчивый (Unstable)** |
| **Работа с диском/связанными списками** | Идеально (последовательный доступ) | Худший выбор для внешних данных |
| **Локальность кэша ЦП** | Хорошая (последовательные проходы), но нужен дополнительный буфер | Очень хорошая (последовательные проходы по массиву, без буфера) |

> 💡 **Что используется на практике.** В стандартных библиотеках чаще встречаются *гибриды*: **Timsort** (Python, Java для объектов) сочетает Merge Sort и Insertion Sort; **introsort** (`std::sort` в C++) — QuickSort, который переключается на HeapSort при слишком глубокой рекурсии и на Insertion Sort для малых подмассивов.

## Подглава 19.5: Запуск и проверка

Соберите программу в одном файле: сверху `#include <stdio.h>` и `#include <stdlib.h>`, затем функции `merge`, `merge_sort`, `swap`, `partition`, `quick_sort` из этой лекции, а ниже — функцию `main`:

```c
void print_array(const int *arr, size_t n) {
    for (size_t i = 0; i < n; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");
}

int main(void) {
    int a[] = {38, 27, 43, 3, 9, 82, 10};
    int b[] = {38, 27, 43, 3, 9, 82, 10};
    size_t n = sizeof(a) / sizeof(a[0]);

    if (n > 1) { // для n == 0 выражение n - 1 у size_t даст огромное число
        merge_sort(a, 0, n - 1);
        quick_sort(b, 0, n - 1);
    }

    printf("Merge Sort: ");
    print_array(a, n);
    printf("QuickSort:  ");
    print_array(b, n);
    return 0;
}
```

Ожидаемый вывод:

```text
Merge Sort: 3 9 10 27 38 43 82
QuickSort:  3 9 10 27 38 43 82
```

## Подсказки к практическим задачам

* **Подсказка к Задаче 1:** На малых размерах (`N <= 16`) оверхед на рекурсивные вызовы и разбиение в QuickSort выше, чем простая перестановка элементов в Insertion Sort. Поэтому гибридный подход активно применяется в стандартных библиотеках языков программирования (Timsort, introsort). Insertion Sort из Лекции 17 сортирует массив целиком, поэтому его нужно адаптировать так, чтобы он сортировал только отрезок `[low, high]`. Для замера времени подключите `<time.h>`: `clock_t start = clock();` до и `(double)(clock() - start) / CLOCKS_PER_SEC` после сортировки. Сортируйте одинаковые копии одного массива и компилируйте с оптимизацией (`gcc -O2`).
* **Подсказка к Задаче 2:** Введите счетчик текущей глубины `depth` как аргумент функции `quick_sort(..., int depth)`. При каждом рекурсивном вызове передавайте `depth + 1` и обновляйте глобальный максимум: `if (depth > max_depth) { max_depth = depth; }` (стандартной функции `max` в Си нет). Для самопроверки: на случайном массиве из 10 000 элементов глубина получится порядка 30–40, а на отсортированном — 10 000 (то есть `n`).
* **Подсказка к Задаче 3:** Для генерации случайных чисел используйте `<stdlib.h>` и `<time.h>` (`srand(time(NULL))`). Вычисление случайного индекса в отрезке: `size_t rand_idx = low + rand() % (high - low + 1);`. Функцию `srand` вызывайте один раз в начале `main`, а не внутри `partition`. Учтите, что `rand()` возвращает числа от 0 до `RAND_MAX`, а в некоторых системах (например, Windows) `RAND_MAX` равен всего 32767, поэтому для массивов длиннее 32 768 элементов такой индекс не покроет весь отрезок. Для массива из 20 000 элементов это не проблема. Обратите внимание: случайный выбор опорного не спасает от массива, целиком состоящего из одинаковых элементов (причина описана в подглаве 19.3).
