# Лекция 22: Иерархические структуры. Двоичное дерево поиска (Binary Search Tree — BST)

В предыдущих лекциях мы детально изучили линейные структуры данных — **Массивы** и **Связанные списки**. 

Массивы дают мгновенный доступ к элементам по индексу за `O(1)`, но требуют `O(n)` времени на вставку и удаление в начало или середину. Односвязные и двусвязные списки позволяют вставлять и удалять элементы за `O(1)` при наличии готового указателя на позицию (или предшествующий узел), но требуют `O(n)` времени на поиск и доступ по индексу.

Сегодня мы переходим к изучению **иерархических (нелинейных) структур данных** — **деревьев**, а именно к **Двоичному дереву поиска (Binary Search Tree — BST)**. Эта структура объединяет лучшие качества массивов и списков: сбалансированное дерево позволяет выполнять **поиск, вставку и удаление элементов за логарифмическое время `O(log n)`**.

---

## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. Дерево (Tree)**
> * **Что это:** Иерархическая нелинейная структура данных, состоящая из узлов, связанных между собой направленными рёбрами (указателями).
> * **Главное правило:** В дереве нет циклов (замкнутых путей), и к каждому узлу (кроме корня) ведёт ровно одно ребро от родительского узла.

> 📌 **2. Корень (Root)**
> * **Что это:** Самый верхний узел дерева, у которого нет родительского узла. Служит единственной точкой входа для всех операций с деревом.

> 📌 **3. Родитель (Parent) и Дочерний узел (Child)**
> * **Что это:** Узел `A` является родителем узла `B`, если от `A` к `B` ведёт прямая ссылка. При этом узел `B` является дочерним узлом (прямым потомком) для `A`.

> 📌 **4. Потомок (Descendant) и Предок (Ancestor)**
> * **Что это:** Узел `B` является потомком узла `A`, если `B` расположен в поддереве с корнем `A` на любом уровне ниже. Узел `A` при этом является предком для `B`.

> 📌 **5. Лист (Leaf / Terminal Node)**
> * **Что это:** Узел дерева, у которого нет ни одного дочернего узла. Оба его указателя (`left` и `right`) равны `NULL`.

> 📌 **6. Поддерево (Subtree)**
> * **Что это:** Дерево, состоящее из выбранного узла (корня поддерева) и всех его потомков.

> 📌 **7. Высота дерева (Height `h`)**
> * **Что это:** Длина максимального пути (количество рёбер) от корня до самого дальнего листа. Для дерева из одного корня высота равна 0.

> 📌 **8. Свойство Двоичного дерева поиска (BST Property)**
> * **Что это:** Главное правило организации данных в BST: для любого узла `X` все значения в его **левом поддереве** строго меньше значения `X` (`left < X`), а все значения в его **правом поддереве** строго больше значения `X` (`right > X`).
> * *Примечание:* В этой лекции и классической реализации BST дубликаты ключей не хранятся и игнорируются при вставке.

> 📌 **9. Сбалансированное дерево (Balanced Tree)**
> * **Что это:** Дерево, структура которого гарантирует, что его высота `h` сохраняется логарифмической `O(log n)` от количества узлов `n`.

> 📌 **10. In-order Successor (Преемник при симметричном обходе)**
> * **Что это:** Узел с минимальным значением, которое строго больше значения текущего узла. Если у узла есть правое поддерево — это наименьший (самый левый) узел в его правом поддереве. Если правого поддерева нет — это ближайший предок, для которого текущий узел лежит в левом поддереве.

> 📌 **11. Обход в глубину (DFS — Depth-First Search)**
> * **Что это:** Семейство методов обхода дерева (In-order, Pre-order, Post-order), при которых алгоритм продвигается максимально глубоко вниз по одной ветке перед возвратом наверх. Может реализовываться как рекурсивно, так и итеративно с использованием явного стека.

> 📌 **12. Обход в ширину (BFS — Breadth-First Search)**
> * **Что это:** Метод обхода дерева по уровням (Level-order Traversal) — сначала посещаются все узлы текущей глубины, затем следующей. Реализуется итеративно с использованием очереди (Queue).

## Подглава 22.1: Почему Деревья? Сравнение с Линейными структурами

Давайте сравним временную сложность базовых операций для четырёх вариантов структур данных на `N` элементах:

| Операция | Неотсортированный массив | Отсортированный массив | Односвязный список | Сбалансированный BST |
| :--- | :--- | :--- | :--- | :--- |
| **Поиск элемента** | `O(n)` (Линейный поиск) | `O(log n)` (Бинарный поиск) | `O(n)` (Проход от `head`) | **`O(log n)`** (`O(h)`) |
| **Вставка элемента** | `O(1)` (в конец) | `O(n)` (Сдвиг элементов) | `O(1)` (при наличии `prev_node`)* | **`O(log n)`** (`O(h)`) |
| **Удаление элемента** | `O(n)` (Поиск + сдвиг) | `O(n)` (Поиск + сдвиг) | `O(1)` (при наличии `prev_node`)* | **`O(log n)`** (`O(h)`) |

*\* Примечание: Вставка и удаление в односвязном списке за O(1) указаны для случая, когда у нас уже есть прямой указатель на предшествующий узел (в односвязном списке нет поля `prev`). Поиск элемента по значению перед удалением в списке требует O(n) времени. Сложность O(log n) для BST достигается в среднем на случайных данных и на сбалансированных деревьях; на отсортированных входных данных без балансировки сложность становится O(n).*

### Вывод:
* **Отсортированный массив** идеален для поиска (`O(log n)`), но крайне неэффективен для частых вставок и удалений (`O(n)`).
* **Связанный список** идеален для локальных вставок и удалений (`O(1)`), но медленен при поиске (`O(n)`).
* **Сбалансированное двоичное дерево поиска (BST)** является золотой серединой: оно поддерживает **и поиск, и вставку, и удаление за `O(log n)`**!

## Подглава 22.2: Анатомия Двоичного дерева поиска (BST)

В Двоичном дереве каждый узел имеет **не более двух дочерних узлов**: левого (`left`) и правого (`right`).

```text
                  [ 50 ]  <--- Корень (Root)
                 /      \
             [ 30 ]     [ 70 ]
            /     \     /    \
        [ 20 ]  [ 40 ][ 60 ] [ 80 ]  <--- Листья (Leaves)
```

### Разбор свойства BST на примере:
Возьмём корень `50`:
* Все узлы в левом поддереве (`30, 20, 40`) **меньше 50**.
* Все узлы в правом поддереве (`70, 60, 80`) **больше 50**.
* Это же правило рекурсивно выполняется для *каждого* узла! Например, для узла `30`: `20 < 30 < 40`.

Благодаря этому свойству поиск в BST аналогичен **бинарному поиску**: на каждом шаге мы сравниваем искомое значение с текущим узлом и отбрасываем **одно из двух поддеревьев (то есть примерно половину оставшихся элементов в сбалансированном дереве)**!

## Подглава 22.3: Реализация BST на языке Си

> ⚠️ **Зависимость от высоты дерева (`h`):**  
> Все основные операции в BST (поиск, вставка, удаление) имеют временную сложность **`O(h)`**, где `h` — высота дерева. В сбалансированном дереве `h = O(log n)`, а в наихудшем вырожденном случае `h = n - 1` (порядок `O(n)`).

### 1. Объявление структуры узла

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>

// Структура узла двоичного дерева поиска
typedef struct TreeNode {
    int data;                   // Хранимое значение
    struct TreeNode *left;      // Указатель на левое поддерево (меньшие элементы)
    struct TreeNode *right;     // Указатель на правое поддерево (большие элементы)
} TreeNode;
```

---

### 2. Выделение памяти под узел (`create_tree_node`)

```c
TreeNode* create_tree_node(int value) {
    TreeNode *new_node = malloc(sizeof(TreeNode));
    if (new_node == NULL) {
        fprintf(stderr, "Ошибка: не удалось выделить память под узел дерева!\n");
        return NULL;
    }
    new_node->data = value;
    new_node->left = NULL;
    new_node->right = NULL;
    return new_node;
}
```

---

### 3. Вставка элемента в BST (`insert_node`) — `O(h)`, в сбалансированном `O(log n)`

Показываем рекурсивную реализацию вставки (также возможна и итеративная): мы ищем подходящее место для нового узла как при поиске, и когда доходим до `NULL`, создаём новый лист.

* **Присваивание результата:** Поскольку корень поддерева (или самого дерева) может измениться при вставке в пустое дерево, функция возвращает указатель на обновлённый корень. Вызов выполняется так: `root = insert_node(root, value);`.
* **Обработка дубликатов:** Если передаваемое значение `value` уже существует в дереве (`value == root->data`), функция молча игнорирует вставку и возвращает исходный узел без изменений.

```c
TreeNode* insert_node(TreeNode *root, int value) {
    // 1. Базовый случай: наткнулись на пустое место — создаём новый узел
    if (root == NULL) {
        return create_tree_node(value);
    }

    // 2. Шаг рекурсии: выбираем направление движения
    if (value < root->data) {
        root->left = insert_node(root->left, value);
    } else if (value > root->data) {
        root->right = insert_node(root->right, value);
    }
    // Если value == root->data, дубликат не вставляем (игнорируем)

    return root;
}
```

---

### 4. Поиск элемента в BST (`search_node`) — `O(h)`, в сбалансированном `O(log n)`

```c
// Рекурсивный поиск
TreeNode* search_node(TreeNode *root, int target) {
    // Базовые случаи: дерево пустое или элемент найден в корне
    if (root == NULL || root->data == target) {
        return root;
    }

    // Движение влево или вправо
    if (target < root->data) {
        return search_node(root->left, target);
    }
    return search_node(root->right, target);
}

// Итеративный поиск (без накладных расходов на стек)
TreeNode* search_node_iterative(TreeNode *root, int target) {
    TreeNode *current = root;
    while (current != NULL && current->data != target) {
        if (target < current->data) {
            current = current->left;
        } else {
            current = current->right;
        }
    }
    return current;
}
```

---

### 5. Удаление узла из BST (`delete_tree_node`) — `O(h)`, в сбалансированном `O(log n)`

Удаление узла из BST — наиболее сложная операция, так как она не должна нарушить свойство порядка. Различают **3 случая**:

1. **Удаляемый узел — Лист (0 дочерних узлов):** Просто освобождаем память узла и зануляем указатель у его родителя.
2. **Удаляемый узел имеет 1 дочерний узел:** Связываем родителя удаляемого узла напрямую с его единственным дочерним узлом и освобождаем память.
3. **Удаляемый узел имеет 2 дочерних узла:** 
   * Ищем **In-order Successor** (наименьший узел в **правом** поддереве — двигаемся 1 раз вправо, затем до упора влево).
   * У преемника **гарантированно нет левого дочернего узла** (иначе он не был бы минимальным в правом поддереве), поэтому его удаление сводится к простому случаю с 0 или 1 (правым) дочерним узлом!
   * Копируем значение найденного преемника в удаляемый узел.
   * Рекурсивно удаляем преемника из правого поддерева.

* **Присваивание результата:** Аналогично вставке, вызов выполняется с присваиванием: `root = delete_tree_node(root, value);`, чтобы корректно обновить ссылку, если удалялся сам корень дерева.

```c
// Поиск минимального узла в дереве (самый левый узел)
TreeNode* find_min(TreeNode *root) {
    TreeNode *current = root;
    while (current != NULL && current->left != NULL) {
        current = current->left;
    }
    return current;
}

// Удаление узла из BST
TreeNode* delete_tree_node(TreeNode *root, int value) {
    if (root == NULL) return NULL;

    // 1. Ищем удаляемый узел
    if (value < root->data) {
        root->left = delete_tree_node(root->left, value);
    } else if (value > root->data) {
        root->right = delete_tree_node(root->right, value);
    } else {
        // Узел найден! Разбираем 3 случая:

        // Случай 1 и 2: 0 или 1 дочерний узел
        if (root->left == NULL) {
            TreeNode *temp = root->right;
            free(root);
            return temp;
        } else if (root->right == NULL) {
            TreeNode *temp = root->left;
            free(root);
            return temp;
        }

        // Случай 3: 2 дочерних узла
        // Находим наименьший узел в правом поддереве (In-order Successor)
        TreeNode *successor = find_min(root->right);

        // Копируем значение преемника в текущий узел
        root->data = successor->data;

        // Удаляем преемника из правого поддерева
        root->right = delete_tree_node(root->right, successor->data);
    }
    return root;
}
```

## Подглава 22.4: Способы обхода дерева (Tree Traversals: DFS и BFS)

В отличие от массива или связанного списка, где обход происходит линейно с начала до конца, у дерева есть два основных семейства способов обхода: обход в глубину (DFS — Depth-First Search) и обход в ширину (BFS — Breadth-First Search).

Для демонстрации обходов рассмотрим усечённое двоичное дерево (без узлов 60 и 80 — дочерних узлов узла 70 из подглавы 22.2):

```text
                  [ 50 ]
                 /      \
             [ 30 ]     [ 70 ]
            /     \
        [ 20 ]   [ 40 ]
```

### 1. Центрированный обход (In-Order Traversal): `Лево -> Корень -> Право`
* **Порядок:** Обходим левое поддерево, посещаем корень, обходим правое поддерево.
* **Ключевая особенность:** Для BST обход In-Order выводит все элементы в **строго отсортированном по возрастанию порядке**!
* *Вывод для дерева выше:* `20, 30, 40, 50, 70`.

```c
void inorder_traversal(const TreeNode *root) {
    if (root == NULL) return;
    inorder_traversal(root->left);   // 1. Лево
    printf("%d ", root->data);       // 2. Корень
    inorder_traversal(root->right);  // 3. Право
}
```

---

### 2. Прямой обход (Pre-Order Traversal): `Корень -> Лево -> Право`
* **Порядок:** Посещаем корень, обходим левое поддерево, обходим правое поддерево.
* **Применение:** Идеально подходит для **клонирования (копирования)** структуры дерева или его сериализации (сохранения в файл).
* *Вывод для дерева выше:* `50, 30, 20, 40, 70`.

```c
void preorder_traversal(const TreeNode *root) {
    if (root == NULL) return;
    printf("%d ", root->data);        // 1. Корень
    preorder_traversal(root->left);   // 2. Лево
    preorder_traversal(root->right);  // 3. Право
}
```

---

### 3. Обратный обход (Post-Order Traversal): `Лево -> Право -> Корень`
* **Порядок:** Обходим левое поддерево, обходим правое поддерево, посещаем корень.
* **Применение:** Идеально подходит для **полной очистки памяти дерева (`free_tree`)**, так как сначала освобождаются дочерние узлы, и только потом сам корень.
* *Вывод для дерева выше:* `20, 40, 30, 70, 50`.

```c
void postorder_traversal(const TreeNode *root) {
    if (root == NULL) return;
    postorder_traversal(root->left);   // 1. Лево
    postorder_traversal(root->right);  // 2. Право
    printf("%d ", root->data);         // 3. Корень
}

// Корректное удаление всего дерева из ОЗУ через Post-Order
void free_tree(TreeNode *root) {
    if (root == NULL) return;
    free_tree(root->left);
    free_tree(root->right);
    free(root);
}
```

---

### 4. Обход в ширину (BFS — Breadth-First Search)
* **Порядок:** Обход происходит по уровням (Level-Order): сначала посещается корень, затем все его дочерние узлы на глубине 1, затем узлы на глубине 2 и так далее.
* **Реализация:** В отличие от DFS, где естественна рекурсия или стек, BFS использует структуру данных **Очередь (Queue)**.
* *Вывод для дерева выше:* `50, 30, 70, 20, 40`.

## Подглава 22.5: Проблема вырождения BST в линейную цепочку и введение в Сбалансированные деревья

Главный подводный камень обычного BST: **его сложность `O(log n)` гарантирована только на сбалансированных деревьях** (`h = O(log n)`).

Если вставить в изначально пустое BST строго отсортированные элементы `1, 2, 3, 4, 5`, дерево **выродится в линейную цепочку**:

```text
[ 1 ]
     \
     [ 2 ]
          \
          [ 3 ]
               \
               [ 4 ]
                    \
                    [ 5 ]
```

В вырожденном дереве сложность поиска, вставки и удаления деградирует из логарифмических `O(log n)` в **линейную сложность `O(n)`** (высота `h = n - 1`).

Ещё одна опасность вырожденного дерева: при рекурсивных операциях (`insert_node`, `delete_tree_node`, обходы In-order/Pre-order/Post-order, `free_tree`) глубина стека вызовов становится равной высоте дерева `h = n - 1`. На глубоком вырожденном дереве из ~10⁵–10⁶ узлов это **может привести** к переполнению стека и аварийному завершению программы по **Stack Overflow** (точный порог зависит от размера стека ОС и оптимизаций компилятора).

### Решение: Самобалансирующиеся деревья (Self-Balancing Trees)
Чтобы избежать деградации до `O(n)`, в промышленной разработке используются модификации BST, которые автоматически поддерживают логарифмическую высоту `O(log n)` с помощью операций **поворотов (Rotations)**:
1. **АВЛ-дерево (AVL Tree):** Дерево со строгой балансировкой (разница высот левого и правого поддеревьев любого узла не превышает 1). Поиск происходит немного быстрее, чем в красно-чёрном дереве (из-за более строгой балансировки), но вставка и удаление требуют больше поворотов.
2. **Красно-чёрное дерево (Red-Black Tree):** Дерево с более гибкой балансировкой за счёт раскраски узлов (самый длинный путь от корня до листа не более чем в 2 раза длиннее самого короткого). Обеспечивает отличный баланс скорости поиска, вставки и удаления. Используется в реализациях `std::map` / `std::set` в C++ и `TreeMap` в Java.

> 📌 **Примечание о базах данных и файловых системах:** Для индексов СУБД (PostgreSQL, MySQL InnoDB) и файловых систем применяют **B-деревья (B-Trees / B+-Trees)** — это отдельная, недвоичная структура данных (в них один узел содержит множество ключей и дочерних ссылок). B-деревья не используют повороты, а балансируются с помощью операций разбиения (split) и слияния (merge) узлов, что идеально оптимизировано под чтение блоков со страниц диска.

## Подглава 22.6: Полный рабочий пример `main()`

Ниже представлен готовый, полностью компилируемый файл на языке Си, демонстрирующий основные операции с BST (построение дерева, In-order обход, поиск, удаление узла с двумя дочерними узлами и очистку памяти):

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>

typedef struct TreeNode {
    int data;
    struct TreeNode *left;
    struct TreeNode *right;
} TreeNode;

TreeNode* create_tree_node(int value) {
    TreeNode *new_node = malloc(sizeof(TreeNode));
    if (new_node == NULL) {
        fprintf(stderr, "Ошибка: не удалось выделить память под узел дерева!\n");
        return NULL;
    }
    new_node->data = value;
    new_node->left = NULL;
    new_node->right = NULL;
    return new_node;
}

TreeNode* insert_node(TreeNode *root, int value) {
    if (root == NULL) return create_tree_node(value);
    if (value < root->data) {
        root->left = insert_node(root->left, value);
    } else if (value > root->data) {
        root->right = insert_node(root->right, value);
    }
    return root;
}

TreeNode* search_node(TreeNode *root, int target) {
    if (root == NULL || root->data == target) return root;
    if (target < root->data) return search_node(root->left, target);
    return search_node(root->right, target);
}

TreeNode* find_min(TreeNode *root) {
    TreeNode *current = root;
    while (current != NULL && current->left != NULL) {
        current = current->left;
    }
    return current;
}

TreeNode* delete_tree_node(TreeNode *root, int value) {
    if (root == NULL) return NULL;

    if (value < root->data) {
        root->left = delete_tree_node(root->left, value);
    } else if (value > root->data) {
        root->right = delete_tree_node(root->right, value);
    } else {
        if (root->left == NULL) {
            TreeNode *temp = root->right;
            free(root);
            return temp;
        } else if (root->right == NULL) {
            TreeNode *temp = root->left;
            free(root);
            return temp;
        }

        TreeNode *successor = find_min(root->right);
        root->data = successor->data;
        root->right = delete_tree_node(root->right, successor->data);
    }
    return root;
}

void inorder_traversal(const TreeNode *root) {
    if (root == NULL) return;
    inorder_traversal(root->left);
    printf("%d ", root->data);
    inorder_traversal(root->right);
}

void free_tree(TreeNode *root) {
    if (root == NULL) return;
    free_tree(root->left);
    free_tree(root->right);
    free(root);
}

int main(void) {
    TreeNode *root = NULL;

    // 1. Построение дерева
    int values[] = {50, 30, 70, 20, 40, 60, 80};
    size_t count = sizeof(values) / sizeof(values[0]);

    for (size_t i = 0; i < count; i++) {
        root = insert_node(root, values[i]);
    }

    // 2. Отсортированный вывод через In-Order
    printf("In-order (отсортированный): ");
    inorder_traversal(root);
    printf("\n");

    // 3. Поиск элемента
    int target = 40;
    TreeNode *found = search_node(root, target);
    if (found != NULL) {
        printf("Элемент %d найден в дереве!\n", target);
    } else {
        printf("Элемент %d не найден!\n", target);
    }

    // 4. Удаление узла с двумя дочерними узлами (узел 30)
    printf("Удаляем узел 30 (с двумя дочерними узлами)...\n");
    root = delete_tree_node(root, 30);

    printf("In-order после удаления: ");
    inorder_traversal(root);
    printf("\n");

    // 5. Очистка памяти
    free_tree(root);
    root = NULL;

    return 0;
}
```

## Практические задачи к Лекции 22

### Задача 1: Расчёт высоты дерева (Tree Height)
Напишите рекурсивную функцию `int get_tree_height(const TreeNode *root)`, которая возвращает максимальную высоту двоичного дерева (количество рёбер от корня до самого дальнего листа). Если дерево пустое (`root == NULL`), функция должна возвращать `-1`.

---

### Задача 2: Проверка корректности BST (Validate BST)
Напишите функцию `bool is_valid_bst(const TreeNode *root)`, которая проверяет, соблюдается ли свойство Двоичного дерева поиска для всех узлов дерева.  
*Подсказка:* Недостаточно просто проверить `left->data < root->data`. Все узлы в левом поддереве должны быть строго меньше корня! Используйте вспомогательную функцию `is_valid_bst_helper(root, min_val, max_val)` с открытым интервалом `(min_val, max_val)`.

### Задача 3: Подсчёт количества узлов и листьев
Напишите две функции:
1. `int count_nodes(const TreeNode *root)` — возвращает общее количество узлов в дереве.
2. `int count_leaves(const TreeNode *root)` — возвращает количество листьев (узлов без дочерних узлов).

## Подсказки к практическим задачам

* **Подсказка к Задаче 1:** Высота дерева равна `1 + max(get_tree_height(root->left), get_tree_height(root->right))`. Для `root == NULL` верните `-1`.
* **Подсказка к Задаче 2:** Включайте заголовочные файлы `#include <limits.h>` и `#include <stdbool.h>`. Передавайте в рекурсивную функцию границы `long long min_val` и `long long max_val` для открытого интервала `(min_val, max_val)`. Базовый случай: `if (root == NULL) return true;`. Используется тип `long long`, чтобы начальные границы `LLONG_MIN` и `LLONG_MAX` находились строго за пределами возможного диапазона `int`, корректно обрабатывая узлы со значениями `INT_MIN` и `INT_MAX`. Начальный вызов из `is_valid_bst(root)`: `return is_valid_bst_helper(root, LLONG_MIN, LLONG_MAX);`. Если `root->data <= min_val || root->data >= max_val`, верните `false`. Для левого поддерева передайте `(min_val, root->data)`, для правого — `(root->data, max_val)`.
* **Подсказка к Задаче 3:** 
  * Для количества всех узлов: если `root == NULL`, верните 0; иначе верните `1 + count_nodes(root->left) + count_nodes(root->right)`.
  * Для количества листьев: если `root == NULL`, верните 0; если `root->left == NULL && root->right == NULL`, верните 1; иначе верните `count_leaves(root->left) + count_leaves(root->right)`.
