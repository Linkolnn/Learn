# Лекция 18: Рекурсия, стек вызовов и переполнение стека (Stack Overflow)

В прошлых лекциях мы изучили алгоритмы анализа сложности **Big O**, **двоичный поиск** и **базовые сортировки**. До сих пор весь наш код был итеративным — мы использовали циклы `for` и `while`. 

Сегодня мы переходим к одной из самых важных и элегантных концепций программирования и Computer Science — **Рекурсии**. Мы разберём не только синтаксис, но и то, что происходит на физическом уровне в оперативной памяти с **Стеком вызовов (Call Stack)**, почему возникают ошибки **Stack Overflow** и как правильно оценивать пространственную сложность рекурсивных алгоритмов.

---

## Подглава 18.1: Что такое рекурсия и как она работает на уровне железа?

### 1. Фундаментальное определение
> **Рекурсия** — это метод решения задачи, при котором функция **вызывает саму себя** для решения уменьшенной подзадачи того же типа.

Математически и логически рекурсия близка к методу математической индукции. Если вы умеете решать базовый вариант задачи и знаете, как свести сложную задачу к чуть более простой, вы можете написать рекурсивный алгоритм.

---

### 2. Физическая механика в ОЗУ — Стек вызовов (Call Stack)

Чтобы понять, как работает рекурсия, нужно вспомнить устройство оперативной памяти процесса (которое мы разбирали в Лекциях 7 и 10). 

Когда программа вызывает любую функцию, в сегменте памяти **Стек (Call Stack)** создаётся специальная область — **Фрейм стека (Stack Frame)**.

```text
+-------------------------------------------------------+
|                 ФРЕЙМ СТЕКА (Stack Frame)             |
+-------------------------------------------------------+
| 1. Переданные аргументы и параметры функции          |
| 2. Адрес возврата (Return Address / IP / PC)          |
| 3. Указатель на предыдущий фрейм (Frame Pointer / RBP)|
| 4. Локальные переменные функции                      |
+-------------------------------------------------------+
```

* **При обычном вызове:** Функция `A()` вызывает `B()`. Фрейм `B()` кладет поверх фрейма `A()`. Когда `B()` завершается, её фрейм **удаляется (pop)** из стека, и управление возвращается в `A()`.
* **При рекурсивном вызове:** Функция `foo()` вызывает `foo()`. В стек помещается **НОВЫЙ фрейм** той же самой функции, со своими собственными локальными переменными и параметрами! Предыдущий фрейм замирает в ожидании результата от нового вызова.

#### Жизненная аналогия:
Представьте русскую Матрёшку. Чтобы добраться до самого центрального подарка, вам нужно открыть первую матрешку (первый фрейм), затем вторую (второй фрейм), третью и так далее. И только когда вы дошли до самой маленькой матрешки (базового случая), вы начинаете собирать матрешку в обратном порядке (возврат значений из функций).

## Подглава 18.2: Анатомия правильной рекурсивной функции

Любая корректно написанная рекурсивная функция **обязана** состоять из двух фундаментальных частей:

```text
              +-----------------------------------+
              |  Рекурсивная функция              |
              +-----------------------------------+
                                |
        +-----------------------+-----------------------+
        |                                               |
        v                                               v
+-------------------------------+               +-------------------------------+
| 1. БАЗОВЫЙ СЛУЧАЙ             |               | 2. ШАГ РЕКУРСИИ               |
| (Base Case / Exit Condition)  |               | (Recursive Step / Reduction)  |
|                               |               |                               |
| Условие, при котором функция  |               | Вызов саму себя с уменьшенными|
| ПРЕКРАЩАЕТ рекурсию и         |               | аргументами, приближающими нас|
| возвращает готовый ответ.     |               | к Базовому Случаю.            |
+-------------------------------+               +-------------------------------+
```

> **⚠️ Золотое правило рекурсии:**  
> Если в вашей функции нет **Базового Случая** или аргумент на **Шаге Рекурсии** не приближается к базовому случаю, функция будет вызывать саму себя **бесконечно**, пока у компьютера не закончится память!

## Подглава 18.3: Пространственная сложность и Переполнение стека (Stack Overflow)

### 1. Глубина рекурсии (Recursion Depth)
**Глубина рекурсии** — это максимальное количество рекурсивных фреймов, одновременно находящихся в стеке вызовов.

Если функция вызывает саму себя N раз подряд перед тем, как достигнет базового случая, в ОЗУ одновременно будет находиться N фреймов.

Это означает, что рекурсия всегда имеет **Пространственную сложность по памяти `O(M) = O(N)`**, где N — глубина рекурсии (даже если внутри функции создана всего одна переменная типа `int`!).

---

### 2. Что такое Stack Overflow (Переполнение стека)?
Размер области стека для процесса ограничен операционной системой (обычно от 1 МБ до 8 МБ в зависимости от ОС и настроек компилятора).

Если рекурсивная функция делает слишком много вложенных вызовов (например, глубина рекурсии равна 1 000 000), выделенная под стек память полностью заполняется. Очередной рекурсивный вызов пытается записать фрейм за пределы границы стека. 

Операционная система мгновенно блокирует этот процесс и завершает программу с ошибкой:
```text
Segmentation fault (core dumped)  // в Linux/Unix
Stack overflow                    // в Windows
```

## Подглава 18.4: Разбор классических рекурсивных алгоритмов на C

Давайте разберем 4 классических примера, на которых строятся все собеседования и теория алгоритмов.

---

### Пример 1: Вычисление Факториала (N!)

Факториал числа N — это произведение всех целых чисел от 1 до N.
* Математическое определение: N! = N * (N - 1)!
* Базовый случай: 0! = 1 и 1! = 1.

```c
#include <stdio.h>

// Рекурсивное вычисление факториала
unsigned long long factorial_recursive(unsigned int n) {
    // 1. БАЗОВЫЙ СЛУЧАЙ
    if (n <= 1) {
        return 1;
    }

    // 2. ШАГ РЕКУРСИИ: n * factorial(n - 1)
    return n * factorial_recursive(n - 1);
}

// Итеративное вычисление (для сравнения)
unsigned long long factorial_iterative(unsigned int n) {
    unsigned long long result = 1;
    for (unsigned int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}
```

#### Визуализация работы `factorial_recursive(3)`:

```text
[Вызов 1] factorial(3) ==> ждет результат 3 * factorial(2)
  [Вызов 2] factorial(2) ==> ждет результат 2 * factorial(1)
    [Вызов 3] factorial(1) ==> БАЗОВЫЙ СЛУЧАЙ! Возвращает 1
  [Возврат] factorial(2) получает 1 ==> считает 2 * 1 = 2, возвращает 2
[Возврат] factorial(3) получает 2 ==> считает 3 * 2 = 6, возвращает 6
Итоговый ответ: 6
```

* **Сложность по времени:** `O(N)` (делается N вызовов).
* **Сложность по памяти:** 
  * Рекурсивный вариант: `O(N)` (в стеке одновременно находится N фреймов).
  * Итеративный вариант: `O(1)` (всего одна переменная `result`).

### Пример 2: Числа Фибоначчи — Опасность наивной рекурсии

Последовательность Фибоначчи: 0, 1, 1, 2, 3, 5, 8, 13, 21, ...
* Формула: F(N) = F(N-1) + F(N-2)
* Базовые случаи: F(0) = 0, F(1) = 1.

```c
#include <stdio.h>

// Наивная рекурсивная функция Фибоначчи
unsigned long long fibonacci_naive(unsigned int n) {
    // Базовые случаи
    if (n == 0) return 0;
    if (n == 1) return 1;

    // Шаг рекурсии: ДВА рекурсивных вызова!
    return fibonacci_naive(n - 1) + fibonacci_naive(n - 2);
}
```

#### Почему наивная рекурсия Фибоначчи — это катастрофа?
Построим дерево вызовов для `fibonacci(5)`:

```text
                         fib(5)
                       /        \
                 fib(4)          fib(3)
                /      \        /      \
            fib(3)    fib(2)  fib(2)   fib(1)
           /     \    /   \   /   \
       fib(2)  fib(1)...
```

Обратите внимание: `fib(3)` вычисляется 2 раза, `fib(2)` вычисляется 3 раза, `fib(1)` вычисляется 5 раз! 
Каждый шаг удваивает количество ветвей рекурсивного дерева.

* **Временная сложность:** **Экспоненциальная `O(2^N)`!**  
  При N = 50 программа будет считаться несколько дней!
* **Пространственная сложность:** `O(N)` (максимальная глубина дерева в стеке равна N).

*(В Блоке 2 Лекции 20 мы изучим Динамическое Программирование и научимся ускорять рекурсию Фибоначчи с `O(2^N)` до быстрых `O(N)` с помощью мемоизации).*

### Пример 3: Порядок выполнения кода (Фаза Unwinding / Сворачивание стека)

Очень важный нюанс: инструкция, написанная **ДО** рекурсивного вызова, выполняется при погружении в рекурсию (сверху вниз). Инструкция, написанная **ПОСЛЕ** рекурсивного вызова, выполняется при возврате из рекурсии (снизу вверх)!

```c
#include <stdio.h>

// Печать чисел от n до 1 (прямой порядок погружения)
void print_descending(int n) {
    if (n <= 0) return; // Базовый случай

    printf("%d ", n);        // Выполняется ДО рекурсивного вызова!
    print_descending(n - 1); // Рекурсивный вызов
}

// Печать чисел от 1 до n (обратный порядок сворачивания)
void print_ascending(int n) {
    if (n <= 0) return; // Базовый случай

    print_ascending(n - 1);  // Рекурсивный вызов
    printf("%d ", n);        // Выполняется ПОСЛЕ возврата из рекурсии!
}

int main(void) {
    printf("Descending: ");
    print_descending(5); // Выведет: 5 4 3 2 1
    printf("\n");

    printf("Ascending: ");
    print_ascending(5);  // Выведет: 1 2 3 4 5
    printf("\n");

    return 0;
}
```

### Пример 4: Проверка строки на Палиндром (Рекурсия с двумя указателями)

Слово является палиндромом, если оно читается одинаково слева направо и справа налево (например, `"radar"`, `"level"`, `"racecar"`).

```c
#include <stdio.h>
#include <stdbool.h>
#include <string.h>

// Вспомогательная рекурсивная функция
bool is_palindrome_recursive(const char *str, int left, int right) {
    // Базовый случай 1: Указатели встретились или пересеклись -> это палиндром!
    if (left >= right) {
        return true;
    }

    // Базовый случай 2: Символы не совпали -> это НЕ палиндром!
    if (str[left] != str[right]) {
        return false;
    }

    // Шаг рекурсии: Сдвигаем левый указатель вправо, правый — влево
    return is_palindrome_recursive(str, left + 1, right - 1);
}

// Обёртка для удобного вызова
bool is_palindrome(const char *str) {
    if (str == NULL) return false;
    int len = strlen(str);
    if (len <= 1) return true;
    
    return is_palindrome_recursive(str, 0, len - 1);
}
```

## Подглава 18.5: Рекурсия vs Итерация (Сравнительный анализ)

| Критерий | Рекурсия | Итерация (Циклы `for`/`while`) |
| :--- | :--- | :--- |
| **Принцип работы** | Функция вызывает саму себя | Повторение блока кода через счетчик/условие |
| **Расход памяти `O(M)`** | **`O(N)`** (активные фреймы в стеке вызовов) | **`O(1)`** (константная память под счетчик) |
| **Скорость работы** | Накладные расходы на создание/удаление фреймов стека | Максимальная скорость процессора (без оверхеда на стек) |
| **Риск ошибки** | **Переполнение стека (Stack Overflow)** | Бесконечный цикл (программа зависает) |
| **Читаемость кода** | Идеальна для рекурсивных структур (деревья, графы, JSON) | Идеальна для линейных массивов и списков |

> **💡 Инженерный вывод:**  
> Всегда используйте **итерацию (циклы)** для простых линейных задач (проход по массиву, поиск максимума, простые математические расчеты).  
> Используйте **рекурсию** там, где задача по своей природе иерархична (обход деревьев, графов, алгоритмы «Разделяй и властвуй», разбор выражений).

## Подсказки к практическим задачам

* **Подсказка к Задаче 1:**  
  * Базовый случай: если `n == 0`, сумма равна `0` (или если `n < 10`, возвращаем `n`).
  * Шаг рекурсии: `(n % 10) + sum_of_digits(n / 10)`. Не забудьте обработать отрицательные числа (`if (n < 0) n = -n;`).
* **Подсказка к Задаче 2:**  
  * Из-за выделения массива `100 КБ` внутри каждого фрейма стека, стек размером ~8 МБ переполнится всего за ~80 итераций. Это наглядно покажет, как большой размер локальных переменных снижает предельную глубину рекурсии.
* **Подсказка к Задаче 3:**  
  * Базовый случай: `if (left >= right) return;`.
  * На каждом шаге меняйте местами `str[left]` и `str[right]` через временную переменную `char temp`, а затем вызывайте `reverse_string_rec(str, left + 1, right - 1)`.
