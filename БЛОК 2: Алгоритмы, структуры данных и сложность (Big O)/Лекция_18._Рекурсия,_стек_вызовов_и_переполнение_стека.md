# Лекция 18: Рекурсия, стек вызовов и переполнение стека (Stack Overflow)

В прошлых лекциях мы изучили оценку сложности **Big O**, **двоичный поиск** и **базовые сортировки**. До сих пор весь наш код был итеративным: мы использовали циклы `for` и `while`.

Сегодня мы переходим к одной из самых важных и элегантных идей программирования — **рекурсии**. Мы разберём не только синтаксис, но и то, что происходит в оперативной памяти со **стеком вызовов (Call Stack)**, почему возникает ошибка **Stack Overflow** и как оценивать пространственную сложность рекурсивных алгоритмов. Рекурсия пригодится нам очень скоро: на ней построены быстрая сортировка и сортировка слиянием (лекция 19), динамическое программирование (лекция 20) и обход деревьев (лекция 22).

---

## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. Рекурсия (Recursion)**
> * **Что это:** Способ решения задачи, при котором функция вызывает саму себя для решения меньшей подзадачи того же вида.

> 📌 **2. Базовый случай (Base Case)**
> * **Что это:** Самая простая версия задачи, ответ на которую известен сразу, без дальнейших вызовов. Именно она останавливает рекурсию.

> 📌 **3. Шаг рекурсии (Recursive Step)**
> * **Что это:** Рекурсивный вызов с «уменьшенными» данными, который приближает задачу к базовому случаю.

> 📌 **4. Стек вызовов (Call Stack) и фрейм стека (Stack Frame)**
> * **Что это:** Область памяти процесса, в которой хранятся данные активных вызовов функций. Каждый вызов получает свой **фрейм**, который удаляется при выходе из функции.

> 📌 **5. Глубина рекурсии (Recursion Depth)**
> * **Что это:** Наибольшее число вложенных вызовов, одновременно находящихся в стеке.

> 📌 **6. Переполнение стека (Stack Overflow)**
> * **Что это:** Ошибка, возникающая, когда стек вызовов исчерпал отведённую ему память (обычно из-за слишком глубокой или бесконечной рекурсии).

> 📌 **7. Хвостовая рекурсия (Tail Recursion)**
> * **Что это:** Рекурсия, в которой рекурсивный вызов — последнее действие функции (после него ничего не вычисляется). Такие вызовы компилятор может заменить циклом.

---

## Подглава 18.1: Что такое рекурсия и как она работает на уровне железа?

### 1. Фундаментальное определение
> **Рекурсия** — это метод решения задачи, при котором функция **вызывает саму себя** для решения уменьшенной подзадачи того же типа.

Логически рекурсия близка к методу математической индукции: если вы умеете решать самый простой вариант задачи и знаете, как свести сложный вариант к чуть более простому, вы можете написать рекурсивный алгоритм.

---

### 2. Физическая механика в ОЗУ — стек вызовов (Call Stack)

Чтобы понять, как работает рекурсия, вспомним устройство памяти процесса: в нём есть область **стека**, где живут локальные переменные функций (мы разбирали её при изучении стека вызовов и динамической памяти в Блоке 1; сегменты памяти подробно — в лекции 29).

Когда программа вызывает функцию, на стеке создаётся специальная область — **фрейм стека (Stack Frame)**.

```text
+-------------------------------------------------------+
|                 ФРЕЙМ СТЕКА (Stack Frame)             |
+-------------------------------------------------------+
| 1. Аргументы функции (если не переданы через регистры)|
| 2. Адрес возврата (куда вернуться после завершения)   |
| 3. Сохранённый указатель на предыдущий фрейм (RBP)    |
| 4. Локальные переменные функции                       |
+-------------------------------------------------------+
```

> ℹ️ Точное содержимое и порядок зависят от архитектуры процессора, соглашения о вызовах (ABI) и оптимизаций компилятора. Например, на x86-64 в Linux первые шесть целочисленных аргументов передаются через регистры, а не через стек, а при оптимизации указатель на предыдущий фрейм часто вообще не сохраняется. Главное, что нужно запомнить: **у каждого вызова — свой фрейм со своими локальными переменными и адресом возврата**. На большинстве платформ стек «растёт вниз», то есть к меньшим адресам.

* **При обычном вызове:** функция `A()` вызывает `B()`. Фрейм `B()` кладётся поверх фрейма `A()`. Когда `B()` завершается, её фрейм **удаляется (pop)** из стека, и управление возвращается в `A()`.
* **При рекурсивном вызове:** функция `foo()` вызывает `foo()`. В стек кладётся **НОВЫЙ фрейм** той же самой функции со своими собственными параметрами и локальными переменными. Предыдущий фрейм «замирает» в ожидании результата нового вызова.

#### Жизненная аналогия
Представьте русскую матрёшку. Чтобы добраться до самой маленькой, нужно открыть первую матрёшку (первый фрейм), затем вторую, третью и так далее. И только дойдя до самой маленькой (базового случая), вы начинаете собирать матрёшку в обратном порядке (возвращать значения из вызовов).

## Подглава 18.2: Анатомия правильной рекурсивной функции

Любая корректно написанная рекурсивная функция **обязана** состоять из двух частей:

```text
              +-----------------------------------+
              |  Рекурсивная функция              |
              +-----------------------------------+
                                |
        +-----------------------+-----------------------+
        |                                               |
        v                                               v
+-------------------------------+               +-------------------------------+
| 1. БАЗОВЫЙ СЛУЧАЙ             |               | 2. ШАГ РЕКУРСИИ               |
| (Base Case / Exit Condition)  |               | (Recursive Step / Reduction)  |
|                               |               |                               |
| Условие, при котором функция  |               | Вызов самой себя с            |
| ПРЕКРАЩАЕТ рекурсию и         |               | уменьшенными аргументами,     |
| возвращает готовый ответ.     |               | приближающими нас к           |
|                               |               | базовому случаю.              |
+-------------------------------+               +-------------------------------+
```

> **⚠️ Золотое правило рекурсии:**
> Если в вашей функции нет **базового случая** или аргумент на **шаге рекурсии** не приближается к базовому случаю, функция будет вызывать саму себя **бесконечно**, пока не переполнится стек и программа не завершится аварийно!

Проверяйте себя двумя вопросами: «Что делает функция в самом простом случае?» и «Почему каждый следующий вызов ближе к этому случаю, чем предыдущий?»

## Подглава 18.3: Пространственная сложность и переполнение стека (Stack Overflow)

### 1. Глубина рекурсии (Recursion Depth)
**Глубина рекурсии** — это максимальное количество рекурсивных фреймов, одновременно находящихся в стеке вызовов.

Если функция вызывает саму себя `d` раз подряд, прежде чем достигнет базового случая, в памяти одновременно будет находиться `d` фреймов.

Поэтому **пространственная сложность рекурсивного алгоритма равна `O(d)`**, где `d` — максимальная глубина рекурсии (даже если внутри функции создана всего одна переменная типа `int`). Глубина может быть разной:
* у факториала `d = n`, поэтому память `O(n)`;
* у рекурсивного двоичного поиска (лекция 16) `d ≈ log n`, поэтому память `O(log n)`;
* у сортировки слиянием (лекция 19) глубина тоже порядка `log n`.

То есть утверждение «рекурсия всегда занимает `O(n)` памяти» неверно: всё определяется глубиной, а не размером входных данных.

---

### 2. Что такое Stack Overflow (переполнение стека)?
Размер стека процесса ограничен операционной системой. Типичные значения: **8 МБ** для основного потока в Linux (посмотреть и изменить: `ulimit -s`, значение в килобайтах) и **1 МБ** в Windows. У дополнительных потоков стек обычно меньше.

Если рекурсия слишком глубока (например, глубина равна 1 000 000), память под стек заканчивается. Очередной вызов пытается записать фрейм за границу стека, процессор обращается к защищённой странице памяти, и операционная система завершает процесс с ошибкой:
```text
Segmentation fault (core dumped)  // Linux / Unix (сигнал SIGSEGV)
Stack overflow                    // Windows (исключение «Stack Overflow»)
```

Ориентир по размеру: у простой функции фрейм занимает десятки байт, поэтому при стеке 8 МБ глубины порядка **сотен тысяч** вызовов исчерпывают его (в наших экспериментах на Linux пустая рекурсия падала примерно на глубине 500 000). А если в каждом фрейме лежит большой локальный массив, предельная глубина падает в разы: для массива в 100 КБ это всего около 80 вызовов.

## Подглава 18.4: Разбор классических рекурсивных алгоритмов на C

Разберём 4 классических примера, на которых строятся алгоритмическая теория и собеседования.

### Пример 1: Вычисление факториала (N!)

Факториал числа N — это произведение всех целых чисел от 1 до N.
* Математическое определение: `N! = N * (N - 1)!`
* Базовый случай: `0! = 1` и `1! = 1`.

```c
#include <stdio.h>

// Рекурсивное вычисление факториала
unsigned long long factorial_recursive(unsigned int n) {
    // 1. БАЗОВЫЙ СЛУЧАЙ
    if (n <= 1) {
        return 1;
    }

    // 2. ШАГ РЕКУРСИИ: n * factorial(n - 1)
    return n * factorial_recursive(n - 1);
}

// Итеративное вычисление (для сравнения)
unsigned long long factorial_iterative(unsigned int n) {
    unsigned long long result = 1;
    for (unsigned int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}
```

> ⚠️ **Переполнение результата.** Тип `unsigned long long` вмещает значения до ~1,8·10¹⁹. Это хватает для `20! = 2 432 902 008 176 640 000`, но уже `21!` не помещается, и результат будет неверным (беззнаковое переполнение «заворачивает» число по модулю 2⁶⁴). Обе функции выше корректны только для `n ≤ 20`.

#### Визуализация работы `factorial_recursive(3)`:

```text
[Вызов 1] factorial(3) ==> ждёт результат 3 * factorial(2)
  [Вызов 2] factorial(2) ==> ждёт результат 2 * factorial(1)
    [Вызов 3] factorial(1) ==> БАЗОВЫЙ СЛУЧАЙ! Возвращает 1
  [Возврат] factorial(2) получает 1 ==> считает 2 * 1 = 2, возвращает 2
[Возврат] factorial(3) получает 2 ==> считает 3 * 2 = 6, возвращает 6
Итоговый ответ: 6
```

* **Сложность по времени:** `O(N)` (делается N вызовов).
* **Сложность по памяти:**
  * Рекурсивный вариант: `O(N)` (в стеке одновременно находится N фреймов).
  * Итеративный вариант: `O(1)` (одна переменная `result`).

### Пример 2: Числа Фибоначчи — опасность наивной рекурсии

Последовательность Фибоначчи: 0, 1, 1, 2, 3, 5, 8, 13, 21, …
* Формула: `F(N) = F(N-1) + F(N-2)`
* Базовые случаи: `F(0) = 0`, `F(1) = 1`.

```c
#include <stdio.h>

// Наивная рекурсивная функция Фибоначчи
unsigned long long fibonacci_naive(unsigned int n) {
    // Базовые случаи
    if (n == 0) return 0;
    if (n == 1) return 1;

    // Шаг рекурсии: ДВА рекурсивных вызова!
    return fibonacci_naive(n - 1) + fibonacci_naive(n - 2);
}
```

#### Почему наивная рекурсия Фибоначчи — это катастрофа?
Полное дерево вызовов для `fibonacci_naive(5)` (всего **15 вызовов**):

```text
                                fib(5)
                    /                          \
               fib(4)                          fib(3)
              /      \                        /      \
         fib(3)      fib(2)              fib(2)      fib(1)
        /     \      /     \             /     \
    fib(2)  fib(1) fib(1) fib(0)     fib(1)  fib(0)
    /    \
fib(1)  fib(0)
```

Обратите внимание: `fib(3)` вычисляется 2 раза, `fib(2)` — 3 раза, `fib(1)` — 5 раз. Одна и та же работа повторяется снова и снова, а число вызовов растёт почти вдвое с каждым увеличением `N`.

* **Временная сложность:** **экспоненциальная.** Число вызовов равно `2·F(N+1) − 1` и растёт примерно как `1,618^N`; для простоты (и как верхнюю границу) пишут `O(2^N)`. Для наглядности: `fib(30)` — около 2,7 млн вызовов, `fib(40)` — около 331 млн (на современном компьютере с оптимизацией это доли секунды), `fib(50)` — около 40 млрд вызовов (десятки секунд и больше), а `fib(90)` потребовал бы сотен лет.
* **Пространственная сложность:** `O(N)` (глубина рекурсии равна N: самая «длинная» ветка дерева — это цепочка `fib(N) → fib(N-1) → … → fib(1)`).
* **Переполнение результата:** `F(93)` — последнее число Фибоначчи, помещающееся в `unsigned long long`.

*(В лекции 20 мы изучим динамическое программирование и ускорим вычисление Фибоначчи с `O(2^N)` до `O(N)` с помощью мемоизации — запоминания уже вычисленных значений.)*

Для сравнения, итеративное решение за `O(N)` по времени и `O(1)` по памяти:

```c
unsigned long long fibonacci_iterative(unsigned int n) {
    if (n == 0) return 0;
    unsigned long long prev = 0, curr = 1; // F(0), F(1)
    for (unsigned int i = 2; i <= n; i++) {
        unsigned long long next = prev + curr;
        prev = curr;
        curr = next;
    }
    return curr;
}
```

### Пример 3: Порядок выполнения кода (фаза сворачивания стека)

Очень важный нюанс: инструкция, написанная **ДО** рекурсивного вызова, выполняется при погружении в рекурсию (сверху вниз). Инструкция, написанная **ПОСЛЕ** рекурсивного вызова, выполняется при возврате из рекурсии (снизу вверх)!

```c
#include <stdio.h>

// Печать чисел от n до 1 (порядок погружения)
void print_descending(int n) {
    if (n <= 0) return; // Базовый случай

    printf("%d ", n);        // Выполняется ДО рекурсивного вызова!
    print_descending(n - 1); // Рекурсивный вызов
}

// Печать чисел от 1 до n (порядок сворачивания)
void print_ascending(int n) {
    if (n <= 0) return; // Базовый случай

    print_ascending(n - 1);  // Рекурсивный вызов
    printf("%d ", n);        // Выполняется ПОСЛЕ возврата из рекурсии!
}

int main(void) {
    printf("Descending: ");
    print_descending(5); // Выведет: 5 4 3 2 1
    printf("\n");

    printf("Ascending: ");
    print_ascending(5);  // Выведет: 1 2 3 4 5
    printf("\n");

    return 0;
}
```

Как это видно в стеке для `print_ascending(3)`: вызовы `(3) → (2) → (1) → (0)` ничего не печатают, они только накапливаются в стеке. Затем `(0)` возвращается, и `(1)` печатает `1`, возвращается `(2)` и печатает `2`, и наконец `(3)` печатает `3`. Фреймы «разворачиваются» в обратном порядке, поэтому числа выходят по возрастанию. Тот же приём позволяет использовать стек вызовов как готовую структуру данных «последним пришёл — первым вышел».

### Пример 4: Проверка строки на палиндром (рекурсия с двумя индексами)

Слово является палиндромом, если читается одинаково слева направо и справа налево (например, `"radar"`, `"level"`, `"racecar"`).

```c
#include <stdio.h>
#include <stdbool.h>
#include <string.h>

// Вспомогательная рекурсивная функция: проверяет подстроку str[left..right]
bool is_palindrome_recursive(const char *str, int left, int right) {
    // Базовый случай 1: индексы встретились или пересеклись -> это палиндром!
    if (left >= right) {
        return true;
    }

    // Базовый случай 2: символы не совпали -> это НЕ палиндром!
    if (str[left] != str[right]) {
        return false;
    }

    // Шаг рекурсии: сдвигаем левый индекс вправо, правый — влево
    return is_palindrome_recursive(str, left + 1, right - 1);
}

// Обёртка для удобного вызова
bool is_palindrome(const char *str) {
    if (str == NULL) return false;
    int len = (int)strlen(str);
    if (len <= 1) return true;

    return is_palindrome_recursive(str, 0, len - 1);
}

int main(void) {
    printf("%d\n", is_palindrome("level")); // 1
    printf("%d\n", is_palindrome("radar")); // 1
    printf("%d\n", is_palindrome("abca"));  // 0
    return 0;
}
```

Разбор для `"level"` (`left`, `right`): `(0,4)`: `l == l` → `(1,3)`: `e == e` → `(2,2)`: `left >= right` → `true`.

> ℹ️ Функция чувствительна к регистру и учитывает пробелы: `"Level"` она не признает палиндромом, как и `"never odd or even"`. Для фраз строку сначала нужно привести к нормальному виду.

## Подглава 18.5: Рекурсия vs итерация (сравнительный анализ)

| Критерий | Рекурсия | Итерация (циклы `for`/`while`) |
| :--- | :--- | :--- |
| **Принцип работы** | Функция вызывает саму себя | Повторение блока кода через счётчик/условие |
| **Расход памяти** | **`O(d)`**, где `d` — глубина рекурсии (активные фреймы в стеке) | **`O(1)`** (память под счётчик и несколько переменных) |
| **Скорость работы** | Накладные расходы на создание/удаление фреймов | Обычно быстрее (без работы со стеком) |
| **Риск ошибки** | **Переполнение стека (Stack Overflow)** | Бесконечный цикл (программа «зависает») |
| **Читаемость кода** | Идеальна для рекурсивных структур (деревья, графы, JSON) | Идеальна для линейных проходов по массивам и спискам |

### Хвостовая рекурсия и оптимизация компилятора

Если рекурсивный вызов — **последнее** действие функции, такая рекурсия называется **хвостовой**. Её можно переписать так, чтобы результат накапливался в дополнительном параметре:

```c
// Хвостовой вариант факториала: acc («накопитель») хранит произведение на пути вниз
unsigned long long factorial_tail(unsigned int n, unsigned long long acc) {
    if (n <= 1) return acc;
    return factorial_tail(n - 1, acc * n); // после вызова ничего не делаем
}
// Вызов: factorial_tail(5, 1) == 120
```

Компилятор может заменить такой вызов переходом (то есть циклом) и не создавать новые фреймы. Но:
* **язык Си этого не гарантирует:** `gcc` делает это при оптимизации (`-O2`), а без оптимизации (`-O0`) хвостовая рекурсия по-прежнему расходует стек;
* поэтому нельзя полагаться на оптимизацию как на «защиту» от переполнения: код может работать в одном режиме сборки и падать в другом.

> **💡 Инженерный вывод:**
> Используйте **итерацию (циклы)** для простых линейных задач (проход по массиву, поиск максимума, простые вычисления). Используйте **рекурсию** там, где задача по природе иерархична (обход деревьев, графов, алгоритмы «разделяй и властвуй», разбор выражений), но следите за глубиной: если она может достигать сотен тысяч, лучше заменить рекурсию циклом (с явным стеком, если нужно).

## Практические задачи к Лекции 18

### Задача 1: Подсчёт суммы цифр числа
Напишите рекурсивную функцию на Си `int sum_of_digits(int n)`, которая вычисляет сумму всех цифр целого числа.
* *Пример:* `sum_of_digits(1234)` должен вернуть `1 + 2 + 3 + 4 = 10`.
* *Условие:* не использовать циклы `for`/`while` и строки. Использовать только остаток от деления `% 10` и деление `/ 10`.
* Укажите временную `O(T)` и пространственную `O(M)` сложность (через число цифр числа).

### Задача 2: Экспериментальное измерение размера стека (Stack Overflow Test)
Напишите программу на Си, которая замеряет максимальную глубину рекурсии до ошибки `Segmentation Fault` (Stack Overflow):
1. Создайте рекурсивную функцию с локальным массивом на `100 КБ`: `volatile char buffer[102400];`. Слово `volatile` и запись в массив (`buffer[0] = 1;`) нужны, чтобы компилятор не выбросил «неиспользуемый» массив.
2. Используйте глобальную переменную-счётчик глубины.
3. Печатайте номер текущей глубины **в `stderr`** (`fprintf(stderr, ...)`) перед следующим рекурсивным вызовом.
4. Соберите без оптимизации (`gcc -O0`), запустите и определите, на какой глубине программа упала. Сравните результат с оценкой `размер стека / 100 КБ` (размер стека — по `ulimit -s`).
5. **Вторая часть:** уберите массив, оставьте только счётчик и печать раз в 10 000 вызовов. На какой глубине падает теперь?

### Задача 3: Рекурсивный разворот строки (C-string) in-place
Напишите рекурсивную функцию `void reverse_string_rec(char *str, int left, int right)`, которая разворачивает строку задом наперёд прямо в той же памяти (без второго массива).
* *Пример:* строка `"Hello"` должна превратиться в `"olleH"`.
* Проверьте граничные случаи: пустая строка, строка из одного символа.

## Подсказки к практическим задачам

* **Подсказка к Задаче 1:**
  * Базовый случай: если `n == 0`, сумма равна `0` (или если `n < 10`, возвращаем `n`).
  * Шаг рекурсии: `(n % 10) + sum_of_digits(n / 10)`.
  * Для отрицательных чисел: `if (n < 0) n = -n;` (делается один раз; дальше `n` уже неотрицательное). Но для `INT_MIN` выражение `-n` само переполняется (неопределённое поведение): если нужна полная корректность, используйте `long long` или беззнаковый тип.
  * Сложность: если в числе `d` цифр, то выполняется `d` вызовов, то есть время `O(d) = O(log n)`, память (фреймы) тоже `O(d)`.
* **Подсказка к Задаче 2:**
  * На Linux при стеке 8 МБ ожидаемая глубина около `8 388 608 / 102 400 ≈ 82`, то есть программа упадёт примерно на 80-й вызов. В Windows (стек 1 МБ) — примерно на 10-м.
  * **Почему `stderr`, а не `printf`:** `stdout` при перенаправлении в файл или через конвейер буферизуется, а при аварийном завершении (SIGSEGV) буфер не сбрасывается, и вы можете не увидеть ни одной строки. `stderr` не буферизуется. (Если хотите использовать `printf`, добавьте `fflush(stdout)` после каждой печати.)
  * Во второй части ожидаемая глубина — порядка сотен тысяч вызовов (у пустой функции фрейм всего около 16 байт). Если собрать с `-O2`, компилятор может превратить рекурсию в цикл, и программа не упадёт вообще, поэтому для этого опыта берите `-O0`.
* **Подсказка к Задаче 3:**
  * Базовый случай: `if (left >= right) return;`.
  * На каждом шаге меняйте местами `str[left]` и `str[right]` через временную переменную `char temp`, а затем вызывайте `reverse_string_rec(str, left + 1, right - 1)`.
  * Вызов: `reverse_string_rec(s, 0, (int)strlen(s) - 1)`. Для пустой строки `right = -1`, и сработает базовый случай.
  * ⚠️ Строку нужно хранить в **изменяемой** памяти: `char s[] = "Hello";`. Запись `char *s = "Hello";` указывает на строковый литерал, который находится в памяти только для чтения, и попытка изменить его приведёт к `Segmentation Fault`.
