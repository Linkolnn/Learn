# Лекция 16: Алгоритмы поиска и двоичный поиск (Binary Search)

В предыдущей лекции мы изучили нотацию **Big O** и научились оценивать скорость работы программ при росте объёма данных `n`. Теперь мы переходим к практическому применению этих знаний.

Одной из самых частых и фундаментальных задач в программировании является **поиск информации**: найти пользователя в базе данных по ID, проверить наличие товара на складе, найти нужную строчку в файле или найти элемент в массиве.

В этой лекции мы разберём два основных подхода к поиску: медленный универсальный **Линейный поиск O(n)** и молниеносный **Двоичный поиск O(log n)**.

---

## Подглава 16.1: Линейный поиск (Linear Search)

### 1. Суть алгоритма
**Линейный поиск** — это самый простой и интуитивный способ найти элемент. 

Представьте, что перед вами лежит стопка из 100 нерассортированных бумажных карточек с фамилиями. Чтобы найти нужную фамилию, у вас нет другого выхода, кроме как брать карточки по одной сверху вниз и проверять каждую.

### 2. Реализация на языке Си

```c
#include <stdio.h>
#include <stddef.h>

// Функция линейного поиска
// Возвращает индекс найденного элемента или -1, если элемент не найден
int linear_search(const int *arr, size_t size, int target) {
    for (size_t i = 0; i < size; i++) {
        if (arr[i] == target) {
            return (int)i; // Элемент найден! Возвращаем его индекс
        }
    }
    return -1; // Прошли весь массив, элемент не найден
}
```

### 3. Оценка сложности Линейного поиска
* **Лучший случай (Омега): `O(1)`** — нужный элемент оказался на самом первом месте (`arr[0]`).
* **Худший случай (Big O): `O(n)`** — нужный элемент находится в самом конце массива или вовсе отсутствует. Программе приходится сделать ровно `n` проверок.
* **Пространственная сложность (Память): `O(1)`** — не требуется никакой дополнительной памяти.

### 4. Главное преимущество и недостаток
* **Плюс:** Работает на **абсолютно любых** данных (неважно, отсортирован массив или элементы перемешаны хаотично).
* **Минус:** Очень медленный на больших объемах. Если в массиве **1 000 000 000 элементов** (1 миллиард), в худшем случае придется сделать 1 миллиард сравнений.

## Подглава 16.2: Двоичный поиск (Binary Search)

### 1. Главное условие
> **⚠️ КРИТИЧЕСКИ ВАЖНОЕ ПРАВИЛО:**  
> Двоичный поиск работает **ТОЛЬКО на предварительно отсортированных данных**!  
> Если массив не отсортирован, использовать бинарный поиск **нельзя**.

### 2. Идея алгоритма: Игра «Угадай число»
Представьте, что ваш друг загадал число от 1 до 100, а вы пытаетесь его угадать. За каждый ответ друг говорит только: «Моё число больше» или «Моё число меньше».

* **Плохая стратегия (Линейная):** Спрашивать «Это 1? Это 2? Это 3?». В худшем случае потребуется 100 попыток.
* **Умная стратегия (Бинарная):** Спросить «Это 50?».
  * Если друг говорит «Моё число больше», вы моментально отбрасываете все числа от 1 до 50! Остался диапазон 51–100.
  * Следующим шагом вы берете середину оставшегося отрезка: «Это 75?».
  * За каждый ответ область поиска **сокращается ровно в 2 раза**!

Число от 1 до 100 угадывается максимум за **7 попыток** (`2^7 = 128`), а число от 1 до 1 000 000 — максимум за **20 попыток** (`2^20 = 1 048 576`)!

---

### 3. Пошаговая механика в коде
Для реализации двоичного поиска в отсортированном массиве используются три указателя/индекса:
1. `left` — левая граница текущего диапазона поиска (изначально `0`).
2. `right` — правая граница текущего диапазона поиска (изначально `size - 1`).
3. `mid` — индекс элемента посередине между `left` и `right`.

На каждом шаге цикла:
1. Находим середину: `mid = left + (right - left) / 2`.
2. Сравниваем значение `arr[mid]` с искомым `target`:
   * Если `arr[mid] == target` — Ура! Элемент найден, возвращаем `mid`.
   * Если `arr[mid] < target` — Искомое число находится **правее**. Сдвигаем левую границу: `left = mid + 1`.
   * Если `arr[mid] > target` — Искомое число находится **левее**. Сдвигаем правую границу: `right = mid - 1`.
3. Повторяем цикл, пока `left <= right`. Если `left` превысил `right`, значит элемента в массиве нет.

---

### 4. Подводный камень: Переполнение типов при расчете `mid`

Во многих учебниках вы можете увидеть такую формулу расчета середины:
```c
int mid = (left + right) / 2; // ❌ ОПАСНО!
```
**В чём баг?** Если массив очень большой (например, больше 1 миллиарда элементов), сумма `left + right` может превысить максимальный предел типа `int` (2 147 483 647) и уйти в **целочисленное переполнение** (Integer Overflow), превратившись в отрицательное число! Это приведет к падению программы.

**Правильная формула:**
```c
size_t mid = left + (right - left) / 2; // ✅ Безопасно от переполнения
```

---

### 5. Реализация Двоичного поиска на Си

```c
#include <stdio.h>
#include <stddef.h>

// Итеративная реализация Двоичного поиска
int binary_search(const int *arr, size_t size, int target) {
    if (size == 0) return -1;

    size_t left = 0;
    size_t right = size - 1;

    while (left <= right) {
        // Безопасный расчет среднего индекса
        size_t mid = left + (right - left) / 2;

        if (arr[mid] == target) {
            return (int)mid; // Элемент найден
        }

        if (arr[mid] < target) {
            left = mid + 1; // Ищем в правой половине
        } else {
            // Защита от выхода за левую границу при size_t (беззнаковом типе)
            if (mid == 0) break; 
            right = mid - 1; // Ищем в левой половине
        }
    }

    return -1; // Элемент не найден
}
```

## Подглава 16.3: Сравнение Линейного и Двоичного поиска

Давайте сравним максимальное количество операций (худший случай `Big O`), требуемое обоим алгоритмам в зависимости от размера массива `n`:

| Размер массива `n` | Линейный поиск `O(n)` | Двоичный поиск `O(log n)` | Выигрыш в скорость |
| :--- | :--- | :--- | :--- |
| **10** элементов | 10 операций | 4 операции | В 2.5 раза быстрее |
| **1 000** элементов | 1 000 операций | 10 операций | В 100 раз быстрее |
| **1 000 000** (1 млн) | 1 000 000 операций | 20 операций | В 50 000 раз быстрее |
| **1 000 000 000** (1 млрд) | 1 000 000 000 операций | 30 операций | В 33 000 000 раз быстрее! |

### Когда что использовать?
1. **Данные НЕ отсортированы и запрос всего один:** Используйте Линейный поиск `O(n)`. Сортировка массива перед одним единственным поиском займет больше времени (`O(n log n)`), чем сам линейный проход.
2. **Данные отсортированы заранее или поисковых запросов много:** Однократно отсортируйте массив, а затем выполняйте миллионы поисков через Двоичный поиск `O(log n)`.

## Практические задачи к Лекции 16

### Задача 1: Поиск первой и последней позиции элемента в отсортированном массиве (LeetCode 34)

В отсортированном массиве могут встречаться дубликаты (повторяющиеся числа). Стандартный `binary_search` возвращает *любой* найденный индекс.

Напишите программу на Си с двумя функциями:
1. `int find_first_position(const int *arr, size_t size, int target)` — возвращает индекс **самого первого (левого)** вхождения числа.
2. `int find_last_position(const int *arr, size_t size, int target)` — возвращает индекс **самого последнего (правого)** вхождения числа.

Обе функции должны иметь временную сложность **`O(log n)`**.

*Пример:*  
Массив: `[1, 2, 4, 4, 4, 5, 7, 9]`, искомое число: `4`.  
Результат: Первое вхождение = индекс `2`, Последнее вхождение = индекс `4`.

### Задача 2: Поиск места для вставки (Search Insert Position — LeetCode 35)

Дан отсортированный массив уникальных целых чисел и значение `target`.

Напишите функцию `int search_insert(const int *arr, size_t size, int target)` со сложностью **`O(log n)`**, которая:
* Возвращает индекс элемента, если он найден в массиве.
* Если элемент не найден — возвращает **индекс, на который его следует вставить**, чтобы массив остался отсортированным.

*Пример 1:* Массив `[1, 3, 5, 6]`, target `5` ==> Ответ: `2` (элемент найден на индексе 2).  
*Пример 2:* Массив `[1, 3, 5, 6]`, target `2` ==> Ответ: `1` (число 2 должно встать между 1 и 3).  
*Пример 3:* Массив `[1, 3, 5, 6]`, target `7` ==> Ответ: `4` (число 7 должно встать в конец).

### Задача 3: Экспериментальное сравнение времени работы (Линейный vs Бинарный)

Напишите программу на Си, которая:
1. Создаёт отсортированный динамический массив на **10 000 000 элементов** (`int`).
2. Генерирует **100 000 случайных чисел** и ищет каждое из них с помощью `linear_search`. Замерьте общее время работы в миллисекундах через `<time.h>`.
3. Ищет те же 100 000 чисел с помощью `binary_search`. Замерьте время работы.
4. Выведите на экран общее время работы обоих алгоритмов и наглядное соотношение скоростей.

## Подсказки к задачам

* **Подсказка к Задаче 1:** В стандартном бинарном поиске, когда вы находите `arr[mid] == target`, вы сразу делаете `return mid`. Чтобы найти *первое* вхождение, не останавливайтесь! Сохраните `mid` в переменную-результат `ans = mid` и продолжайте поиск в **левой половине** (`right = mid - 1`). Для последнего вхождения — сохраните результат и продолжайте поиск в **правой половине** (`left = mid + 1`).
* **Подсказка к Задаче 2:** Проследите за поведением указателя `left` во время работы итеративного бинарного поиска. Когда цикл `while (left <= right)` завершается без находки, где именно оказывается значение переменной `left`?
* **Подсказка к Задаче 3:** Для замера времени используйте `<time.h>`:
  ```c
  clock_t start = clock();
  // Выполнение 100 000 поисков
  clock_t end = clock();
  double time_spent = (double)(end - start) * 1000.0 / CLOCKS_PER_SEC;
  ```
