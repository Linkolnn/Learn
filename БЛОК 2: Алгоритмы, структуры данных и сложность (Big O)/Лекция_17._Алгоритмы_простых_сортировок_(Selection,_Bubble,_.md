# Лекция 17: Алгоритмы простых сортировок (Selection, Bubble, Insertion Sort)

В прошлых лекциях мы разобрали фундаментальный инструмент анализа алгоритмов — **нотацию Big O**, а также изучили **двоичный поиск (Binary Search)**, который позволяет находить элементы за мгновенные `O(log n)`. Однако у двоичного поиска есть строгое требование: **массив должен быть заранее отсортирован**.

Сегодня мы переходим к изучению алгоритмов сортировки. В этой лекции мы подробно разберем три базовых квадратичных алгоритма: **Сортировку пузырьком (Bubble Sort)**, **Сортировку выбором (Selection Sort)** и **Сортировку вставками (Insertion Sort)**.

---

## Подглава 17.1: Зачем изучать алгоритмы сложности O(n²)?

Начинающие разработчики часто спрашивают: *«Зачем учить сортировки со сложностью O(n²), если в реальной жизни используются быстрая сортировка (QuickSort) или сортировка слиянием (MergeSort) за O(n log n)?»*

На это есть 4 фундаментальные причины:

1. **Базовый фундамент алгоритмического мышления:** Простые сортировки наглядно демонстрируют работу с двумя указателями, вложенными циклами и мутацией памяти *in-place* (без выделения дополнительной памяти).
2. **Эффективность на малых объемах данных:** На массивах из 10–20 элементов простые сортировки (особенно Insertion Sort) работают **быстрее**, чем сложные алгоритмы вроде QuickSort, так как не несут накладных расходов на рекурсию и разбиение.
3. **Оптимизация гибридных алгоритмов:** Продашкен-сортировки (например, `Timsort` в Python/JS/Java или `Introsort` в C++ `std::sort`) переключаются на **Insertion Sort**, когда размер подмассива становится меньше 16–32 элементов.
4. **Понятие устойчивости (Stability):** Простые сортировки идеально подходят для изучения важного свойства — сохранения относительного порядка равных элементов.

## Подглава 17.2: Сортировка пузырьком (Bubble Sort)

### 1. Идея и принцип работы
Идея алгоритма проста: мы проходим по массиву слева направо и сравниваем соседние элементы `arr[j]` и `arr[j + 1]`. Если левый элемент больше правого, мы меняем их местами (делаем `swap`).

В результате первого полного прохода самый большой элемент «всплывает» на самую последнюю позицию массива (как пузырек воздуха в воде). При втором проходе второй по величине элемент всплывает на предпоследнюю позицию, и так далее.

### 2. Реализация на Си с подробными комментариями
Если на каком-то из проходов мы не сделали **ни одного обмена**, значит массив уже полностью отсортирован, и выполнение цикла можно досрочно завершить!

```c
#include <stdio.h>
#include <stdbool.h>

// Функция обмена двух элементов по указателю
void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

// Оптимизированная пузырьковая сортировка
void bubble_sort(int *arr, size_t n) {
    // 💡 ПОЯСНЕНИЕ 1: Зачем нужна проверка if (n < 2) return;
    // 1. Массив из 0 или 1 элемента сортировать не нужно — он уже отсортирован.
    // 2. Главная причина — защита от выходя за границы и подвоха с типом size_t:
    //    size_t — это беззнаковый тип (unsigned). Если n = 0, то выражение (n - 1)
    //    приведет к беззнаковому переполнению (underflow) и превратится в огромное число SIZE_MAX.
    //    Цикл превратится в бесконечный и вызовет Segfault при попытке обратиться к arr[i].
    if (n < 2) return;

    // 💡 ПОЯСНЕНИЕ 2: Зачем во внешнем цикле условие i < n - 1?
    // Массиву из n элементов требуется максимум (n - 1) проходов.
    // Почему? Когда первые (n - 1) самых крупных элементов всплывут на свои места справа,
    // самый последний оставшийся элемент автоматически окажется на своем единственно правильном месте слева!
    for (size_t i = 0; i < n - 1; i++) {
        bool swapped = false; // Флаг: были ли обмены на этой итерации?

        // Внутренний цикл сравнивает пары arr[j] и arr[j + 1].
        // Граница (n - 1 - i) необходима по двум причинам:
        // 1. Из-за обращения к arr[j + 1] мы обязаны ограничить j значением (n - 2), чтобы (j + 1) не вышел за границы массива (n - 1).
        // 2. С каждым шагом i крайние справа i элементов УЖЕ гарантированно отсортированы (всплыли),
        //    поэтому их повторно сравнивать не нужно — вычитание -i экономит лишние итерации.
        for (size_t j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                swap(&arr[j], &arr[j + 1]);
                swapped = true;
            }
        }

        // Если обменов не было — массив отсортирован, выходим досрочно!
        if (!swapped) {
            break;
        }
    }
}
```

### 3. Оценка сложности
* **Временная сложность (Time Complexity):**
  * **Худший случай:** `O(n²)` — массив отсортирован в обратном порядке (каждая пара сравнивается и меняется).
  * **Средний случай:** `O(n²)`.
  * **Лучший случай:** `O(n)` — благодаря флажку `swapped`, на отсортированном массиве алгоритм делает 1 проход и завершается.
* **Пространственная сложность (Space Complexity):** `O(1)` — сортировка выполняется *in-place* (без выделения доп. памяти).
* **Устойчивость (Stability):** **Устойчивая** (не меняет порядок равных элементов, так как `arr[j] > arr[j + 1]` строгое).

## Подглава 17.3: Сортировка выбором (Selection Sort)

### 1. Идея и принцип работы
Сортировка выбором делит массив на две части: отсортированную (слева) и неотсортированную (справа). 

На каждом шаге мы ищем **минимальный элемент** в неотсортированной части массива и меняем его местами с первым неотсортированным элементом.

### 2. Реализация на Си с подробными комментариями
```c
#include <stdio.h>

void selection_sort(int *arr, size_t n) {
    // 💡 ПОЯСНЕНИЕ: Защита от n < 2
    // Если n = 0 или n = 1, сортировать нечего.
    // Также предотвращает ошибку беззнакового вычитания (n - 1) при n = 0 (size_t underflow).
    if (n < 2) return;

    // 💡 ПОЯСНЕНИЕ: Почему i < n - 1?
    // Нам достаточно сделать (n - 1) итераций. Когда мы выберем и поставим на свои места
    // самые маленькие элементы для позиций от 0 до (n - 2), на позиции (n - 1)
    // автоматически останется самый большой элемент массива.
    for (size_t i = 0; i < n - 1; i++) {
        size_t min_idx = i; // Предполагаем, что текущий элемент минимальный

        // Ищем индекс минимального элемента в оставшейся неотсортированной части [i+1 ... n-1]
        for (size_t j = i + 1; j < n; j++) {
            if (arr[j] < arr[min_idx]) {
                min_idx = j;
            }
        }

        // Меняем найденный минимум с текущим элементом i
        if (min_idx != i) {
            int temp = arr[i];
            arr[i] = arr[min_idx];
            arr[min_idx] = temp;
        }
    }
}
```

### 3. Главная фишка и сложность
Главное преимущество Сортировки выбором — она делает **не более `n` обменов памяти** (операций записи). Это критически важно для работы с памятью, у которой ограничен ресурс перезаписи (например, Flash-память или EEPROM в микроконтроллерах).

* **Временная сложность (Time Complexity):**
  * **Худший, Средний и Лучший случаи:** Всегда `O(n²)`, так как поиск минимума требует полного прохода по неотсортированной части независимо от порядка данных.
* **Пространственная сложность (Space Complexity):** `O(1)` *in-place*.
* **Устойчивость (Stability):** **Неустойчивая** в базовой реализации (при далеком обмене элемент может «перепрыгнуть» через равный ему элемент).

## Подглава 17.4: Сортировка вставками (Insertion Sort)

### 1. Идея и принцип работы
Аналогия из реальной жизни — **сортировка карт в руке**. Вы берете по одной карте из кучи и вставляете её на правильное место среди уже отсортированных карт в вашей руке, сдвигая более крупные карты вправо.

### 2. Реализация на Си с подробными комментариями
```c
#include <stdio.h>

void insertion_sort(int *arr, size_t n) {
    // 💡 ПОЯСНЕНИЕ: Защита от n < 2
    // Отсекаем массивы размером 0 и 1 элемент — они уже отсортированы.
    if (n < 2) return;

    // Цикл начинается с i = 1, так как элемент с индексом 0 считаем условно "отсортированной картой".
    // Берем по очереди элементы начиная со 2-го (индекс 1) и ищем им место среди левых элементов [0 ... i-1].
    for (size_t i = 1; i < n; i++) {
        int key = arr[i]; // Запоминаем текущий элемент для вставки
        int j = (int)i - 1;

        // Сдвигаем элементы arr[0..i-1], которые больше key, на одну позицию вправо
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }

        // Вставляем key на освободившееся место
        arr[j + 1] = key;
    }
}
```

### 3. Почему Insertion Sort — лучший среди простых сортировок?
* Если массив **уже частично отсортирован** (например, новые данные поступают в реальном времени), Insertion Sort работает с потрясающей скоростью за **`O(n)`**.
* Алгоритм делает минимальное количество операций записи/сдвигов при почти упорядоченных данных.
* **Временная сложность:**
  * **Худший случай:** `O(n²)` (массив отсортирован наоборот).
  * **Средний случай:** `O(n²)`.
  * **Лучший случай:** `O(n)` (уже отсортированный массив).
* **Пространственная сложность:** `O(1)` *in-place*.
* **Устойчивость:** **Устойчивая** (элементы сдвигаются только если строго больше `key`).

## Подглава 17.5: Сводное сравнение алгоритмов

| Алгоритм | Худшее время `O(T)` | Среднее время `O(T)` | Лучшее время `O(T)` | Память `O(M)` | Устойчивость | Главное преимущество |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Bubble Sort** | `O(n²)` | `O(n²)` | `O(n)` | `O(1)` | Устойчивый | Простейшая концепция, флаг раннего выхода |
| **Selection Sort** | `O(n²)` | `O(n²)` | `O(n²)` | `O(1)` | Неустойчивый | Минимальное число обменов (максимум `n` swap) |
| **Insertion Sort** | `O(n²)` | `O(n²)` | `O(n)` | `O(1)` | Устойчивый | Идеален для частично отсортированных данных |
