# Лекция 17: Алгоритмы простых сортировок (Selection, Bubble, Insertion Sort)

В прошлых лекциях мы разобрали фундаментальный инструмент анализа алгоритмов — **нотацию Big O**, а также изучили **двоичный поиск (Binary Search)**, который позволяет находить элементы за `O(log n)`. Однако у двоичного поиска есть строгое требование: **массив должен быть заранее отсортирован**.

Сегодня мы переходим к алгоритмам сортировки. В этой лекции мы подробно разберём три базовых квадратичных алгоритма: **сортировку выбором (Selection Sort)**, **сортировку пузырьком (Bubble Sort)** и **сортировку вставками (Insertion Sort)**. Быстрые алгоритмы `O(n log n)` (QuickSort и MergeSort) мы изучим в лекции 19, а рекурсия, на которой они построены, — тема лекции 18.

## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. Сортировка (Sorting)**
> * **Что это:** Расстановка элементов в заданном порядке (в этой лекции — по возрастанию).

> 📌 **2. Квадратичная сложность `O(n²)`**
> * **Что это:** Время работы растёт пропорционально квадрату размера данных: при увеличении массива в 10 раз время растёт примерно в 100 раз. Обычно возникает из-за вложенных циклов по всему массиву.

> 📌 **3. In-place (на месте)**
> * **Что это:** Алгоритм сортирует массив прямо в нём, используя лишь `O(1)` дополнительной памяти (несколько переменных), а не создаёт копию массива.

> 📌 **4. Устойчивость (Stability)**
> * **Что это:** Сортировка называется **устойчивой**, если равные по ключу элементы остаются в том же относительном порядке, что и до сортировки. Пример: список студентов уже отсортирован по имени; если теперь отсортировать его по оценке **устойчивой** сортировкой, то внутри каждой оценки студенты останутся в алфавитном порядке. Неустойчивая сортировка может этот порядок перемешать.

> 📌 **5. Инверсия**
> * **Что это:** Пара элементов, стоящих «не в том порядке»: `i < j`, но `arr[i] > arr[j]`. В отсортированном массиве инверсий нет, в массиве, отсортированном наоборот, их максимум — `n(n-1)/2`. Число инверсий хорошо показывает, «насколько массив далёк от отсортированного».

## Подглава 17.1: Зачем изучать алгоритмы сложности O(n²)?

Начинающие разработчики часто спрашивают: *«Зачем учить сортировки со сложностью O(n²), если в реальной жизни используются быстрая сортировка (QuickSort) или сортировка слиянием (MergeSort) за O(n log n)?»*

На это есть 4 фундаментальные причины:

1. **Базовый фундамент алгоритмического мышления:** Простые сортировки наглядно демонстрируют работу с индексами, вложенными циклами и изменением данных *in-place* (без выделения дополнительной памяти).
2. **Эффективность на малых объёмах данных:** На массивах из десятков элементов простые сортировки (особенно Insertion Sort) работают **быстрее** сложных алгоритмов вроде QuickSort, так как не несут накладных расходов на рекурсию и разбиение.
3. **Основа гибридных алгоритмов:** Промышленные сортировки переключаются на вставки на маленьких подмассивах. Например, `Timsort` (Python, JavaScript в V8, `Arrays.sort` для объектов в Java) использует сортировку вставками на небольших кусках, а популярные реализации `std::sort` в C++ (на базе `Introsort`) переходят на неё, когда подмассив короче примерно 16 элементов. Точные пороги зависят от реализации.
4. **Понятие устойчивости (Stability):** Простые сортировки идеально подходят, чтобы разобраться с важным свойством — сохранением относительного порядка равных элементов.

> ℹ️ В реальных программах на Си обычно вызывают готовую функцию `qsort` из `<stdlib.h>` (она принимает указатель на функцию сравнения, как `bsearch` из лекции 16). Свои сортировки мы пишем, чтобы понимать, как всё устроено.

### Откуда берётся `n²`
Во всех трёх алгоритмах есть вложенные циклы. Например, в худшем случае пузырьку нужно `(n-1) + (n-2) + … + 1 = n(n-1)/2` сравнений. Для `n = 5000` это `12 497 500` сравнений. Константу `1/2` и слагаемое `-n/2` Big O отбрасывает, остаётся `O(n²)`.

## Подглава 17.2: Сортировка пузырьком (Bubble Sort)

### 1. Идея и принцип работы
Мы проходим по массиву слева направо и сравниваем соседние элементы `arr[j]` и `arr[j + 1]`. Если левый элемент больше правого, меняем их местами (`swap`).

В результате первого полного прохода самый большой элемент «всплывает» на последнюю позицию массива (как пузырёк воздуха в воде). При втором проходе второй по величине элемент всплывает на предпоследнюю позицию, и так далее.

**Разбор на примере.** Массив `[5, 2, 4, 1, 3]`:

| Проход | Состояние массива после прохода | Что произошло |
| :-: | :--- | :--- |
| 1 | `[2, 4, 1, 3, 5]` | `5` «всплыло» в конец |
| 2 | `[2, 1, 3, 4, 5]` | `4` встало на своё место |
| 3 | `[1, 2, 3, 4, 5]` | массив отсортирован, но обмены были |
| 4 | `[1, 2, 3, 4, 5]` | обменов нет → флаг `swapped` остался `false`, выходим |

### 2. Реализация на Си с подробными комментариями
Если на каком-то из проходов мы не сделали **ни одного обмена**, значит массив уже полностью отсортирован, и выполнение можно досрочно завершить.

```c
#include <stdio.h>
#include <stddef.h>
#include <stdbool.h>

// Обмен двух элементов по указателям
static void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

// Оптимизированная пузырьковая сортировка
void bubble_sort(int *arr, size_t n) {
    // 💡 ПОЯСНЕНИЕ 1: Зачем нужна проверка if (n < 2) return;
    // 1. Массив из 0 или 1 элемента сортировать не нужно — он уже отсортирован.
    // 2. Главная причина — тип size_t: он беззнаковый (unsigned). Если n = 0, то
    //    выражение (n - 1) не даст -1, а «обернётся» в огромное число SIZE_MAX.
    //    Цикл пойдёт по гигантскому диапазону и полезет за границы массива
    //    (неопределённое поведение, обычно Segmentation Fault).
    if (n < 2) return;

    // 💡 ПОЯСНЕНИЕ 2: Зачем во внешнем цикле условие i < n - 1?
    // Массиву из n элементов нужно максимум (n - 1) проходов.
    // Когда (n - 1) самых крупных элементов встанут на свои места справа,
    // оставшийся элемент слева автоматически окажется на единственно верном месте.
    for (size_t i = 0; i < n - 1; i++) {
        bool swapped = false; // Флаг: были ли обмены на этом проходе?

        // Внутренний цикл сравнивает пары arr[j] и arr[j + 1].
        // Граница (n - 1 - i) нужна по двум причинам:
        // 1. Из-за обращения к arr[j + 1] нужно ограничить j значением n - 2,
        //    чтобы (j + 1) не вышло за последний индекс n - 1.
        // 2. После i проходов крайние справа i элементов УЖЕ стоят на своих местах,
        //    поэтому их повторно сравнивать не нужно.
        for (size_t j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                swap(&arr[j], &arr[j + 1]);
                swapped = true;
            }
        }

        // Если обменов не было — массив отсортирован, выходим досрочно!
        if (!swapped) {
            break;
        }
    }
}
```

### 3. Оценка сложности
* **Временная сложность (Time Complexity):**
  * **Худший случай:** `O(n²)` — массив отсортирован в обратном порядке (каждая пара сравнивается и меняется): `n(n-1)/2` сравнений и столько же обменов.
  * **Средний случай:** `O(n²)` (в среднем обменов около `n²/4`).
  * **Лучший случай:** `O(n)` — благодаря флагу `swapped` на отсортированном массиве выполняется 1 проход (`n - 1` сравнений) без обменов.
* **Пространственная сложность (Space Complexity):** `O(1)` — сортировка *in-place*.
* **Устойчивость (Stability):** **Устойчивая**: равные элементы не меняются местами, так как условие `arr[j] > arr[j + 1]` строгое.

## Подглава 17.3: Сортировка выбором (Selection Sort)

### 1. Идея и принцип работы
Сортировка выбором делит массив на две части: отсортированную (слева) и неотсортированную (справа).

На каждом шаге мы ищем **минимальный элемент** в неотсортированной части и меняем его местами с первым элементом этой части.

**Разбор на примере.** Массив `[5, 2, 4, 1, 3]`:

| Шаг `i` | Минимум в `arr[i..n-1]` | Массив после обмена |
| :-: | :--- | :--- |
| 0 | `1` (индекс 3) | `[1, 2, 4, 5, 3]` |
| 1 | `2` (уже на месте) | `[1, 2, 4, 5, 3]` |
| 2 | `3` (индекс 4) | `[1, 2, 3, 5, 4]` |
| 3 | `4` (индекс 4) | `[1, 2, 3, 4, 5]` |

### 2. Реализация на Си с подробными комментариями
```c
#include <stdio.h>
#include <stddef.h>

void selection_sort(int *arr, size_t n) {
    // 💡 ПОЯСНЕНИЕ: Защита от n < 2
    // Если n = 0 или n = 1, сортировать нечего.
    // Также предотвращает «заворачивание» беззнакового (n - 1) при n = 0.
    if (n < 2) return;

    // 💡 ПОЯСНЕНИЕ: Почему i < n - 1?
    // Достаточно (n - 1) шагов. Когда на позиции 0…(n - 2) встали
    // самые маленькие элементы, на позиции (n - 1) автоматически остался самый большой.
    for (size_t i = 0; i < n - 1; i++) {
        size_t min_idx = i; // Предполагаем, что текущий элемент минимальный

        // Ищем индекс минимального элемента в неотсортированной части [i+1 ... n-1]
        for (size_t j = i + 1; j < n; j++) {
            if (arr[j] < arr[min_idx]) {
                min_idx = j;
            }
        }

        // Меняем найденный минимум с элементом i (если это не один и тот же элемент)
        if (min_idx != i) {
            int temp = arr[i];
            arr[i] = arr[min_idx];
            arr[min_idx] = temp;
        }
    }
}
```

### 3. Главная фишка и сложность
Главное преимущество сортировки выбором — она делает **не более `n - 1` обменов** (на каждый шаг не больше одного), тогда как у пузырька и вставок число записей может быть порядка `n²`. Это важно, когда запись в память дорогая или ограничена по ресурсу (например, Flash-память или EEPROM в микроконтроллерах).

* **Временная сложность (Time Complexity):**
  * **Худший, средний и лучший случаи:** всегда `O(n²)` (ровно `n(n-1)/2` сравнений): поиск минимума требует полного прохода по неотсортированной части независимо от порядка данных.
* **Пространственная сложность (Space Complexity):** `O(1)` *in-place*.
* **Устойчивость (Stability):** **Неустойчивая** в базовой реализации: обмен «далёких» элементов может перенести элемент через равный ему. Пример: `[(A,4), (B,4), (C,1)]` → после первого шага `(C,1)` меняется местами с `(A,4)`, получается `[(C,1), (B,4), (A,4)]`, то есть `A` оказался после `B`.

## Подглава 17.4: Сортировка вставками (Insertion Sort)

### 1. Идея и принцип работы
Аналогия из жизни — **сортировка карт в руке**. Вы берёте по одной карте из колоды и вставляете её на правильное место среди уже отсортированных карт в руке, сдвигая более крупные карты вправо.

**Разбор на примере.** Массив `[5, 2, 4, 1, 3]` (слева от `|` — отсортированная часть):

| Шаг `i` | Берём `key` | Состояние массива |
| :-: | :-: | :--- |
| начало | — | `[5 \| 2, 4, 1, 3]` |
| 1 | `2` | `[2, 5 \| 4, 1, 3]` |
| 2 | `4` | `[2, 4, 5 \| 1, 3]` |
| 3 | `1` | `[1, 2, 4, 5 \| 3]` |
| 4 | `3` | `[1, 2, 3, 4, 5]` |

### 2. Реализация на Си с подробными комментариями
```c
#include <stdio.h>
#include <stddef.h>

void insertion_sort(int *arr, size_t n) {
    // Для n = 0 и n = 1 цикл ниже просто не выполнится (i = 1 < n — ложь),
    // поэтому отдельная проверка не нужна. Беззнакового вычитания (n - 1) здесь нет.

    // Элемент с индексом 0 считаем «отсортированной картой», поэтому начинаем с i = 1.
    for (size_t i = 1; i < n; i++) {
        int key = arr[i]; // Запоминаем текущий элемент для вставки
        size_t j = i;     // j — позиция, на которую «опускаем» key

        // Пока слева есть элемент, который больше key, сдвигаем его вправо.
        // Условие j > 0 проверяется ПЕРВЫМ: так мы никогда не читаем arr[-1].
        // (Используем size_t и условие j > 0 вместо int и j >= 0, чтобы не смешивать
        //  знаковые и беззнаковые типы.)
        while (j > 0 && arr[j - 1] > key) {
            arr[j] = arr[j - 1];
            j--;
        }

        // Вставляем key на освободившееся место
        arr[j] = key;
    }
}
```

### 3. Почему Insertion Sort — лучший среди простых сортировок?
* На **почти отсортированных** данных (например, в конец отсортированного списка дописали несколько новых элементов) он работает очень быстро. Точнее, время равно `O(n + k)`, где `k` — число инверсий: если `k` мало, получается почти `O(n)`.
* Каждый элемент сдвигается ровно на столько позиций, на сколько он «не на месте», поэтому лишней работы на упорядоченных данных нет.
* **Временная сложность:**
  * **Худший случай:** `O(n²)` (массив отсортирован наоборот).
  * **Средний случай:** `O(n²)`.
  * **Лучший случай:** `O(n)` (уже отсортированный массив: каждое сравнение сразу завершает внутренний цикл).
* **Пространственная сложность:** `O(1)` *in-place*.
* **Устойчивость:** **Устойчивая** (элементы сдвигаются только если строго больше `key`).

## Подглава 17.5: Сводное сравнение алгоритмов

| Алгоритм | Худшее время | Среднее время | Лучшее время | Память | Устойчивость | Главное преимущество |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Bubble Sort** | `O(n²)` | `O(n²)` | `O(n)` | `O(1)` | Устойчивая | Простейшая идея, флаг раннего выхода |
| **Selection Sort** | `O(n²)` | `O(n²)` | `O(n²)` | `O(1)` | Неустойчивая | Не более `n - 1` обменов |
| **Insertion Sort** | `O(n²)` | `O(n²)` | `O(n)` | `O(1)` | Устойчивая | Быстрая на почти отсортированных данных |

На практике из трёх вставки обычно самые быстрые, а пузырёк — самый медленный (из-за большого числа обменов).

### Проверка своих функций
Чтобы убедиться, что сортировка работает, пишут вспомогательную функцию и тестируют на граничных случаях (пустой массив, один элемент, повторы, уже отсортированный и обратный порядок):

```c
#include <stdbool.h>

bool is_sorted(const int *arr, size_t n) {
    for (size_t i = 1; i < n; i++) {
        if (arr[i - 1] > arr[i]) return false;
    }
    return true;
}

int main(void) {
    int a[] = {5, 2, 4, 1, 3};
    size_t n = sizeof(a) / sizeof(a[0]);

    insertion_sort(a, n);
    for (size_t i = 0; i < n; i++) printf("%d ", a[i]);
    printf("\nsorted: %s\n", is_sorted(a, n) ? "yes" : "no");
    return 0;
}
```

## Подсказки к практическим задачам

* **Подсказка к Задаче 1:** При поиске минимума в массиве `{(Anna,4), (Boris,4), (Clara,1)}` элемент `Clara` меняется местами с `Anna`, и получается `{Clara, Boris, Anna}`: `Anna` оказалась **после** `Boris`. Пузырёк же и вставки меняют/сдвигают элементы только при строгом `>`, поэтому `Anna` и `Boris` не поменяются местами.
* **Подсказка к Задаче 2:** Введите счётчики `long long comparisons` и `long long swaps` (глобальные или передавайте указатели на них в функции) и увеличивайте их при каждом сравнении **двух элементов массива** (`arr[j] > arr[j+1]`) и каждой перестановке. Проверки индексов (`j > 0`, `j < n`) не считаются. Для самопроверки: при `N = 5000`
  * Selection Sort всегда делает `12 497 500` сравнений; перестановок `0` на отсортированном и `2500` на обратном массиве (при проверке `min_idx != i`);
  * Bubble Sort на отсортированном массиве: `4 999` сравнений и `0` обменов; на обратном: `12 497 500` сравнений и столько же обменов;
  * Insertion Sort на отсортированном массиве: `4 999` сравнений и `0` сдвигов; на обратном — `12 497 500` сравнений и сдвигов;
  * на случайном массиве у пузырька и вставок получается порядка `6,2 млн` обменов/сдвигов (около `n²/4`).
* **Подсказка к Задаче 3:** Передавайте в каждую функцию сортировки **копию** исходного случайного массива (например, через `memcpy`), чтобы все алгоритмы тестировались на абсолютно одинаковых данных. Заполняйте массив через `rand()` (для воспроизводимости можно вызвать `srand(42)`), собирайте с оптимизацией `gcc -O2` и после каждой сортировки проверяйте результат функцией `is_sorted`. Время считайте так: `(double)(end - start) * 1000.0 / CLOCKS_PER_SEC` миллисекунд.
