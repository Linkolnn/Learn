# Лекция 34.3: Chrome DevTools для вёрстки (Elements, Styles, Computed, Layout, Device Toolbar, Console и Network)

В этой лекции мы освоим главный рабочий инструмент современного фронтенд-разработчика и верстальщика — панель разработчика **Chrome DevTools** (аналогичные инструменты присутствуют в Edge, Firefox, Safari и Brave). Вы научитесь инспектировать DOM-дерево, редактировать HTML и CSS «на лету», исследовать правила каскада и специфичности, визуализировать блочную модель **Box Model**, отлаживать сетки **Flexbox** и **CSS Grid**, эмулировать мобильные устройства и медленную сеть, а также мгновенно находить и устранять ошибки вёрстки.

---

## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. Chrome DevTools (Developer Tools)**
> * **Что это:** Встроенный в браузер комплекс профессиональных инструментов для инспекции, отладки, профилирования и анализа производительности веб-страниц.

> 📌 **2. Инспектирование элементов (DOM Inspection)**
> * **Что это:** Процесс выбора конкретного визуального элемента на странице для мгновенного перехода к его узлу в DOM-дереве и связанным CSS-стилям.

> 📌 **3. Принудительное состояние элемента (Force Element State / Pseudo-classes)**
> * **Что это:** Режим DevTools, позволяющий искусственно зафиксировать псевдокласс элемента (`:hover`, `:focus`, `:active`, `:visited`, `:focus-within`) для отладки интерактивных состояний без удержания курсора мыши.

> 📌 **4. Вкладка Computed (Вычисленные стили)**
> * **Что это:** Раздел DevTools, отображающий итоговые физические значения всех CSS-свойств элемента в пикселях (`px`) после применения каскада, специфичности и перевода относительных единиц (`rem`, `%`, `vw`).

> 📌 **5. Device Toolbar (Device Mode)**
> * **Что это:** Инструмент эмуляции экранов различных мобильных устройств, планшетов, разрешений, ориентации экрана, сенсорного ввода (Touch) и ограничения скорости сети (Throttling).

> 📌 **6. Переменная `$0`**
> * **Что это:** Специальный синтаксический псевдоним в консоли DevTools, содержащий прямую ссылку на DOM-узел, выбранный в данный момент на вкладке Elements.

## Подглава 34.3.1: Зачем верстальщику DevTools? Открытие и навигация

Разработка и вёрстка сайтов «вслепую» (только путем редактирования кода в редакторе и постоянного обновления страницы) невероятно медленна и приведет к часам бессмысленного поиска ошибок. **DevTools** превращает браузер в живую лабораторию, где любые гипотезы проверяются за секунды.

```text
+-----------------------------------------------------------------------+
|  ВЕБ-СТРАНИЦА (Интерфейс)                                             |
|  [Выбор элемента Ctrl+Shift+C] ──> Клик по кнопке                    |
+-----------------------------------------------------------------------+
|  PANEL CHROMEDEVTOOLS (F12)                                           |
|  +----------+---------+----------+--------+----------------+-------+  |
|  | Elements | Styles  | Computed | Layout | Device Toolbar |Network|  |
|  +----------+---------+----------+--------+----------------+-------+  |
|  | DOM-узел | Каскад  | Размеры  | Flex / | Эмуляция       | Зап-  |  |
|  | и теги   | и цвета | BoxModel | Grid   | смартфонов     | росы  |  |
|  +----------+---------+----------+--------+----------------+-------+  |
+-----------------------------------------------------------------------+
```

### Способы вызова и горячие клавиши:

1. **`F12`** или **`Ctrl + Shift + I`** (`Cmd + Option + I` на macOS) — открытие / закрытие панели DevTools.
2. **`Ctrl + Shift + C`** (`Cmd + Option + C` на macOS) — активация режима **Инспектора элементов**. Позволяет навести курсор на любой объект на странице и сразу подсветить его в DOM-дереве.
3. **Клик правой кнопкой мыши по элементу $
ightarrow$ «Посмотреть код» (Inspect)** — мгновенный переход к конкретному узлу.
4. **`Ctrl + Shift + M`** (`Cmd + Shift + M` на macOS) — переключение режима эмуляции мобильных устройств (**Device Toolbar**).
5. **`Ctrl + Shift + P`** (`Cmd + Shift + P` на macOS) — вызов меню команд DevTools (Command Menu) для быстрого поиска функций (например, *Capture full size screenshot*, *Toggle dark theme*).

### Настройка положения панели (Dock side):
В правом верхнем углу панели DevTools (иконка `⋮`) можно выбрать удобное расположение:
* **Dock to right** (справа) — стандарт при верстке на широкоформатных мониторах.
* **Dock to bottom** (снизу) — удобен при анализе длинных строк кода и таблиц.
* **Undock into separate window** — вынос DevTools в отдельное окно (идеально для двух мониторов).

## Подглава 34.3.2: Вкладка Elements — исследование и редактирование DOM-дерева

Вкладка **Elements** отображает текущее состояние **DOM-дерева (Document Object Model)** в реальном времени.

```html
<!-- DOM-дерево в панели Elements -->
<div class="todo-item todo-item--completed" data-id="101">
  <input type="checkbox" class="todo-item__checkbox" checked>
  <span class="todo-item__text">Купить продукты</span>
  <button type="button" class="todo-item__delete-btn">×</button>
</div>
```

### Главные возможности работы с DOM на вкладке Elements:

1. **Мгновенная правка текста и атрибутов:**
   * Двойной клик по названию тега, имени атрибута или значению позволяет изменить его «на лету».
   * Двойной клик по текстовому содержимому узла позволяет отредактировать текст без перезагрузки страницы.
2. **Редактирование узла как HTML (Edit as HTML):**
   * Нажмите `F2` или кликните правой кнопкой мыши $
ightarrow$ *Edit as HTML*. Позволяет вставить или переписать целую структуру тегов.
3. **Изменение структуры (Drag & Drop):**
   * Вы можете зажать узлы левой кнопкой мыши и перемещать их вверх/вниз по DOM-дереву, меняя их порядок в потоке.
4. **Удаление и скрытие узлов:**
   * Клавиша `Delete` или `Backspace` — полностью удаляет узел из DOM.
   * Клавиша `H` (Hide) — переключает временное свойство `visibility: hidden` для выбранного элемента.
5. **Принудительная фиксация псевдоклассов (Force State):**
   * Для отладки всплывающих меню, кнопок при наведении или фокусе нажмите кнопку **`:hov`** в правом верхнем углу вкладки стилей и отметьте нужный чекбокс:
     * `:hover` — состояние наведённого курсора.
     * `:focus` / `:focus-visible` — состояние фокуса клавиатуры.
     * `:active` — состояние зажатой кнопки мыши.
     * `:visited` — состояние посещённой ссылки.
6. **Точки останова в DOM (DOM Breakpoints):**
   * Клик правой кнопкой по узлу $
ightarrow$ *Break on*:
     * *Subtree modifications* — остановка исполнения JS при добавлении/удалении дочерних элементов.
     * *Attribute modifications* — остановка при изменении атрибутов (например, смене `class`).
     * *Node removal* — остановка при удалении самого элемента.

## Подглава 34.3.3: Вкладка Styles — каскад, перечёркнутые правила и специфичность

Подпанель **Styles** (справа от DOM-дерева) — главное место работы с CSS. Она показывает **все** CSS-правила, применимые к выбранному в DOM-дереве элементу.

```text
+-----------------------------------------------------------------------+
| STYLES (Инспекция каскада)                                            |
| element.style {                                                       |
|   color: red; /* Инлайновый стиль (Специфичность 1,0,0,0) */          |
| }                                                                     |
|                                                                       |
| .todo-item--completed .todo-item__text {  /* style.css:42 */          |
|   text-decoration: line-through;                                      |
|   color: #94a3b8;                                                     |
| }                                                                     |
|                                                                       |
| .todo-item__text {                         /* style.css:18 */          |
|   color: #1e293b;  <--- ПЕРЕЧЁРКНУТО (Переопределено более          |
|   font-size: 16px;       специфичным селектором)                      |
| }                                                                     |
|                                                                       |
| * {                                        /* user agent stylesheet */ |
|   box-sizing: border-box;                                             |
| }                                                                     |
+-----------------------------------------------------------------------+
```

### Как читать правила на вкладке Styles:

1. **Порядок каскада:** Правила расположены строго по приоритету **сверху вниз**. Самое приоритетное правило находится вверху (`element.style` или наиболее специфичный селектор).
2. **Перечёркнутые свойства (Strikethrough):**
   * Перечёркнутая строка означает, что данное свойство было **переопределено** другим правилом с более высокой специфичностью или расположенным ниже в каскаде.
3. **Недействительные правила (Invalid Properties):**
   * Жёлтый восклицательный знак рядом со свойством указывает на **синтаксическую ошибку** (ошибка в написании свойства или значения, например `colr: red`).
   * Неподдерживаемые текущим браузером свойства также помечаются как недействительные.
4. **Указание источника:** В правом углу каждого блока правил указано имя файла и номер строки (например, `main.css:104`). Клик по ней перенесет вас на вкладку *Sources*.
5. **Инлайн-стили (`element.style`):** Верхний блок позволяет временно добавить стили прямо в атрибут `style="..."` текущего элемента.

### Интерактивные визуальные инструменты панели Styles:

* 🎨 **Color Picker (Выбор цвета):** Клик по цветному квадратику возле значения цвета открывает палитру. Позволяет переключать форматы (HEX, RGB, HSL), выбирать цвет пипеткой с экрана и проверять **Contrast Ratio** (соответствие стандартам доступности WCAG AA/AAA).
* 📦 **Box-shadow / Text-shadow Editor:** Клик по иконке тени открывает визуальные ползунки для настройки смещения $X$, $Y$, размытия и цвета.
* 📈 **Cubic-bezier Editor:** Клик по иконке кривой анимации рядом с `transition-timing-function` позволяет настроить плавность анимации на интерактивном графике.

## Подглава 34.3.4: Вкладка Computed — диагностика Box Model и вычисленных значений

Если на вкладке *Styles* отображаются исходные написанные CSS-правила, то вкладка **Computed** показывает **итоговый физический результат**, который браузер применил к элементу.

```text
+-----------------------------------------------------------------------+
| COMPUTED & BOX MODEL PANEL                                            |
|                                                                       |
|               +---------------------------------------+               |
|               | MARGIN: 16px 0px 16px 0px             |               |
|               |   +-------------------------------+   |               |
|               |   | BORDER: 1px 1px 1px 1px       |   |               |
|               |   |   +-----------------------+   |   |               |
|               |   |   | PADDING: 12px 16px    |   |   |               |
|               |   |   |   +---------------+   |   |   |               |
|               |   |   |   | CONTENT       |   |   |   |               |
|               |   |   |   | 320px x 48px  |   |   |   |               |
|               |   |   |   +---------------+   |   |   |               |
|               |   |   +-----------------------+   |   |               |
|               |   +-------------------------------+   |               |
|               +---------------------------------------+               |
|                                                                       |
|  Filter: [ font-size                   ] [x] Group                    |
|  font-size: 16px ──────────────> (из .todo-item__text в style.css:18) |
|  width: 320px ─────────────────> (вычислено из parent flex-container) |
+-----------------------------------------------------------------------+
```

### Зачем нужна вкладка Computed?

1. **Инспекция интерактивной схемы Box Model:**
   * В верхней части вкладки отображается наглядная диаграмма прямоугольника элемента с точными пиксельными размерами **Content**, **Padding**, **Border** и **Margin**.
2. **Перевод относительных единиц в пиксели:**
   * Если в CSS написано `font-size: 1.25rem` или `width: 50%`, вкладка Computed покажет точное значение в пикселях (например, `20px` и `360px`).
3. **Поиск источника итогового значения:**
   * Раскрывающийся список возле любого свойства показывает, какое конкретно CSS-правило выграло в каскаде и установило это значение. Клик по стрелочке мгновенно переносит к правилу на вкладку *Styles*.
4. **Фильтрация свойств:**
   * Поле поиска *Filter* позволяет мгновенно проверить конкретные свойства (например, ввести `z-index`, `opacity` или `display`).

## Подглава 34.3.5: Вкладка Layout — визуализация Flexbox и CSS Grid

Современная раскладка на **Flexbox** и **CSS Grid** требует визуального контроля осей, направлений и границ сетки. DevTools предоставляет подпанель **Layout** на вкладке Elements.

```text
+-----------------------------------------------------------------------+
| LAYOUT PANEL (Инспекция Flex & Grid)                                 |
|                                                                       |
|  Grid Overlays:                                                       |
|  [x] .todo-grid (2 columns, 3 rows) ── Color: [ Blue  ]               |
|  Grid Settings:                                                       |
|  (o) Show line numbers  ( ) Show line names  [*] Show track sizes     |
|                                                                       |
|  Flexbox Overlays:                                                    |
|  [x] .todo-header (flex row) ───────── Color: [ Purple]               |
+-----------------------------------------------------------------------+
```

### Инструменты отладки CSS Grid:

1. **Маркер `grid` в DOM-дереве:** Элементы с `display: grid` помечаются специальной кнопкой-значком `grid`. Клик по ней включает полупрозрачное наложение сетки прямо поверх страницы.
2. **Отображение номеров и имён линий:** На панели Layout можно включить:
   * Номера треков и линий (Line numbers).
   * Имена областей (`grid-template-areas`).
   * Размеры треков (`Show track sizes`).
3. **Цветовая дифференциация:** Можно задать индивидуальный цвет подсвечиваемой сетки для каждого контейнера.

### Инструменты отладки Flexbox:

1. **Маркер `flex` в DOM-дереве:** Элементы с `display: flex` или `inline-flex` помечаются иконкой `flex`.
2. **Визуальный редактор Flexbox (Flex Editor):** На вкладке *Styles* рядом с правилом `display: flex` появляется иконка с кнопками быстрых переключателей:
   * `flex-direction` (row / column).
   * `justify-content` (flex-start / center / space-between / space-around).
   * `align-items` (stretch / center / flex-start / flex-end).
   * Мгновенный визуальный эксперимент без ручного ввода свойств!

## Подглава 34.3.6: Device Toolbar — эмуляция мобильных устройств и адаптивности

Переключение в режим **Device Toolbar** осуществляется комбинацией **`Ctrl + Shift + M`** (`Cmd + Shift + M`) или кликом по иконке смартфона/планшета в левом верхнем углу DevTools.

```text
+-----------------------------------------------------------------------+
| DEVICE TOOLBAR                                                        |
| [Dimensions: Responsive v] [375 x 667 px] [100% v] [Throttling: Fast 3G] |
+-----------------------------------------------------------------------+
|  +-----------------------------------+                                |
|  |  [<- Эмуляция экрана iPhone ->]   |                                |
|  |                                   |                                |
|  |  • Курсор мыши превращается       |                                |
|  |    в серо-круглый тач-указатель    |                                |
|  |  • Проверка медиазапросов         |                                |
|  |    @media (min-width / max-width) |                                |
|  |                                   |                                |
|  +-----------------------------------+                                |
+-----------------------------------------------------------------------+
```

### Главные функции режима Device Toolbar:

1. **Выбор профилей устройств (Presets):**
   * Предустановленные профили: *iPhone 12/14 Pro*, *Pixel 7*, *iPad Air*, *Samsung Galaxy*, *4K Display*.
2. **Режим свободной трансформации (Responsive):**
   * Позволяет плавно растягивать и сжимать окно мышью за боковые маркеры для поиска некрасивых переломов верстки (Breakpoints).
3. **Эмуляция поворота экрана (Rotate Screen):**
   * Иконка поворота переключает ориентацию между альбомной (Landscape) и портретной (Portrait).
4. **Эмуляция сенсорного ввода (Touch Cursor):**
   * Курсор мыши превращается в серый круг, имитируя нажатия пальцем на тачскрине.
5. **Ограничение скорости сети (Network Throttling):**
   * Переключатель скорости позволят проверить поведение страницы при слабом интернет-соединении:
     * **No throttling** — максимальная скорость хоста.
     * **Fast 3G** — эмуляция хорошего мобильного 3G (задержка 56ms, 1.5 Mbps).
     * **Slow 3G** — эмуляция плохого мобильного интернета (задержка 400ms, 400 Kbps).
     * **Offline** — проверка работы сайта при полном отсутствии сети (PWA / Service Workers).

## Подглава 34.3.7: Экспресс-обзор вкладок Console и Network

Хотя глубокая отладка JavaScript изучается в следующих блоках курса, базовые знания вкладок **Console** и **Network** необходимы верстальщику уже сейчас.

```text
+-----------------------------------------------------------------------+
| CONSOLE PANEL                                                         |
| > $0  <--- Ссылка на выбранный DOM-элемент                            |
| < <div class="todo-item">...</div>                                    |
| > $0.style.backgroundColor = 'yellow'                                 |
| > $('.todo-item')  <--- Аналог document.querySelector()               |
| ❌ [GET http://example.com/logo.png 404 (Not Found)]                  |
+-----------------------------------------------------------------------+
| NETWORK PANEL                                                         |
| [x] Disable cache  |  Throttling: [ No throttling v ]                |
| Name           | Status | Type | Size   | Time  | Waterfall           |
| index.html     | 200    | doc  | 2.4 KB | 12ms  | ▇                   |
| style.css      | 200    | css  | 8.1 KB | 18ms  |  ▇                  |
| main.js        | 304    | js   | 4.2 KB | 5ms   |   ▇                 |
| avatar.png     | 404    | png  | 182 B  | 45ms  |    █                |
+-----------------------------------------------------------------------+
```

### 1. Вкладка Console (Консоль):
* **Критические ошибки верстки:** Отображает ошибки загрузки ресурсов (например, картинка или файл стилей вернули `404 Not Found`).
* **Консольный указатель `$0`:** Волшебная переменная `$0` хранит ссылку на узел, который выбран прямо сейчас во вкладке *Elements*. Введя `$0` в консоли, вы получаете к нему полный доступ.
* **Сокращения `$()` и `$$()`:**
  * `$('selector')` — сокращение для `document.querySelector('selector')`.
  * `$$('selector')` — сокращение для `document.querySelectorAll('selector')`.

### 2. Вкладка Network (Сеть):
* **Фильтрация ресурсов:** Фильтры *Doc*, *CSS*, *JS*, *Img*, *Media*, *Fetch/XHR* позволяют легко найти нужный загруженный файл.
* **Отключение кэширования (Disable cache):** Чекбокс *Disable cache* гарантирует, что браузер будет загружать свежую версию CSS/JS при каждом обновлении страницы (пока открыта панель DevTools).
* **Проверка статусов ответа сервера:**
  * `200 OK` — файл успешно загружен.
  * `304 Not Modified` — файл получен из браузерного кэша.
  * `404 Not Found` — файл не найден по указанному пути в HTML/CSS.

## Подглава 34.3.8: Пошаговый практикум — Поиск и исправление 5 багов в «сломанной» верстке

Рассмотрим реальный кейс: верстальщик получил учебную страницу с 5 характерными ошибками. Научимся находить и исправлять их с помощью DevTools.

### Дан сломанный кодовый фрагмент:

```html
<!-- index.html -->
<!DOCTYPE html>
<html>
<head>
  <title>Сломанная страница</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <header class="header">
    <h1 class="header__title">Портал верстки</h1>
    <button class="header__btn">Войти</button>
  </header>

  <main class="content">
    <div class="card-grid">
      <div class="card">Карточка 1</div>
      <div class="card">Карточка 2</div>
      <div class="card">Карточка 3</div>
    </div>
  </main>
</body>
</html>
```

### Пошаговый алгоритм отладки через DevTools:

#### 🐛 Баг 1: На мобильных устройствах страница показывается мелким шрифтом, сжата и есть горизонтальный скролл.
* **Диагностика в DevTools:** Нажмите `Ctrl + Shift + M` (Device Toolbar). Выберите iPhone 12. Страница выглядит как десктопный сайт в микромасштабе.
* **Причина:** В `<head>` отсутствует обязательный метатег Viewport.
* **Исправление:** Добавляем в `<head>`:
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  ```

#### 🐛 Баг 2: Заголовок `.header__title` остаётся белым и не окрашивается в голубой цвет `#38bdf8`.
* **Диагностика в DevTools:** Нажимаем `Ctrl + Shift + C`, кликаем по заголовку. В панели *Styles* правило `#header__title` вообще не отображается!
* **Причина:** В CSS использован ID-селектор `#header__title`, а в HTML задан класс `class="header__title"`.
* **Исправление:** Меняем `#header__title` на `.header__title` в CSS.

#### 🐛 Баг 3: Кнопка «Войти» не нажимается и не реагирует на курсор.
* **Диагностика в DevTools:** Инспектируем кнопку `.header__btn`. На вкладке *Styles* видим перечёркнутый курсор и свойство `pointer-events: none`.
* **Причина:** Свойство `pointer-events: none` отключает реакцию на клики мыши.
* **Исправление:** Удаляем свойство `pointer-events: none` на вкладке *Styles* прямо в браузере и проверяем кликабельность.

#### 🐛 Баг 4: Три карточки `.card` выходят за пределы экрана и не помещаются в одну строку.
* **Диагностика в DevTools:** Выделяем `.card` и переходим на вкладку **Computed**. Видим, что ширина контента $33.333\%$ суммируется с `padding: 30px` и `border: 5px`, из-за чего итоговая ширина каждой карточки становится больше $33.333\%$.
* **Причина:** Установлен устаревший режим `box-sizing: content-box`.
* **Исправление:** Меняем в *Styles* на `box-sizing: border-box`.

#### 🐛 Баг 5: При узком экране карточки сжимаются в микро-колонки вместо переноса на новые строки.
* **Диагностика в DevTools:** Выделяем контейнер `.card-grid` и нажимаем иконку **Flex Editor** рядом с `display: flex`.
* **Причина:** По умолчанию `flex-wrap: nowrap`.
* **Исправление:** Нажимаем кнопку `flex-wrap: wrap` в редакторе Flexbox или добавляем `flex-wrap: wrap` в CSS.

## Подсказки и решения к практическим задачам

### Решение Задачи 1:
1. **Спецификатор селекторов:**
   * `main a` — Specificity `(0, 0, 0, 2)` (2 тега).
   * `.nav-link` — Specificity `(0, 0, 1, 0)` (1 класс).
   * `#hero-link` — Specificity `(0, 1, 0, 0)` (1 ID).
   * `.btn.btn--primary` — Specificity `(0, 0, 2, 0)` + **`!important`**.
2. **Итоговый цвет:** **Blue (Синий)**. Модификатор `!important` побеждает любые ID и обычные селекторы.
3. **Перечёркнутые правила:** Правила `color: black`, `color: green` и `color: red` будут перечёркнуты в панели *Styles*.

### Решение Задачи 2:
1. Итоговая вычисленная ширина без `border-box`:
   $$	ext{Width} = 300	ext{px} + (20	ext{px} 	imes 2) + (2	ext{px} 	imes 2) = 344	ext{px}$$
2. Диаграмма Box Model покажет `344px` по ширине.
3. Для фиксации размера нужно добавить свойство `box-sizing: border-box;`.

### Решение Задачи 3:
1. Выделите узел кнопки в Elements.
2. В подпанели Styles нажмите **`:hov`** и поставьте галочку напротив **`:focus-visible`**.
