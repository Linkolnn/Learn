## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. Динамическая типизация (Dynamic Typing)**
> * **Что это:** Свойство языка, при котором тип связан со *значением*, а не с *переменной*. Переменная в JS может сначала хранить число, а затем быть переназначена на строку или объект.

> 📌 **2. Примитивные типы данных (Primitives)**
> * **Что это:** Неизменяемые (immutable) базовые значения. Они **ведут себя как значения**: при присваивании и передаче в функцию копируется само значение. Где именно движок физически хранит значение (в стеке, регистре или в куче — например, длинные строки обычно в куче), — деталь реализации. В JS существует 7 примитивов: `number`, `string`, `boolean`, `null`, `undefined`, `bigint`, `symbol`.

> 📌 **3. Ссылочный тип данных (Reference Type / Object)**
> * **Что это:** Единственный не-примитивный тип данных в JS (`object`). Объекты хранятся в куче (Heap), а переменная содержит только ссылку на объект.

> 📌 **4. Оператор `typeof`**
> * **Что это:** Унарный оператор, возвращающий строку с названием типа операнда: `"number"`, `"string"`, `"boolean"`, `"undefined"`, `"object"`, `"function"`, `"symbol"`, `"bigint"`.

> 📌 **5. Безопасный целочисленный диапазон (Safe Integer Range)**
> * **Что это:** Диапазон целых чисел ±(2⁵³ − 1), то есть ±9 007 199 254 740 991. В нём каждое целое число типа `number` (IEEE-754, двойная точность) представляется однозначно, и вычисления с целыми остаются точными. За его пределами часть целых чисел «склеивается» с соседними.

> 📌 **6. `BigInt`**
> * **Что это:** Примитив для целых чисел произвольной длины (введён в ES2020). Записывается с суффиксом `n` (например, `100n`).

> 📌 **7. `Symbol`**
> * **Что это:** Примитив для создания уникальных идентификаторов. Каждый вызов `Symbol("id")` создаёт новый, ни с чем не равный символ: `Symbol("id") !== Symbol("id")`. (Исключение — символы из глобального реестра `Symbol.for`.)

## Подглава 38.1: Динамическая типизация и 8 типов данных в JS

JavaScript — **динамически типизированный** язык со **слабой (неявной) типизацией**:
1. **Динамическая:** тип проверяется во время выполнения кода (runtime), а не заранее.
2. **Слабая:** JS при необходимости автоматически приводит типы (Coercion, Лекция 39), например `"5" - 2 === 3`.

```javascript
let data = 42;         // data хранит number
data = "Hello World";  // теперь data хранит string
data = { age: 25 };    // теперь data хранит ссылку на object
```

### Сводная таблица 8 типов данных в JavaScript

В спецификации ECMAScript определено **8 типов данных**:

| № | Тип данных | Категория | Пример значения | Что копируется при присваивании |
|---|---|---|---|---|
| 1 | **`number`** | Примитив | `42`, `3.14`, `NaN`, `Infinity` | Значение |
| 2 | **`string`** | Примитив | `"hello"`, `'world'`, `` `text` `` | Значение |
| 3 | **`boolean`** | Примитив | `true`, `false` | Значение |
| 4 | **`null`** | Примитив | `null` | Значение |
| 5 | **`undefined`** | Примитив | `undefined` | Значение |
| 6 | **`bigint`** | Примитив | `9007199254740992n` | Значение |
| 7 | **`symbol`** | Примитив | `Symbol("id")` | Значение |
| 8 | **`object`** | **Ссылочный** | `{ name: "John" }`, `[1, 2]`, `new Date()` | **Ссылка** на объект |

> ℹ️ Формально в JS **всё передаётся по значению**; просто для объектов этим значением является ссылка. Поэтому две переменные могут указывать на один и тот же объект (Лекция 49).

> ⚠️ **Важное замечание про функции и массивы:**
> С точки зрения спецификации массивы (`Array`), даты (`Date`), ошибки (`Error`) и функции (`Function`) **не являются отдельными типами данных**. Все они относятся к типу **`object`**. Функции — это *callable objects* (объекты, которые можно вызвать: у них есть внутренний метод `[[Call]]`).

### Краткий обзор `number`, `string` и `boolean`

```javascript
// number — один тип и для целых, и для дробных чисел
let price = 19.99;
let count = 5;
console.log(1 / 0);           // Infinity (деление на ноль не ломает программу)
console.log("abc" * 2);       // NaN (Not a Number — «не число», результат неверной операции)
console.log(typeof NaN);      // "number" (NaN сам относится к типу number!)
console.log(NaN === NaN);     // false (NaN не равен даже самому себе)

// string — текст в одинарных, двойных или обратных кавычках
let s1 = 'одинарные';
let s2 = "двойные";
let name = "Анна";
let s3 = `Привет, ${name}!`;  // обратные кавычки: подстановка ${...} и многострочный текст
// Строки неизменяемы: s2[0] = "Х" ничего не меняет, новую строку нужно создавать заново

// boolean — логическое значение: только true или false
let isActive = true;
```
Подробнее: числа и точность — Лекция 54, строки — Лекция 55.

## Подглава 38.2: Оператор `typeof` и его исторические аномалии

Оператор `typeof` возвращает строку с названием типа значения. У него две формы записи:
* `typeof x` (оператор)
* `typeof(x)` (то же самое, скобки просто группируют выражение — это не вызов функции)

```javascript
typeof undefined           // "undefined"
typeof 0                   // "number"
typeof NaN                 // "number" (!)
typeof 10n                 // "bigint"
typeof true                // "boolean"
typeof "foo"               // "string"
typeof Symbol("id")        // "symbol"
typeof { name: "Alice" }   // "object"
typeof [1, 2, 3]           // "object" (массивы — это объекты!)
typeof notDeclaredAnywhere // "undefined" (для необъявленной переменной typeof НЕ выбрасывает ошибку)
```

### 🚨 Две главные исторические аномалии `typeof`

#### 1. `typeof null === "object"` (ошибка первой версии языка)
В первой реализации JavaScript (1995 г.) значение хранилось как «тег типа» + данные. Тег объектов состоял из нулевых битов, а `null` представлялся нулевым указателем (`0x00`, как `NULL` в Си), то есть тоже целиком из нулей. Поэтому `typeof` принимал `null` за объект.

Позднее было предложение исправить это (чтобы `typeof null` возвращал `"null"`), но его отклонили: исправление сломало бы огромное количество существующего кода в вебе. Поэтому ошибка осталась навсегда.

#### 2. `typeof` возвращает `"function"` для функций
Хотя отдельного типа «функция» в спецификации нет (это объекты), `typeof` возвращает `"function"` для любого объекта, который можно вызвать (в том числе для классов), — это сделано для удобства.

```javascript
console.log(typeof null);         // "object" (хотя null — примитив!)
console.log(typeof function(){}); // "function" (особый случай для вызываемых объектов)
```

## Подглава 38.3: Особенности `null` и `undefined`

Оба типа содержат ровно по одному значению: `null` и `undefined`.

### Сравнительный анализ `null` vs `undefined`

```text
  +-------------------------------------------------------------------------+
  |                              СМЫСЛОВОЙ РАЗДЕЛ                            |
  +-------------------------------------+-----------------------------------+
  |               null                  |             undefined             |
  +-------------------------------------+-----------------------------------+
  | Явное "НИЧЕГО", пустота, намеренно  | Значение НЕ НАЗНАЧЕНО /           |
  | обнулённая ссылка или результат.    | отсутствует.                      |
  | Присваивается разработчиком.        | Появляется само (движок).         |
  +-------------------------------------+-----------------------------------+
```

### Где возникает `undefined`:
1. Объявление переменной без значения: `let x; // undefined`.
2. Чтение несуществующего свойства объекта: `user.age // undefined`, если у `user` нет свойства `age`.
3. Чтение элемента массива за пределами индексов: `[1, 2][10] // undefined`.
4. Функция без явного `return`: `function f(){}  f(); // undefined`.
5. Пропущенные аргументы функции: `function g(a, b){ console.log(b); }  g(1); // undefined`.

### Правила сравнений `null` и `undefined`

```javascript
// 1. Строгое сравнение (без приведения типов):
console.log(null === undefined); // false (разные типы: Null и Undefined)

// 2. Нестрогое сравнение:
console.log(null == undefined);  // true (особое правило: они равны только друг другу)
console.log(null == 0);          // false (для null и undefined оператор == не приводит их к числу)
console.log(null == false);      // false

// 3. Операторы сравнения <, >, <=, >= приводят операнды к числам:
//    null превращается в 0, а undefined — в NaN
console.log(null > 0);           // false (0 > 0)
console.log(null >= 0);          // true  (0 >= 0)
console.log(undefined > 0);      // false (NaN > 0)
console.log(undefined < 0);      // false (NaN < 0)
console.log(undefined >= 0);     // false (NaN >= 0)
```
> ⚠️ Классическая ловушка: `null >= 0` равно `true`, но при этом `null > 0` и `null == 0` равны `false`. Причина в том, что `>=` приводит `null` к числу, а `==` для `null` работает по особому правилу. Подробнее — в Лекциях 39 и 41.

## Подглава 38.4: Глубокий разбор `BigInt` (числа произвольной длины)

### Проблема IEEE-754 в типе `number`
Обычные числа в JS хранятся в формате **IEEE-754 Double Precision (64 бита)**:
* 1 бит — знак
* 11 бит — экспонента
* 52 бита — мантисса (дробная часть)

Благодаря неявной единице перед мантиссой точность составляет **53 бита**, поэтому наибольшее целое число, до которого все целые представимы без пропусков, — **2⁵³ − 1**:
`Number.MAX_SAFE_INTEGER = 9007199254740991` (около 9 квадриллионов).

Дальше начинается потеря точности:
```javascript
console.log(9007199254740991 + 1); // 9007199254740992
console.log(9007199254740991 + 2); // 9007199254740992 (!) — число ...993 не представимо, результат округлён
```

### Появление `BigInt`
Тип `BigInt` позволяет работать с целыми числами **любой длины** (практически ограничено лишь памятью и лимитами движка).

#### Создание `BigInt`:
1. Суффикс `n` в конце литерала: `const big = 12345678901234567890n;`
2. Конструктор `BigInt()`: `const big2 = BigInt("12345678901234567890");`
   (`BigInt(1.5)` даст `RangeError`, `BigInt("1.5")` — `SyntaxError`: дробные значения не допускаются.)

#### Правила и ограничения `BigInt`:
1. **Нельзя смешивать `BigInt` и `Number`** в арифметике без явного приведения.
2. **Деление целочисленное:** дробная часть отбрасывается (в сторону нуля: `-7n / 2n === -3n`).
3. **Унарный плюс запрещён:** `+10n` вызывает `TypeError` (унарный минус `-10n` допустим).
4. **Функции `Math` не работают с `BigInt`:** `Math.max(1n, 2n)` вызовет `TypeError`.
5. **`JSON.stringify` не умеет сериализовать `BigInt`:** `JSON.stringify({ id: 1n })` вызовет `TypeError: Do not know how to serialize a BigInt` (нужно сначала преобразовать в строку).

```javascript
const a = 10n;
const b = 3n;

console.log(a + b);       // 13n
console.log(a / b);       // 3n (дробная часть .333... отброшена!)

// console.log(a + 5);    // TypeError: Cannot mix BigInt and other types
console.log(a + BigInt(5)); // 15n

// Сравнения между разными типами работают:
console.log(2n > 1);      // true
console.log(1n == 1);     // true  (нестрогое сравнение)
console.log(1n === 1);    // false (разные типы)
```

## Подглава 38.5: Глубокий разбор `Symbol` (уникальные идентификаторы)

`Symbol` — примитив, значения которого **уникальны**.

```javascript
const sym1 = Symbol("description");
const sym2 = Symbol("description");

console.log(sym1 === sym2); // false! Символы уникальны, несмотря на одинаковое описание.
```
Описание (`"description"`) нужно только для отладки. Символы нельзя неявно превратить в строку (`"" + sym1` вызовет `TypeError`); используйте `String(sym1)` или `sym1.toString()`. Вызывать `new Symbol()` нельзя.

### Зачем нужны символы?

#### 1. Скрытые свойства объектов
Ключами свойств объектов могут быть только **строки** или **символы**. Свойства с символьными ключами:
* не попадают в цикл `for..in`;
* пропускаются в `Object.keys()`, `Object.values()` и `JSON.stringify()`;
* доступны через `Object.getOwnPropertySymbols(obj)` или `Reflect.ownKeys(obj)`.

```javascript
const idSymbol = Symbol("id");

const user = {
  name: "John",
  [idSymbol]: "SECRET_12345" // символ как ключ (в квадратных скобках)
};

for (let key in user) {
  console.log(key); // выведет только "name"
}

console.log(JSON.stringify(user)); // {"name":"John"} (символ скрыт от сериализации!)
console.log(user[idSymbol]);       // "SECRET_12345" (прямой доступ по символу)
```
> ⚠️ Символьные свойства «скрыты» от обычного перебора, но это **не приватность**: их можно получить через `Object.getOwnPropertySymbols`. Копирование объекта через `Object.assign` и spread (`{ ...user }`) символьные свойства **тоже копирует**. Для настоящих приватных полей используется `#private` (Лекция 83).

#### 2. Глобальный реестр символов (`Symbol.for` и `Symbol.keyFor`)
Если один и тот же символ нужен в разных частях приложения:
* `Symbol.for(key)` — ищет символ с ключом `key` в глобальном реестре, а если его нет — создаёт.
* `Symbol.keyFor(sym)` — возвращает ключ символа из реестра (для обычных символов вернёт `undefined`).

```javascript
const globalSym1 = Symbol.for("app.userId");
const globalSym2 = Symbol.for("app.userId");

console.log(globalSym1 === globalSym2); // true! Это один и тот же символ из реестра.
console.log(Symbol.keyFor(globalSym1));  // "app.userId"
```

#### 3. Системные символы (Well-Known Symbols)
Встроенные символы, позволяющие переопределять стандартное поведение объектов:
* **`Symbol.iterator`** — делает объект итерируемым для цикла `for..of` (Лекция 59).
* **`Symbol.toPrimitive`** — собственное правило превращения объекта в примитив (Лекция 53).
* **`Symbol.toStringTag`** — меняет результат `Object.prototype.toString.call(obj)`.

```javascript
const customUser = {
  name: "Alice",
  money: 500,

  [Symbol.toPrimitive](hint) {
    if (hint === "number") return this.money;
    if (hint === "string") return `User ${this.name}`;
    return this.money;
  }
};

console.log(+customUser);       // 500 (hint: number)
console.log(`${customUser}`);   // "User Alice" (hint: string)
console.log(customUser + 100);  // 600 (hint: default)
```

```javascript
function strictTypeOf(value) {
  if (value === null) return "null";
  if (Number.isNaN(value)) return "nan";
  if (Array.isArray(value)) return "array";

  // Для остальных значений берём «класс» из Object.prototype.toString:
  // строка имеет вид "[object ClassName]", отрезаем "[object " (8 символов) и "]"
  const rawType = Object.prototype.toString.call(value);
  return rawType.slice(8, -1).toLowerCase();
}

// Проверки:
console.log(strictTypeOf(null));           // "null"
console.log(strictTypeOf(NaN));            // "nan"
console.log(strictTypeOf([1, 2]));         // "array"
console.log(strictTypeOf(new Date()));     // "date"
console.log(strictTypeOf(/abc/));          // "regexp"
console.log(strictTypeOf(100n));           // "bigint"
console.log(strictTypeOf(Symbol("x")));    // "symbol"
console.log(strictTypeOf(() => {}));       // "function"
console.log(strictTypeOf({}));             // "object"
```
Обратите внимание: у асинхронных функций «класс» будет `"asyncfunction"`, а не `"function"`; если нужно, добавьте проверку `typeof value === "function"` перед последней строкой.

function sumToBigInt(arr) {
  return arr.reduce((acc, item) => {
    if (typeof item === "bigint") {
      return acc + item;
    }
    if (typeof item === "number" && Number.isInteger(item)) {
      return acc + BigInt(item);
    }
    // Строка из одних цифр (необязательный минус). /^-?\d+$/ — регулярное выражение, подробнее позже
    if (typeof item === "string" && /^-?\d+$/.test(item)) {
      return acc + BigInt(item);
    }
    return acc; // дробные числа и прочее игнорируем
  }, 0n);
}

console.log(sumToBigInt([10n, 20, "100", 50n, 5.5])); // 180n

const counter = {
  from: 1,
  to: 5,

  // 1. Итератор для for..of (запись *[...] — генератор, подробнее в Лекции 95)
  *[Symbol.iterator]() {
    for (let current = this.from; current <= this.to; current++) {
      yield current;
    }
  },

  // 2. Преобразование в примитив
  [Symbol.toPrimitive](hint) {
    // Вычисляем сумму диапазона
    let sum = 0;
    for (let i = this.from; i <= this.to; i++) sum += i;

    if (hint === "string") return `Counter (${this.from}..${this.to})`;
    return sum; // для "number" и "default"
  }
};

  console.log(num); // 1, 2, 3, 4, 5
}

console.log(counter + 10);  // (1+2+3+4+5) + 10 = 15 + 10 = 25
console.log(`${counter}`);  // "Counter (1..5)"

<summary>👉 Решение Задачи 6 (`parseJSONWithBigInt`)</summary>

```javascript
function parseJSONWithBigInt(jsonString) {
  const MAX = BigInt(Number.MAX_SAFE_INTEGER);

  // Ищем целые числа из 16 и более цифр, стоящие как значение
  // (после ":", "[" или ","), за которыми не следует дробная часть или экспонента
  const regex = /([:\[,]\s*)(-?\d{16,})(?![\d.eE])/g;

  // Оборачиваем в строку с префиксом ТОЛЬКО те числа, которые выходят за безопасный диапазон
  const safeJson = jsonString.replace(regex, (match, prefix, num) => {
    const big = BigInt(num);
    return big > MAX || big < -MAX ? `${prefix}"_bigint_${num}"` : match;
  });

  return JSON.parse(safeJson, (key, value) => {
    if (typeof value === "string" && value.startsWith("_bigint_")) {
      return BigInt(value.slice(8));
    }
    return value;
  });
}

const rawJSON = '{"id": 9007199254740993123, "count": 1000000000000000, "name": "Test"}';
const parsed = parseJSONWithBigInt(rawJSON);

console.log(typeof parsed.id);     // "bigint"
console.log(parsed.id.toString()); // "9007199254740993123"
console.log(typeof parsed.count);  // "number" (число в безопасном диапазоне остаётся number)
```
**Ограничения этого упрощённого решения:** оно не учитывает числа внутри строк (например, `"note": "x: 12345678901234567890"`) и может испортить строку с таким содержимым; префикс `"_bigint_"` в обычной строке будет принят за маркер. В современных движках для надёжного решения используется третий аргумент функции-ревайвера `JSON.parse` — `context.source` (проверяйте поддержку в вашей версии браузера/Node.js). Обратите внимание и на обратную сторону: `JSON.stringify` не умеет сериализовать `BigInt` (`TypeError`), поэтому при отправке данных его приходится преобразовывать в строку.
