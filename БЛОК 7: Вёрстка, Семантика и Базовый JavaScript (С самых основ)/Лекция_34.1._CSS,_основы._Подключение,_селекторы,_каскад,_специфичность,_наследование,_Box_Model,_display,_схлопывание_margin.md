## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. CSS (Cascading Style Sheets — «каскадные таблицы стилей»)**
> * **Что это:** Язык стилей, с помощью которого описывают, **как выглядит** веб-страница: цвета, шрифты, размеры, отступы, расположение блоков. HTML отвечает за структуру и смысл содержимого (заголовок, абзац, кнопка), а CSS — за его внешний вид. Это не язык программирования, а **декларативный** язык: вы описываете желаемый результат, а браузер сам решает, как его нарисовать.
> * **Как выглядит:** CSS состоит из правил вида `селектор { свойство: значение; }`. Селектор указывает, к каким элементам применить стили, а в фигурных скобках перечислены нужные свойства: `h1 { color: blue; }`.
> * **Почему «каскадные»:** если к одному элементу подходит сразу несколько правил, браузер по строгим правилам (каскад, см. термин 2) выбирает, какое из них победит.

> 📌 **2. Каскад (Cascading)**
> * **Что это:** Алгоритм разрешения конфликтов, определяющий, какое из нескольких конкурирующих CSS-правил будет применено к элементу. Каскад учитывает источник правила, специфичность селектора и порядок объявления в коде.

> 📌 **3. Специфичность (Specificity)**
> * **Что это:** Весовой коэффициент CSS-селектора, рассчитываемый по формуле `(Inline, ID, Class/Attribute/Pseudo-class, Element/Pseudo-element)`. Чем выше вес селектора, тем выше его приоритет над конкурирующими правилами.

> 📌 **4. Наследование (Inheritance)**
> * **Что это:** Механизм, при котором дочерние элементы автоматически перенимают значения некоторых CSS-свойств от своих родительских элементов (например, `color`, `font-family`, `line-height`).

> 📌 **5. Блочная модель CSS (Box Model)**
> * **Что это:** Модель прямоугольного контейнера, представляющая любой HTML-элемент на странице в виде четырех вложенных областей: содержимого (`content`), внутренних отступов (`padding`), рамки (`border`) и внешних отступов (`margin`).

> 📌 **6. Режим `box-sizing: border-box`**
> * **Что это:** Способ расчёта размеров блока, при котором свойства `width` и `height` задают суммарный физический размер элемента, включая `padding` и `border`. Широко принятая практика современной вёрстки.

> 📌 **7. Схлопывание отступов (Margin Collapse)**
> * **Что это:** Поведение блочных элементов в нормальном потоке документа, при котором вертикальные внешние отступы (`margin-top` и `margin-bottom`) соседних или вложенных блоков объединяются в один отступ, равный максимальному из них.

> 📌 **8. Нормальный поток (Normal Flow)**
> * **Что это:** Способ размещения элементов на странице, который браузер использует **по умолчанию**, пока вы не применили приёмы, меняющие расположение блоков: `float`, `position: absolute` / `fixed`, `display: flex` / `grid`. Элементы идут в том порядке, в котором записаны в HTML: **блочные** (`<div>`, `<p>`, `<h1>`) выстраиваются сверху вниз, каждый с новой строки; **строчные** (`<span>`, `<a>`) — слева направо внутри строки и переносятся на следующую строку, когда не хватает места.

> 📌 **9. BFC (Block Formatting Context)**
> * **Что это:** Изолированная область страницы, внутри которой блоки размещаются по своим правилам и не «склеиваются» по `margin` с внешним миром. BFC создают, например, `overflow: hidden` (и любой `overflow`, кроме `visible`), `display: flow-root`, `float`, `inline-block` и абсолютное позиционирование. Контейнеры `flex` и `grid` создают собственные форматирующие контексты (flex/grid), и `margin` их детей тоже не схлопывается с внешним миром.

> 📌 **10. User Agent Stylesheet (стили браузера по умолчанию)**
> * **Что это:** Встроенная таблица стилей самого браузера: именно из неё берутся крупный шрифт у `<h1>`, отступ 8px у `<body>`, маркеры и отступ слева у `<ul>`. Значения немного различаются между браузерами. Ваши стили (стили автора) побеждают её независимо от специфичности.

> 📌 **11. Сброс стилей (CSS Reset)**
> * **Что это:** Небольшой блок CSS в самом начале файла стилей, который обнуляет или выравнивает стили браузера по умолчанию (отступы, `box-sizing` и т. п.), чтобы вёрстка начиналась с предсказуемого «нуля». Подробно — в подглаве 34.1.4.

> 📌 **12. Псевдокласс (Pseudo-class)**
> * **Что это:** Ключевое слово с одним двоеточием (`:hover`, `:first-child`), которое выбирает существующий элемент в определённом состоянии или позиции. Вес — как у класса. Подробно — в подглаве 34.1.2.

> 📌 **13. Псевдоэлемент (Pseudo-element)**
> * **Что это:** Ключевое слово с двумя двоеточиями (`::before`, `::placeholder`), которое выбирает виртуальную часть элемента, не записанную в HTML. Вес — как у тега. Подробно — в подглаве 34.1.2.

> 📌 **14. Функция `clamp(МИН, ЖЕЛАЕМОЕ, МАКС)`**
> * **Что это:** CSS-функция, которая берёт «желаемое» значение, но не позволяет ему стать меньше минимума или больше максимума. Чаще всего используется для плавно меняющегося размера шрифта без медиазапросов. Подробно — в подглаве 34.1.3.

## Подглава 34.1.1: Способы подключения CSS к HTML-документу

Существует 3 основных способа связывания стилей CSS с разметкой HTML:

```text
+-----------------------------------------------------------------------+
| 1. Внешняя таблица стилей (Рекомендуемый стандарт)                    |
|    <link rel="stylesheet" href="style.css">                           |
+-----------------------------------------------------------------------+
| 2. Внутренние стили в документе (Тег <style> в <head>)                |
|    <style> h1 { color: blue; } </style>                               |
+-----------------------------------------------------------------------+
| 3. Инлайновые стили в атрибуте (Антипаттерн в продакшене!)            |
|    <h1 style="color: blue;">Заголовок</h1>                            |
+-----------------------------------------------------------------------+
```

> ℹ️ Есть ещё директива `@import` внутри самого CSS-файла (`@import url("other.css");`). Использовать её не рекомендуется: браузер узнаёт о втором файле только после загрузки первого, и загрузка замедляется. Подключайте несколько файлов отдельными `<link>`.

### 1. Внешний файл стилей (`<link rel="stylesheet">`)
Самый чистый и промышленный подход. Стили хранятся в отдельном файле с расширением `.css`, который подключается в секции `<head>` HTML-документа:
```html
<head>
  <meta charset="UTF-8">
  <link rel="stylesheet" href="css/style.css">
</head>
```
* **Плюсы:** Разделение ответственности (Separation of Concerns), возможность кэширования файла браузером, использование одного файла на тысячах страниц.

> ℹ️ Браузер не рисует страницу, пока не загрузит и не разберёт CSS из `<link>` (стили «блокируют отрисовку»), поэтому `<link>` размещают в `<head>`. Почему так устроено, разберём в Лекции 35 (CSSOM и Render Tree).

### 2. Внутренние стили (`<style>`)
Стили объявляются внутри тега `<style>` в секции `<head>` HTML-страницы:
```html
<head>
  <style>
    body {
      background-color: #f8fafc;
      font-family: sans-serif;
    }
  </style>
</head>
```
* **Применение:** внедрение критического CSS (**Critical CSS**) при оптимизации первой отрисовки страницы, небольшие одностраничные демо. В e-mail-вёрстке, наоборот, чаще используют inline-стили: многие почтовые клиенты вырезают `<link>` и часть `<style>`.

### 3. Встроенные / инлайновые стили (`style="..."`)
CSS-свойства пишутся прямо в атрибуте `style` конкретного HTML-тега:
```html
<button style="background-color: red; color: white;">Кнопка</button>
```
* **Почему это антипаттерн:** Высочайшая специфичность (перебивает классы), невозможность переиспользования, засорение HTML-разметки, проблемы с поддержкой. *Исключение:* динамический расчет координат или размеров через JavaScript (свойство `element.style`, Лекция 103). Стили, выставленные таким образом, тоже становятся инлайновыми и побеждают любые селекторы (кроме правил с `!important`).

## Подглава 34.1.2: Селекторы, Специфичность, Каскад и Наследование

### 1. Классификация CSS-селекторов

Селектор указывает браузеру, к каким именно элементам страницы необходимо применить стили.

#### А. Базовые селекторы:
* **Универсальный селектор (`*`):** выбирает абсолютно все элементы на странице (`* { box-sizing: border-box; }`).
* **Селектор по тегу (`h1`, `p`, `button`):** стилизует все теги данного типа.
* **Селектор по классу (`.btn`, `.card__title`):** выбирает элементы с соответствующим атрибутом `class="..."`. Основной рабочий инструмент!
* **Селектор по ID (`#main-header`):** выбирает единственный элемент с уникальным атрибутом `id="..."`.
* **Селектор атрибута (`[type="email"]`, `a[href^="https"]`):** выбирает элементы по наличию или значению атрибута. Варианты: `[attr]` — атрибут есть; `[attr="x"]` — точное значение; `[attr^="x"]` — начинается с `x`; `[attr$="x"]` — заканчивается на `x`; `[attr*="x"]` — содержит `x`.
* **Группировка (`h1, h2, h3`):** запятая применяет одни и те же стили сразу нескольким селекторам. Каждый селектор из списка считается **отдельно**, вес не суммируется.

#### Б. Комбинаторы (Связи между элементами):
* **Потомок (`div p`):** выбирает все `<p>` внутри `<div>` на любой глубине вложенности.
* **Дочерний / прямой потомок (`ul > li`):** выбирает только тех `<li>`, которые являются прямыми детьми `<ul>`.
* **Соседний селектор (`h2 + p`):** выбирает элемент `<p>`, расположенный **непосредственно сразу** за `<h2>`.
* **Последующий селектор (`h2 ~ p`):** выбирает все `<p>`, идущие после `<h2>` на том же уровне вложенности.

#### В. Псевдоклассы и Псевдоэлементы:

Эти два понятия легко перепутать, поэтому начнём с определений.

> 📌 **Псевдокласс (pseudo-class)** — ключевое слово с **одним** двоеточием (`:hover`), которое добавляют к селектору, чтобы выбрать элемент **в определённом состоянии** (на него навели курсор, он получил фокус, ссылка посещена) или **в определённой позиции** среди соседей (первый, последний, чётный). Сам элемент при этом уже есть в HTML; псевдокласс лишь уточняет условие выбора. По весу специфичности приравнивается к **классу** `(0, 0, 1, 0)`.
>
> 📌 **Псевдоэлемент (pseudo-element)** — ключевое слово с **двумя** двоеточиями (`::before`), которое выбирает **виртуальную часть** элемента: то, чего нет в HTML-разметке (текст, сгенерированный стилями до или после содержимого) или что является частью элемента (первая строка, подсказка внутри поля ввода). Браузер «достраивает» такие части сам. По весу приравнивается к **тегу** `(0, 0, 0, 1)`.

| | Псевдокласс | Псевдоэлемент |
| :--- | :--- | :--- |
| **Что выбирает** | существующий элемент в нужном состоянии или позиции | виртуальную часть элемента |
| **Вопрос, на который отвечает** | «Какой именно?» (в каком состоянии) | «Какая часть?» |
| **Синтаксис** | одно двоеточие: `a:hover` | два двоеточия: `p::first-line` |
| **Есть в исходном HTML** | да, элемент записан в разметке | нет, создаётся стилями или браузером |
| **Вес специфичности** | как у класса `(0, 0, 1, 0)` | как у тега `(0, 0, 0, 1)` |
| **Примеры** | `:hover`, `:focus`, `:first-child`, `:nth-child(odd)`, `:not(.disabled)` | `::before`, `::after`, `::placeholder`, `::first-line` |

> ℹ️ Исторически псевдоэлементы допускалось писать и с одним двоеточием (`:before`, `:after`). Это устаревшая запись: в новом коде используйте двойное двоеточие, чтобы отличать псевдоэлементы от псевдоклассов. В DevTools (Лекция 34.3) `::before` и `::after` отображаются отдельными строками в дереве элементов, хотя в вашем HTML их нет.

* **Псевдоклассы (состояние элемента):**
  * Состояния ввода и мыши: `:hover` (наведение), `:focus` (фокус ввода), `:focus-visible` (фокус, который показывают при навигации с клавиатуры), `:active` (момент клика), `:link` (непосещённая ссылка), `:visited` (посещённая ссылка).
  * Позиционирование в дереве: `:first-child`, `:last-child`, `:nth-child(2n)` (четные), `:nth-child(odd)` (нечетные).
  * Отрицание: `:not(.disabled)` — «любой элемент, кроме имеющего класс `disabled`». Это функциональный псевдокласс: он принимает аргумент в скобках, а его вес равен весу аргумента.
* **Псевдоэлементы (виртуальные под-элементы):**
  * `::before` и `::after`: генерируют декоративный контент перед или после содержимого элемента. **Обязательно требуют наличия свойства `content: ""`!**
  * `::placeholder`: стилизация подсказки внутри `<input>`.
  * `::first-line` и `::first-letter`: первая строка и первая буква текста блока (буквица).
  * `::selection`: часть текста, которую пользователь выделил мышью.
  * `::marker`: маркер или номер пункта списка.

```css
/* Пример использования псевдоклассов и псевдоэлементов */
.btn {
  position: relative;
  background-color: #3b82f6;
}

.btn:hover {
  background-color: #2563eb; /* Смена цвета при наведении */
}

.btn::before {
  content: ""; /* Обязательное свойство! */
  display: inline-block;
  width: 8px;
  height: 8px;
  background-color: white;
}
```

> ⚠️ **Порядок правил для ссылок.** Записывайте их в порядке `:link` → `:visited` → `:hover` → `:active` (мнемоника **LVHA**). Все четыре имеют одинаковую специфичность, поэтому побеждает правило, записанное ниже (см. правило каскада №2).

#### Г. Как браузер сопоставляет селектор с элементами
Браузер читает селектор **справа налево**: для `.menu a` он берёт каждый `<a>` на странице и проверяет, есть ли у него предок `.menu` (а не ищет сначала `.menu`). На практике это значит: плоские селекторы по классам одновременно и быстрые, и предсказуемые. Как браузер строит из правил CSSOM, мы разберём в Лекции 35.

### 2. Специфичность CSS (CSS Specificity)

Когда один и тот же элемент попадает под действие нескольких противоречащих друг другу CSS-правил, браузер определяет победителя по **весу специфичности**.

Вес селектора рассчитывается в виде 4-компонентной группы **`(Inline, ID, Class, Type)`**:

```text
+----------------------------------------------------+-----------------+
| Категория                                          | Весовой вес     |
+----------------------------------------------------+-----------------+
| 1. Инлайновые стили (style="...")                  | (1, 0, 0, 0)    |
| 2. Селекторы по ID (#header)                       | (0, 1, 0, 0)    |
| 3. Классы, атрибуты, псевдоклассы (.btn, :hover)   | (0, 0, 1, 0)    |
| 4. Теги и псевдоэлементы (div, h1, ::before)       | (0, 0, 0, 1)    |
| 5. Универсальный селектор (*), комбинаторы         | (0, 0, 0, 0)    |
+----------------------------------------------------+-----------------+
```

#### Сравнительный пример расчёта специфичности:

Пусть в разметке есть `<div class="container" id="main-content"><p class="text">...</p></div>`, и четыре правила претендуют на цвет абзаца:

```css
p                        { color: black; }   /* (0, 0, 0, 1) — 1 тег */
.text                    { color: blue; }    /* (0, 0, 1, 0) — 1 класс: сильнее правила p */
div.container p.text     { color: green; }   /* (0, 0, 2, 2) — 2 класса + 2 тега: сильнее .text */
#main-content .text      { color: red; }     /* (0, 1, 1, 0) — 1 ID + 1 класс: сильнее ВСЕХ выше */
```

Абзац будет **красным**. Компоненты сравниваются слева направо и не «переливаются» друг в друга: один ID `(0, 1, 0, 0)` сильнее любого количества классов, хоть `(0, 0, 11, 0)`.

#### Правила каскада:
Упрощённый порядок, по которому браузер выбирает победителя: **(а)** источник и важность (стили браузера по умолчанию слабее стилей автора; `!important` переворачивает порядок) → **(б)** специфичность → **(в)** порядок записи в коде.
1. Если веса специфичности **разные**, побеждает правило с наибольшим весом.
2. Если веса специфичности **абсолютно одинаковы**, побеждает правило, написанное **позже (ниже по коду)**. Если стили лежат в нескольких файлах, «позже» определяется порядком подключения `<link>`.
3. Модификатор **`!important`** побеждает обычные объявления, даже если у них выше специфичность (включая инлайновые стили). Между двумя `!important` снова решают специфичность и порядок. Использование считается дурным тоном: каскад ломается, и перебить такое правило можно только другим `!important`.

---

### 3. Наследование свойств

Некоторые CSS-свойства автоматически передаются от родительских элементов к дочерним:
* **Наследуемые свойства (связанные с текстом):** `color`, `font-family`, `font-size`, `line-height`, `text-align`, `visibility`.
* **Ненаследуемые свойства (геометрия блока):** `width`, `height`, `padding`, `margin`, `border`, `background`, `display`, `position`.

Принудительное управление наследованием:
```css
.child {
  color: inherit; /* Принудительно унаследовать у родителя */
  margin: initial; /* Сбросить к значению по умолчанию спецификации */
  all: unset;     /* наследуемые свойства -> inherit, остальные -> initial (почти все свойства, кроме direction и unicode-bidi) */
}
```

## Подглава 34.1.3: Единицы измерения и цвета в CSS

Все CSS-размеры делятся на **абсолютные** и **относительные**.

### 1. Абсолютные единицы:
* **`px` (пиксели):** базовая единица. Это **CSS-пиксель** — логическая единица, а не физическая точка экрана: на экранах с высокой плотностью (Retina) один CSS-пиксель занимает несколько физических. Размеры в `px` предсказуемы: `16px` везде одинаковы. Масштабирование страницы в браузере (`Ctrl` + `+` / `-`) увеличивает и `px`-размеры, а вот настройка «размер шрифта по умолчанию» в параметрах браузера на размеры в `px` не влияет.

### 2. Относительные единицы:
* **`rem` (Root EM):** размер относительно `font-size` корневого элемента `<html>`. По умолчанию в браузерах `1rem = 16px`, то есть `2rem = 32px`. Размеры в `rem` меняются вместе с настройкой размера шрифта в браузере.
* **`em`:** для свойства `font-size` — относительно `font-size` **родителя**; для остальных свойств (`padding`, `margin`, `width`) — относительно `font-size` **самого элемента**. При вложенности значения `em` перемножаются (внутри блока с `1.2em` блок с `1.2em` даст уже `1.44` от исходного), что затрудняет расчёты.
* **`%` (проценты):** относительно соответствующего параметра родителя: для `width` — ширины области контента родителя, для `height` — высоты родителя (если она задана явно). Внимание: вертикальные `padding` и `margin` в процентах тоже считаются от **ширины** родителя.
* **`vw` (Viewport Width):** 1% от ширины видимого окна браузера (`50vw` = половина экрана).
* **`vh` (Viewport Height):** 1% от высоты видимого окна браузера (`100vh` = полная высота экрана).

> ⚠️ `100vw` включает ширину полосы прокрутки. На настольных браузерах блок с `width: 100vw` может оказаться шире видимой области и вызвать горизонтальную прокрутку. Для ширины «на всю страницу» обычно достаточно `width: 100%` (или просто ничего не задавать: блок сам растянется).

> Совет: в мобильных браузерах `100vh` может включать область под адресной строкой, и блок «вылезает» за экран. Для таких случаев есть единицы `dvh` и `svh` (современные браузеры).

### 3. Безразмерные значения:
* Ноль пишут без единицы: `margin: 0`.
* **`line-height: 1.5`** без единицы — это множитель от `font-size` самого элемента (`16px` × `1.5` = `24px`). Безразмерное значение наследуется как множитель, поэтому именно оно считается рекомендуемым для `line-height`.

### 4. Что выбирать: `px`, `rem` или `clamp()`?

Единого правила нет: подход зависит от проекта и команды. В этом курсе мы придерживаемся такого соглашения:

| Что задаём | Единицы в курсе | Почему |
| :--- | :--- | :--- |
| Отступы (`margin`, `padding`, `gap`), рамки, скругления углов | **`px`** | Предсказуемо. Отступы в `em` и `rem` привязывают макет к размеру шрифта: изменили `font-size` — «поплыл» весь интерфейс, а вложенные `em` ещё и перемножаются. Проценты же считаются от ширины родителя. |
| Размер шрифта | **`px`** + медиазапросы либо **`clamp()`**, где границы и «смещение» удобно задавать в **`rem`** | В `px` размер точно совпадает с макетом, а изменения на разных экранах задаются явно. В `clamp()` значения в `rem` делают текст чувствительным к настройке шрифта в браузере, а часть `vw` отвечает за плавное изменение (см. пункт 6). |
| Ширина контейнеров | **`%`**, **`max-width`** в `px`, иногда **`clamp()`** | Контейнер растягивается, но не шире заданного предела. |
| Размеры внутри компонента, которые должны следовать его шрифту (отступы кнопки или бейджа, иконка рядом с текстом) | **`em`** | `1em` — это размер шрифта самого элемента: изменили шрифт — пропорционально изменились и отступы. Это исключение из общего правила про отступы (пример ниже). |
| Высота экранных секций | **`vh` / `dvh`**, `min-height` | Привязка к высоте окна. |

Пример с `em`: отступы кнопки зависят от её шрифта, поэтому уменьшенная копия получается пропорциональной:

```css
.btn       { font-size: 16px; padding: 0.6em 1.2em; }  /* отступы: 9.6px 19.2px */
.btn--small { font-size: 12px; }                        /* те же пропорции: 7.2px 14.4px */
```

> ℹ️ **Честно о компромиссе.** Шрифты в `px` не реагируют на настройку «размер шрифта по умолчанию» в браузере, а размеры в `rem` — реагируют. Поэтому в проектах с повышенными требованиями к доступности шрифты нередко задают именно в `rem`. Единицу `rem` нужно знать: вы будете встречать её в чужом коде, дизайн-системах и библиотеках, а внутри `clamp()` она особенно удобна как «промежуточная» единица (пункт 6). Но на практике, когда `rem` или `em` применяют ко всем отступам подряд, они часто мешают, и для отступов проще и надёжнее фиксированные значения в `px`; `em` оставляют для внутренностей компонента, которые должны следовать его шрифту. (В SCSS, Лекция 34.5, такие значения выносят в переменные, чтобы держать единую шкалу отступов.)

### 5. Фиксированные значения и медиазапросы

Самый прямолинейный подход: задать размер в `px` и изменить его на нужных экранах с помощью **медиазапросов** (`@media`, подробно — в Лекции 34.2):

```css
.hero__title {
  font-size: 28px;               /* мобильные экраны */
}

@media (min-width: 768px) {
  .hero__title { font-size: 36px; }   /* планшеты */
}

@media (min-width: 1200px) {
  .hero__title { font-size: 48px; }   /* десктопы */
}
```

Размер меняется скачками на границах (`768px`, `1200px`), зато вы точно контролируете результат на каждом формате экрана.

### 6. Функции `clamp()`, `min()` и `max()`

**`clamp(МИН, ЖЕЛАЕМОЕ, МАКС)`** подбирает значение автоматически: берёт «желаемое», но не меньше `МИН` и не больше `МАКС`. Размер меняется плавно, без медиазапросов.

```css
.hero__title {
  font-size: clamp(16px, 2vw, 24px);
}
```

Здесь «желаемое» значение — `2vw` (2% ширины окна). Результат при разной ширине экрана:

| Ширина окна | `2vw` | Итог `font-size` | Почему |
| :--- | :--- | :--- | :--- |
| 320px | 6.4px | **16px** | меньше минимума, берётся минимум |
| 800px | 16px | **16px** | на границе минимума |
| 1000px | 20px | **20px** | внутри диапазона, берётся желаемое |
| 1200px | 24px | **24px** | на границе максимума |
| 1600px | 32px | **24px** | больше максимума, берётся максимум |

**Как подобрать «желаемое» значение под макет.** Пусть дизайнер хочет `16px` на экране `320px` и `24px` на экране `1200px`. Желаемое значение — линейная функция от ширины: `смещение + наклон·vw`.

```text
наклон   = (24 − 16) / (1200 − 320) = 0.00909  ->  0.909vw
смещение = 16 − 0.00909 * 320       = 13.09px
```

```css
font-size: clamp(16px, 13.09px + 0.909vw, 24px);
/* 320px -> 16px;  760px -> 20px;  1200px и шире -> 24px */
```

Такая запись заменяет целый набор медиазапросов одной строкой.

**Версия с `rem`.** Границы и «смещение» удобно записывать в `rem` (при стандартных `16px` на `1rem`: `16px` = `1rem`, `24px` = `1.5rem`, `13.09px` = `0.818rem`), а `vw`-часть оставить как есть:

```css
font-size: clamp(1rem, 0.818rem + 0.909vw, 1.5rem);
/* при стандартном шрифте браузера (16px) результат тот же: 16px -> 20px -> 24px */
```

Разница проявляется, если пользователь изменил «размер шрифта по умолчанию» в браузере. Допустим, там стоит `20px`: границы и смещение вырастут пропорционально, и текст станет крупнее:

| Ширина окна | Версия в `px` | Версия в `rem` при шрифте браузера 16px | Версия в `rem` при шрифте браузера 20px |
| :--- | :--- | :--- | :--- |
| 320px | 16px | 16px | 20px |
| 760px | 20px | 20px | 23.27px |
| 1200px | 24px | 24px | 27.27px |
| 1920px | 24px | 24px | 30px |

Поэтому формулу `смещение + наклон·vw` в реальных проектах часто записывают именно в `rem`: размер по-прежнему плавно зависит от ширины окна, но остаётся чувствительным к настройкам пользователя.

**`clamp()` годится не только для шрифтов**, например для ширины контейнера:

```css
.container {
  width: clamp(280px, 90%, 1200px); /* 90% ширины родителя, но от 280px до 1200px */
}
```

`min(a, b)` берёт наименьшее из значений, `max(a, b)` — наибольшее. Например, `width: min(100%, 600px)` — то же самое, что `width: 100%; max-width: 600px`.

> ⚠️ **Не задавайте шрифт только в `vw`** (`font-size: 3vw`): на узком экране текст станет нечитаемо мелким, а на широком огромным. Всегда ограничивайте значение через `clamp()`. Чтобы текст при масштабировании страницы (`Ctrl` + `+`) увеличивался нормально, держите разницу между минимумом и максимумом умеренной (на практике — не более 2–2,5 раза).

**Что выбрать для шрифта: `@media` или `clamp()`?** Медиазапросы дают полный контроль над каждым форматом экрана, `clamp()` — плавное изменение и меньше кода. Оба подхода встречаются в реальных проектах и могут сочетаться: `clamp()` (с границами в `px` или `rem`) для заголовков, медиазапросы для остальной вёрстки.

### 7. Цвета в CSS

| Запись | Пример | Пояснение |
| :--- | :--- | :--- |
| Имя цвета | `red`, `white`, `transparent` | Около 150 именованных цветов; `transparent` — прозрачный. |
| HEX | `#2563eb`, `#fff` | Три пары цифр `RR GG BB` в шестнадцатеричной системе (от `00` до `FF`): красный, зелёный, синий. `#fff` — короткая запись `#ffffff`. |
| RGB / RGBA | `rgb(37, 99, 235)`, `rgba(37, 99, 235, 0.5)` | Те же три канала в десятичной записи (0–255); четвёртое число — непрозрачность от 0 до 1. |
| HSL | `hsl(221, 83%, 53%)` | Оттенок (0–360°), насыщенность и светлота: удобно подбирать палитру. |

`#2563eb`, `rgb(37, 99, 235)` и `hsl(221, 83%, 53%)` — это один и тот же синий цвет. При выборе цвета текста и фона следите за **контрастом** (для обычного текста — не ниже 4,5:1): в Chrome DevTools он показывается в палитре цвета (Лекция 34.3).

Свойства оформления, которые встречаются в примерах этой лекции:

| Свойство | Что задаёт |
| :--- | :--- |
| `color` / `background-color` | цвет текста / цвет фона |
| `font-family` / `font-size` / `font-weight` | шрифт / размер / насыщенность (`400` обычный, `600`–`700` жирный) |
| `line-height` | высота строки |
| `text-align` / `text-decoration` | выравнивание текста / подчёркивание (`none` убирает его у ссылок) |
| `border` / `border-radius` | рамка (`1px solid #cbd5e1`) / скругление углов |
| `cursor` | вид указателя мыши (`pointer` — «рука» над кнопкой) |

## Подглава 34.1.4: Блочная модель (Box Model), `box-sizing` и сброс стилей (CSS Reset)

Любой элемент в CSS рассматривается как прямоугольник.

```text
+-------------------------------------------------------+
|                    MARGIN (Внешний отступ)            |
|  +-------------------------------------------------+  |
|  |                 BORDER (Рамка)                  |  |
|  |  +-------------------------------------------+  |  |
|  |  |              PADDING (Внутренний отступ)  |  |  |
|  |  |  +-------------------------------------+  |  |  |
|  |  |  |           CONTENT (Контент)         |  |  |  |
|  |  |  |           (width x height)          |  |  |  |
|  |  |  +-------------------------------------+  |  |  |
|  |  +-------------------------------------------+  |  |
|  +-------------------------------------------------+  |
+-------------------------------------------------------+
```

### Сравнение режимов `content-box` и `border-box`

#### 1. `box-sizing: content-box` (Режим по умолчанию):
Свойства `width` и `height` задают размеры **только зоны контента**. Поля `padding` и `border` прибавляются сверху к ширине элемента, раздувая его физический размер!

```text
Итоговая ширина = width + padding-left + padding-right + border-left + border-right
```

```css
/* Пример проблемного блока */
.box-old {
  box-sizing: content-box;
  width: 200px;
  padding: 20px;
  border: 5px solid black;
  /* Итоговая ширина = 200 + 20*2 + 5*2 = 250px: блок «раздулся» */
}
```

#### 2. `box-sizing: border-box` (современная практика):
Свойства `width` и `height` указывают **полный физический размер блока**. Если задать `padding` или `border`, область контента автоматически ужимется внутри заданных рамок. (Если `padding` и `border` вместе больше заданной `width`, элемент всё равно не станет уже их суммы.)

```text
Итоговая ширина = width   (ровно 200px: padding и border уже входят внутрь)
```

```css
/* Глобально включаем border-box (box-sizing не наследуется, поэтому используем *) */
*, *::before, *::after {
  box-sizing: border-box;
}

.box-modern {
  width: 200px;
  padding: 20px;
  border: 5px solid black;
  /* Итоговая ширина = строго 200px! */
}
```

> ℹ️ `margin` не входит в `width` ни в одном из режимов.

### Сброс стилей (CSS Reset)

**Откуда берутся «лишние» отступы и размеры.** У каждого браузера есть встроенная таблица стилей (**user agent stylesheet**; в DevTools её правила подписаны так же, Лекция 34.3). Из неё берутся отступ `8px` у `<body>`, крупный шрифт и вертикальные отступы у `<h1>`, отступ слева и маркеры у `<ul>`, собственный шрифт у кнопок и полей ввода. Если ничего с этим не делать, то к отступам из вашего макета добавляются отступы браузера, да ещё и немного разные в разных браузерах.

**Сброс стилей** — небольшой блок CSS в самом начале файла, который приводит эти значения к предсказуемому «нулю». Дальше все отступы и размеры вы задаёте явно. Включать `box-sizing: border-box` — тоже часть сброса, а не отдельный приём.

#### Минимальный сброс (используем в курсе):

```css
*, *::before, *::after {
  box-sizing: border-box; /* width и height включают padding и border */
  margin: 0;              /* убираем внешние отступы браузера... */
  padding: 0;             /* ...и внутренние: все отступы задаём сами */
}
```

* **`*, *::before, *::after`** — универсальный селектор и псевдоэлементы: правило действует на все элементы без исключения. `box-sizing` не наследуется, поэтому его нужно задавать именно всем элементам сразу.
* **`margin: 0; padding: 0;`** — убирает стандартные отступы у заголовков, абзацев, списков и `<body>`.

**Почему сброс работает, хотя вес у `*` нулевой `(0, 0, 0, 0)`?** Вспомните правила каскада: сначала сравнивается **источник**, и стили автора всегда сильнее стилей браузера, независимо от специфичности. А ваши собственные правила (классы) потом без труда перебивают сброс, потому что их вес выше.

#### Расширенный сброс (часто добавляют в реальных проектах):

```css
img, picture, video, canvas, svg {
  display: block;   /* убирает зазор под картинкой: по умолчанию она строчная и стоит на линии текста */
  max-width: 100%;  /* картинка не вылезает за границы контейнера */
}

input, button, textarea, select {
  font: inherit;    /* поля форм по умолчанию не наследуют шрифт страницы */
}
```

> ⚠️ **Что изменится после сброса.** У списков пропадает отступ слева, и маркеры (точки, цифры) оказываются у самого края блока или даже за ним. Меню обычно делают без маркеров (`list-style: none;`), а в текстовых списках возвращают отступ (`padding-left: 24px;`). Между заголовками и абзацами тоже пропадают зазоры: теперь их нужно задавать самим.

**Размещайте сброс первым** в файле стилей (если он в отдельном файле, то первым `<link>`), чтобы все остальные правила могли его переопределять.

#### Другие подходы:
* **Классический reset** (Эрик Мейер) — обнуляет почти все стили браузера.
* **normalize.css** — не обнуляет всё подряд, а только выравнивает различия между браузерами и сохраняет полезные значения по умолчанию.
* В библиотеках и фреймворках есть собственные встроенные сбросы (например, Reboot в Bootstrap и Preflight в Tailwind CSS).

Минимального сброса, показанного выше, достаточно для наших задач.

## Подглава 34.1.5: Типы отображения элементов (`display`)

Свойство `display` определяет роли элемента в потоке документа и способ его взаимодействия с соседями.

| Значение       | Новая строка? | `width` / `height`                                                            | `margin` / `padding`                                                                                                           |
| :------------- | :-----------: | :---------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------- |
| `block`        |      Да       | Работают; ширина по умолчанию 100% родителя                                   | Работают со всех сторон                                                                                                        |
| `inline`       |      Нет      | **Игнорируются**. <br>Размер по содержимому                                   | Горизонтальные работают. Вертикальный `margin` игнорируется, вертикальный `padding` рисуется, но не раздвигает соседние строки |
| `inline-block` |      Нет      | Работают                                                                      | Работают со всех сторон                                                                                                        |
| `none`         |       —       | Элемент остаётся в DOM, но не попадает в дерево отрисовки и не занимает места | —                                                                                                                              |

### 1. `display: block` (Блочные элементы)
* Примеры: `<div>`, `<p>`, `<h1>`–`<h6>`, `<section>`, `<header>`, `<article>`.
* Элемент начинается с новой строки и растягивается на 100% ширины родителя.
* Полноценно воспринимает `width`, `height`, `margin` и `padding`.

### 2. `display: inline` (Строчные элементы)
* Примеры: `<span>`, `<a>`, `<strong>`, `<em>`, `<code>`.
* Выстраиваются в одну строку друг за другом.
* **Игнорируют** свойства `width` и `height`.
* Вертикальные `margin-top` и `margin-bottom` **не работают**! Вертикальные `padding` визуально отображаются, но не раздвигают границы строки.

### 3. `display: inline-block` (Блочно-строчные элементы)
* Примеры: `<button>`, `<input>` (по умолчанию `inline-block`). `<img>` формально строчный *заменяемый* элемент, но ведёт себя как `inline-block`: `width` и `height` на него действуют.
* Элементы выстраиваются в одну строку (как `inline`), но при этом **полноценно воспринимают `width`, `height`, `margin` и `padding` со всех сторон** (как `block`).

### 4. `display: none` и родственные приёмы скрытия
* `display: none` — элемент **остаётся в DOM** (JavaScript его находит через `querySelector`), но не попадает в дерево отрисовки (Render Tree, Лекция 35): не рисуется и **не занимает места**.
* `visibility: hidden` — элемент невидим, но **продолжает занимать место** в потоке.
* `opacity: 0` — элемент прозрачен, место занимает и остаётся кликабельным.

### 5. Другие значения `display`
`display: flex` и `display: grid` превращают контейнер в особую систему расположения дочерних элементов вместо обычного нормального потока: гибкую (Flexbox) или сеточную (Grid). Их мы разберём в Лекции 34.2.

## Подглава 34.1.6: Схлопывание внешних отступов (Margin Collapse)

В нормальном потоке документа вертикальные внешние отступы (`margin-top` и `margin-bottom`) соседних или вложенных блочных элементов **не суммируются**, а схлопываются в один общий отступ, равный **максимальному из них**.

```text
  [ Блок 1 ] (margin-bottom: 30px)
       |
       |  <--- Физический отступ между блоками будет не 50px, а MAX(30, 20) = 30px!
       |
  [ Блок 2 ] (margin-top: 20px)
```

### Сценарии схлопывания:
1. **Соседние блоки в потоке:** у верхнего блока `margin-bottom: 30px`, у нижнего `margin-top: 20px`. Итоговое расстояние между ними = `30px`.
2. **Родитель и первый/последний ребёнок:** если у родителя нет `border`, `padding` или `overflow: hidden`, `margin-top` первого ребёнка «проваливается» наружу и становится отступом самого родителя. То же касается `margin-bottom` последнего ребёнка, но только если у родителя не задана высота (`height`).
3. **Пустой блок:** у блока без содержимого, рамки, `padding` и высоты верхний и нижний `margin` схлопываются сами с собой.
4. **Отрицательные значения:** положительный и отрицательный `margin` складываются (`30px` и `-10px` дадут `20px`); два отрицательных дают меньшее из них.

### Когда отступы НЕ схлопываются:
* **Горизонтальные** `margin-left` и `margin-right` не схлопываются никогда.
* Между детьми контейнера с `display: flex` или `display: grid` (Лекция 34.2).
* У элементов `inline-block`, а также у `float` и абсолютно позиционированных элементов.

### Как предотвратить схлопывание отступов:
* Перевести контейнер в `display: flex` или `display: grid` (изучим в Лекции 34.2).
* Добавить родителю минимальный `padding` (например, `padding-top: 1px`) или `border`.
* Задать контейнеру свойство `overflow: auto` или `overflow: hidden` (создание BFC — Block Formatting Context). Побочный эффект: `overflow` обрезает или прокручивает выступающее содержимое.
* Самый чистый способ без побочных эффектов: `display: flow-root` (создаёт BFC только ради изоляции отступов).

7. **Не лечите конфликты через `!important` и инлайновые стили:** понижайте или повышайте специфичность осознанно (плоские классы БЭМ).

.card__title {

### Ответ к Задаче 8:
1. Сброс обнулил `margin` и `padding` у всех элементов. У `<ul>` исчез стандартный отступ слева (около 40px), а маркеры рисуются **снаружи** блока списка, поэтому оказываются у самого края или за ним. У `<h1>` и `<p>` исчезли вертикальные отступы браузера по умолчанию, и между ними нет зазора.
2. Возвращаем отступы осознанно, по классам (БЭМ):
```css
.article__list {
  padding-left: 24px;     /* место для маркеров */
}

.article__title {
  margin-bottom: 12px;    /* зазор между заголовком и абзацем */
}
```
3. Для меню: `.menu__list { list-style: none; }` (маркеры убираются, а отступа слева после сброса уже нет).
