В этой лекции мы переходим к визуальному оформлению и стилизации веб-интерфейсов с помощью **CSS3 (Cascading Style Sheets)**. Мы изучим все способы подключения стилей, разберём каскад, расчет специфичности и наследование свойств, освоим разновидности селекторов, единицы измерения, глубоко разберём устройство **блочной модели (Box Model)**, правила работы режимов `box-sizing`, типы отображения элементов **`display`** (`block`, `inline`, `inline-block`, `none`) и физику схлопывания внешних отступов (**Margin Collapse**).

> 🗺️ **Место лекции в курсе.** Лекция продолжает Лекцию 34 (HTML5, семантика, БЭМ): мы стилизуем ту же разметку и используем БЭМ-имена классов. Дальше по плану: **Лекция 34.2** — раскладка (Flexbox, Grid, `@media`); **Лекция 35** — как браузер превращает HTML и CSS в пиксели (DOM, CSSOM, Render Tree); **Лекция 103** — управление классами и стилями из JavaScript (`classList`, `element.style`, `getComputedStyle`). В Этапах 3–4 сквозного проекта вы будете использовать Tailwind CSS: это набор готовых однoклассовых правил, и законы каскада и специфичности из этой лекции действуют там без изменений.

## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. CSS (Cascading Style Sheets)**
> * **Что это:** Формальный язык описания внешнего вида веб-страницы (цвета, шрифты, размеры, отступы, расположение блоков), написанной на языке разметки (HTML).

> 📌 **2. Каскад (Cascading)**
> * **Что это:** Алгоритм разрешения конфликтов, определяющий, какое из нескольких конкурирующих CSS-правил будет применено к элементу. Каскад учитывает источник правила, специфичность селектора и порядок объявления в коде.

> 📌 **3. Специфичность (Specificity)**
> * **Что это:** Весовой коэффициент CSS-селектора, рассчитываемый по формуле `(Inline, ID, Class/Attribute/Pseudo-class, Element/Pseudo-element)`. Чем выше вес селектора, тем выше его приоритет над конкурирующими правилами.

> 📌 **4. Наследование (Inheritance)**
> * **Что это:** Механизм, при котором дочерние элементы автоматически перенимают значения некоторых CSS-свойств от своих родительских элементов (например, `color`, `font-family`, `line-height`).

> 📌 **5. Блочная модель CSS (Box Model)**
> * **Что это:** Модель прямоугольного контейнера, представляющая любой HTML-элемент на странице в виде четырех вложенных областей: содержимого (`content`), внутренних отступов (`padding`), рамки (`border`) и внешних отступов (`margin`).

> 📌 **6. Режим `box-sizing: border-box`**
> * **Что это:** Способ расчёта размеров блока, при котором свойства `width` и `height` задают суммарный физический размер элемента, включая `padding` и `border`. Широко принятая практика современной вёрстки.

> 📌 **7. Схлопывание отступов (Margin Collapse)**
> * **Что это:** Поведение блочных элементов в нормальном потоке документа, при котором вертикальные внешние отступы (`margin-top` и `margin-bottom`) соседних или вложенных блоков объединяются в один отступ, равный максимальному из них.

> 📌 **8. Нормальный поток (Normal Flow)**
> * **Что это:** Порядок размещения элементов по умолчанию, пока вы не меняли раскладку: блочные элементы идут сверху вниз, каждый с новой строки, строчные — слева направо внутри строки.

> 📌 **9. BFC (Block Formatting Context)**
> * **Что это:** Изолированная область раскладки, внутри которой блоки располагаются по своим правилам и не «склеиваются» по `margin` с внешним миром. BFC создают, например, `overflow: hidden` (и любой `overflow`, кроме `visible`), `display: flow-root`, `float`, `inline-block` и абсолютное позиционирование. Контейнеры `flex` и `grid` создают собственные форматирующие контексты (flex/grid), и `margin` их детей тоже не схлопывается с внешним миром.

## Подглава 34.1.1: Способы подключения CSS к HTML-документу

Существует 3 основных способа связывания стилей CSS с разметкой HTML:

```text
+-----------------------------------------------------------------------+
| 1. Внешняя таблица стилей (Рекомендуемый стандарт)                     |
|    <link rel="stylesheet" href="style.css">                           |
+-----------------------------------------------------------------------+
| 2. Внутренние стили в документе (Тег <style> в <head>)                |
|    <style> h1 { color: blue; } </style>                               |
+-----------------------------------------------------------------------+
| 3. Инлайновые стили в атрибуте (Антипаттерн в продакшене!)            |
|    <h1 style="color: blue;">Заголовок</h1>                            |
+-----------------------------------------------------------------------+
```

### 1. Внешний файл стилей (`<link rel="stylesheet">`)
Самый чистый и промышленный подход. Стили хранятся в отдельном файле с расширением `.css`, который подключается в секции `<head>` HTML-документа:
```html
<head>
  <meta charset="UTF-8">
  <link rel="stylesheet" href="css/style.css">
</head>
```
* **Плюсы:** Разделение ответственности (Separation of Concerns), возможность кэширования файла браузером, использование одного файла на тысячах страниц.

> ℹ️ Браузер не рисует страницу, пока не загрузит и не разберёт CSS из `<link>` (стили «блокируют отрисовку»), поэтому `<link>` размещают в `<head>`. Почему так устроено, разберём в Лекции 35 (CSSOM и Render Tree).

### 2. Внутренние стили (`<style>`)
Стили объявляются внутри тега `<style>` в секции `<head>` HTML-страницы:
```html
<head>
  <style>
    body {
      background-color: #f8fafc;
      font-family: sans-serif;
    }
  </style>
</head>
```
* **Применение:** внедрение критического CSS (**Critical CSS**) при оптимизации первой отрисовки страницы, небольшие одностраничные демо. В e-mail-вёрстке, наоборот, чаще используют inline-стили: многие почтовые клиенты вырезают `<link>` и часть `<style>`.

### 3. Встроенные / инлайновые стили (`style="..."`)
CSS-свойства пишутся прямо в атрибуте `style` конкретного HTML-тега:
```html
<button style="background-color: red; color: white;">Кнопка</button>
```
* **Почему это антипаттерн:** Высочайшая специфичность (перебивает классы), невозможность переиспользования, засорение HTML-разметки, проблемы с поддержкой. *Исключение:* динамический расчет координат или размеров через JavaScript (свойство `element.style`, Лекция 103). Стили, выставленные таким образом, тоже становятся инлайновыми и побеждают любые селекторы (кроме правил с `!important`).

## Подглава 34.1.2: Селекторы, Специфичность, Каскад и Наследование

### 1. Классификация CSS-селекторов

Селектор указывает браузеру, к каким именно элементам страницы необходимо применить стили.

#### А. Базовые селекторы:
* **Универсальный селектор (`*`):** выбирает абсолютно все элементы на странице (`* { box-sizing: border-box; }`).
* **Селектор по тегу (`h1`, `p`, `button`):** стилизует все теги данного типа.
* **Селектор по классу (`.btn`, `.card__title`):** выбирает элементы с соответствующим атрибутом `class="..."`. Основной рабочий инструмент!
* **Селектор по ID (`#main-header`):** выбирает единственный элемент с уникальным атрибутом `id="..."`.
* **Селектор атрибута (`[type="email"]`, `a[href^="https"]`):** выбирает элементы по наличию или значению атрибута. Варианты: `[attr]` — атрибут есть; `[attr="x"]` — точное значение; `[attr^="x"]` — начинается с `x`; `[attr$="x"]` — заканчивается на `x`; `[attr*="x"]` — содержит `x`.
* **Группировка (`h1, h2, h3`):** запятая применяет одни и те же стили сразу нескольким селекторам. Каждый селектор из списка считается **отдельно**, вес не суммируется.

#### Б. Комбинаторы (Связи между элементами):
* **Потомок (`div p`):** выбирает все `<p>` внутри `<div>` на любой глубине вложенности.
* **Дочерний / прямой потомок (`ul > li`):** выбирает только тех `<li>`, которые являются прямыми детьми `<ul>`.
* **Соседний селектор (`h2 + p`):** выбирает элемент `<p>`, расположенный **непосредственно сразу** за `<h2>`.
* **Последующий селектор (`h2 ~ p`):** выбирает все `<p>`, идущие после `<h2>` на том же уровне вложенности.

#### В. Псевдоклассы и Псевдоэлементы:
* **Псевдоклассы (состояние элемента):**
  * Состояния ввода и мыши: `:hover` (наведение), `:focus` (фокус ввода), `:active` (момент клика), `:visited` (посещенная ссылка).
  * Позиционирование в дереве: `:first-child`, `:last-child`, `:nth-child(2n)` (четные), `:nth-child(odd)` (нечетные), `:not(.disabled)`.
* **Псевдоэлементы (виртуальные под-элементы):**
  * `::before` и `::after`: генерируют декоративный контент перед или после содержимого элемента. **Обязательно требуют наличия свойства `content: ""`!**
  * `::placeholder`: стилизация подсказки внутри `<input>`.

```css
/* Пример использования псевдоклассов и псевдоэлементов */
.btn {
  position: relative;
  background-color: #3b82f6;
}

.btn:hover {
  background-color: #2563eb; /* Смена цвета при наведении */
}

.btn::before {
  content: ""; /* Обязательное свойство! */
  display: inline-block;
  width: 8px;
  height: 8px;
  background-color: white;
}
```

> ⚠️ **Порядок правил для ссылок.** Записывайте их в порядке `:link` → `:visited` → `:hover` → `:active` (мнемоника **LVHA**). Все четыре имеют одинаковую специфичность, поэтому побеждает правило, записанное ниже (см. правило каскада №2).

#### Г. Как браузер сопоставляет селектор с элементами
Браузер читает селектор **справа налево**: для `.menu a` он берёт каждый `<a>` на странице и проверяет, есть ли у него предок `.menu` (а не ищет сначала `.menu`). На практике это значит: плоские селекторы по классам одновременно и быстрые, и предсказуемые. Как браузер строит из правил CSSOM, мы разберём в Лекции 35.

### 2. Специфичность CSS (CSS Specificity)

Когда один и тот же элемент попадает под действие нескольких противоречащих друг другу CSS-правил, браузер определяет победителя по **весу специфичности**.

Вес селектора рассчитывается в виде 4-компонентной группы **`(Inline, ID, Class, Type)`**:

```text
+-----------------------------------------------------------------------------+
| Категория                                     | Весовой коэффициент          |
+-----------------------------------------------+-----------------------------+
| 1. Инлайновые стили (style="...")             | (1, 0, 0, 0)                |
| 2. Селекторы по ID (#header)                  | (0, 1, 0, 0)                |
| 3. Классы, атрибуты, псевдоклассы (.btn, :hover) | (0, 0, 1, 0)             |
| 4. Теги и псевдоэлементы (div, h1, ::before)   | (0, 0, 0, 1)                |
| 5. Универсальный селектор (*), комбинаторы     | (0, 0, 0, 0)                |
+-----------------------------------------------------------------------------+
```

#### Сравнительный пример расчёта специфичности:

Пусть в разметке есть `<div class="container" id="main-content"><p class="text">...</p></div>`, и четыре правила претендуют на цвет абзаца:

```css
p                        { color: black; }   /* (0, 0, 0, 1) — 1 тег */
.text                    { color: blue; }    /* (0, 0, 1, 0) — 1 класс: сильнее правила p */
div.container p.text     { color: green; }   /* (0, 0, 2, 2) — 2 класса + 2 тега: сильнее .text */
#main-content .text      { color: red; }     /* (0, 1, 1, 0) — 1 ID + 1 класс: сильнее ВСЕХ выше */
```

Абзац будет **красным**. Компоненты сравниваются слева направо и не «переливаются» друг в друга: один ID `(0, 1, 0, 0)` сильнее любого количества классов, хоть `(0, 0, 11, 0)`.

#### Правила каскада:
Упрощённый порядок, по которому браузер выбирает победителя: **(а)** источник и важность (стили браузера по умолчанию слабее стилей автора; `!important` переворачивает порядок) → **(б)** специфичность → **(в)** порядок записи в коде.
1. Если веса специфичности **разные**, побеждает правило с наибольшим весом.
2. Если веса специфичности **абсолютно одинаковы**, побеждает правило, написанное **позже (ниже по коду)**. Если стили лежат в нескольких файлах, «позже» определяется порядком подключения `<link>`.
3. Модификатор **`!important`** побеждает обычные объявления, даже если у них выше специфичность (включая инлайновые стили). Между двумя `!important` снова решают специфичность и порядок. Использование считается дурным тоном: каскад ломается, и перебить такое правило можно только другим `!important`.

### 3. Наследование свойств

Некоторые CSS-свойства автоматически передаются от родительских элементов к дочерним:
* **Наследуемые свойства (связанные с текстом):** `color`, `font-family`, `font-size`, `line-height`, `text-align`, `visibility`.
* **Ненаследуемые свойства (геометрия блока):** `width`, `height`, `padding`, `margin`, `border`, `background`, `display`, `position`.

Принудительное управление наследованием:
```css
.child {
  color: inherit; /* Принудительно унаследовать у родителя */
  margin: initial; /* Сбросить к значению по умолчанию спецификации */
  all: unset;     /* наследуемые свойства -> inherit, остальные -> initial (почти все свойства, кроме direction и unicode-bidi) */
}
```

## Подглава 34.1.3: Единицы измерения в CSS

Все CSS-размеры делятся на **абсолютные** и **относительные**:

### 1. Абсолютные единицы:
* **`px` (пиксели):** базовая единица. Это **CSS-пиксель** — логическая единица, а не физическая точка экрана: на экранах с высокой плотностью (Retina) один CSS-пиксель занимает несколько физических. Размер в `px` фиксирован и не подстраивается под настройку размера шрифта в браузере.

### 2. Относительные единицы:
* **`rem` (Root EM):** размер относительно `font-size` корневого элемента `<html>`. По умолчанию в браузерах `1rem = 16px`. Хороший выбор для шрифтов и отступов (`2rem = 32px`): размеры масштабируются вместе с настройкой шрифта в браузере (доступность). Тонкие рамки (`1px`) обычно оставляют в `px`.
* **`em`:** для свойства `font-size` — относительно `font-size` **родителя**; для остальных свойств (`padding`, `margin`, `width`) — относительно `font-size` **самого элемента**. При вложенности значения `em` перемножаются, поэтому для шрифтов чаще берут `rem`.
* **`%` (проценты):** относительно соответствующего параметра родителя: для `width` — ширины области контента родителя, для `height` — высоты родителя (если она задана явно). Внимание: вертикальные `padding` и `margin` в процентах тоже считаются от **ширины** родителя.
* **`vw` (Viewport Width):** 1% от ширины видимого окна браузера (`50vw` = половина экрана).
* **`vh` (Viewport Height):** 1% от высоты видимого окна браузера (`100vh` = полная высота экрана).

> Совет: в мобильных браузерах `100vh` может включать область под адресной строкой, и блок «вылезает» за экран. Для таких случаев есть единицы `dvh` и `svh` (современные браузеры).

## Подглава 34.1.4: Блочная модель (Box Model) и управление `box-sizing`

Любой элемент в CSS рассматривается как прямоугольник.

```text
+-------------------------------------------------------+
|                    MARGIN (Внешний отступ)            |
|  +-------------------------------------------------+  |
|  |                 BORDER (Рамка)                  |  |
|  |  +-------------------------------------------+  |  |
|  |  |              PADDING (Внутренний отступ)  |  |  |
|  |  |  +-------------------------------------+  |  |  |
|  |  |  |           CONTENT (Контент)         |  |  |  |
|  |  |  |           (width x height)          |  |  |  |
|  |  |  +-------------------------------------+  |  |  |
|  |  +-------------------------------------------+  |  |
|  +-------------------------------------------------+  |
+-------------------------------------------------------+
```

### Сравнение режимов `content-box` и `border-box`

#### 1. `box-sizing: content-box` (Режим по умолчанию):
Свойства `width` и `height` задают размеры **только зоны контента**. Поля `padding` и `border` прибавляются сверху к ширине элемента, раздувая его физический размер!

```text
Итоговая ширина = width + padding-left + padding-right + border-left + border-right
```

```css
/* Пример проблемного блока */
.box-old {
  box-sizing: content-box;
  width: 200px;
  padding: 20px;
  border: 5px solid black;
  /* Итоговая ширина = 200 + 20*2 + 5*2 = 250px: блок «раздулся» */
}
```

#### 2. `box-sizing: border-box` (современная практика):
Свойства `width` и `height` указывают **полный физический размер блока**. Если задать `padding` или `border`, область контента автоматически ужимется внутри заданных рамок.

```text
Итоговая ширина = width   (ровно 200px: padding и border уже входят внутрь)
```

```css
/* Глобально включаем border-box (box-sizing не наследуется, поэтому используем *) */
*, *::before, *::after {
  box-sizing: border-box;
}

.box-modern {
  width: 200px;
  padding: 20px;
  border: 5px solid black;
  /* Итоговая ширина = строго 200px! */
}
```

> ℹ️ `margin` не входит в `width` ни в одном из режимов. В примерах ниже к сбросу `box-sizing` добавлено `margin: 0; padding: 0;`. Это уже **другой приём (CSS reset)**: он убирает стандартные отступы браузера у заголовков, абзацев и списков, чтобы все отступы задавались явно. Для работы `border-box` он не нужен.

## Подглава 34.1.5: Типы отображения элементов (`display`)

Свойство `display` определяет роли элемента в потоке документа и способ его взаимодействия с соседями.

| Значение | Новая строка? | `width` / `height` | `margin` / `padding` |
| :--- | :---: | :--- | :--- |
| `block` | Да | Работают; ширина по умолчанию 100% родителя | Работают со всех сторон |
| `inline` | Нет | **Игнорируются**; размер по содержимому | Горизонтальные работают. Вертикальный `margin` игнорируется, вертикальный `padding` рисуется, но не раздвигает соседние строки |
| `inline-block` | Нет | Работают | Работают со всех сторон |
| `none` | — | Элемент остаётся в DOM, но не попадает в дерево отрисовки и не занимает места | — |

### 1. `display: block` (Блочные элементы)
* Примеры: `<div>`, `<p>`, `<h1>`–`<h6>`, `<section>`, `<header>`, `<article>`.
* Элемент начинается с новой строки и растягивается на 100% ширины родителя.
* Полноценно воспринимает `width`, `height`, `margin` и `padding`.

### 2. `display: inline` (Строчные элементы)
* Примеры: `<span>`, `<a>`, `<strong>`, `<em>`, `<code>`.
* Выстраиваются в одну строку друг за другом.
* **Игнорируют** свойства `width` и `height`.
* Вертикальные `margin-top` и `margin-bottom` **не работают**! Вертикальные `padding` визуально отображаются, но не раздвигают границы строки.

### 3. `display: inline-block` (Блочно-строчные элементы)
* Примеры: `<button>`, `<input>` (по умолчанию `inline-block`). `<img>` формально строчный *заменяемый* элемент, но ведёт себя как `inline-block`: `width` и `height` на него действуют.
* Элементы выстраиваются в одну строку (как `inline`), но при этом **полноценно воспринимают `width`, `height`, `margin` и `padding` со всех сторон** (как `block`).

### 4. `display: none` и родственные приёмы скрытия
* `display: none` — элемент **остаётся в DOM** (JavaScript его находит через `querySelector`), но не попадает в дерево отрисовки (Render Tree, Лекция 35): не рисуется и **не занимает места**.
* `visibility: hidden` — элемент невидим, но **продолжает занимать место** в потоке.
* `opacity: 0` — элемент прозрачен, место занимает и остаётся кликабельным.

### 5. Другие значения `display`
`display: flex` и `display: grid` превращают контейнер в гибкую или сеточную раскладку. Их мы разберём в Лекции 34.2.

## Подглава 34.1.6: Схлопывание внешних отступов (Margin Collapse)

В нормальном потоке документа вертикальные внешние отступы (`margin-top` и `margin-bottom`) соседних или вложенных блочных элементов **не суммируются**, а схлопываются в один общий отступ, равный **максимальному из них**.

```text
  [ Блок 1 ] (margin-bottom: 30px)
       |
       |  <--- Физический отступ между блоками будет не 50px, а MAX(30, 20) = 30px!
       |
  [ Блок 2 ] (margin-top: 20px)
```

### Сценарии схлопывания:
1. **Соседние блоки в потоке:** у верхнего блока `margin-bottom: 30px`, у нижнего `margin-top: 20px`. Итоговое расстояние между ними = `30px`.
2. **Родитель и первый/последний ребёнок:** если у родителя нет `border`, `padding` или `overflow: hidden`, `margin-top` первого ребёнка «проваливается» наружу и становится отступом самого родителя. То же касается `margin-bottom` последнего ребёнка, но только если у родителя не задана высота (`height`).
3. **Пустой блок:** у блока без содержимого, рамки, `padding` и высоты верхний и нижний `margin` схлопываются сами с собой.
4. **Отрицательные значения:** положительный и отрицательный `margin` складываются (`30px` и `-10px` дадут `20px`); два отрицательных дают меньшее из них.

### Когда отступы НЕ схлопываются:
* **Горизонтальные** `margin-left` и `margin-right` не схлопываются никогда.
* Между детьми контейнера с `display: flex` или `display: grid` (Лекция 34.2).
* У элементов `inline-block`, а также у `float` и абсолютно позиционированных элементов.

### Как предотвратить схлопывание отступов:
* Перевести контейнер в `display: flex` или `display: grid` (изучим в Лекции 34.2).
* Добавить родителю минимальный `padding` (например, `padding-top: 1px`) или `border`.
* Задать контейнеру свойство `overflow: auto` или `overflow: hidden` (создание BFC — Block Formatting Context). Побочный эффект: `overflow` обрезает или прокручивает выступающее содержимое.
* Самый чистый способ без побочных эффектов: `display: flow-root` (создаёт BFC только ради изоляции отступов).

### Чек-лист базовой CSS-стилизации:
1. **Всегда включайте глобальный сброс Box Model:** `*, *::before, *::after { box-sizing: border-box; }`.

### Ответ к Задаче 2:
1. **Расчет весов:**
