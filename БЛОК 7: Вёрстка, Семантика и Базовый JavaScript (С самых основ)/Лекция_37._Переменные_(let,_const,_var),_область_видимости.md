# Лекция 37: Переменные (let, const, устаревший var), область видимости блочная vs функциональная, поднятие (Hoisting) и временная мёртвая зона (TDZ)

В этой лекции мы детально изучим механизм работы с переменными в JavaScript. ## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. Переменная (Variable)**
> * **Что это:** Поименованное «хранилище» данных в памяти программы. По имени переменной мы читаем или меняем хранящееся значение. Внутри движка это запись в таблице (Environment Record), хранящая значение (для примитивов) или ссылку на объект.

> 📌 **2. Область видимости (Scope)**
> * **Что это:** Участок кода, в пределах которого переменная доступна по имени. В JS существует глобальная, функциональная и блочная области видимости.

> 📌 **3. Лексическое окружение (Lexical Environment)**
> * **Что это:** Понятие из спецификации ECMAScript: «таблица» с переменными текущей области видимости (**Environment Record**) и ссылкой на внешнее окружение (**Outer Lexical Environment**). Это **модель для понимания**, как работает язык; конкретные движки (в том числе V8) реализуют её по-своему и могут хранить переменные в регистрах, на стеке или в специальных объектах-контекстах.

> 📌 **4. Поднятие (Hoisting)**
> * **Что это:** Поведение JavaScript, при котором объявления переменных (`var`, `let`, `const`) и функций (`Function Declaration`) становятся известны движку **до** выполнения первой строки кода своей области видимости. Код при этом физически никуда не «поднимается» — это лишь удобный образ того, что происходит.

> 📌 **5. Временная мёртвая зона (Temporal Dead Zone / TDZ)**
> * **Что это:** Период от начала области видимости (где переменная `let` или `const` уже известна, но находится в состоянии *Uninitialized*) до строки, где она объявляется и получает значение. Любое обращение к переменной в TDZ приводит к ошибке `ReferenceError`.

> 📌 **6. Затенение (Shadowing)**
> * **Что это:** Ситуация, когда во внутренней области видимости объявлена переменная с тем же именем, что и во внешней. Внутри неё имя «указывает» на внутреннюю переменную, а внешняя временно становится недоступной.

## Подглава 37.1: Способы объявления переменных в JS (`let`, `const`, `var`)

### 0. Основы: что такое переменная и как её объявить
**Объявить** переменную — значит создать её и дать имя. **Присвоить** — положить в неё значение.

```javascript
let age = 25;        // объявили и сразу присвоили значение
let city;            // объявили без значения: сейчас там undefined
city = "Москва";     // присвоили значение позже
let a = 1, b = 2;    // можно объявить несколько через запятую
```

**Правила имён (идентификаторов):**
* состоят из букв, цифр, `_` и `$`, но **не могут начинаться с цифры**;
* **регистр важен:** `age` и `Age` — разные переменные;
* нельзя использовать зарезервированные слова (`let`, `class`, `return`, `if` и др.);
* принято писать в **camelCase** (`userName`, `totalPrice`) и давать понятные имена: `userAge`, а не `x1`;
* значения-константы, известные заранее и не меняющиеся, часто пишут в `UPPER_SNAKE_CASE`: `const MAX_USERS = 100;`.

Типы значений (числа, строки и т. д.) мы изучим в Лекции 38.

### История и сравнение
До стандарта **ES6 (ES2015)** в JavaScript существовал единственный способ объявления переменных — ключевое слово `var`. В ES6 были добавлены `let` и `const`, устранившие большинство исторических проблем.

### Сравнительный анализ `let`, `const` и `var`:

| Характеристика | `let` | `const` | `var` |
| :--- | :--- | :--- | :--- |
| **Область видимости** | Блочная (`{ ... }`) | Блочная (`{ ... }`) | Функциональная (или глобальная) |
| **Переприсвоение (Reassignment)** | Разрешено | ❌ Запрещено (`TypeError`) | Разрешено |
| **Повторное объявление в одной области** | ❌ Запрещено (`SyntaxError`) | ❌ Запрещено (`SyntaxError`) | Разрешено (новая переменная не создаётся, используется прежняя) |
| **Инициализация при объявлении** | Необязательна (по умолчанию `undefined`) | **Обязательна** (иначе `SyntaxError`) | Необязательна (по умолчанию `undefined`) |
| **Поведение при Hoisting** | Находится в **TDZ** | Находится в **TDZ** | Инициализируется как `undefined` |
| **Свойство в `window` (в глобальной области обычного скрипта, не модуля)** | Нет | Нет | **Да** (`var x = 1` → `window.x === 1`) |

### Особенности `const` и мутабельность объектов:
Ключевое слово `const` запрещает **переприсваивание самой переменной** (то есть замену значения или ссылки), но **не делает объект неизменяемым**:

```javascript
const user = { name: "Алексей", role: "Developer" };

// 1. Изменение свойства ОБЪЕКТА — РАЗРЕШЕНО!
user.role = "Lead"; // Успешно!
user.age = 30;      // Успешно!

// 2. Переприсвоение ПЕРЕМЕННОЙ — ЗАПРЕЩЕНО!
// user = { name: "Иван" }; // Uncaught TypeError: Assignment to constant variable.

// 3. const без значения — ошибка разбора:
// const limit; // Uncaught SyntaxError: Missing initializer in const declaration

// Если нужно запретить изменение свойств объекта (неглубокая заморозка):
const frozenUser = Object.freeze({ name: "Алексей", role: "Developer" });
// frozenUser.role = "Lead"; // В "use strict" выбросит TypeError, в обычном режиме молча проигнорируется
```
> `Object.freeze` замораживает только **верхний уровень** свойств: вложенные объекты остаются изменяемыми. Подробнее — в Лекции 75.

## Подглава 37.2: Область видимости: Глобальная, Функциональная и Блочная

Область видимости определяет, где переменная доступна для чтения и записи.

```text
+-------------------------------------------------------------------+
| GLOBAL SCOPE (глобальная область)                                 |
|   let globalVar = "I am Global";   // let/const НЕ попадают в window|
|                                                                   |
|   function foo() {                                                |
|     // FUNCTION SCOPE                                             |
|     var funcVar = "I am Function Scope";                          |
|                                                                   |
|     if (true) {                                                   |
|       // BLOCK SCOPE                                              |
|       let blockVar = "I am Block Scope";                          |
|       var funcVarInsideIf = "I leak outside block!";              |
|     }                                                             |
|     // funcVarInsideIf — ДОСТУПНА ЗДЕСЬ!                          |
|     // blockVar — ReferenceError: blockVar is not defined          |
|   }                                                               |
+-------------------------------------------------------------------+
```

### 1. Блочная область видимости (`let` / `const`):
Фигурные скобки `{ ... }` блока кода (тело `if`, циклов `for`/`while`, блоки `try..catch` или даже одиночный блок `{}`) создают новую блочную область видимости для `let` и `const`. (Фигурные скобки объектного литерала `{ name: "A" }` область видимости не создают.)

```javascript
{
  let blockScoped = "Видна только внутри скобок";
  const alsoBlock = 100;
}
// console.log(blockScoped); // ReferenceError: blockScoped is not defined
```

### 2. Функциональная область видимости (`var`):
Переменные `var` игнорируют обычные блоки кода (`if`, `for`, `switch`) и «протекают» наружу — до ближайшей функции (или до глобальной области, если функции нет):

```javascript
function calculate() {
  if (true) {
    var total = 500; // var проигнорирует блок if!
  }
  console.log(total); // 500 — переменная видна в пределах всей функции!
}
```

### 3. Цепочка видимости и затенение (Shadowing)
Когда движок встречает имя переменной, он ищет её сначала в текущей области видимости, затем — во внешней, и так вверх до глобальной. Первая найденная переменная «побеждает»; одноимённые во внешних областях при этом **затеняются**:

```javascript
let color = "синий";           // внешняя область

function paint() {
  let color = "красный";       // внутренняя область: затеняет внешнюю
  console.log(color);          // "красный"
}

paint();
console.log(color);            // "синий" — внешняя переменная не изменилась
```

### 4. Классическая ловушка `var` в циклах:
Из-за отсутствия блочной области видимости `var` создаёт **одну единую переменную** на все итерации цикла. Функция внутри `setTimeout` (Лекция 73) запускается **позже**, когда цикл уже завершился и `i` стала равна `3`:

```javascript
// Проблема с var:
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("var i:", i), 100);
}
// Вывод через 100ms:
// var i: 3
// var i: 3
// var i: 3

// Решение с let (на КАЖДОЙ итерации создаётся своя переменная j):
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log("let j:", j), 100);
}
// Вывод через 100ms:
// let j: 0
// let j: 1
// let j: 2
```
(Почему каждая функция «помнит» своё `j` — это замыкания, Лекция 68.)

## Подглава 37.3: Модель движка — Lexical Environment и Hoisting

Для объяснения поведения переменных удобно считать, что выполнение JS-кода делится на два этапа. Это **модель**, а не буквальное описание работы V8 (мы помним из Лекции 36, что V8 компилирует код в байт-код и исполняет его, а не интерпретирует текст построчно):
1. **Этап создания окружения (Creation Phase):** при входе в область видимости (скрипт, функцию, блок) движок ещё до исполнения кода «узнаёт» обо всех объявлениях в ней и заводит для них записи в **Lexical Environment**.
2. **Этап выполнения (Execution Phase):** инструкции выполняются по порядку, переменные получают значения, производятся вычисления.

```text
+-------------------------------------------------------------------+
| LEXICAL ENVIRONMENT (состояние в момент входа в область)          |
| +---------------------------------------------------------------+ |
| | Environment Record (Запись окружения):                        | |
| |   - a:      undefined          (объявлена через var)          | |
| |   - b:      <uninitialized>    (let/const: TDZ)               | |
| |   - myFunc: <function object>  (Function Declaration)         | |
| +---------------------------------------------------------------+ |
| | Outer Environment Reference (ссылка на внешнее окружение)     | |
| +---------------------------------------------------------------+ |
+-------------------------------------------------------------------+
```

### Что происходит при Hoisting (Поднятии):

* **`Function Declaration`:** становится известной целиком вместе с телом. Функцию можно вызвать ещё **до** строки её объявления в коде.
* **`var`:** переменная известна с самого начала области видимости, и ей сразу присваивается значение **`undefined`**.
* **`let` / `const`:** имя тоже известно с начала области видимости, но значение не присвоено — переменная в состоянии **`Uninitialized`** (неинициализирована) до строки объявления. Это и есть TDZ. (То же верно для объявлений `class`.)

```javascript
console.log(a); // undefined (var известна и равна undefined)
var a = 5;

sayHello(); // "Привет!" (Function Declaration доступна целиком)
function sayHello() {
  console.log("Привет!");
}

// console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 10;
```

> ⚠️ **Не путайте `Function Declaration` и `Function Expression`.** Если функция записана как значение переменной, поднимается только переменная, но не функция:
> ```javascript
> greet(); // TypeError: greet is not a function  (greet есть, но равна undefined)
> var greet = function () { console.log("Привет!"); };
> ```
> Для `let`/`const` такой вызов до объявления дал бы `ReferenceError` (TDZ). О `Function Expression` подробнее — в Лекции 47.

## Подглава 37.4: Временная мёртвая зона (Temporal Dead Zone — TDZ)

**Temporal Dead Zone (TDZ)** — это промежуток между началом области видимости и строкой, на которой объявлена и инициализирована переменная `let` или `const`.

```javascript
{ // <--- Вход в блочную область видимости. Начинается TDZ для 'x'!
  //
  // TDZ продолжается здесь
  // console.log(x); // Uncaught ReferenceError: Cannot access 'x' before initialization
  //
  let x = 42; // <--- Строка объявления и инициализации. Конец TDZ для 'x'!
  console.log(x); // 42 — переменная доступна!
}
```

### Важные нюансы TDZ:

1. **TDZ зависит от ВРЕМЕНИ выполнения, а не только от положения в файле:**

```javascript
function printValue() {
  console.log(value); // Будет ошибка или нет — зависит от момента вызова!
}

// printValue(); // Ошибка! Если вызвать здесь, value ещё в TDZ.

let value = "JS Engine";

printValue(); // Успешно выведет "JS Engine": вызов произошёл ПОСЛЕ выхода из TDZ
```

2. **TDZ и параметры по умолчанию (затенение):**

```javascript
let y = 10;

function test(y = y) { // Ошибка!
  return y;
}
// test(); // Uncaught ReferenceError: Cannot access 'y' before initialization
```
Здесь параметр `y` затеняет внешнюю `y`. Выражение справа от `=` — тоже имя `y`, и оно ссылается на **сам параметр `y`** (а не на внешнюю переменную), который в этот момент ещё не инициализирован, то есть находится в TDZ. (Параметры по умолчанию — Лекция 46.)

3. **`typeof` в TDZ тоже выбрасывает ошибку.** Для полностью необъявленной переменной `typeof x` безопасно вернёт `"undefined"`, но для переменной в TDZ — `ReferenceError`:
```javascript
{
  // typeof z; // ReferenceError: Cannot access 'z' before initialization
  let z = 1;
}
```

## Подглава 37.5: Полноценный практический пример (HTML + JS)

Приведённый ниже автономный HTML-документ демонстрирует различие между `var`, `let` и `const`, поднятие функций, границы TDZ и поведение в циклах. Сохраните его в файл, откройте в браузере и откройте DevTools (Лекция 34.3).

```html

    .success { color: #4ade80; }
    .error { color: #f87171; }
  </style>
</head>
<body>
  <h1>Лаборатория JavaScript: Scope, Hoisting & TDZ</h1>
  <div id="output" class="log-box"></div>

  <script>
    "use strict";
    const logBox = document.getElementById("output");

    function log(msg, isError = false) {
      const line = document.createElement("div");
      line.className = isError ? "error" : "success";
      line.textContent = msg;
      logBox.appendChild(line);
    }

    log("--- 1. Hoisting: var и Function Declaration ---");
    log("Значение myVar до объявления: " + myVar);          // "undefined"
    var myVar = "Я var!";
    log("Значение myVar после объявления: " + myVar);
    log(hoistedFn());                                       // функция работает до своего объявления
    function hoistedFn() {
      return "Function Declaration доступна до строки объявления";
    }

    log("\n--- 2. Temporal Dead Zone (TDZ) ---");
    try {
      log(myLet); // myLet ещё в TDZ → ReferenceError, который перехватывает catch
    } catch (err) {
      log("Перехвачена ошибка TDZ: " + err.message, true);
    }
    let myLet = "Я let!";
    log("Значение myLet после инициализации: " + myLet);

    log("\n--- 3. Мутабельность свойств const-объекта ---");
    const appConfig = { theme: "dark", version: 1 };
    appConfig.theme = "light"; // Изменение свойства — разрешено
    log("Изменённое свойство const-объекта: theme = " + appConfig.theme);

    log("\n--- 4. Циклы: var и let (результат появится через 50 мс) ---");
    for (var k = 0; k < 2; k++) {
      setTimeout(() => log(`var k = ${k}`), 50);   // выведет 2 и 2
    }
    for (let i = 0; i < 2; i++) {
      setTimeout(() => log(`let i = ${i}`), 50);   // выведет 0 и 1
    }
  </script>
</body>
</html>
```

## Подглава 37.6: Чек-лист разработчика & Практические задачи

### Чек-лист правил работы с переменными:
1. **Используйте `const` по умолчанию:** объявляйте переменные через `const`. Если значение переменной нужно менять, используйте `let`.
2. **В новом коде `var` не нужен:** вместо него всегда есть `let` или `const`. Но `var` нужно уметь читать (старые проекты, собеседования — Лекция 69).
3. **Объявляйте переменную до первого использования и как можно ближе к месту, где она нужна:** так код понятнее, а в TDZ вы не попадёте.
4. **Не полагайтесь на Hoisting переменных:** единственное полезное поднятие — это `Function Declaration` для организации структуры файла.
5. **Помните о мутабельности `const`:** он не запрещает менять свойства объекта. `Object.freeze()` блокирует их, но только на верхнем уровне.

## Подсказки и решения к практическим задачам

<details>
<summary><b>Решение задачи 1</b></summary>

**Ответ:**
```text
undefined
2
1
```
**Объяснение:**
1. Внутри `foo()` объявление `var a` относится ко всей функции и начинается с значения `undefined`. Локальная `a` затеняет глобальную `a`. Поэтому первый `console.log(a)` выводит `undefined` (а не `1`!).
2. Затем выполняется присваивание `a = 2`, и второй `console.log(a)` выводит `2`.
3. Внешний `console.log(a)` обращается к глобальной переменной `a`, значение которой осталось `1`.
</details>

<details>
<summary><b>Решение задачи 2</b></summary>

**Исправленный код:**
```javascript
function processOrders(count) {
  if (count > 0) {
    let total = count * 100; // Объявление let ДО использования!
    console.log("Обработка " + total + " заказов");
  }
}
processOrders(5);
```
**Объяснение:** в исходном коде `console.log(total)` выполнялся, пока `total` находилась в TDZ, что вызывало `ReferenceError: Cannot access 'total' before initialization`.
</details>

<details>
<summary><b>Решение задачи 3</b></summary>

**Способ 1 (через `let` — рекомендуемый):**
```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log("Индекс:", i), 100);
}
```

**Способ 2 (через IIFE / замыкание):**
```javascript
for (var i = 0; i < 3; i++) {
  (function(currentI) {
    setTimeout(function() {
      console.log("Индекс:", currentI);
    }, 100);
  })(i);
}
```
**Пояснение:** IIFE (Immediately Invoked Function Expression) — функция, которая создаётся и тут же вызывается: `(function(...) { ... })(значение)`. На каждой итерации она получает текущее значение `i` в параметр `currentI` — у каждого вызова своя область видимости и своя копия значения. Именно её «запоминает» функция внутри `setTimeout` (замыкания — Лекция 68).
</details>

2 Local Function
3 Global

**Объяснение:** каждая область видимости объявляет свой `x`, который затеняет внешнюю переменную только внутри своей области. (`console.log` выводит строки без кавычек.)
</details>

<details>
<summary><b>Решение задачи 5</b></summary>

**Исправленный код:**
```javascript
"use strict";
const settings = Object.freeze({
  apiUrl: "https://api.example.com",
  timeout: 5000
});

// settings.timeout = 10000; // В "use strict" вызовет Uncaught TypeError: Cannot assign to read only property 'timeout' of object
```
**Пояснение:** без `"use strict"` присваивание было бы молча проигнорировано. Заморозка неглубокая: если бы в `settings` был вложенный объект, его свойства остались бы изменяемыми.
</details>

<details>
<summary><b>Решение задачи 6</b></summary>

**Ответ:**
```text
Uncaught ReferenceError: Cannot access 'value' before initialization
```
**Объяснение:** при входе в `demo()` локальная `let value` уже известна движку и затеняет глобальную `value`, но до строки `let value = "B"` находится в **TDZ**. Поэтому `console.log(value)` не берёт значение `"A"` из внешней области, а выбрасывает `ReferenceError`. Это и доказывает, что `let` тоже «поднимается»: если бы нет, вывелось бы `"A"`.
</details>
