# Лекция 34.5: Препроцессор SCSS (Синтаксис SCSS, Dart Sass, npm-скрипты, переменные, вложенность, партиалы, @use / @forward, миксины, функции, @extend и БЭМ)

В этой лекции мы изучим мощный инструмент современной верстки — препроцессор **SCSS (SASS)**. Мы разберём установку и компиляцию стилей через **Dart Sass** и npm-скрипты, научимся проектировать чистую модульную архитектуру с помощью современных директив **`@use`** и **`@forward`**, изучим переменные, миксины, функции и селектор **`&`** для идеальной интеграции с **БЭМ**, а также сравним возможности SCSS с современным нативным CSS3.

---

## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. CSS-препроцессор (CSS Preprocessor)**
> * **Что это:** Инструмент, расширяющий стандартный синтаксис CSS с помощью переменных, вложенности, миксинов, функций и модулей, с последующей компиляцией в валидный CSS-код, понятный браузеру.

> 📌 **2. SCSS (Sassy CSS)**
> * **Что это:** Диалект языка SASS с синтаксисом, максимально близким к CSS (использует фигурные скобки `{}` и точки с запятой `;`). Является строгим надмножеством (superset) CSS: любой валидный CSS-код одновременно является валидным SCSS-кодом.

> 📌 **3. Dart Sass**
> * **Что это:** Официальная, эталонная и наиболее актуальная реализация компилятора SASS/SCSS, поддерживаемая core-командой SASS (прежние реализации `Ruby Sass` и `LibSass` / `Node Sass` объявлены устаревшими и больше не развиваются).

> 📌 **4. Партиал (Partial)**
> * **Что это:** Вспомогательный SCSS-файл, название которого начинается с нижнего подчёркивания (например, `_variables.scss`). Компилятор Dart Sass не превращает партиалы в отдельные `.css` файлы, а использует их для сборки единого итогового бандла.

> 📌 **5. Директивы `@use` и `@forward`**
> * **Что это:** Современные стандартные директивы SASS для импорта и модульной агрегации стилей. `@use` загружает партиал с изоляцией пространства имён, а `@forward` реэкспортирует функции, миксины и переменные из партиалов дальше по цепочке. Заменяют директиву `@import`, которая объявлена устаревшей и будет удалена в Dart Sass 3.0.

> 📌 **6. Плейсхолдер (`%placeholder`)**
> * **Что это:** Специальный шаблонный CSS-селектор в SCSS, начинающийся с символа `%`. Не попадает в итоговый CSS-файл до тех пор, пока не будет вызван через директиву `@extend`.

## Подглава 34.5.1: Введение в SCSS/SASS и установка Dart Sass через npm

### 1. Зачем нужен препроцессор в эпоху современного CSS?
В ранних версиях CSS отсутствие переменных, повторно используемых функций и модульности приводило к дублированию кода (нарушение принципа **DRY — Don't Repeat Yourself**) и разрастанию одиночных стилей на тысячи строк. 

Препроцессор **SCSS** решает эту проблему на этапе сборки:
1. **Модульность:** разбиение проекта на десятки мелких логических файлов (партиалов) без потери производительности (в браузер уходит единый сжатый CSS-файл).
2. **Переиспользование:** создание шаблонов (миксинов) и функций вычисления параметров.
3. **Сокращение кода:** лаконичная запись вложенных селекторов и интеграция с БЭМ.

```text
+------------------------+      +--------------------------+      +------------------------+
| SCSS Исходники         |      | Компилятор Sass          |      | Итоговый CSS           |
| - _variables.scss      |      | (npm i -D sass)          |      | dist/css/style.css     |
| - _mixins.scss         | ---> | sass --watch src:dist    | ---> | (Один файл             |
| - main.scss            |      |                          |      | для браузера)          |
+------------------------+      +--------------------------+      +------------------------+
```

### 2. SCSS vs SASS: В чём разница?
Язык SASS имеет два синтаксиса:
* **SASS (Indented Syntax, `.sass`):** отступовый синтаксис без фигурных скобок `{}` и точек с запятой `;`. Чувствителен к отступам. Поддерживается, но используется заметно реже.
* **SCSS (Sassy CSS, `.scss`):** современный синтаксис с `{}` и `;`. Полностью совместим с классическим CSS. **Именно синтаксис SCSS является индустриальным стандартом.**

### 3. Установка и запуск компилятора Dart Sass
Для работы с SCSS необходим Node.js и пакет **`sass` (Dart Sass)**.

Установка локально в devDependencies проекта (на основе знаний из Лекции 34.4):
```bash
npm install -D sass
```

Добавление скриптов компиляции в `package.json`:
```json
{
  "name": "todo-app-scss",
  "version": "1.0.0",
  "private": true,
  "scripts": {
    "build:css": "sass src/scss/main.scss dist/css/style.css --style=compressed --no-source-map",
    "dev:css": "sass --watch src/scss/main.scss dist/css/style.css"
  },
  "devDependencies": {
    "sass": "^1.80.6"
  }
}
```

Запуск скриптов:
```bash
npm run dev:css     # режим разработки: следит за файлами и перекомпилирует CSS
npm run build:css   # однократная сборка для продакшена
```

* **`sass --watch`:** запускает фоновый процесс, который отслеживает любые изменения в `.scss` файлах и мгновенно перекомпилирует итоговый `dist/css/style.css`.
* **`--style=compressed`:** минифицирует итоговый CSS-файл для продакшена.

## Подглава 34.5.2: Переменные, Вложенность (`Nesting`) и родительский селектор `&`

### 1. Переменные в SCSS (`$variable`)
Переменные в SCSS объявляются с помощью знака доллара **`$`**:

```scss
// Объявление переменных
$font-primary: 'Inter', system-ui, sans-serif;
$color-primary: #2563eb;
$color-danger: #ef4444;
$spacing-base: 16px;
$radius-md: 8px;

// Использование (комментарии `//` есть только в SCSS и в итоговый CSS не попадают)
.button {
  font-family: $font-primary;
  background-color: $color-primary;
  padding: $spacing-base ($spacing-base * 1.5);
  border-radius: $radius-md;
}
```

### 2. Вложенность (`Nesting`) и амперсанд `&`
Вложенность позволяет записывать дочерние селекторы внутри родительских, повторяя структуру HTML-разметки:

```scss
.card {
  background-color: #ffffff;
  padding: 20px;

  // Вложенный селектор: переводится в .card p
  p {
    color: #475569;
  }

  // Элемент БЭМ через &: переводится в .card__title (подробнее в подглаве 34.5.5)
  &__title {
    font-size: 1.25rem;
    color: #1e293b;
  }

  // Амперсанд &: обращение к текущему родительскому селектору
  &:hover {
    box-shadow: 0 10px 15px -3px rgba(0, 0, 0, 0.1);
  }

  // Модификатор БЭМ: переводится в .card--featured
  &--featured {
    border: 2px solid $color-primary;
  }
}
```

### 🚨 Предупреждение о специфичности: Правило 3 уровней
Глубокая вложенность — самая частая ошибка новичков при работе с SCSS. 

**Антипаттерн (Задушенная специфичность):**
```scss
// УЖАСНО: Порождает селектор вида .nav ul li a span
.nav {
  ul {
    li {
      a {
        span {
          color: red; // Специфичность (0, 0, 1, 4): один класс и четыре тега
        }
      }
    }
  }
}
```

**Правило 3 уровней (Level 3 Rule):**
Никогда не вкладывайте селекторы глубже **3 уровней** (а при использовании БЭМ — не глубже 1–2 уровней). Помните из Лекции 34.1: селектор `.nav ul li a span` весит (0, 0, 1, 4), и переопределить его простым классом `(0, 0, 1, 0)` не получится. Высокая специфичность усложняет отладку в DevTools!

## Подглава 34.5.3: Модульность: Партиалы (`_partial.scss`), `@use` и `@forward`

### 1. Концепция партиалов
Чтобы проект оставался поддерживаемым, стили делят на небольшие файлы — **партиалы**. Имя партиала всегда начинается с нижнего подчёркивания: `_variables.scss`, `_button.scss`, `_mixins.scss`.

Компилятор Dart Sass игнорирует файлы с `_` на старте и не создает для них отдельные CSS-файлы.

### 2. Почему `@import` устарел?
Раньше в SCSS использовалась директива `@import 'variables'`. **Сегодня `@import` официально признан устаревшим (deprecated; предупреждения появились в Dart Sass 1.80, удалён он будет в Dart Sass 3.0) по 3 причинам:**
1. **Глобальное загрязнение:** все переменные и миксины попадали в единое глобальное пространство имён (конфликты имён импортированных библиотек).
2. **Дублирование CSS:** если 10 файлов делали `@import 'mixins'`, и там был CSS-код, он копировался в итоговый бандл 10 раз!
3. **Неясность источника:** глядя на переменную или миксин в коде, нельзя понять, в каком из подключённых файлов они объявлены.

### 3. Директива `@use`: Изоляция пространств имён
Директива **`@use`** импортирует партиал с созданием отдельного пространства имён (названного по имени файла):

```scss
// _variables.scss
$color-primary: #3b82f6;
$color-bg: #f8fafc;

// _button.scss
@use 'variables'; // Создаёт модуль 'variables'

.btn {
  // Обращение через имя модуля и точку:
  background-color: variables.$color-primary;
}
```

Правила `@use`:
* `@use` пишется в начале файла, до любых правил (кроме `@forward`).
* Каждый модуль загружается один раз, поэтому его CSS не дублируется.

Вы можете задать кастомный псевдоним или убрать пространство имён:
```scss
@use 'variables' as v; // Использование: v.$color-primary
@use 'variables' as *; // Без префикса (использовать с осторожностью!)
```

#### Переопределение переменных при импорте (`with`):
```scss
// _theme.scss
$theme-dark: false !default; // !default позволяет переопределять переменную

// main.scss
@use 'theme' with (
  $theme-dark: true
);
```

### 4. Директива `@forward`: Агрегация и реэкспорт
Директива **`@forward`** применяется в промежуточных индексных файлах (`_index.scss`), чтобы собрать множество мелких партиалов и отдать их наружу единым модулем:

```scss
// abstracts/_index.scss
@forward 'variables';
@forward 'mixins';
@forward 'functions';

// main.scss
@use 'abstracts' as a; // Получаем доступ сразу ко всем переменным и миксинам из abstracts!
```

> ℹ️ `@forward` только пробрасывает содержимое дальше. Внутри самого `_index.scss` забранные через `@forward` переменные и миксины недоступны: для этого в нём нужен ещё и `@use`.

## Подглава 34.5.4: Управляющие абстракции: Миксины (`@mixin`), Функции (`@function`) и `@extend`

### 1. Миксины (`@mixin` и `@include`)
Миксины позволяют создавать повторно используемые блоки CSS-свойств с поддержкой параметров:

```scss
// 1. Объявление миксина с аргументами по умолчанию
@mixin flex-center($direction: row, $gap: 0) {
  display: flex;
  flex-direction: $direction;
  justify-content: center;
  align-items: center;
  gap: $gap;
}

// 2. Использование миксина
.hero {
  @include flex-center(column, 20px);
}

.icon-box {
  @include flex-center(); // Использует значения по умолчанию
}
```

#### Передача блока стилей через `@content`:
```scss
// Миксин для медиазапросов (адаптив)
@mixin respond-to($breakpoint) {
  @if $breakpoint == 'tablet' {
    @media (min-width: 768px) { @content; }
  } @else if $breakpoint == 'desktop' {
    @media (min-width: 1024px) { @content; }
  } @else {
    @error "Неизвестная точка: #{$breakpoint}"; // Ошибка компиляции вместо молчаливого пропуска
  }
}

// Использование
.card {
  width: 100%;

  @include respond-to('tablet') {
    width: 50%;
  }
}
```

### 2. Кастомные функции (`@function` и `@return`)
В отличие от миксинов, возвращающих блоки CSS-свойств, **функции возвращают конкретное вычисленное значение**:

```scss
@use 'sass:math'; // Встроенный модуль Sass для математики (пишется в начале файла)

// Функция перевода пикселей в rem (базовый шрифт 16px)
@function px-to-rem($px-value) {
  @return math.div($px-value, 16px) * 1rem;
}

.title {
  font-size: px-to-rem(24px); // Скомпилируется в: font-size: 1.5rem;
  margin-bottom: px-to-rem(16px); // Скомпилируется в: margin-bottom: 1rem;
}
```

> ⚠️ Делить через `/` (`$a / 16px`) в современном Sass нельзя: этот синтаксис объявлен устаревшим. Используйте `math.div()`.

### 3. `@extend` и плейсхолдеры (`%placeholder`)
Директива `@extend` позволяет нескольким селекторам наследовать стили друг друга.

#### ⚠️ В чём опасность `@extend .class`?
`@extend .class` добавляет новый селектор во **все** правила, где встречается этот класс, в том числе в сложные (`.card .class`). Из-за этого итоговый CSS неожиданно разрастается, а порядок правил и специфичность меняются в местах, о которых вы не думали.

#### Безопасный подход: Плейсхолдеры (`%`)
Плейсхолдеры (`%placeholder-name`) не генерируют независимый CSS-класс, а служат чистой заготовкой для наследования:

```scss
// Плейсхолдер (не скомпилируется сам по себе)
%button-base {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  padding: 10px 20px;
  border-radius: 6px;
  font-weight: 600;
  border: none;
  cursor: pointer;
}

// Наследование
.btn-primary {
  @extend %button-base;
  background-color: #2563eb;
  color: #ffffff;
}

.btn-danger {
  @extend %button-base;
  background-color: #ef4444;
  color: #ffffff;
}
```

**Результат в скомпилированном CSS:**
```css
/* Sass сгруппировал базовые стили в один эффективный селектор */
.btn-primary, .btn-danger {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  padding: 10px 20px;
  border-radius: 6px;
  font-weight: 600;
  border: none;
  cursor: pointer;
}

.btn-primary { background-color: #2563eb; color: #ffffff; }
.btn-danger { background-color: #ef4444; color: #ffffff; }
```

> ℹ️ Многие команды вообще отказываются от `@extend` в пользу миксинов: поведение миксина проще предсказать.

## Подглава 34.5.5: Интеграция SCSS с методологией БЭМ и сравнение с нативным CSS3

### 1. SCSS + БЭМ = Идеальная гармония
Благодаря амперсанду **`&`**, SCSS избавляет от бесконечного дублирования имени блока при написании БЭМ-структур (изученных в Лекции 34):

```scss
// Блок Todo Item
.todo-item {
  display: flex;
  align-items: center;
  padding: 12px;
  background-color: #ffffff;

  // Элемент: .todo-item__checkbox
  &__checkbox {
    margin-right: 12px;
  }

  // Элемент: .todo-item__text
  &__text {
    flex: 1;
    color: #1e293b;
  }

  // Модификатор блока: .todo-item--completed
  &--completed {
    opacity: 0.6;

    // Вложенный элемент внутри модификатора
    .todo-item__text {
      text-decoration: line-through;
    }
  }
}
```

### 2. SCSS vs Нативный современный CSS3
Современный CSS уже получил переменные (`--var`) и нативную вложенность. Зачем же до сих пор нужен SCSS?

| Возможность | Нативный CSS | SCSS / SASS |
| :--- | :--- | :--- |
| **Переменные** | Runtime: `var(--color)`, значение можно менять в браузере (JS, темы) | Build-time: `$color` превращается в константу при компиляции, в браузере переменной уже нет |
| **Вложенность** | Поддерживается современными браузерами (`.card { & .child { } }`), но **нельзя дописать суффикс**: `&__title` в нативном CSS не работает | `&__title` и `&--modifier` компилируются в плоский CSS, что очень удобно для БЭМ |
| **Переменные в `@media`** | ❌ `@media (min-width: var(--bp))` не работает | ✅ `@media (min-width: $bp)` |
| **Модульность** | CSS `@import` загружает файлы отдельными сетевыми запросами | Сборка десятков файлов в один бандл (`@use`, `@forward`) без лишних запросов |
| **Миксины и функции** | Миксинов нет. Функции `@function --name()` пока только в Chrome / Edge 139+ (в Firefox и Safari нет) | Полная поддержка `@mixin`, `@function`, `@if`, `@each` во всех браузерах (результат — обычный CSS) |
| **Работа с цветом** | `color-mix()` и относительные цвета (`oklch(from var(--c) l c h)`) | Модуль `sass:color`: `color.adjust()`, `color.scale()`, `color.mix()` (считаются при сборке) |

На практике их часто сочетают: SCSS отвечает за структуру (партиалы, миксины, `&__element`), а CSS-переменные `--var` хранят значения, которые должны меняться в браузере (например, тёмная и светлая темы).

## Подглава 34.5.6: Полный практический пример архитектуры SCSS-проекта

### Структура папок (упрощённая «Архитектура 7-1»):
```text
src/scss/
├── abstracts/
│   ├── _index.scss
│   ├── _variables.scss
│   └── _mixins.scss
├── components/
│   └── _todo-card.scss
└── main.scss
```

#### 1. Файл `src/scss/abstracts/_variables.scss`:
```scss
$color-primary: #2563eb;
$color-success: #16a34a;
$color-text: #0f172a;
$color-bg: #f8fafc;
$radius-base: 8px;
```

#### 2. Файл `src/scss/abstracts/_mixins.scss`:
```scss
@mixin flex-between {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
```

#### 3. Файл `src/scss/abstracts/_index.scss`:
```scss
@forward 'variables';
@forward 'mixins';
```

#### 4. Файл `src/scss/components/_todo-card.scss`:
```scss
@use '../abstracts' as a;

.todo-card {
  @include a.flex-between;
  padding: 16px;
  background-color: #ffffff;
  border-radius: a.$radius-base;
  border: 1px solid #e2e8f0;

  &__title {
    font-size: 1rem;
    color: a.$color-text;
  }

  &__status {
    padding: 4px 8px;
    border-radius: 4px;
    font-size: 0.875rem;

    &--done {
      background-color: rgba(22, 163, 74, 0.1);
      color: a.$color-success;
    }
  }
}
```

#### 5. Главный файл-точка входа `src/scss/main.scss`:
```scss
@use 'abstracts' as a;
@use 'components/todo-card';

body {
  font-family: system-ui, sans-serif;
  background-color: a.$color-bg;
  padding: 40px;
```

```scss
@use 'sass:math';

$base-font: 16px;

// Функция
@function px-to-rem($px) {
  @return math.div($px, $base-font) * 1rem;
}

// Миксин
@mixin respond-to($breakpoint) {
  @if $breakpoint == 'mobile' {
    @media (max-width: 767px) { @content; }
  } @else if $breakpoint == 'tablet' {
    @media (min-width: 768px) and (max-width: 1023px) { @content; }
  } @else if $breakpoint == 'desktop' {
    @media (min-width: 1024px) { @content; }
  } @else {
    @error "Неизвестная точка: #{$breakpoint}";
  }
}

// Использование
.header {
  padding: px-to-rem(32px); // 2rem

  @include respond-to('mobile') {
    padding: px-to-rem(16px); // 1rem
  }
}
```
