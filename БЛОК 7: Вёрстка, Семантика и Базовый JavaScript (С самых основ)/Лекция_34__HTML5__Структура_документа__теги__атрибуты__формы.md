# Лекция 34: HTML5. Структура документа, теги, атрибуты, формы, семантика и БЭМ

В этой лекции мы закладываем фундаментальную основу веб-разработки — язык гипертекстовой разметки **HTML5 (HyperText Markup Language)**. Мы разберём анатомию HTML-документа, базовый синтаксис тегов и атрибутов, методы разметки текста, ссылок, медиафайлов, списков и таблиц, освоим построение доступных интерактивных **форм** (`<form>`, `<label>`, `<input>`), изучим **семантические элементы HTML5** и методологию именования классов **БЭМ (Блок, Элемент, Модификатор)**.

---

## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. HTML5 (HyperText Markup Language 5)**
> * **Что это:** Стандартный язык гипертекстовой разметки, определяющий структуру и смысловое содержание веб-страниц для браузера.

> 📌 **2. Тег (HTML Tag) и Элемент (HTML Element)**
> * **Что это:** **Тег** — синтаксическая конструкция в угловых скобках (`<p>`, `</p>`). **Элемент** — полная логическая единица, включающая открывающий тег, содержимое и закрывающий тег (у пустых элементов вроде `<img>` закрывающего тега нет).

> 📌 **3. Атрибут (HTML Attribute)**
> * **Что это:** Дополнительное свойство или параметр тега, указываемый в открывающем теге в формате `имя="значение"` (например, `href="https://..."`, `type="text"`, `class="btn"`).

> 📌 **4. Элементы форм (`<form>`, `<label>`, `<input>`)**
> * **Что это:** Набор HTML-тегов, предназначенный для сбора пользовательского ввода (текст, даты, чекбоксы, файлы) и его передачи на сервер или в JavaScript-обработчик.

> 📌 **5. Семантическая вёрстка (Semantic HTML)**
> * **Что это:** Подход к разметке, при котором теги выбираются исходя из их смыслового значения (`<header>`, `<nav>`, `<main>`, `<article>`, `<footer>`), а не внешнего вида. Облегчает поисковую индексацию (SEO) и доступность (Accessibility / a11y).

> 📌 **6. БЭМ (Блок, Элемент, Модификатор)**
> * **Что это:** Соглашение об именовании CSS-классов в HTML-атрибуте `class` (`block`, `block__element`, `block--modifier`), предложенное компанией Яндекс. Обеспечивает изоляцию стилей, предотвращает конфликты имён и готовит разметку к удобной стилизации.

## Подглава 34.1: Что такое HTML, структура документа, теги и атрибуты

**HTML** не является языком программирования — это язык **структурной разметки**. Он сообщает браузеру, какие логические блоки (заголовки, абзацы, кнопки, формы) присутствуют на странице.

```text
+-----------------------------------------------------------------+
|                         <!DOCTYPE html>                         |
| +-------------------------------------------------------------+ |
| | <html lang="ru">                                            | |
| | +---------------------------------------------------------+ | |
| | | <head>                                                  | | |
| | |   <meta charset="UTF-8">                                | | |
| | |   <meta name="viewport" content="...">                  | | |
| | |   <title>Заголовок вкладки</title>                      | | |
| | | </head>                                                 | | |
| | +---------------------------------------------------------+ | |
| | +---------------------------------------------------------+ | |
| | | <body>                                                  | | |
| | |   <h1>Заголовок страницы</h1>                           | | |
| | |   <p>Основное содержимое, видимое пользователю...</p>   | | |
| | | </body>                                                 | | |
| | +---------------------------------------------------------+ | |
| | </html>                                                     | |
| +-------------------------------------------------------------+ |
+-----------------------------------------------------------------+
```

### 1. Стандартная структура HTML5-документа

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Моё первое веб-приложение</title>
  <link rel="icon" href="favicon.ico">
</head>
<body>
  <h1>Привет, мир!</h1>
  <p>Это стандартный HTML5-документ.</p>
</body>
</html>
```

* **`<!DOCTYPE html>`:** объявление типа документа. Сообщает браузеру, что страница должна обрабатываться по стандарту HTML5 (предотвращает переход браузера в режим совместимости со старыми стандартами — *Quirks Mode*).
* **`<html lang="ru">`:** корневой элемент страницы. Атрибут `lang` критичен для скринридеров (автоматическое чтение голосом) и поисковых систем.
* **`<head>`:** контейнер для служебных метаданных, подключений стилей, скриптов и заголовка страницы. **Содержимое `<head>` не отображается на самой странице.**
* **`<meta charset="UTF-8">`:** указывает кодировку символов UTF-8. Должен находиться в первых 1024 байтах документа, поэтому его ставят первым элементом в `<head>`.
* **`<meta name="viewport" content="width=device-width, initial-scale=1.0">`:** нужен для адаптивной вёрстки. Задаёт ширину области просмотра, равную ширине экрана устройства; без него мобильные браузеры показывают страницу как уменьшенную версию для компьютера.
* **`<title>`:** заголовок страницы, отображаемый на вкладке браузера и в результатах выдачи поисковиков.
* **`<link rel="icon" href="favicon.ico">`:** подключает значок страницы (favicon), который виден на вкладке браузера.
* **`<body>`:** тело документа, содержащее весь видимый интерфейс.

### 2. Синтаксис тегов и атрибутов

* **Парные теги:** имеют открывающий и закрывающий тег: `<p>Текст</p>`.
* **Пустые (void) элементы:** не имеют содержимого и закрывающего тега: `<img src="cat.jpg" alt="Кот">`, `<br>`, `<hr>`, `<input type="text">`, `<meta>`, `<link>`. Запись со слэшем (`<br />`) тоже допустима, но в HTML5 слэш ни на что не влияет: «самозакрывающихся» тегов в HTML нет.
* **Атрибуты:** записываются в открывающем теге как `имя="значение"`; значение лучше всегда брать в кавычки. **Булевы атрибуты** (`required`, `checked`, `selected`, `disabled`, `hidden`) пишутся без значения: само их наличие включает свойство.
* **Комментарии:** `<!-- Текст комментария -->` — браузер их не показывает.
* **Спецсимволы (HTML-сущности):** символы, которые нельзя вставить в текст напрямую, записываются через `&...;`: `&lt;` → `<`, `&gt;` → `>`, `&amp;` → `&`, `&copy;` → ©, `&nbsp;` — неразрывный пробел.
* **Глобальные атрибуты:** доступны для любых HTML-тегов:
  * `id="header"` — уникальный идентификатор элемента на странице (на одной странице не может повторяться!).
  * `class="btn btn--primary"` — имена CSS-классов (через пробел) для стилизации и JS.
  * `title="Подсказка"` — всплывающая подсказка при наведении курсора.
  * `hidden` — скрывает элемент: он не отображается и не занимает места на странице.
  * `tabindex="0"` — включает элемент в порядок фокусировки клавишей `Tab`.

## Подглава 34.2: Текст, ссылки, изображения, списки и таблицы

### 1. Работа с текстом
* **Заголовки `<h1>`–`<h6>`:** иерархическая структура документа. Тег `<h1>` обозначает главную тему страницы; по рекомендации для SEO и доступности его используют **ровно один раз на странице**. Уровни не пропускают: после `<h2>` идёт `<h3>`, а не `<h5>`.
* **Абзац `<p>`:** основной текстовый блок.
* **Смысловые акценты:**
  * `<strong>`: сильная важность (по умолчанию жирный; передаёт смысл, а не только внешний вид).
  * `<em>`: смысловой акцент/интонация (по умолчанию курсив).
  * `<b>` и `<i>`: стилистическое жирное и курсивное выделение без передачи смысловой важности.
* **Форматированный код:** `<code>` (однострочный код) и `<pre>` (блок кода с сохранением пробелов и переносов строк).

### 2. Гиперссылки (`<a>`)
Тег `<a>` (anchor) создает гиперссылку для перехода между страницами или секциями.

```html
<!-- Внешняя ссылка в новой вкладке -->
<a href="https://github.com" target="_blank" rel="noopener noreferrer">Открыть GitHub</a>

<!-- Внутренняя якорная ссылка: ведёт к элементу с id="contacts" на этой же странице -->
<a href="#contacts">Перейти к контактам</a>
<h2 id="contacts">Контакты</h2>

<!-- Специальные протоколы -->
<a href="mailto:support@example.com">Написать E-mail</a>
<a href="tel:+79991112233">Позвонить</a>
```
> ⚠️ **Важно (безопасность):** раньше при `target="_blank"` новая вкладка получала доступ к исходной через `window.opener` и могла подменить её содержимое (уязвимость *Reverse Tabnabbing*). Современные браузеры уже обрабатывают `target="_blank"` как `rel="noopener"`, но явное `rel="noopener noreferrer"` остаётся хорошей практикой (поддержка старых браузеров); `noreferrer` дополнительно не передаёт заголовок `Referer`.

### 3. Изображения (`<img>`)

```html
<img src="images/logo.png" alt="Логотип компании" width="200" height="50" loading="lazy">
```
* **`src`:** путь к файлу изображения (относительный или абсолютный).
* **`width` и `height`:** размеры в пикселях; браузер заранее резервирует место, и страница не «прыгает» при загрузке картинки.
* **`alt`:** текстовое описание изображения. **Критично для SEO и доступности!** Если изображение не загрузится или страницу читает незрячий пользователь через Screen Reader, зачитается именно текст `alt`. Для чисто декоративных картинок указывайте пустой `alt=""`: скринридер их пропустит.
* **`loading="lazy"`:** ленивая загрузка (изображение подгружается только при приближении к нему во время прокрутки); Не ставьте её картинкам, которые видны сразу при открытии страницы (в основном которые находятся в hero или в welcome секциях): их нужно загрузить как можно раньше, а ленивая загрузка только задержит их. Используйте `lazy` для картинок ниже, которые пользователь увидит после прокрутки.

### 4. Списки
* **Неупорядоченный список (`<ul>` + `<li>`):** список с маркерами; `<li>` — один пункт списка.
* **Упорядоченный список (`<ol>` + `<li>`):** нумерованный список (`type="1"`, `"a"`, `"A"`, `"i"` или `"I"` задаёт вид нумерации).
* **Список определений (`<dl>`, `<dt>`, `<dd>`):** пары «термин — описание».

```html
<ul>
  <li>Яблоки</li>
  <li>Молоко</li>
</ul>

<ol>
  <li>Установить редактор кода</li>
  <li>Создать файл index.html</li>
</ol>
```

```html
<dl>
  <dt>HTML5</dt>
  <dd>Язык разметки веб-страниц.</dd>
  <dt>CSS3</dt>
  <dd>Язык описания внешнего вида элементов.</dd>
</dl>
```

### 5. Таблицы
Служат для представления структурированных данных (не для верстки макета!).

```html
<table>
  <caption>Таблица пользователей</caption>
  <thead>
    <tr>
      <th scope="col">ID</th>
      <th scope="col">Имя</th>
      <th scope="col">Роль</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>1</td>
      <td>Алексей</td>
      <td>Администратор</td>
    </tr>
  </tbody>
</table>
```
* **`colspan="N"`** и **`rowspan="N"`:** объединение ячеек по горизонтали и вертикали.

## Подглава 34.3: Интерактивные формы: `<form>`, `<label>`, `<input>` и типы ввода

Формы позволяют собирать данные от пользователя. Они понадобятся вам при разработке Todo App на Этапе 1 практического трека и в любых веб-интерфейсах.

```text
+-----------------------------------------------------------------+
| <form action="/api/tasks" method="POST">                        |
|                                                                 |
|  <label for="title">Название задачи:</label>                    |
|  <input type="text" id="title" name="task_title" required>      |
|                                                                 |
|  <label for="priority">Приоритет:</label>                       |
|  <select id="priority" name="priority">                         |
|    <option value="low">Низкий</option>                          |
|    <option value="high">Высокий</option>                        |
|  </select>                                                      |
|                                                                 |
|  <button type="submit">Добавить задачу</button>                 |
|                                                                 |
| </form>                                                         |
+-----------------------------------------------------------------+
```

### 1. Тег `<form>`
Служит обёрткой для элементов ввода.
* **`action="/submit"`:** URL-адрес, куда отправляются данные формы (если не указан, данные уходят на адрес текущей страницы).
* **`method`:** HTTP-метод отправки — `GET` (по умолчанию) или `POST`:
  * `GET`: данные передаются в URL-строке (`?task_title=buy+milk`). Используется для поиска и фильтрации.
  * `POST`: данные передаются в теле HTTP-запроса. Используется для создания и изменения данных, передачи паролей.
* **`enctype="multipart/form-data"`:** нужен, если форма с методом `POST` отправляет файлы (`<input type="file">`).
* **Важно:** в отправляемые данные попадают только поля с атрибутом **`name`**; его значение становится именем параметра (`task_title=...`).

### 2. Связка `<label>` и `<input>`
**Запомните правило:** каждое поле ввода (кроме `hidden` и кнопок) должно быть связано с тегом `<label>`! `placeholder` подсказку не заменяет: она исчезает при вводе и читается не всеми скринридерами.

```html
<!-- Вариант 1: Явная связь через атрибуты for и id -->
<label for="user-email">Ваш E-mail:</label>
<input type="email" id="user-email" name="email" placeholder="name@example.com" required>

<!-- Вариант 2: Неявная связь (вложенность) -->
<label>
  <input type="checkbox" name="agree" required> Я согласен с условиями
</label>
```
> 💡 **Зачем нужен `<label>`:** Нажатие на текст внутри `<label>` автоматически переносит фокус или активирует связанный `<input>` (например, попадание пальцем в мелкий чекбокс на смартфоне становится легким!).

### 3. Основные типы `<input type="...">`

| Тип `type` | Назначение | Примечание / Атрибуты |
| :--- | :--- | :--- |
| **`text`** | Однострочный текстовый ввод | `placeholder`, `minlength`, `maxlength` |
| **`password`** | Ввод пароля (маскируется точками) | `autocomplete="current-password"` |
| **`email`** | Ввод E-mail адреса | Браузер делает базовую проверку формата (есть `@` и домен); существование адреса не проверяется |
| **`number`** | Ввод числовых значений | `min="1"`, `max="100"`, `step="1"` |
| **`checkbox`** | Чекбокс (флаг Да/Нет) | `checked`; неотмеченный чекбокс в данные формы не попадает |
| **`radio`** | Переключатель (выбор 1 из N) | Одинаковое `name` у всей группы и разные `value` у вариантов |
| **`date` / `time`** | Выбор даты или времени | Браузерный виджет выбора; значение передаётся в формате `YYYY-MM-DD` / `HH:MM` |
| **`file`** | Загрузка файла | `accept="image/*"`, `multiple` |
| **`hidden`** | Скрытое поле с данными | Не видно пользователю, передаётся на сервер; значение можно изменить через DevTools, поэтому секреты в нём хранить нельзя |
| **`submit`** | Кнопка отправки формы | Альтернатива `<button type="submit">` |

**Общие атрибуты полей:** `name` (имя параметра), `value` (значение), `required` (обязательное), `disabled` (недоступное), `readonly` (только чтение), `placeholder` (подсказка в пустом поле), `autofocus` (фокус при загрузке).

### 4. Другие элементы формы
* **`<textarea>`:** многострочное текстовое поле (`rows="4"`, `cols="50"`).
* **`<select>` и `<option>`:** выпадающий список (`selected`, `multiple`).
* **`<button>`:** интерактивная кнопка (`type="submit"`, `type="button"`, `type="reset"`). **Всегда явно указывайте `type`**, так как по умолчанию кнопка внутри формы имеет тип `submit`!

## Подглава 34.4: Семантика HTML5 и методология БЭМ

### 1. Семантическая структура HTML5
Вместо бессмысленных блоков `<div class="header">` и `<div class="footer">` HTML5 предлагает семантические элементы:

* **`<header>`:** шапка сайта или статьи.
* **`<nav>`:** блок главной навигации.
* **`<main>`:** уникальное главное содержимое страницы (только 1 на страницу!).
* **`<article>`:** независимый завершённый блок (пост, карточка товара).
* **`<section>`:** смысловой раздел документа с заголовком.
* **`<aside>`:** второстепенное, косвенно связанное с основным содержимое (чаще всего боковая колонка или блок «Похожие статьи»).
* **`<footer>`:** подвал сайта или секции.
* **`<div>` и `<span>`:** нейтральные контейнеры без смысла (`div` — для блоков, `span` — для фрагмента текста). Используйте их, только если подходящего семантического тега нет.

### 2. Методология БЭМ (Блок, Элемент, Модификатор)
При росте веб-приложения классическое именование классов превращается в хаос. **БЭМ** — это соглашение об именовании классов в атрибуте `class`, созданное для структурирования кода.

#### Компоненты БЭМ:

1. **Блок (Block):** независимый компонент интерфейса, который можно перенести в любое место страницы или другой проект.
   * *Именование:* `.card`, `.btn`, `.todo-app`, `.header`.
2. **Элемент (Element):** составная часть блока, которая не может использоваться отдельно от него.
   * *Именование:* разделяется двумя подчёркиваниями `__`: `.card__title`, `.card__button`, `.todo-app__input`, `.header__nav`. Элементы не вкладываются друг в друга в имени: `.card__title__text` — неверно, пишите `.card__text`.
3. **Модификатор (Modifier):** свойство, состояние или тема блока или элемента (изменяет внешний вид или поведение).
   * *Именование:* разделяется двумя дефисами `--`: `.btn--primary`, `.btn--disabled`, `.todo-item--completed`, `.card__title--large`. Модификатор всегда пишется вместе с базовым классом: `class="btn btn--primary"`.

```text
  .todo-app              .todo-app__input          .todo-item--completed
  └─ Блок                └─ Элемент блока          └─ Модификатор блока
     (самостоятельный)      (через __)                (через --)
```

#### Пример БЭМ-разметки для Todo App:

```html
<!-- Блок todo-app -->
<section class="todo-app">
  <h2 class="todo-app__title">Список задач</h2>

  <!-- Форма добавления задачи -->
  <form class="todo-app__form">
    <label for="new-task" class="todo-app__label">Новая задача:</label>
    <input type="text" id="new-task" name="title" class="todo-app__input" placeholder="Введите задачу..." required>
```

## Подглава 34.6: Чек-лист верстальщика & Практические задачи

### Чек-лист фронтенд-разработчика при создании HTML5-документа:
1. **Наличие `<!DOCTYPE html>` и `<html lang="ru">`:** гарантируют корректную обработку стандарта.
2. **Обязательные метатеги в `<head>`:** `charset="UTF-8"` и Viewport для адаптивности.
3. **Один `<h1>` (рекомендация) и один видимый `<main>` на страницу.**
4. **Доступность ссылок и изображений:** у всех `<img>` есть атрибут `alt` (у декоративных — пустой `alt=""`), у внешних ссылок с `target="_blank"` стоит `rel="noopener noreferrer"`.
5. **Связка элементов формы:** у каждого поля ввода (кроме `hidden` и кнопок) есть связанный `<label>` (через `for` + `id` или вложенностью), а у отправляемых полей задан `name`.
6. **Кнопкам явно задан `type`:** `<button type="submit">` или `<button type="button">`.
7. **Соблюдение БЭМ:** классы оформлены в единой структуре `block__element--modifier`.

## Подсказки и решения к практическим задачам

* **Решение Задачи 1 (Исправление ошибок):**
  Ошибки: 1) нет `<!DOCTYPE html>`; 2) нет атрибута `lang` у `<html>`; 3) нет `<meta charset="UTF-8">` (и `viewport`); 4) не закрыт тег `<title>`: браузер примет весь последующий код за текст заголовка; 5) два тега `<h1>` на странице; 6) у `<img>` нет обязательного атрибута `alt`; 7) у внешней ссылки с `target="_blank"` нет `rel="noopener noreferrer"`; 8) у `<input>` нет связанного `<label>` (и нет `name`); 9) у `<button>` не указан `type`, и он не находится в форме.
  ```html
  <!DOCTYPE html>

    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
  ```
