## 💡 Глоссарий ключевых терминов практикума

> 📌 **1. Инспекция памяти стороннего процесса (Process Memory Inspection)**
> * **Что это:** Чтение и анализ содержимого виртуального адресного пространства одного процесса (Target, «цель») из другого процесса (Scanner, «сканер») с соблюдением прав доступа операционной системы.

> 📌 **2. Псевдофайловая система `/proc`**
> * **Что это:** Виртуальная файловая система ядра Linux, предоставляющая интерфейс к данным ядра. Для процесса с идентификатором `PID` файл `/proc/[PID]/maps` содержит карту его виртуальной памяти, а файл `/proc/[PID]/mem` позволяет читать и записывать содержимое его виртуального адресного пространства (смещение в файле равно виртуальному адресу).

> 📌 **3. Системные вызовы `process_vm_readv()` и `process_vm_writev()`**
> * **Что это:** Системные вызовы Linux (начиная с ядра 3.2), которые копируют данные напрямую между адресными пространствами двух процессов за один системный вызов. В отличие от `ptrace`, не нужно переносить данные по одному машинному слову за вызов. Работают только с теми страницами, к которым у целевого процесса есть соответствующие права (в read-only страницы записать нельзя).

> 📌 **4. Системный вызов `ptrace`**
> * **Что это:** Низкоуровневый системный вызов, позволяющий одному процессу (Tracer) трассировать, приостанавливать, инспектировать и изменять регистры и память другого процесса (Tracee). Именно на нём построены отладчики.

> 📌 **5. Поэтапное сканирование и фильтрация (First Scan & Next Scan / Filter)**
> * **Что это:** Алгоритм поиска переменной в памяти. На первом этапе (First Scan) запоминаются адреса всех ячеек, хранящих заданное начальное значение. После изменения значения в целевой программе на следующих этапах (Next Scan) проверяются только ранее сохранённые адреса, пока список не сузится до одного или нескольких кандидатов.

> 📌 **6. Подсистема защиты Yama (`/proc/sys/kernel/yama/ptrace_scope`)**
> * **Что это:** Модуль безопасности ядра Linux (LSM), ограничивающий возможность подключаться к чужим процессам через `ptrace` и читать их память (включая `process_vm_readv` и `/proc/[PID]/mem`). Чтобы обойти ограничение, процессу нужны права root или привилегия `CAP_SYS_PTRACE`.

> 📌 **7. Выравнивание (Alignment)**
> * **Что это:** Правило размещения данных в памяти: переменная размером N байт обычно лежит по адресу, кратному N (на x86-64: `int32_t` — по адресу, кратному 4, `int64_t` — кратному 8). Благодаря этому сканер может проверять не каждый байт, а только каждый 4-й (или 8-й).

## Подглава 29.1.1: Архитектурные механизмы доступа к ОЗУ стороннего процесса в Linux

Операционная система изолирует процессы друг от друга. Как правило, виртуальный адрес `0x7ffe12345678` в Процессе А указывает на совершенно иную физическую страницу ОЗУ, чем тот же адрес `0x7ffe12345678` в Процессе Б (исключение — специально разделяемая память). Поэтому адрес из одного процесса нельзя просто разыменовать в другом: нужен специальный механизм ядра.

Для системных отладчиков и диагностических утилит ядро Linux предоставляет три основных метода чтения и записи памяти стороннего процесса:

### Сравнение способов чтения/записи памяти процесса в Linux:

| Метод | Используемые API / Файлы | Производительность | Привилегии и особенности |
| :--- | :--- | :--- | :--- |
| **1. `process_vm_readv` / `process_vm_writev`** | `<sys/uio.h>` | **Максимальная** при чтении крупных блоков (копирование нескольких областей за 1 системный вызов) | Тот же пользователь, что и у цели, **либо** root / `CAP_SYS_PTRACE`; плюс разрешение Yama. Запись возможна только в страницы, открытые на запись |
| **2. Псевдофайл `/proc/[PID]/mem`** | `open()`, `lseek()` / `pread()`, `read()`, `write()` | Высокая (обычный файловый ввод-вывод) | Те же требования доступа, что и для подключения через `ptrace`; выполнять `PTRACE_ATTACH` при этом не обязательно. Запись обычно разрешена и в страницы «только для чтения» |
| **3. Системный вызов `ptrace`** | `ptrace(PTRACE_PEEKDATA)`, `ptrace(PTRACE_POKEDATA)` | **Низкая** (за один вызов переносится одно машинное слово: 8 байт на x86-64) | Нужно быть Tracer'ом целевого процесса (подключиться через `PTRACE_ATTACH`/`PTRACE_SEIZE`); цель при этом останавливается. Используется отладчиками для управления точками останова (`INT 3`) |

В нашем проекте мы задействуем **`process_vm_readv()`** и **`process_vm_writev()`**: они удобны и быстры, а информацию о структуре сегментов будем извлекать из **`/proc/[PID]/maps`**.

## Подглава 29.1.2: Алгоритм работы Memory Scanner

Процесс сканирования и изменения переменной в стороннем процессе состоит из 4 этапов:

```text
[ Инициализация ] ──> Ввод PID целевого процесса
                           │
                           ▼
[ 1. Анализ /proc/[PID]/maps ] ──> Парсинг карты памяти, выбор сегментов с правами 'rw-p' (Heap, Stack, Data)
                           │
                           ▼
[ 2. Первичное сканирование ]  ──> Чтение памяти через process_vm_readv(),
(First Scan)                      сохранение адресов ячеек со значением V1 в массив matches[]
                           │
                           ▼
[ 3. Повторная фильтрация ]    ──> (Значение в Target меняется с V1 на V2)
(Next Scan / Filter)              Проверка сохранённых адресов из matches[]. Отсеивание несовпадений.
                           │
                           ▼ (Повторяется, пока не останется 1-2 адреса)
[ 4. Перезапись памяти ]       ──> process_vm_writev() записывает новое значение V_NEW по найденному адресу
```

1. **Парсинг `/proc/[PID]/maps`:** Сканер считывает файл карты памяти целевого процесса и отбирает только приватные области, доступные и для чтения, и для записи (`rw-p`). Код (`r-xp`), константы (`r--p`) и разделяемые области (`rw-s`) пропускаются.
2. **Первичное сканирование (First Scan):** Сканер порциями читает память выбранных областей через `process_vm_readv()`, ищет в них 4-байтовые числа, равные искомому значению (например, `int32_t val = 100`), и сохраняет их виртуальные адреса в массив результатов `matches[]`.
3. **Повторная фильтрация (Next Scan):** После того как целевая программа меняет значение переменной (например, `100 -> 85`), сканер перепроверяет **только адреса из массива `matches[]`**. Адреса, где значение не стало равно новому, отбрасываются. Процесс повторяется, пока не останется один-два кандидата.
4. **Модификация (Write Memory):** Сканер вызывает `process_vm_writev()` и записывает новое значение по найденному адресу прямо в память целевого процесса.

> 💡 **Почему «кандидатов» может остаться несколько.** Одно и то же значение программа нередко хранит в нескольких местах: в самой переменной, во временной копии на стеке (например, при передаче аргумента в `printf`), в буфере и т. д. Такие копии тоже «меняются вместе с переменной» и проходят фильтрацию. Отличить настоящую переменную можно, сравнив адреса с тем, что печатает сама целевая программа, либо записав тестовое значение по каждому адресу и посмотрев, что изменится в программе.

## Подглава 29.1.3: Создание демонстрационной целевой программы (`target_app.c`)

Для тестирования сканера создадим демонстрационную целевую программу `target_app.c`. Она создаёт переменную `health` в куче (Heap) и один раз при запуске печатает свой PID и адрес этой переменной. Затем в цикле она выводит текущее значение `health` и ждёт нажатия Enter; после каждого нажатия `health` уменьшается на 15.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <unistd.h>

int main(void) {
    // Выделяем память в куче (Heap)
    int32_t *health = (int32_t *)malloc(sizeof(int32_t));
    if (health == NULL) {
        perror("Ошибка выделения памяти");
        return 1;
    }

    *health = 100; // Начальное значение здоровья

    printf("==================================================\n");
    printf("  ЦЕЛЕВАЯ ДЕМО-ПРОГРАММА (Target App)\n");
    printf("  PID процесса   : %d\n", getpid());
    printf("  Адрес 'health' : %p (Heap)\n", (void *)health);
    printf("==================================================\n\n");

    while (1) {
        printf("[Target PID %d] Здоровье (health) = %d. Нажмите [Enter] для получения урона (-15)...",
               getpid(), *health);
        fflush(stdout); // приглашение не оканчивается '\n', поэтому сбрасываем буфер вручную

        // Ждём Enter: читаем и отбрасываем всю введённую строку
        int ch;
        while ((ch = getchar()) != '\n' && ch != EOF) {
        }
        if (ch == EOF) { // ввод закрыт (Ctrl+D) — выходим из цикла
            break;
        }

        *health -= 15;
        if (*health < 0) {
            *health = 100; // Сброс
            printf("\n*** Здоровье восстановлено до 100 ***\n");
        }
    }

    printf("\n");
    free(health);
    return 0;
}
```

## Подглава 29.1.4: Исходный код сканера памяти (`memory_scanner.c`)

Ниже — готовый код консольного сканера памяти на C11. Он проверен: компилируется без предупреждений командой из Подглавы 29.1.5 и работает на Linux x86-64 (сценарий из Подглавы 29.1.5 выполнен на нём вживую).

**Как устроен код:**
* `parse_memory_regions()` — читает `/proc/[PID]/maps` и оставляет только области `rw-p`;
* `read_remote_memory()` / `write_remote_memory()` — обёртки над `process_vm_readv()` / `process_vm_writev()`;
* `first_scan()` — читает области блоками по 4096 байт и ищет значение с шагом 4 байта;
* `next_scan()` — перечитывает только сохранённые адреса и оставляет совпавшие;
* `read_int32()` / `read_address()` — безопасный ввод (вместо `scanf`, который при вводе букв оставляет мусор во входном потоке и приводит к неопределённому поведению);
* `main()` — меню.

```c
#define _GNU_SOURCE  // нужен для объявления process_vm_readv / process_vm_writev
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>
#include <string.h>
#include <ctype.h>
#include <errno.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/uio.h>

#define MAX_MATCHES 100000
#define MAX_REGIONS 1024
#define CHUNK_SIZE 4096

// Структура для хранения информации о сегменте памяти из /proc/[PID]/maps
typedef struct {
    uintptr_t start_addr;
    uintptr_t end_addr;
    char permissions[5];
} MemoryRegion;

// Структура хранилища найденных совпадений
typedef struct {
    uintptr_t addresses[MAX_MATCHES];
    size_t count;
} MatchList;

// 1. Чтение карты памяти целевого процесса и отбор сегментов rw-p
size_t parse_memory_regions(pid_t pid, MemoryRegion *regions, size_t max_regions) {
    char maps_path[64];
    snprintf(maps_path, sizeof(maps_path), "/proc/%d/maps", (int)pid);

    FILE *f = fopen(maps_path, "r");
    if (f == NULL) {
        perror("Ошибка открытия /proc/[PID]/maps");
        return 0;
    }

    char line[4096];  // строки с длинными путями бывают длиннее 256 символов
    size_t region_count = 0;

    while (fgets(line, sizeof(line), f) && region_count < max_regions) {
        unsigned long start, end;
        char perms[5];

        // Пример строки: 00400000-00452000 rw-p 00000000 08:01 123456 /path/file
        // sscanf возвращает число успешно разобранных полей: здесь их ТРИ (start, end, perms)
        if (sscanf(line, "%lx-%lx %4s", &start, &end, perms) == 3) {
            // Нам нужны области с правами чтения и записи, приватные (rw-p)
            if (perms[0] == 'r' && perms[1] == 'w' && perms[3] == 'p') {
                regions[region_count].start_addr = (uintptr_t)start;
                regions[region_count].end_addr = (uintptr_t)end;
                memcpy(regions[region_count].permissions, perms, 4);
                regions[region_count].permissions[4] = '\0';
                region_count++;
            }
        }
    }

    fclose(f);
    return region_count;
}

// 2. Чтение фрагмента памяти из стороннего процесса через process_vm_readv
bool read_remote_memory(pid_t pid, uintptr_t remote_addr, void *local_buf, size_t size) {
    struct iovec local_iov = { .iov_base = local_buf, .iov_len = size };
    struct iovec remote_iov = { .iov_base = (void *)remote_addr, .iov_len = size };

    errno = 0;  // чтобы после неудачи errno точно относился к этому вызову
    ssize_t nread = process_vm_readv(pid, &local_iov, 1, &remote_iov, 1, 0);
    // -1 (ошибка) и частичное чтение (меньше size) считаем неудачей
    return (nread == (ssize_t)size);
}

// 3. Запись значения в память стороннего процесса через process_vm_writev
bool write_remote_memory(pid_t pid, uintptr_t remote_addr, const void *local_buf, size_t size) {
    struct iovec local_iov = { .iov_base = (void *)local_buf, .iov_len = size };
    struct iovec remote_iov = { .iov_base = (void *)remote_addr, .iov_len = size };

    ssize_t nwritten = process_vm_writev(pid, &local_iov, 1, &remote_iov, 1, 0);
    return (nwritten == (ssize_t)size);
}

// 4. Первичное сканирование (First Scan)
void first_scan(pid_t pid, int32_t target_val, MatchList *matches) {
    MemoryRegion regions[MAX_REGIONS];
    size_t num_regions = parse_memory_regions(pid, regions, MAX_REGIONS);

    matches->count = 0;
    if (num_regions == 0) {
        printf("[First Scan] Не найдено ни одной области rw-p. Проверьте PID.\n\n");
        return;
    }
    printf("[First Scan] Поиск значения %d в %zu областях памяти (rw-p)...\n",
           (int)target_val, num_regions);

    uint8_t buffer[CHUNK_SIZE];
    bool overflow = false;

    for (size_t r = 0; r < num_regions; r++) {
        uintptr_t curr = regions[r].start_addr;
        uintptr_t end = regions[r].end_addr;

        while (curr < end) {
            size_t bytes_to_read = (end - curr > CHUNK_SIZE) ? CHUNK_SIZE : (end - curr);

            if (read_remote_memory(pid, curr, buffer, bytes_to_read)) {
                // Сканируем буфер с шагом в 4 байта (выравнивание int32_t)
                for (size_t offset = 0; offset + sizeof(int32_t) <= bytes_to_read;
                     offset += sizeof(int32_t)) {
                    int32_t val;
                    memcpy(&val, buffer + offset, sizeof(val));  // безопасно для любого выравнивания
                    if (val == target_val) {
                        if (matches->count < MAX_MATCHES) {
                            matches->addresses[matches->count++] = curr + offset;
                        } else {
                            overflow = true;
                        }
                    }
                }
            } else if (errno == EPERM || errno == ESRCH) {
                // Сбой, который не лечится пропуском страницы: нет прав или процесс не существует
                fprintf(stderr, "[First Scan] Нет доступа к процессу %d: %s\n",
                        (int)pid, strerror(errno));
                fprintf(stderr, "  Запустите сканер через sudo или проверьте ptrace_scope.\n\n");
                matches->count = 0;
                return;
            }
            // Прочие сбои (например, EFAULT на недоступной странице) — просто идём дальше
            curr += bytes_to_read;
        }
    }

    printf("[First Scan] Готово. Найдено совпадений: %zu\n", matches->count);
    if (overflow) {
        printf("[First Scan] Внимание: список ограничен %d адресами, часть совпадений потеряна!\n",
               MAX_MATCHES);
    }
    printf("\n");
}

// 5. Повторная фильтрация (Next Scan / Filter)
void next_scan(pid_t pid, int32_t target_val, MatchList *matches) {
    printf("[Next Scan] Фильтрация списка из %zu адресов по новому значению %d...\n",
           matches->count, (int)target_val);

    size_t new_count = 0;

    for (size_t i = 0; i < matches->count; i++) {
        uintptr_t addr = matches->addresses[i];
        int32_t val = 0;

        if (read_remote_memory(pid, addr, &val, sizeof(int32_t))) {
            if (val == target_val) {
                matches->addresses[new_count++] = addr;
            }
        }
    }

    matches->count = new_count;
    printf("[Next Scan] Готово. Совпадений осталось: %zu\n\n", matches->count);
}

// Вывод списка найденных адресов (первые 10)
void print_matches(const MatchList *matches) {
    printf("=== СПИСОК НАЙДЕННЫХ АДРЕСОВ (%zu) ===\n", matches->count);
    size_t limit = (matches->count > 10) ? 10 : matches->count;
    for (size_t i = 0; i < limit; i++) {
        printf("  [%zu] 0x%lx\n", i + 1, (unsigned long)matches->addresses[i]);
    }
    if (matches->count > 10) {
        printf("  ... и ещё %zu адресов\n", matches->count - 10);
    }
    printf("=======================================\n\n");
}

// Безопасный ввод целого числа (вместо scanf, который при ошибке оставляет мусор во вводе).
// Возвращает: 1 — число считано, 0 — введено не число, -1 — конец ввода (EOF).
static int read_int32(const char *prompt, int32_t *out) {
    char buf[64];
    printf("%s", prompt);
    fflush(stdout);
    if (fgets(buf, sizeof(buf), stdin) == NULL) {
        return -1;
    }
    char *endp;
    errno = 0;
    long v = strtol(buf, &endp, 10);
    if (endp == buf || errno == ERANGE || v < INT32_MIN || v > INT32_MAX) {
        printf("Некорректное число!\n");
        return 0;
    }
    while (isspace((unsigned char)*endp)) {
        endp++;
    }
    if (*endp != '\0') {
        printf("Некорректное число!\n");
        return 0;
    }
    *out = (int32_t)v;
    return 1;
}

// Безопасный ввод адреса в hex (с префиксом 0x или без него)
static int read_address(const char *prompt, uintptr_t *out) {
    char buf[64];
    printf("%s", prompt);
    fflush(stdout);
    if (fgets(buf, sizeof(buf), stdin) == NULL) {
        return -1;
    }
    char *endp;
    errno = 0;
    unsigned long long v = strtoull(buf, &endp, 16);
    if (endp == buf || errno == ERANGE) {
        printf("Некорректный адрес!\n");
        return 0;
    }
    *out = (uintptr_t)v;
    return 1;
}

int main(void) {
    printf("=== СИСТЕМНЫЙ СКАНЕР ПАМЯТИ (Memory Scanner C11) ===\n\n");

    int32_t pid_in;
    if (read_int32("Введите PID целевого процесса: ", &pid_in) != 1 || pid_in <= 0) {
        fprintf(stderr, "Некорректный PID!\n");
        return 1;
    }
    pid_t target_pid = (pid_t)pid_in;

    static MatchList matches;  // static: структура ~800 КБ, не нужно держать её на стеке
    matches.count = 0;

    while (1) {
        printf("----------------------------------------\n");
        printf("Меню действия:\n");
        printf(" 1. Первичное сканирование (First Scan)\n");
        printf(" 2. Повторная фильтрация (Next Scan)\n");
        printf(" 3. Вывести текущие найденные адреса\n");
        printf(" 4. Записать новое значение в найденный адрес\n");
        printf(" 0. Выход\n");

        int32_t choice;
        int rc = read_int32("Выберите пункт: ", &choice);
        if (rc < 0 || (rc == 1 && choice == 0)) {
            break;
        }
        if (rc == 0) {
            continue;
        }

        if (choice == 1) {
            int32_t val;
            if (read_int32("Введите начальное значение (int32_t): ", &val) != 1) {
                continue;
            }
            first_scan(target_pid, val, &matches);
            print_matches(&matches);
        } else if (choice == 2) {
            if (matches.count == 0) {
                printf("Сначала выполните Первичное сканирование (First Scan)!\n\n");
                continue;
            }
            int32_t val;
            if (read_int32("Введите НОВОЕ изменённое значение (int32_t): ", &val) != 1) {
                continue;
            }
            next_scan(target_pid, val, &matches);
            print_matches(&matches);
        } else if (choice == 3) {
            print_matches(&matches);
        } else if (choice == 4) {
            if (matches.count == 0) {
                printf("Нет доступных адресов для записи!\n\n");
                continue;
            }

            uintptr_t target_addr;
            if (matches.count == 1) {
                target_addr = matches.addresses[0];
                printf("Выбран единственный найденный адрес: 0x%lx\n", (unsigned long)target_addr);
            } else {
                if (read_address("Введите адрес из списка для записи (в hex, например 0x7ffd1234): ",
                                 &target_addr) != 1) {
                    continue;
                }
                bool in_list = false;
                for (size_t i = 0; i < matches.count; i++) {
                    if (matches.addresses[i] == target_addr) {
                        in_list = true;
                        break;
                    }
                }
                if (!in_list) {
                    printf("Этого адреса нет среди найденных!\n\n");
                    continue;
                }
            }

            int32_t new_val;
            if (read_int32("Введите НОВОЕ значение для записи (int32_t): ", &new_val) != 1) {
                continue;
            }

            if (write_remote_memory(target_pid, target_addr, &new_val, sizeof(int32_t))) {
                printf(" УСПЕХ! Значение %d записано по адресу 0x%lx\n\n",
                       (int)new_val, (unsigned long)target_addr);
            } else {
                perror("Ошибка записи в память процесса (process_vm_writev)");
                printf(" Убедитесь, что у вас есть права root или настроен ptrace_scope!\n\n");
            }
        } else {
            printf("Неизвестный пункт меню!\n\n");
        }
    }

    printf("Сканер завершил работу.\n");
    return 0;
}
```

## Подглава 29.1.6: Чек-лист системного программиста при работе с памятью процессов

1. **Учитывайте разрешения подсистемы Yama LSM (`ptrace_scope`):**
   В Ubuntu и ряде других дистрибутивов значение `/proc/sys/kernel/yama/ptrace_scope` по умолчанию равно `1`. Это значит, что подключаться к процессу (и читать его память через `process_vm_readv` / `process_vm_writev`) можно только к своим потомкам. Значения: `0` — без ограничений для процессов одного пользователя, `1` — только потомки, `2` — только root / `CAP_SYS_PTRACE`, `3` — подключение запрещено полностью (и изменить это без перезагрузки нельзя). Для работы сканера запускайте его через `sudo` или (временно и только на тестовой машине) выполните `echo 0 | sudo tee /proc/sys/kernel/yama/ptrace_scope`; это ослабляет защиту системы, поэтому потом верните значение `1`. При отсутствии прав вызовы завершаются ошибкой `EPERM`.
2. **Сканируйте только записываемые области (`rw-p`):**
   Области `r--p` (константы) и `r-xp` (код) обычно не содержат переменных, значения которых меняются в ходе работы, поэтому искать там нечего. Кроме того, `process_vm_writev` не сможет записать в страницы без права записи и вернёт ошибку `EFAULT`.
3. **Соблюдайте естественные границы выравнивания типов (Alignment):**
   Компиляторы размещают `int32_t` и `float` по адресам, кратным 4, а `int64_t` и `double` — кратным 8 (на x86-64). Поэтому сканируйте с шагом, равным размеру типа (`offset += 4` или `offset += 8`). Сканирование с шагом в 1 байт в 4 раза медленнее и даёт ложные совпадения (число «склеивается» из соседних переменных). Оговорка: данные в упакованных структурах (`packed`) могут быть невыровнены, и тогда шаг 4 их пропустит.
4. **Обрабатывайте сбои чтения (границы страниц):**
   Если читаемый блок задевает недоступную страницу, `process_vm_readv` возвращает `-1` с `errno = EFAULT` либо читает лишь часть данных (меньше запрошенного). Оба случая нужно считать неудачей, пропустить блок и продолжить сканирование (так и сделано в коде `first_scan()`). А вот `EPERM` (нет прав) и `ESRCH` (процесса нет) пропускать бессмысленно: надо сообщить пользователю и остановиться.

## Подсказки к практическим задачам

* **Подсказка к Задаче 1:**
  1. Для `float` используйте шаг `sizeof(float)` (4 байта).
  2. Числа `float` из-за особенностей стандарта IEEE 754 хранятся приближённо (например, число 0.1 не имеет точного двоичного представления), а результаты вычислений накапливают небольшие погрешности в младших разрядах. Поэтому вместо `==` сравнивают абсолютную разницу: `if (fabsf(val - target_val) < 0.001f)` (нужен `#include <math.h>`). Допуск зависит от масштаба чисел: `float` хранит около 7 значащих цифр, и для значений порядка миллионов допуск `0.001f` слишком мал, там сравнивают относительную погрешность. Читать значение из буфера надо через `memcpy(&val, buffer + offset, sizeof(val))`, а не приведением указателя.
  3. Для `int64_t`: переменная `val` и `target_val` становятся `int64_t`, шаг равен `sizeof(int64_t)` (8), ввод — через `strtoll`, вывод — через макрос `PRId64` из `<inttypes.h>`; записывается и сравнивается 8 байт (`sizeof(int64_t)`).

* **Подсказка к Задаче 2:**
  ```c
  #define _GNU_SOURCE
  #include <stdint.h>
  #include <stdatomic.h>
  #include <pthread.h>
  #include <time.h>
  #include <sys/types.h>
  // write_remote_memory() — из memory_scanner.c

  typedef struct {
      pid_t pid;
      uintptr_t addr;
      int32_t val;
      atomic_bool running;   // атомарный флаг: его меняет главный поток, читает фоновый
  } FreezerArgs;

  void *freezer_thread(void *arg) {
      FreezerArgs *args = (FreezerArgs *)arg;
      const struct timespec delay = { .tv_sec = 0, .tv_nsec = 50 * 1000 * 1000 }; // 50 мс
      while (atomic_load(&args->running)) {
          write_remote_memory(args->pid, args->addr, &args->val, sizeof(int32_t));
          nanosleep(&delay, NULL); // перезапись 20 раз в секунду
      }
      return NULL;
  }

  // Использование:
  //   FreezerArgs a = { .pid = pid, .addr = addr, .val = 999 };
  //   atomic_init(&a.running, true);
  //   pthread_t th;
  //   pthread_create(&th, NULL, freezer_thread, &a);
  //   ...                                    // заморозка работает
  //   atomic_store(&a.running, false);       // остановка
  //   pthread_join(th, NULL);
  ```
  Компилировать с ключом `-pthread`. Без атомарного флага (или `volatile`) компилятор мог бы закэшировать `running` в регистре, и поток не остановился бы; обычный `bool` читать и писать из разных потоков без синхронизации нельзя (гонка данных). Вместо устаревшего `usleep()` используется `nanosleep()`.

* **Подсказка к Задаче 3:**
  ```c
  #define _GNU_SOURCE
  #include <stdint.h>
  #include <stdbool.h>
  #include <stdio.h>
  #include <fcntl.h>
  #include <unistd.h>
  #include <sys/types.h>

  bool read_via_proc_mem(pid_t pid, uintptr_t addr, int32_t *val_out) {
      char path[64];
      snprintf(path, sizeof(path), "/proc/%d/mem", (int)pid);
      int fd = open(path, O_RDONLY);
      if (fd < 0) return false;

      if (lseek64(fd, (off64_t)addr, SEEK_SET) == (off64_t)-1) {
          close(fd);
          return false;
      }

      ssize_t res = read(fd, val_out, sizeof(int32_t));
      close(fd);
      return (res == (ssize_t)sizeof(int32_t));
  }
  ```
  Две операции `lseek64` + `read` можно заменить одним вызовом `pread(fd, val_out, 4, (off_t)addr)`: он не меняет позицию в файле. Права доступа к `/proc/[PID]/mem` — те же, что для `ptrace` (см. чек-лист, п. 1). Если адрес не отображён в память процесса, `read()` вернёт ошибку (`EIO`).
