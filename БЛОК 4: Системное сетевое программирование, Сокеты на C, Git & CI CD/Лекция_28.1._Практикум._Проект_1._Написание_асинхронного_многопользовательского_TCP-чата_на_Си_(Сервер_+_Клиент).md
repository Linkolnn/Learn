## 💡 Глоссарий ключевых терминов лекции

> 📌 **1. Мультиплексирование ввода-вывода (I/O Multiplexing)**
> * **Что это:** Подход, позволяющий **одному потоку выполнения** (Single Thread) отслеживать состояние сразу множества файловых дескрипторов (сокетов) и реагировать только на те из них, которые готовы к чтению или записи.

> 📌 **2. Системный вызов `select()`**
> * **Что это:** Классический POSIX-вызов мультиплексирования. Он принимает битовые маски дескрипторов (`fd_set`) и блокирует процесс до тех пор, пока хотя бы на одном из сокетов не появится событие (приход данных, новое подключение, разрыв связи) или не истечёт тайм-аут (если он задан).

> 📌 **3. Неблокирующий сокет (Non-blocking Socket / `O_NONBLOCK`)**
> * **Что это:** Режим работы сокета, при котором вызовы `accept()`, `recv()` или `send()` возвращают управление немедленно. Если данные не готовы (или нет места в буфере отправки), вызов не задерживает поток, а возвращает `-1` с кодом ошибки `EAGAIN` или `EWOULDBLOCK`.

> 📌 **4. Рассылка сообщений (Broadcasting / Fan-Out)**
> * **Что это:** Паттерн, при котором входящее сообщение от одного клиента пересылается всем остальным активным участникам чата.

> 📌 **5. Фреймирование сообщений (Message Framing)**
> * **Что это:** Соглашение протокола прикладного уровня, определяющее границы сообщений внутри непрерывного байтового потока TCP (Byte Stream). В нашем чате границей сообщения служит символ переноса строки `\n`.
> * **Важно:** один вызов `recv()` может вернуть **часть** сообщения, **ровно одно** сообщение или **несколько** сообщений сразу. Поэтому сервер накапливает полученные байты в буфере клиента и обрабатывает только **целые** строки.

> 📌 **6. Внезапное отключение (Ungraceful Disconnect) и `SIGPIPE`**
> * **Что это:** Ситуация, когда соединение закрывается не штатным обменом `FIN`, а сбросом (`RST`) или просто пропадает (обрыв сети, выключение ПК).
> * Если **процесс** клиента аварийно завершился, ядро ОС само закроет его сокеты. Если же пропала сеть или питание, сервер ничего не получит и узнает об обрыве только по тайм-ауту или TCP keepalive.
> * Запись в сокет, соединение которого уже сброшено (получен `RST`), приводит к ошибке `EPIPE` и к сигналу `SIGPIPE`, который по умолчанию **завершает процесс**.

> 📌 **7. Ограничение `FD_SETSIZE`**
> * **Что это:** Константа (в Linux/glibc — `1024`): размер набора `fd_set` в битах. Значение дескриптора, передаваемого в `FD_SET()`, должно быть **строго меньше** `FD_SETSIZE`, иначе — неопределённое поведение (UB, Undefined Behavior: стандарт не задаёт результат, программа может упасть или работать неверно).

## Подглава 28.1.1: Архитектурные паттерны серверов: Многопоточность vs Мультиплексирование I/O

При проектировании сетевого сервера, обслуживающего сотни одновременных клиентов, разработчик выбирает между двумя фундаментальными подходами:

```text
[ Подход 1: Thread-per-Client (Многопоточный) ]
   Listen Socket
       │
       ├── Accept ──> Thread 1 (Client 1) ──> Blocking recv() [Стек ~8 МБ виртуальной памяти]
       ├── Accept ──> Thread 2 (Client 2) ──> Blocking recv() [Стек ~8 МБ виртуальной памяти]
       └── Accept ──> Thread 3 (Client 3) ──> Blocking recv() [Стек ~8 МБ виртуальной памяти]

[ Подход 2: Event-Driven I/O Multiplexing (Однопоточный событийный) ]
   Listen Socket + Client Sockets (All Non-blocking)
       │
       ▼
   select() / poll() / epoll() ──> [Один поток / Один Event Loop]
       │
       ├── Готов listen_fd  ──> accept() нового клиента
       └── Готов client_fd ──> recv() и broadcast()
```

### Сравнение архитектур:

1. **Многопоточный подход (Thread-per-Client — `pthread`):**
   * *Плюсы:* Простая линейная логика кода. Один поток обслуживает одного клиента в блокирующем режиме.
   * *Минусы:* Каждый поток резервирует стек (по умолчанию в Linux — до 8 МБ **виртуальной** памяти; физически используется только занятая часть), плюс у ядра растут накладные расходы на планирование и переключение контекста (Context Switch).
   * *Предел:* порядка тысяч клиентов на сервер.

2. **Событийный подход (I/O Multiplexing — `select`/`poll`/`epoll`):**
   * *Плюсы:* Все клиенты обслуживаются **в одном потоке**. Минимальное потребление памяти (нет сотен стеков), отсутствие переключений контекста потоков.
   * *Минусы:* Необходимость неблокирующего кода и ручного хранения состояния каждого клиента (например, буфера недочитанной строки).
   * *Предел:* зависит от вызова. У `select()` — не более `FD_SETSIZE` (1024) дескрипторов. `poll()` этого лимита лишён, а `epoll()` (Linux) выдерживает десятки и сотни тысяч соединений (проблема C10K — 10 000 соединений, и её более поздние версии).

## Подглава 28.1.2: Проектирование прикладного протокола чата и неблокирующие сокеты

### 1. Перевод сокета в неблокирующий режим
Для того чтобы сокет не замораживал поток выполнения при отсутствии данных, используется системный вызов `fcntl()`:

```c
int set_nonblocking(int fd) {
    int flags = fcntl(fd, F_GETFL, 0);
    if (flags == -1) return -1;
    return fcntl(fd, F_SETFL, flags | O_NONBLOCK);
}
```

### 2. Спецификация прикладного протокола TCP-чата
Так как TCP является потоковым протоколом (Byte Stream) без сохранения границ сообщений, мы задаём простые правила фреймирования:
* **Разделитель кадра:** Каждое текстовое сообщение завершается символом переноса строки `\n` (или `\r\n`). Максимальная длина строки — 1023 байта; более длинная строка отбрасывается.
* **Идентификация:** Каждому подключенному клиенту присваивается имя (по умолчанию `User<socket_fd>`).
* **Формат сообщений в чате:** `[Никнейм]: Текст сообщения\n`
* **Служебные команды:**
  * `/nick <новое_имя>` — сменить никнейм. Ник должен быть непустым, без пробелов, не длиннее 31 байта (кириллическая буква в UTF-8 занимает 2 байта) и не совпадать с ником другого пользователя.
  * `/list` — запросить у сервера список всех пользователей онлайн.
  * `/quit` — корректно выйти из чата.

## Подглава 28.1.3: Исходный код асинхронного TCP-сервера (`server.c`)

Сервер использует вызов `select()` для мониторинга служебного сокета `listen_fd` и сокетов всех подключенных клиентов. Для каждого клиента сервер хранит буфер `inbuf`, в котором накапливаются байты до символа `\n`.

> ⚠️ **Ограничение учебной версии:** исходящие сообщения отправляются «как есть» одним вызовом `send()`. Если буфер отправки медленного клиента переполнен, сообщение для него теряется. В промышленном коде для каждого клиента заводят очередь исходящих данных и отслеживают готовность к записи (`writefds` в `select()` или `POLLOUT` в `poll()`).

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <signal.h>
#include <sys/types.h>
#include <sys/socket.h>
#include <sys/select.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <fcntl.h>

#define PORT 8888
#define MAX_CLIENTS 30
#define BUFFER_SIZE 1024
#define NICK_LEN 32

typedef struct {
    int fd;                     // 0 — ячейка свободна
    char nick[NICK_LEN];
    char ip[INET_ADDRSTRLEN];
    int port;
    char inbuf[BUFFER_SIZE];    // накопленные, но ещё не обработанные байты
    size_t inlen;               // сколько байт сейчас лежит в inbuf
    int skip;                   // 1 — отбрасываем остаток слишком длинной строки до ближайшего '\n'
} Client;

Client clients[MAX_CLIENTS];

// Перевод сокета в неблокирующий режим
int set_nonblocking(int fd) {
    int flags = fcntl(fd, F_GETFL, 0);
    if (flags == -1) return -1;
    return fcntl(fd, F_SETFL, flags | O_NONBLOCK);
}

// Отправка строки одному клиенту (без очереди: см. «Ограничение учебной версии»)
void send_str(int fd, const char *msg) {
    ssize_t sent = send(fd, msg, strlen(msg), 0);
    if (sent < 0 && errno != EAGAIN && errno != EWOULDBLOCK) {
        perror("Ошибка send()");
    }
}

// Рассылка сообщения всем клиентам, кроме отправителя (sender_fd = 0 — всем)
void broadcast_message(const char *msg, int sender_fd) {
    for (int i = 0; i < MAX_CLIENTS; i++) {
        if (clients[i].fd > 0 && clients[i].fd != sender_fd) {
            send_str(clients[i].fd, msg);
        }
    }
}

// Отключение клиента и очистка ресурсов
void disconnect_client(int index) {
    if (index < 0 || index >= MAX_CLIENTS || clients[index].fd <= 0) return;

    char leave_msg[BUFFER_SIZE];
    snprintf(leave_msg, sizeof(leave_msg), "*** Пользователь %s [%s:%d] покинул чат. ***\n",
             clients[index].nick, clients[index].ip, clients[index].port);

    printf("%s", leave_msg);
    close(clients[index].fd);
    clients[index].fd = 0;
    clients[index].inlen = 0;
    clients[index].skip = 0;

    broadcast_message(leave_msg, 0);
}

// Обработка одной ПОЛНОЙ строки (без '\n'). Возвращает 1, если клиент был отключён.
int process_line(int i, char *line) {
    int sd = clients[i].fd;

    if (line[0] == '\0') return 0; // пустая строка — игнорируем

    if (strcmp(line, "/nick") == 0 || strncmp(line, "/nick ", 6) == 0) {
        char *new_nick = line + 5;
        while (*new_nick == ' ') new_nick++;                 // пропускаем пробелы перед ником
        char *end = new_nick + strlen(new_nick);
        while (end > new_nick && end[-1] == ' ') *--end = '\0'; // и после него

        size_t len = strlen(new_nick);
        if (len == 0 || len >= NICK_LEN || strchr(new_nick, ' ') != NULL) {
            send_str(sd, "*** Ник должен быть непустым, без пробелов и не длиннее 31 байта. ***\n");
            return 0;
        }
        for (int j = 0; j < MAX_CLIENTS; j++) {
            if (j != i && clients[j].fd > 0 && strcmp(clients[j].nick, new_nick) == 0) {
                send_str(sd, "*** Этот ник уже занят. ***\n");
                return 0;
            }
        }

        char change_msg[BUFFER_SIZE];
        snprintf(change_msg, sizeof(change_msg),
                 "*** Пользователь %s сменил ник на %s ***\n", clients[i].nick, new_nick);
        printf("%s", change_msg);
        snprintf(clients[i].nick, NICK_LEN, "%s", new_nick);
        broadcast_message(change_msg, 0);
        return 0;
    }

    if (strcmp(line, "/list") == 0) {
        char list_msg[MAX_CLIENTS * 80 + 64];
        snprintf(list_msg, sizeof(list_msg), "*** Список пользователей онлайн:\n");
        for (int j = 0; j < MAX_CLIENTS; j++) {
            if (clients[j].fd > 0) {
                char user_info[128];
                snprintf(user_info, sizeof(user_info), " - %s [%s:%d]\n",
                         clients[j].nick, clients[j].ip, clients[j].port);
                strncat(list_msg, user_info, sizeof(list_msg) - strlen(list_msg) - 1);
            }
        }
        send_str(sd, list_msg);
        return 0;
    }

    if (strcmp(line, "/quit") == 0) {
        disconnect_client(i);
        return 1;
    }

    // Обычное текстовое сообщение -> рассылка всем, кроме отправителя
    char out_msg[BUFFER_SIZE + NICK_LEN + 32];
    snprintf(out_msg, sizeof(out_msg), "[%s]: %s\n", clients[i].nick, line);
    printf("%s", out_msg);
    broadcast_message(out_msg, sd);
    return 0;
}

int main(void) {
    // Игнорируем SIGPIPE, чтобы запись в закрытый сокет не убивала процесс сервера
    signal(SIGPIPE, SIG_IGN);

    for (int i = 0; i < MAX_CLIENTS; i++) {
        clients[i].fd = 0;
    }

    // 1. Создание прослушивающего сокета
    int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
    if (listen_fd < 0) {
        perror("Ошибка вызова socket()");
        exit(EXIT_FAILURE);
    }

    // 2. Включение опции SO_REUSEADDR
    int opt = 1;
    if (setsockopt(listen_fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt)) < 0) {
        perror("Ошибка setsockopt(SO_REUSEADDR)");
        close(listen_fd);
        exit(EXIT_FAILURE);
    }

    // 3. Перевод прослушивающего сокета в неблокирующий режим
    if (set_nonblocking(listen_fd) < 0) {
        perror("Ошибка set_nonblocking()");
        close(listen_fd);
        exit(EXIT_FAILURE);
    }

    // 4. Привязка к порту 8888
    struct sockaddr_in server_addr;
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;
    server_addr.sin_addr.s_addr = htonl(INADDR_ANY);
    server_addr.sin_port = htons(PORT);

    if (bind(listen_fd, (struct sockaddr *)&server_addr, sizeof(server_addr)) < 0) {
        perror("Ошибка вызова bind()");
        close(listen_fd);
        exit(EXIT_FAILURE);
    }

    // 5. Перевод сокета в режим прослушивания
    if (listen(listen_fd, 10) < 0) {
        perror("Ошибка вызова listen()");
        close(listen_fd);
        exit(EXIT_FAILURE);
    }

    printf("===================================================\n");
    printf("  АСИНХРОННЫЙ МНОГОПОЛЬЗОВАТЕЛЬСКИЙ TCP ЧАТ СЕРВЕР\n");
    printf("  Запущен на порту %d (select / non-blocking)\n", PORT);
    printf("===================================================\n\n");
    fflush(stdout);

    fd_set readfds;

    // Главный Event Loop сервера
    while (1) {
        FD_ZERO(&readfds);
        FD_SET(listen_fd, &readfds);
        int max_fd = listen_fd;

        // Добавляем все клиентские сокеты в множество readfds
        for (int i = 0; i < MAX_CLIENTS; i++) {
            int sd = clients[i].fd;
            if (sd > 0) {
                FD_SET(sd, &readfds);
            }
            if (sd > max_fd) {
                max_fd = sd;
            }
        }

        // Блокировка вызова select до появления событий на сокетах
        int activity = select(max_fd + 1, &readfds, NULL, NULL, NULL);
        if (activity < 0) {
            if (errno == EINTR) continue; // прервано сигналом: readfds недействителен, начинаем заново
            perror("Ошибка вызова select()");
            break;
        }

        // А. Новое входящее подключение на listen_fd
        if (FD_ISSET(listen_fd, &readfds)) {
            struct sockaddr_in client_addr;
            socklen_t addrlen = sizeof(client_addr);
            int new_socket = accept(listen_fd, (struct sockaddr *)&client_addr, &addrlen);

            if (new_socket < 0) {
                if (errno != EAGAIN && errno != EWOULDBLOCK && errno != EINTR) {
                    perror("Ошибка вызова accept()");
                }
            } else if (new_socket >= FD_SETSIZE || set_nonblocking(new_socket) < 0) {
                // дескриптор не поместится в fd_set (иначе UB) или не удалось сделать его неблокирующим
                close(new_socket);
            } else {
                char ip_str[INET_ADDRSTRLEN];
                inet_ntop(AF_INET, &client_addr.sin_addr, ip_str, sizeof(ip_str));
                int client_port = ntohs(client_addr.sin_port);

                int added = 0;
                for (int i = 0; i < MAX_CLIENTS; i++) {
                    if (clients[i].fd == 0) {
                        clients[i].fd = new_socket;
                        clients[i].inlen = 0;
                        clients[i].skip = 0;
                        snprintf(clients[i].nick, NICK_LEN, "User%d", new_socket);
                        snprintf(clients[i].ip, sizeof(clients[i].ip), "%s", ip_str);
                        clients[i].port = client_port;

                        printf("[ПОДКЛЮЧЕНИЕ] fd=%d, IP=%s:%d, Nick=%s\n",
                               new_socket, ip_str, client_port, clients[i].nick);

                        char welcome_msg[BUFFER_SIZE];
                        snprintf(welcome_msg, sizeof(welcome_msg),
                                 "*** Добро пожаловать в TCP-чат! Ваш ник: %s. Команды: /nick <имя>, /list, /quit ***\n",
                                 clients[i].nick);
                        send_str(new_socket, welcome_msg);

                        char join_msg[BUFFER_SIZE];
                        snprintf(join_msg, sizeof(join_msg),
                                 "*** Пользователь %s [%s:%d] присоединился к чату. ***\n",
                                 clients[i].nick, ip_str, client_port);
                        broadcast_message(join_msg, new_socket);

                        added = 1;
                        break;
                    }
                }

                if (!added) {
                    send_str(new_socket, "Сервер переполнен. Попробуйте позже.\n");
                    close(new_socket);
                }
            }
        }

        // Б. Чтение входящих данных от подключенных клиентов
        for (int i = 0; i < MAX_CLIENTS; i++) {
            int sd = clients[i].fd;
            if (sd <= 0 || !FD_ISSET(sd, &readfds)) continue;

            Client *c = &clients[i];

            // Дописываем новые байты в конец уже накопленных (место под '\0' не нужно: ищем '\n' через memchr)
            ssize_t valread = recv(sd, c->inbuf + c->inlen, sizeof(c->inbuf) - c->inlen - 1, 0);

            if (valread == 0) {              // клиент прислал FIN — чистый разрыв
                disconnect_client(i);
                continue;
            }
            if (valread < 0) {
                // EAGAIN/EWOULDBLOCK/EINTR — это не разрыв, просто данных пока нет
                if (errno != EAGAIN && errno != EWOULDBLOCK && errno != EINTR) {
                    disconnect_client(i);
                }
                continue;
            }

            c->inlen += (size_t)valread;

            // Выделяем из буфера все ПОЛНЫЕ строки (оканчивающиеся на '\n')
            char *start = c->inbuf;
            char *end = c->inbuf + c->inlen;
            char *nl;
            int closed = 0;

            // Если ранее отбросили слишком длинную строку — пропускаем её остаток до ближайшего '\n'
            if (c->skip) {
                nl = memchr(start, '\n', (size_t)(end - start));
                if (nl == NULL) {   // конец строки ещё не пришёл — выбрасываем всё
                    c->inlen = 0;
                    continue;
                }
                start = nl + 1;
                c->skip = 0;
            }

            while ((nl = memchr(start, '\n', (size_t)(end - start))) != NULL) {
                *nl = '\0';
                if (nl > start && nl[-1] == '\r') nl[-1] = '\0'; // поддержка \r\n
                if (process_line(i, start)) {
                    closed = 1; // клиент отключён (/quit) — остаток буфера не нужен
                    break;
                }
                start = nl + 1;
            }
            if (closed) continue;

            // Недочитанный «хвост» (неполная строка) переносим в начало буфера
            c->inlen = (size_t)(end - start);
            memmove(c->inbuf, start, c->inlen);

            // Буфер заполнен, а '\n' так и нет — строка слишком длинная, отбрасываем
            if (c->inlen == sizeof(c->inbuf) - 1) {
                send_str(sd, "*** Слишком длинная строка, она отброшена. ***\n");
                c->inlen = 0;
                c->skip = 1; // остаток этой строки (до '\n') тоже выбросим
            }
        }
    }

    close(listen_fd);
    return EXIT_FAILURE; // сюда попадаем только после ошибки select()
}
```

## Подглава 28.1.4: Исходный код клиентского приложения (`client.c`)

Клиент использует вызов `select()` для асинхронного одновременного отслеживания клавиатурного ввода пользователя (`STDIN_FILENO`) и входящих сетевых сообщений от сокета `sock_fd`.

> 💡 Ввод с клавиатуры читается через `read()`, а не через `fgets()`. Причина: `fgets()` использует собственный буфер библиотеки stdio и может забрать из ввода сразу несколько строк, а `select()` об оставшихся в этом буфере строках ничего не знает. Разбивать ввод на строки не нужно: границы сообщений определяет сервер по символу `\n`.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <signal.h>
#include <sys/types.h>
#include <sys/socket.h>
#include <sys/select.h>
#include <netinet/in.h>
#include <arpa/inet.h>

#define SERVER_IP "127.0.0.1"
#define PORT 8888
#define BUFFER_SIZE 1024

// Отправка всего буфера (send() на блокирующем сокете может отправить меньше, чем просили)
static int send_all(int fd, const char *buf, size_t len) {
    size_t total = 0;
    while (total < len) {
        ssize_t n = send(fd, buf + total, len - total, 0);
        if (n < 0) {
            if (errno == EINTR) continue;
            return -1;
        }
        total += (size_t)n;
    }
    return 0;
}

int main(int argc, char *argv[]) {
    signal(SIGPIPE, SIG_IGN);

    const char *ip = (argc > 1) ? argv[1] : SERVER_IP;
    int port = (argc > 2) ? atoi(argv[2]) : PORT;
    if (port <= 0 || port > 65535) {
        fprintf(stderr, "Неверный номер порта: %s\n", argv[2]);
        return EXIT_FAILURE;
    }

    // 1. Создание сокета
    int sock_fd = socket(AF_INET, SOCK_STREAM, 0);
    if (sock_fd < 0) {
        perror("Ошибка вызова socket()");
        exit(EXIT_FAILURE);
    }

    // 2. Настройка адреса сервера
    struct sockaddr_in server_addr;
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons((unsigned short)port);

    // inet_pton() возвращает 0 при неверном формате адреса (errno при этом не меняется), поэтому perror() здесь не годится
    if (inet_pton(AF_INET, ip, &server_addr.sin_addr) <= 0) {
        fprintf(stderr, "Невалидный IP-адрес сервера: %s\n", ip);
        close(sock_fd);
        exit(EXIT_FAILURE);
    }

    // 3. Подключение к серверу (3-Way Handshake)
    if (connect(sock_fd, (struct sockaddr *)&server_addr, sizeof(server_addr)) < 0) {
        perror("Ошибка подключения к серверу (connect)");
        close(sock_fd);
        exit(EXIT_FAILURE);
    }

    printf("===================================================\n");
    printf("  УСПЕШНОЕ ПОДКЛЮЧЕНИЕ К ЧАТУ %s:%d\n", ip, port);
    printf("  Введите сообщение и нажмите Enter. /quit для выхода.\n");
    printf("===================================================\n\n");

    fd_set readfds;
    char buffer[BUFFER_SIZE];

    // Главный цикл клиента
    while (1) {
        FD_ZERO(&readfds);
        FD_SET(STDIN_FILENO, &readfds); // Отслеживание ввода с клавиатуры
        FD_SET(sock_fd, &readfds);      // Отслеживание сообщений от сокета

        int max_fd = (sock_fd > STDIN_FILENO) ? sock_fd : STDIN_FILENO;

        int activity = select(max_fd + 1, &readfds, NULL, NULL, NULL);
        if (activity < 0) {
            if (errno == EINTR) continue; // прервано сигналом: readfds недействителен
            perror("Ошибка вызова select()");
            break;
        }

        // А. Поступили сообщения от сервера
        if (FD_ISSET(sock_fd, &readfds)) {
            ssize_t bytes_read = recv(sock_fd, buffer, sizeof(buffer) - 1, 0);
            if (bytes_read == 0) {
                printf("\n*** Соединение с сервером закрыто. ***\n");
                break;
            }
            if (bytes_read < 0) {
                if (errno == EINTR) continue;
                perror("Ошибка чтения recv()");
                break;
            }
            buffer[bytes_read] = '\0';
            fputs(buffer, stdout);
            fflush(stdout);
        }

        // Б. Пользователь ввел текст в консоли
        if (FD_ISSET(STDIN_FILENO, &readfds)) {
            ssize_t n = read(STDIN_FILENO, buffer, sizeof(buffer));
            if (n == 0) {
                break; // Ввод закрыт (Ctrl+D / EOF)
            }
            if (n < 0) {
                if (errno == EINTR) continue;
                perror("Ошибка чтения с клавиатуры");
                break;
            }
            if (send_all(sock_fd, buffer, (size_t)n) < 0) {
                perror("Ошибка отправки send()");
                break;
            }
        }
    }

    close(sock_fd);
    printf("Чат-клиент завершил работу.\n");
    return 0;
}
```

## Подглава 28.1.5: Автоматизация сборки через `Makefile` и Инструкция по запуску

## Подглава 28.1.6: Чек-лист сетевого инженера при разработке TCP-серверов

1. **Игнорируйте сигнал `SIGPIPE`:**  
   Вызов `signal(SIGPIPE, SIG_IGN);` обязателен. По умолчанию запись в сокет, который клиент уже закрыл (и ответил `RST`), приводит к мгновенной гибели процесса сервера по сигналу `SIGPIPE`. (В Linux альтернатива — флаг `MSG_NOSIGNAL` в `send()`.)
2. **Переводите сокеты в неблокирующий режим (`O_NONBLOCK`):**  
   Сам `recv()` после сообщения от `select()` о готовности обычно не заблокируется, а вот `send()` в сокет медленного клиента (чей буфер приёма переполнен) **остановит обработку всех остальных клиентов**. Кроме того, `select()` изредка сообщает о готовности ложно (например, клиент успел отменить соединение до `accept()`).
3. **Устанавливайте опцию `SO_REUSEADDR`:**  
   Позволяет перезапустить сервер сразу, не дожидаясь, пока закончится `TIME_WAIT` (в Linux — 60 секунд) у старых соединений на том же порту.
4. **Проверяйте возвращаемое значение `recv()`:**  
   * `> 0`: прочитаны данные (может быть часть сообщения или несколько сообщений).
   * `== 0`: клиент прислал TCP `FIN` (чистый разрыв) — отключайте клиента.
   * `< 0`: если `errno` равен `EAGAIN` / `EWOULDBLOCK` / `EINTR` — это **не** разрыв, просто данных пока нет; любая другая ошибка — отключайте клиента.
5. **Не полагайтесь на границы `recv()`:**  
   TCP — поток байтов. Накапливайте данные в буфере клиента и обрабатывайте только целые строки (до `\n`).
6. **Защищайтесь от выхода за границы буферов:**  
   Не выходите за размер буфера при `recv()` (оставляйте место под завершающий `'\0'`, если работаете со строкой) и используйте `snprintf` вместо `sprintf`.
7. **Проверяйте `fd < FD_SETSIZE`** перед `FD_SET()`: иначе запись за пределы `fd_set` (UB).
8. **После `select()` с ошибкой `EINTR` не используйте `readfds`** — набор в этом случае не определён; повторите цикл.

## Подсказки и решения к практическим задачам

* **Подсказка к Задаче 1:**  
  Добавьте ветку в `process_line()` **до** блока «Обычное текстовое сообщение»:
  ```c
  if (strncmp(line, "/msg ", 5) == 0) {
      char target_nick[NICK_LEN];
      char msg_text[BUFFER_SIZE];
      // ширина в формате защищает от переполнения: 31 символ ника (+ '\0') и 1023 символа текста
      if (sscanf(line + 5, "%31s %1023[^\n]", target_nick, msg_text) == 2) {
          int target_fd = -1;
          for (int j = 0; j < MAX_CLIENTS; j++) {
              if (clients[j].fd > 0 && strcmp(clients[j].nick, target_nick) == 0) {
                  target_fd = clients[j].fd;
                  break;
              }
          }
          if (target_fd > 0) {
              char pm[BUFFER_SIZE + NICK_LEN + 32];
              snprintf(pm, sizeof(pm), "[ЛС от %s]: %s\n", clients[i].nick, msg_text);
              send_str(target_fd, pm);
          } else {
              send_str(sd, "*** Пользователь с таким ником не найден. ***\n");
          }
      } else {
          send_str(sd, "*** Использование: /msg <ник> <сообщение> ***\n");
      }
      return 0;
  }
  ```

* **Подсказка к Задаче 2:**  
  Используйте `time(NULL)` для получения текущего времени в секундах; при подключении клиента сразу записывайте его в `last_activity`. Структуру `struct timeval tv = { .tv_sec = 5, .tv_usec = 0 };` нужно **заново заполнять перед каждым вызовом** `select(max_fd + 1, &readfds, NULL, NULL, &tv)`, потому что Linux уменьшает её значение. Проверку `if (now - clients[i].last_activity > 60) disconnect_client(i);` выполняйте для всех клиентов на каждой итерации цикла, в том числе когда `select()` вернул `0` (тайм-аут без событий).

* **Подсказка к Задаче 3:**  
  `poll()` снимает ограничение `FD_SETSIZE` (1024): `select()` умеет работать только с дескрипторами, номера которых меньше 1024, а в `poll()` номер дескриптора — просто поле структуры `struct pollfd`, и размер массива ограничен лишь вашей памятью. Кроме того, не нужно заново собирать битовые маски перед каждым вызовом (достаточно массива `fds[]` с полями `events`/`revents`). Но `poll()`, как и `select()`, на каждом вызове просматривает все дескрипторы (O(n)); этот недостаток устраняет `epoll()` в Linux.
